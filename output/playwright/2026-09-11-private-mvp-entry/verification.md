# 私有 MVP 入口验证

2026-09-11，独立分支 `feat/private-mvp-entry`。生产构建预览为 `http://127.0.0.1:4317`，浏览器会话 `scenedesk-release-entry`，连接现有本地 API、数据库与本地 OIDC 测试身份。该记录验证入口与导航切片，不代表真实用户、真实 AI 或部署验收。

## 已验证行为

| 范围 | 实际检查与结果 |
|---|---|
| 默认入口 | 本地 OIDC 登录后，单个可访问工作室直接落到项目列表；无原型、创建工作室、成员设置或费用入口 |
| 项目创建 | 页面实际创建测试项目，API 重读确认已保存；负责人由当前身份确定，用户不必进入成员运营流程；完成后直达 `/content` |
| 项目往返 | 项目列表“进入项目”直达剧本与集场镜；“全部项目”“项目设定”均可返回；列表标题不残留前一项目名称 |
| 项目搜索 | 搜索无匹配显示明确空结果，“清空搜索”恢复完整列表 |
| 设置与版本 | 新项目实际并发更名后，已打开的归档确认提交旧版本并收到 HTTP 412；弹窗继续显示原对象，项目保持 active；“关闭并核对最新项目”返回新项目，重新打开确认后使用新对象 |
| 后置与未知地址 | 工作室 members、billing，项目 editing、delivery 显示未开放说明；返回链接可进入项目或集场镜 |
| 原型与旧全局地址 | 正常发布构建中 journey、settings、register、appish 均不会打开原型；检查构建产物没有 CutWorkspace、Prototype、Journey、DesignPage 或旧 WorkspacePages 模块文件 |
| 无工作室与未登录 | 单独使用只读响应夹具验证展示。无工作室时可刷新访问、退出，没有工作室创建；未登录时只有私有登录路径，没有设计原型入口；结束后恢复真实本地会话 |
| 实际布局 | 1512×982 项目列表、1366×900 归档冲突、390×844 列表／空内容／设置／未开放入口／未开通访问／登录页面；文档和 shell 无横向溢出，主区域未越出视口；截图经目视检查 |

[主流程结果](flow-results.json)记录真实项目创建和路由检查。[最终结果](final-results.json)记录最终文案、明确冲突恢复、标题、空状态及布局。最终脚本捕获到的业务写请求仅为该测试项目的更名和旧版本归档尝试；没有模型或媒体处理写请求。两组脚本均无 `pageerror`；测试中的预期 412、登录展示夹具 401 与首次预览别名的 403 不当作应用 JavaScript 错误。

## 运行条件与证据边界

API 只接受已配置的本地 `4311` Origin。隔离的 `4317` 预览首次写请求被正确拒绝。随后只在此 Playwright 会话的测试传输层转发写请求，将 Origin 适配为已配置的 `4311`；HTTP 响应和事务来自真实 API，CSRF、会话、项目访问和 CAS 仍由服务端执行。产品校验没有放宽。这不能替代真实部署时前后端同源配置的验收。

“无工作室”和“未登录”是明确的展示夹具：只替换对应列表／会话读取，不撤销其他正在使用本地服务的测试身份，不把这两项称为服务端授权验收。实际项目创建、并发更名、归档冲突与导航使用真实本地业务。测试项目 ID 为 `cc5f1072-ffbc-46a5-bbe0-61d8a83b5f4f`，名称带“私有入口验收”；现有业务场次未修改。

最后的 `npm run check` 通过契约同步、UI 规则、类型、生产构建与 48 项单元检查，0 失败、取消、跳过。该切片没有修改 API、SQL、存储、模型或媒体代码，因此没有新增数据库或媒体验收声明。GitHub 集成、远端 CI 和合并由主实施任务继续核对。
