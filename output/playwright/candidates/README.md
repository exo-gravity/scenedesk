# 候选与采用浏览器验收

`verify-candidates.js` 使用 Playwright CLI 的现有登录浏览器，连接本机生产构建 `http://127.0.0.1:4311`、真实业务 API、受限数据库角色和已验收四秒视频。脚本每次创建明确标记的技术验收场次与两个镜头，不修改原剧本场次；账号、工作室、项目和视频身份是本机夹具，不能当作空数据库 CI 脚本或客户验收。

覆盖：跨镜头草稿恢复，非法区间阻止提交，微秒区间归档，代理播放边界，实际 412 后保留理由并明确重核，成功采用后 IDB 删除失败只重试清理，重复归档去重，同视频两个镜头不同区间，改要求保留旧采用并显式沿用，新候选不自动采用，清除决定历史，以及 320px 下失效候选链接。

截图由实际生产构建生成，验收结果及限制见 [实现记录](../../../docs/implementation/35-candidates-and-adoption.md)。脚本不会输出会话、CSRF、签名地址或对象存储凭据。现有候选与决定是技术测试数据，全部保持历史。

`verify-navigation-receipt.js` 接续完整流程创建的场次，验证编辑期间要求更新后的明确重绑定，再延迟已提交归档的网络回复，确认切镜后不被旧回执拉回，且旧草稿清理完成。`verify-layout.js` 检查 1366×768、1512×982、320×740 的生产构建布局与分镜条位置。
