# 面向营销人员的广告视频 MVP v0.1

> 后续广告探索：本文保留客户假设与条件方案，不是当前短剧 MVP 的交付清单或已验证结论。当前阶段以[完整方案](ai-drama-workbench-product-design-v1.1.md)和[外部验证准备](implementation/20-external-validation-and-launch-plan.md)为准。

日期：2026-09-07。状态：围绕「如果广告 MVP 以营销人员为主用户」的条件方案。首批用户预期来自商家／教育机构；本稿建议尚不等于研发范围冻结，也不改变短剧 MVP 的发布优先级。教育在此指招生与课程推广。

最新范围：用户已明确整体长期支持广告与短剧，当前优先短剧设计、复用底层核心能力。本稿作为后续广告扩展参考，完整广告原型与试点不是当前短剧 MVP 的前置任务。整体基线见 [短剧优先方案 v0.2](ai-video-platform-mvp-plan-v0.2.md)。

## 1. 定位与首发用户

定位：帮助营销人员把已有商品／课程资料和素材，转成信息正确、可以修改、符合推广要求的短视频。

首发用户建议进一步限定为：负责实际内容制作、有重复推广需求、能提供并确认业务资料，希望自己完成视频的营销人员。专职投放优化、品牌战略和专业影视制作不共同定义首发流程。

核心任务：用户带着一次真实推广需求进入，完成资料确认、创意选择、视频制作、问题修改和交付，并能在下一次任务中复用资料与做法。

短剧和营销视频分别规划入口、术语、主要流程和验收，共用基础能力。独立入口可以位于同一品牌与平台，不要求先拆分研发团队或部署。

## 2. 首发任务范围

建议以「已有资料与素材的商品／课程推广短片」为任务范围，先从有真实试点客户的一个行业和一种视频形式开始。可用 15–45 秒竖版作为样例规格讨论；这不是渠道规定、模型能力承诺或已确认范围。

优先支持现有图片／视频配合文案、旁白、字幕和必要的 AI 补充画面。营销人员确认商品、课程、价格、优惠、日期、品牌表达与行动引导等业务事实；系统提供表达建议。

复杂剧情广告、全新真人替身、长篇品牌影片、完整教学课程分别验证后扩展。首发具体行业、素材条件、时长与渠道仍需用样本确定。

## 3. 主流程与控制点

| 步骤 | 用户完成的决定 | 系统承担的工作 | 控制点 |
|---|---|---|---|
| 提供资料 | 上传素材／粘贴介绍，选择推广对象 | 提取、整理资料，提示缺少的关键信息 | 手动输入可完成流程；链接导入是可选便利 |
| 确认推广要求 | 确认事实、受众、主卖点、行动引导与规格 | 复用品牌资料，提出可选表达 | 区分用户确认事实和 AI 建议，缺失事实不自动编造 |
| 选择创意 | 比较少量开头和表达方向，修改脚本 | 提供例如 2–3 个文字／静态预览方案 | 数量是初始设计建议；选定方案后再进行主要付费生成 |
| 生成初稿 | 确认制作范围与预估费用 | 选素材、生成必要片段、组织声音字幕并组装视频 | 不要求用户先选模型、搭节点或逐镜写提示词 |
| 修改成片 | 指定具体文案、片段、声音或顺序的修改 | 展示修改范围，更新相关内容并保留旧版本 | 支持替换片段和恢复原版本，修改影响范围可见 |
| 核对与交付 | 检查品牌与业务信息、观看完整视频、确认导出 | 提供约定规格、字幕与封面，记录交付版本 | 生成完成不自动等于已确认可发布 |

创意预览帮助用户在投入主要生成成本前做选择，不宣称能预测实际投放效果。用户先看建议再确认，减少从空白编辑器起步的负担。

## 4. 制作界面与修改能力

默认界面由成片预览、按顺序排列的内容片段、当前片段编辑区组成。片段可显示「开头、商品展示、主要卖点、行动引导」等业务含义，但不强制每条视频遵守完全相同的结构。

首版提供文案编辑、素材替换、片段增删与重排、基础裁切及声音调整。自然语言可以作为辅助入口；任何修改仍应定位到具体内容和版本。完整专业时间线和无限节点画布后续按真实需求引入。

局部修改按依赖处理：

- 改独立叠加的价格文字：更新对应文字层；如果旁白也读了价格，列出需要一起修改的声音与字幕。
- 替换商品展示片段：优先保留其他片段；必要时调整相邻衔接和声音长度。
- 改脚本：明确受影响的配音、字幕、画面及总时长，由用户确认修改范围。
- 生成片段内部的局部变化：仅在实际已接入能力支持时使用局部编辑，否则重做该片段并替换。

修改后的内容形成新版本，已确认交付的历史文件不被静默覆盖。资料更新时提示当前草稿与新资料的差异，不能声称所有历史视频自动同步。

## 5. MVP 能力与后续边界

| 首版必要能力 | 首版深度 | 后续扩展 |
|---|---|---|
| 商品／课程与品牌资料 | 手动整理、素材上传、事实确认、明确范围内复用 | 目录同步、复杂多品牌规则 |
| 营销需求与创意 | 一个推广需求、少量候选、可修改脚本 | 行业策略库、创意实验管理 |
| 成片制作 | 一种主形式、已有素材与必要生成、声音字幕和基础剪辑 | 更多形式、模型路径、精细编辑 |
| 修改与历史 | 片段替换、文案调整、依赖提示、保留历史 | 更强的语义编辑与自动影响分析 |
| 内容复用 | 复制已采用方案，替换资料后重新确认 | 多商品／课程矩阵、参数化批量生产 |
| 确认与交付 | 指定版本的内部确认、下载交付 | 渠道发布、效果回传、客户门户 |
| 团队与费用 | 现有简单内部角色、项目参与、费用预估、任务状态与失败恢复 | 工厂排产、复杂权限、跨组织协作 |

批量生成多种创意、自动投放与预算优化、完整归因、大型模板市场不作为首版条件。内容工厂可试用相同流程，先验证可复用性，不由其全部生产管理需求定义本次 MVP。

## 6. 模型与架构原则

Seedance 等领先模型继续优先评估。系统根据已验证的输入条件与制作任务采用默认路径，用户主要控制表达与内容；不在首版建设面向所有模型的自动优化路由。

优先保留需要准确展示的商品图、讲师／机构素材。Logo、价格、日期和字幕尽量使用可编辑文字／图形层合成。AI 生成适用于确有价值的补充画面；具体可用性仍通过真实素材验证。

营销方向独立维护业务资料、推广要求、创意与变体；共享租户、媒体、资产版本、生成任务、声音、剪辑、审阅和费用能力。业务流程模块分开，不提前建设复杂的通用流程搭建平台。

前台隐藏专业参数后，后台仍需保留实际输入、所用版本、候选采用、修改关系和费用。简单界面要求系统承担更多默认决策、质量检查与失败修正。

## 7. 如何判断 MVP 成立

主要验收：目标用户能否独立完成一个有真实用途的推广任务，并愿意用它完成下一次任务。

建议跟踪：

- 首次独立完成率：开始制作的目标用户中，完成并确认可用交付的比例；记录中途放弃原因。
- 从提供资料到可用成片的时间：拆分用户操作、生成等待与返工，避免只统计模型耗时。
- 每条可用成片总成本：包含未采用候选、返工、运行成本和人工支持；用户劳动与平台成本分别记录。
- 核心错误与修正成功率：业务信息错误、商品画面失真、字幕／声音问题，以及用户能否自己修好。
- 实际使用与重复任务：导出后是否用于预期场景，下一次真实制作需求是否继续使用。

用户确认可用与实际发布分别记录。点击生成、下载量和生成成功率不足以单独证明价值；销量、线索与投放效果需要真实发布数据和合适的比较方法。验收阈值先用试点基线确定，本稿不编造市场指标。

## 8. 迭代顺序

1. MVP：一个明确场景的自助制作、修改与交付闭环。
2. 重复生产：复用品牌资料、已采用方案与小批次创意变化，验证持续使用。
3. 专业生产：根据工厂客户证据加入批次、多人分工、多品牌管理和生产队列。
4. 分发与反馈：按客户实际渠道接入发布与效果数据，再决定是否进入投放管理。

商业验证同时关注客户愿意为何种价值付费、持续需求及人工支持成本，不因为生成单价可计算就直接确定收费套餐。

## 10. 广告子场景的推进参考

本节保留为后续广告侧任务的细化；当前整体执行顺序以 [短剧优先 MVP 推进方案](ai-video-platform-mvp-plan-v0.2.md) 为准。

当前处于广告 MVP 讨论阶段。以下是推进顺序，不是已完成的试点、已验证的模型效果或已承诺的开发排期。短剧方向的整体排期保持待定。

### 第一步：选一个真实任务，形成一页需求

优先选择能直接接触到营销人员、拿到真实资料并安排试用的场景。先邀请约 3 位同类用户，每人提供一个近期实际制作任务、原始资料、已有成片（如有）和当前制作方式。

一页需求只回答：谁使用、推广什么、有什么素材、要交付什么视频、允许怎样修改、怎样认定可用。先选电商或教育的一种具体任务，另一行业后续验证。

目前待补充的信息是：哪类真实试用用户更容易接触。如果暂时没有，可以用明确标记的示例资料先做演示原型；演示不能替代需求验证。

### 第二步：验证样片效果与操作流程

两个验证可以并行安排：

- 制作样片：用同一真实任务跑通素材、脚本、生成、声音、合成和一次典型修改，记录等待、费用及人工处理。优先评估 Seedance 的适用路径，具体执行取决于已选服务、账号与可用预算。人工辅助样片用于确认效果与技术可行性，不算用户自助完成。
- 可点击原型：只覆盖资料确认、创意选择、成片修改、导出四个核心界面。让目标用户尝试完成任务，观察信息是否够用、操作是否能理解。模拟生成与导出应明确标记，不将其计入实际完成率。

交付物为样片验证记录、四个核心界面的原型，以及据此收敛的一页开发范围。样片或流程不成立时，先调整任务范围或制作方式。

### 第三步：开发能从头到尾工作的首版

把一条流程做通：上传并确认资料 → 选择脚本 → 生成并组装初稿 → 修改文案／替换片段／更新相关声音字幕 → 导出。

首版固定一种主要视频形式与交付规格。保存、版本、费用提示、任务状态、失败恢复和简单内部权限随完整流程一起提供。画布、完整专业时间线、内容工厂批量排产、投放管理后续再安排。

开发顺序先实现单个任务的完整可运行路径，再补齐必要的修改与恢复操作；不以页面数量或模块全部完成作为可用的判断依据。

### 第四步：小范围真实试用并决定下一轮

建议先安排约 3–5 位同类营销人员，用真实任务独立操作。记录完成者与未完成者、人工帮助、可用性确认、耗时、总成本、实际用途及下一次任务是否继续使用。这些人数是试点安排建议，不代表统计显著性。

优先修复阻止独立完成的共同问题，再决定增加模板、批量能力或另一个行业。真实发布由用户在自己的渠道操作；试用阶段不默认建设自动发布或投放功能。

当前最先需要的交付物是一页样板任务定义；此后用样片和四屏原型把范围具体化，再确定开发任务和排期。排期需要研发人数、现有基础与模型服务条件，当前不作无依据的工期承诺。
