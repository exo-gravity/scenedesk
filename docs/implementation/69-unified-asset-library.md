# 统一资产库前端

对应[用户接受方案](../design/unified-asset-library-2026-09-15.md)。本切片复用既有 assets、asset_revisions、shared_imports 与 media 服务，不修改数据库约束、固定引用或供应商执行行为。

## 实现范围

- 资产与媒体页共用范围、分类、搜索导航，统一从资产库进入。旧 `/media` 和确切资产/素材详情链接仍可解析；新浏览链接采用 `/assets?type=…`。项目进入共享时保留项目导航和返回范围。
- 类型标签直接表达内容；低频文本与声音设定收在“更多”。搜索条件保留在 URL；媒体上传本机恢复仍使用原来的范围键，不因导航改名遗失记录。
- 项目自建资产与已引入的共享固定版本共用图库。共享引入记录从确切修订读取封面与设定；分页继续加载，未加载全部时不声称不存在匹配的共享资产。
- 详情默认阅读和预览，历史/确认、直接使用位置及固定参考来源按需展开。保留新修订、历史确认、归档和草稿恢复。
- 图片关联角色通过明确选择和编辑草稿完成，新固定版本仍需人工保存，不通过浏览或查询参数自动写入。

## 验证与发布

最终产品源 `76931826f4c3bfe3f0c8fb4d872b3e837ccf7c7a` 的契约、UI 规则、类型、生产构建和 240 项测试通过。实际浏览器覆盖固定共享历史封面、搜索/分类刷新、图片加入角色及新修订恢复、历史确认、上传历史、播放、错误重试、桌面/窄屏/深色；细节与限制见[UI 证据](../../output/playwright/2026-09-15-unified-library/README.md)。测试在独立 API、PostgreSQL 与私有存储中进行，隔离资源清理成功，无真实模型调用。

项目导航按用户最后要求固定为「剧本 → 场次 → 资产」。完整本地服务 4311 已更新到同一不可变构建，入口哈希与验收构建一致，API ready 正常；未修改真实演示及新创作项目。GitHub CI 和合入事实以本片 PR 为准。

## 保留边界

不改变媒体与创作资产的领域身份、服务器授权、不可变修订与明确引入。共享图片关联目前在共享角色范围、项目图片在所属项目角色范围选择；不新增私有资产发布共享、独立复制或素材反向使用索引。文本分类提供原文件下载，未扩展成在线文档。大量分页、并发冲突及全部权限负例本轮未重新进行浏览器验收。
