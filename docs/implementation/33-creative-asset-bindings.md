# 场次、镜头与台词的实际资产引用

本切片在已导入素材和人工资产设定上工作，不调用付费模型。将原先拒绝所有资产引用的占位校验替换为实际的权限、固定版本、种类、造型和媒体归属检查。完整 MVP 的其余工作仍见[实施进度](22-implementation-progress.md)。

## 可操作行为

剧目和场次可以选择默认资产固定版。场次、镜头入口和出口分别编辑角色状态、固定造型、声音覆盖及道具状态。角色身份、造型 ID 与父资产固定版有不同含义；后两者必须成对保存且属于该角色。道具持有人省略表示沿用上层，显式空值表示无人持有，两者不会混为一谈。这里记录预期状态，不建立成片已满足连续性的事实。

台词保留稳定行标识、原文依据和来源关系，可以明确说话人和该句声音固定版。单句覆盖不修改场次声音、角色默认声音或既有镜头要求。镜头参考支持导入素材及从某个资产固定版选取素材，记录用途、固定来源和对应资产身份。项目样片参考单独保存，使用项目版本校验，不占用虚构的场次或剧目身份。

共享资产先明确引入所选固定版，再用于项目。引入 v1 不自动引入 v2，资产当前指针也不会升级场次或台词的旧引用。归档停止新引用；原来同一使用位置、同一资产／媒体／用途的引用可以保留或修改说明。把归档引用移到另一位置、移除后重新加入，都会作为新引用拒绝。

## 持久化与权限

迁移 `0010_creative_asset_bindings.sql` 新建 `creative_references`、`creative_asset_bindings` 和 `project_quality_references`。前两者只允许剧目、场次、镜头固定修订三种实际使用者，恰有一个非空，并分别用项目复合外键限定。状态绑定额外记录资产身份、固定版及造型外键，不能以任意 target type/id 绕过归属。

受限运行角色调用的数据库触发器从真实使用者文档派生关系。手工编辑与提案采纳使用同一校验边界，提案保存时验证、采纳时再次验证；期间资产归档会使整次采纳回滚。提案的临时标识不是真实镜头身份，即使恰好等于已有镜头 UUID，也不能继承该镜头的归档引用或隐含台词历史；来源镜头必须明确记录。镜头固定修订的台词关系也由数据库从 ShotSpec 同事务生成，包含说话人和声音固定版，不允许接口 JSON 与行投影各写一套值。修改剧目／场次只替换当前关系；镜头旧修订及其全部引用保持不可变。直接伪造、删除仍有效的投影或修改历史会被拒绝。

行级权限按实际所属项目计算。共享资产的使用位置列表不会泄露无权查看的私有项目；返回真实场次、剧目或镜头固定版，镜头附带所属镜头身份以定位历史。当前权限检查在命令重试及幂等缓存返回前执行。

## 编辑恢复

场次、镜头、剧目默认资产和项目样片的输入保存在本标签页的本地草稿。场次／镜头兼容旧格式草稿，新增字段只在旧草稿缺失时从当前文档补足。保存仍使用对象版本，新增内容仍使用内容树版本。

冲突后保留输入，展示服务器当前内容供核对，再由用户明确更新基线。角色、道具、台词按稳定身份合并，未修改字段采用服务器值，双方修改同一字段时保留本地输入；不自动换用最新资产或声音。移除与显式无人持有同样参与合并。字段合并只发生在人工复核操作后。
