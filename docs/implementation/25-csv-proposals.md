# CSV 导入、提案修订与采纳

2026-09-10：E02 的无模型导入切片。依据 [14 的提案规则](14-scene-mvp-closure.md#4-提案直接进入当前场次)；后续正式创作依据、场次主责、AI 分析仍单独实施。合入状态见 [实施进度](22-implementation-progress.md)。

## 用户可完成的工作

在集场镜页面打开「CSV 与提案」，选择 UTF-8 文件或粘贴 CSV。必填列 `episode,scene,shot_label,intent`，可选 `dialogue,duration_seconds,notes`；页面展示固定列映射及可下载模板。带引号的逗号、换行、BOM 保留；非法引号、缺列、重复／未知列、跨场追加、非法时长会报错，整批不创建内容。

`new_structure` 按提案内明确的父子关系创建独立单集、场次、镜头；同名既有对象在最终确认中提示，不按名称合并。`append_to_scene` 固定场次、单集与场次修订，所有输入必须来自一个来源场次；页面明确映射，服务端只在既有镜头后追加，不接受自报位置覆盖现有顺序。

导入保存为可找回的提案；可以改名称、场次概述、镜头意图、台词、预计时长与说明，再保存新的人工修订。原始第 1 版和旧修订可只读查看。勾选采纳前检查父项；用户确认本次新增数量后，才创建所选内容。已采纳提案显示每项「已创建／未采纳」，不能继续用另一组选择采纳；当前已创建镜头在集场镜中继续编辑。

导入表单、提案编辑、单项编辑与勾选在当前用户、项目和标签页的 IndexedDB 草稿中恢复。恢复不是服务器保存；并发修订必须明确核对，失败保留输入。此恢复范围沿用 [内容草稿约束](24-content-structure.md)，不是跨设备备份。

## 数据与事务

- `0005_proposals.sql` 保存原始 CSV、SHA-256、导入指纹、可变生命周期根、不可变人工修订及永久采纳结果；复合外键和强制 RLS 限定项目。受限 API 角色无权更新或删除原始来源、修订与采纳记录，数据库触发器也保护来源及历史。
- 同一来源摘要、规范化目标和内容基线复用同一提案。项目写锁串行化导入；指纹唯一约束兜底。手工改变目标／基线会更新当前指纹，历史保持原值；若与已有提案重复返回冲突。
- 修改使用提案 CAS；基线必须由调用方明确提供当前值。保存时固定完整 `ContentTree` 快照，读取详情可比较当前内容，服务端不自动刷新过期基线。
- 采纳同一事务内检查内容根 CAS、提案修订、保存基线、目标归属／修订、所有操作及所选依赖，再按单集、场次、镜头顺序调用共享创建命令。只递增一次内容根；任一错误整体回滚。
- 临时 UUID 仅表达提案内部身份，实际对象由服务端另行分配。新结构的同级顺序按提案位置稳定排序后追加；追加到场次严格按提案操作顺序。现有对象、位置与镜头要求版本不变。
- 固定 `proposal_applications` 将操作 ID 映射到实际对象，记录所选集合、提案修订和结果内容版本。24 小时幂等响应保存期之外，生命周期与永久采纳唯一记录仍防止重复创建。相同请求键重放原响应。
- 非法父项、归档创建、重复 ID、来源删除或越权引用被拒绝。操作级原文证据采纳时进入镜头固定要求；原始 CSV 及所有人工编辑留在提案历史。资产建议在资产库建立前明确拒绝。

解析器固定使用 MIT 许可的 `csv-parse@7.0.2`，不添加下游依赖；采用[同步解析 API](https://csv.js.org/parse/api/sync/)处理最多 500,000 码点的有界输入，启用[严格列数、BOM、记录长度及行号选项](https://csv.js.org/parse/options/)。时长以十进制字符串转 BigInt 微秒，最后检查安全整数范围；文本不作公式或脚本执行。

## 契约补充

在同一 MVP 范围内补充只读可选 `Proposal.baseContentSnapshot` 和 `Proposal.application`（`ProposalApplication`），用于真实差异复核及关闭页面后找回部分采纳结果。详情／历史返回，列表可省略；历史提案内容仍使用指定号码，生命周期及采纳事实始终反映当前根。写入类型不接受这些服务端字段。

修改源是 `build_contract.py`，并重新生成 OpenAPI 与 TypeScript；新增接口数量为零。五个已实现操作：`importShotList`、`listProposals`、`getProposal`、`editProposal`、`applyProposal`。分页游标绑定当前用户、项目和所有筛选条件，不能跨查询复用。
