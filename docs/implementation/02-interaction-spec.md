# 02 信息架构与关键页面行为

状态同步（2026-09-10）：核心页面与导航已确认，四项[制作专项](../design/production-detail-design-v0.4.md)评审暂无异议、暂时收口；真实用户验证与业务实现仍待执行，正式工程保持暂停。

本文件规定 MVP 页面行为。场次镜头制作提供分镜模式与自由画布，新增画布交互见[场次画布设计](../design/scene-canvas-interaction-v0.1.md)。UX-01 验证具体操作及默认呈现，当前设计仍待目标用户试点。需求编号引用 [产品需求](01-product-requirements.md)，任务与试点见 [12](12-mvp-workflows-and-pilot.md)。桌面网页优先，窄屏以查看、评论与状态为主，复杂制作的移动端交互后续独立评价。

## 1. 导航和工作区

**最新范围优先于原画布后置判断：** 每场次镜头制作同时提供分镜模式／自由画布，共用素材、任务、候选、剪辑及固定稿审阅。制作区工具栏切换模式，顶部工作入口不变。节点位置与镜头排序独立；有镜头关联时定位同一对象，无关联探索内容通过可收起入口保留。细节以[场次画布交互](../design/scene-canvas-interaction-v0.1.md)为准；持久化与 API 设计已补入[18](18-canvas-workspace-contract.md)，业务原型尚未实现这些服务端行为。

工作室常驻导航：项目、我的工作、资产；用量、成员与设置放低频入口。项目目录：场次、剧本与设定、项目资产、整集与交付；默认按集查看场次，规格／成员／预算从项目信息或设置进入，不增加必经的概览仪表盘。场次标题旁提供“镜头制作／剪辑”两个编辑视图；右侧用“审阅稿 v1 · 待修改”这类带版本与状态的入口进入完整审阅工作区，不再将审阅列为第三个同级编辑页签。三类能力共享项目、场次与镜头身份，审阅明确绑定固定版本；不重复建三套业务对象。“我的工作”是待处理作业、待审稿和评论关联轻任务的聚合，不另建复杂项目管理中心。

场次编辑与固定稿入口的关系于 2026-09-09 确认，2026-09-10 的导航与连续体验进一步收口，当前以[核心体验 v0.3](../design/scene-walkthrough-review-v0.3.md)和[确认范围](../design/approved-baseline-2026-09-10.md)为准。视图切换不是强制工序。预览整场针对当前剪辑草稿，审阅入口针对其标明的固定稿；无固定稿时显示“尚无审阅稿”，在剪辑中固定并提交后才产生可进入的审阅目标。默认入口展示最新固定稿的真实状态，旧版本在审阅工作区选择；从待审任务直接进入其指定版本，不重定向至最新稿。返回编辑恢复原场次、镜头和未提交输入。

主要路径为“继续制作当前场次”。工作室及项目名始终可见；深链接恢复项目、场次和选中对象，服务端重新授权。保存最近位置属于用户偏好，不改变项目内容。

当前已确认布局：进入场次后收起项目目录，保留顶部上下文与返回；分镜使用当前镜头大预览、中央底部有界输入和底部分镜条，自由画布保留整场节点与独立探索。助手及持续资产浏览非模态停靠，窄桌面不并列两个完整辅助栏；短参考选择器可以就近展开，具体规则见18。生成计划在当前上下文检查，任务进度不遮挡内容。默认定位最近制作或待处理镜头，先看当前采用和最近结果，历史折叠。显示上下文所需信息，不同时展开全部参数。支持键盘焦点、明确文字状态和加载提示；不能仅用颜色表达已采用或有风险。

## 2. 页面清单

| 页面 | 默认内容与主要操作 | 空／忙／异常状态 |
|---|---|---|
| 登录与邀请 | 账号登录、接受内部邀请、选择工作室 | 失效邀请、邮箱不匹配、已接受显示不同原因；不自动按邮箱域加入 |
| 工作室项目 | 有权项目、负责人、最近活动、我的待办；管理者新建 | 空项目引导创建／联系管理员；无项目权限不显示项目存在细节 |
| 项目信息／设置 | 规格、成员、预算；场次和交付概况归各自页面，不作进入制作的必经概览 | 未设质量参考提示待补；归档状态只读；汇总不同制作状态而非一个完成率 |
| 剧本与设定 | 文本／固定 CSV 录入预览、修订、文本选区分镜建议、人工结构修改 | 新增提案不覆盖同名对象；依赖和行错误可定位；过期提案不能直接应用 |
| 项目／共享资产 | 媒体显示名／标签搜索、固定版本、上传、引入、直接使用位置 | 设定 draft 可试作并有标签；新引用媒体须 ready 且有权使用；共享不暴露来源项目 |
| 分镜工作台 | 镜头意图、入／出状态、台词、参考、计划、候选与采用 | 缺输入、能力不支持、预算不足、排队、提交待核对、媒体恢复分别展示 |
| 候选查看 | 原尺寸查看、播放、版本信息、区间选取、继续尝试 | 来源输入过时标签；失败作业没有伪媒体卡；候选多时按镜头收纳 |
| 剪辑与声音 | 大预览＋分镜条、局部裁切、两种替换模式、声音／字幕编辑、预览与固定版本；底层有轨道数据，首版不铺完整多轨 NLE 界面 | 不同画幅显式选择 contain／cover；未处理替换影响阻止应用为可渲染稿，但允许工作稿保存恢复；未保存与已渲染状态分开 |
| 审阅 | 固定播放器、时间码意见、来源跳转、返工处理清单与决定 | 目标文件未就绪不能批准；旧意见不漂移到新时间码；关闭后仍可读历史 |
| 交付 | 从采用导出源素材包、有剪辑时附预览、外部 MP4／SRT 回传和最终交付 | 无时间线不阻断源包；工作材料与最终交付不同标签；失败恢复原包不生成新素材 |
| 我的工作 | 评论关联轻任务与生成／待审状态分别显示，定位目标和处理结果 | 无任务不等于无制作内容；执行完成不代表批准，自动状态不能手工覆盖 |
| 设置与用量 | 成员、角色、连接健康、预算、预占和实际消费 | 不显示密钥；连接失效阻止新执行，旧任务仍可核账；未知消费单独显示 |

本文所说供应商结果“入库存储完成”对应媒体 ready；媒体 archived 是另一个归档状态，不能把二者混为一谈。新引用或生成输入须 ready；已有归档媒体的保留、移动与权限撤销按[18 的引用规则](18-canvas-workspace-contract.md#3-逻辑存储与不变量)处理。

## 3. 首次成功路径

新建项目表单先填名称；负责人默认预填创建者对应成员，规格默认值可修改，预算由管理者设置。项目首页列出连接、预算和必要资料的就绪状态及可处理人。未填完整剧目设定也可以进入某一场次；管理员预先完成连接和预算是明确的试点准备工作，不藏在演示数据里。

资料入口有三种，创建结果都回到同一个分镜工作台：

| 输入 | 用户动作 | 固定结果与异常恢复 |
|---|---|---|
| 已有剧本文本 | 粘贴或导入 UTF-8 文本，保存修订；选中一段文字后请求分镜建议，明确追加到当前场次或新建结构 | 展示固定修订、所选原文与明确附带上下文；AI 只提出 create 操作，不能修改／归档已有对象 |
| 已有分镜 | 使用固定字段 CSV，上传后逐行预览集／场次／镜头映射 | 必填 episode、scene、shot_label、intent；可带 dialogue、duration_seconds、notes；错误指向行／列，确认后新增 |
| 少量手工内容 | 就地新增集、场次和镜头，逐项填写必要要求 | 保存成功即能准备参考；人工编辑、移动、排序和归档继续可用 |

CSV 提供可下载模板和以下完整最小示例，首版不承诺任意 Word／PDF／表格格式解析：

```csv
episode,scene,shot_label,intent,dialogue,duration_seconds,notes
第1集,咖啡厅,SH-01,双人中景建立位置关系,你到了吗？,6,先核对人物位置
```

提案列表展示待新增内容和对应原文，可保存人工修改并重开；勾选子对象时一并展示必须创建的父对象，确认前可取消。同名集／镜头编号不作为覆盖依据；提案 target 明确区分新结构与追加到已有场次。当前场次入口默认后者，显示固定 episodeId／sceneId 与基线，只新增镜头；CSV 追加时所有选中行必须明确映射同一目标场次，跨场混入先拒绝并提示分批或新建结构。重复提交同一次采纳不会重复建立结构；基线变化保留当前选择并要求重新检查。首版界面不提供 AI update/archive 重拆入口，用户可人工修改已有结构。

镜头最初只需意图、动作／对白、必要参考与模式要求。当前镜头显示可填写的入场／出场状态，以及前一镜头已知出场状态；未知项留空或标未知，不自动推断为连续。台词条目保留说话人和表演要求，后续可关联已采用声音／字幕。景别、运镜和精细控制按任务展开。

缺参考时在当前人物／用途旁点击“导入并用于此处”，验收成功后选择固定版本并回到原镜头。draft 标签说明可在项目内试作；“确认资产”不阻挡生成。只有已核验且本任务需要时才提供图像／声音生成入口。参考或服务不满足模式时解释具体缺项和可执行动作。

首次成功路径继续到：导入或生成可播放视频→选择合法区间→明确采用→加入第一份剪辑草稿或直接导出源素材包。内部切片先走导入素材路径，真实模型接入后使用同一候选／交接流程。多个镜头可作为一次制作范围，但输出仍由人标定区间，不假定模型返回精确切点。

## 4. 生成前检查面板

展示范围、来源规格版本、最终提示、引用素材预览、人物／对象与用途、模型配置、输出要求、预计费用和估计有效期。每项显示来自剧目、场次、镜头还是“仅本次”；不同人物身份与造型分别列出，不能仅给一组难以辨认的图片。

按同一人物／对象和用途解析输入：镜头明确选择优先于场次，场次优先于剧目；一次性计划修改在当前计划中最后生效。替换、追加、仅本次不使用分别显示，冲突无法可靠解析时让用户明确选择，不静默丢弃。详细语义依 03／06 的契约执行；平台表达的身份、动作等含义不等同模型必然独立支持的参数。

修改表演文本或参考默认标记“仅用于本次尝试”，返回再准备计划仍保留这些修改及排除项；显式“保存到镜头要求”才更新镜头并重新准备。已提交计划不编辑，从它继续尝试建立新计划。重新准备时显示真正参与输入的来源差异；无关镜头排序不应令整项目计划失效。有关输入变更也不自动提交新付费任务。

正式按钮文案为“按此计划生成”，明确此次会产生费用。以下情况不可提交：输入媒体未 ready／越权、必要参考缺失、能力未启用、估计或配置已过期、预算不足、输入版本已变化。对确实允许的高费用操作使用已有项目预算与单批次确认，不无限新增审批环节。

提交按钮本地禁用只改善体验；实际重复保护由服务端幂等负责。提交响应丢失时使用同一请求键查询／重发；已有作业进入“正在核对提交结果”时不提供普通重新生成按钮，可另开新尝试但必须明确原费用仍可能发生且预算已计入。

## 5. 候选与采用

默认同镜头收纳候选，先看当前采用和最近结果，再展开历史。预览、采用、剪辑使用与审阅状态分别表示，查看过不等于采用。视频对比首版支持顺序播放／切换，不提前承诺帧级同步比较。候选显示可识别名称、尝试序号、来源要求和费用状态。

采用操作必须包含媒体使用区间；连续素材拆成多个候选时各自保存区间，不复制媒体文件。当前镜头规格已变时，展示候选对应旧规格及差异，允许明确沿用旧结果：建立关联到当前要求的新候选，并保留 sourceTakeId，再执行采用，不假装旧结果已自动满足新要求。

采用成功后提供“加入剪辑”“更新已有草稿”“导出精剪素材包”，允许关闭后稍后处理。源素材包从已采用的媒体和区间建立固定快照，无须已有剪辑、渲染或批准；导出的是工作材料。已存在草稿时列出直接使用旧结果的草稿及片段，用户明确选定目标；未更新的稿显示“当前采用与该剪辑使用不同”。

替换面板显示旧／新源区间、当前时间线位置、片段时长、全稿时长差及受影响条目，只提供两种模式：

| 模式 | 必须完成的选择 | 保存结果 |
|---|---|---|
| 保持该片段时长（默认） | 新候选中选出足够长的源区间，显示按实际帧边界归一后的区间 | 保持后续位置，不自动变速／循环／补帧；不足时禁用应用到可渲染稿，提示换区间、换候选或改变时长 |
| 改变片段时长 | 明确确认后续主视频调整；逐条决定受影响音频／字幕保持原时间、随已知关联调整，或手动设置新区间 | 汇总所有移动／裁切／保留，未完成时保存工作稿，完整校验并确认后按Cut及工作稿版本一次应用 |

跨越切点或超出新范围的声音字幕必须展开处理，不默认删除或假定和视频一起移动。用户可手动修订／移除草稿条目并在预览确认，不能留主视频空洞或重叠；未处理项列出名称与位置并阻止应用到可渲染稿，未完成编辑仍可保存。原生混合音轨与独立对白的保留选择也参与预览。每份草稿分别确认与保存，不跨项目广播替换。

预览所依据草稿版本过期时保留用户已选候选、区间和处理决定，获取新稿重新计算并标出冲突，不能自动覆盖。可放弃剪辑更新而保留已成功的采用；旧审稿和交付始终不变。

## 6. 剪辑、提交审阅与返工

工作稿持续保存。手动“生成审片版本”先核对当前工作稿已保存、已归一确认并应用，再固定可渲染编排。若仍有未应用工作，明确选择“仅固定上次已确认编排”才能排除它，不能静默渲染旧内容。每次固定版本有明确名称／序号、来源草稿版本与输出规格。源媒体发生新生成不会改变该版本。已知台词与音频／字幕片段的关联在详情中可见、可人工确认；只用于定位和影响提示，不自动宣称声音准确或口型一致。

原生混合音轨默认保留；加入替代对白时必须明确是否静音该视频片段原轨。界面说明混合音轨无法仅凭静音选择保留背景音乐而单独移除对白。导入字幕或根据计划台词整理字幕后，按实际采用声音回放核对；未核对的草案不显示为已验证转写。

点击时间码评论定位到实际观看文件；评论可有结束时间，超出视频长度拒绝保存。镜头候选审阅使用候选局部播放器时间，后台同时保留对应源媒体偏移。负责人作出通过／需修改决定；每轮决定关闭该审阅，重新确认创建新的审阅轮次，不覆盖旧决定。

返工从评论打开来源。负责人／管理者可由该评论建立轻任务并分配给项目成员，预填原审稿、评论、已知镜头／候选／源区间和要求；协作者可直接查看来源继续制作，并更新分配给自己的任务。外部成片仅有文件和交接清单时显示外部版本和时间码，由用户明确关联目标，不能虚构逐镜映射。

任务的处理结果选择“提供新结果”或“保留原方案并说明理由”：前者关联新候选／新稿及已知区间，后者保留原版本和说明。任务执行完成不自动解决正式审阅，也不继承旧批准。新稿提交审阅时展示本轮处理清单，按旧意见列出原依据、新结果／保留理由和待处理项；负责人可顺序切换原稿与新稿。

正式批准页同时展示被批准文件及处理清单；仍未修改的意见需要明确处理理由或继续标为待处理，不能通过关闭旧评论使其消失。有权负责人可基于创作取舍作决定并留说明，不要求所有讨论都必须变成任务或强制逐条批准。

### 素材交接与外部回传

源素材包预览列出固定采用版本、去重源文件、镜头／台词对应、源入出点、已知声音／字幕和可读清单。默认不带未采用候选；文件采用可识别名称及稳定短 ID。没有平台剪辑时明确“无平台时间线／预览”；已有剪辑时可选择固定版本附预览、时间线与实际有的 SRT。不能因没有全片渲染而禁止源包导出。

从工作包点击“回传精剪结果”自动带出对应包和版本，导入 MP4，可附 SRT，显示文件验收状态、实际规格和字幕时长检查。独立导入允许来源未关联，须明示未知。MP4 与附带 SRT 一起固定为外部稿，播放器明确字幕来自文件还是画面烧录；SRT 不被解释为外部逐镜工程映射。任何文件变更建立新版本，旧稿及批准保持。

交付页分开显示工作材料和最终交付。最终交付只选取已批准的整集／外部固定稿；批准者核对本次文件、字幕和处理清单后创建交付记录。无字幕数据时不提供导出 SRT 选项，不生成空文件宣称齐全；包下载展示版本、文件清单和恢复状态。

### 媒体检索与共享准备

上传媒体保留可识别原文件名展示，生成媒体默认按对象／用途／尝试序号命名；用户可修改显示名和标签，媒体字节、校验值和历史引用不变。素材选择器支持名称／标签检索及类型筛选，显示已知来源、创建者和时间；不要求先把每份未采用媒体建成设定资产才能找回。

创作者在项目内准备固定共享版本，管理者查看包含的媒体／依赖清单后一次发布；不要求再次上传同一媒体。普通成员引入指定共享版本后回到原镜头，来源项目的私有内容不可见。draft 项目资产可试作，资产确认与共享发布分别显示，不混成生成审批。

## 7. 保存与多人修改

可编辑对象使用版本号。保存时版本不同返回冲突：保留本地未保存内容，展示服务器最新版，可复制文本或手动合并后重新提交；不直接 last-write-wins。镜头排序对 ContentTree.revision 检查，工作稿保存检查自己的版本，应用归一检查Cut及工作稿来源版本。替换方案、文本选区和未采纳提案选择作为可恢复编辑内容保留，涉及新版本时重新校验。

首版可每个页面处理小范围对象冲突，不提供实时多人光标或逐字协同。上传和生成任务在离开页面后继续，用户回来可恢复进度；浏览器不能作为唯一运行状态保存点。

## 8. 关键文案与错误恢复

| 情境 | 应表达的事实 | 下一步 |
|---|---|---|
| 提交响应未知 | 供应商可能已接受，正在核对；本次预占仍保留 | 查看作业；不能把重新 POST 包装成安全重试 |
| 生成成功、归档失败 | 结果已生成，正在恢复素材保存 | 重试归档；显示来源有效期风险给运营处理 |
| 旧输入结果 | 该结果使用了此前的镜头／参考版本 | 查看差异，保留、继续或明确采用 |
| 已审稿变更 | 本次修改会生成新稿，旧稿及批准保留 | 从旧稿派生草稿 |
| 权限撤销 | 当前无权继续访问 | 停止轮询、清理页面敏感缓存、返回工作室选择 |
| 预算不足 | 展示有权读取的已用、在途、剩余及本计划估计；工作室总账仅管理者可见 | 调整计划或由管理者调整预算 |
| 配置已更新 | 本计划的模型配置已变化，需要重新检查 | 重新生成计划，不静默升级模型 |
| 本次参考已排除 | 该项仅本次不使用，上级设定仍保留 | 重新准备时保留排除；显式保存到镜头才改后续要求 |
| 候选不足原时长 | 所选区间不能保持现有镜头时长 | 换区间／候选，或进入改变时长并处理影响 |
| 替换仍有未处理项 | 列出需要决定的音频／字幕及位置 | 工作稿可先保存；逐项处理后应用可渲染编排，不静默删除或移动 |
| 源包无平台剪辑 | 本包包含采用源素材与区间，无时间线／审片预览 | 可继续导出供精剪，工作材料不等于最终批准 |
| 外部时间线未知 | 已保存该 MP4／SRT 和已知交接包，未取得逐镜工程映射 | 在实际文件时间码评论，返工由人明确关联目标 |

## 9. 埋点与验收观察

只记录必要操作事件：资料预览／录入、进入制作、参考准备、计划形成／提交、候选查看／采用、替换预览／保存、开始及提交返工结果、剪辑固定、提交审阅、决定、源包／成片导出和外部回传。使用项目内对象标识及耗时，不把提示词、剧本、私有媒体 URL 和密钥写入分析日志。记录失败原因与来源（客户端／服务端／供应商），区分人工活动和异步等待。

验收按 01 的三门槛分别记录：46 秒单场内部切片；连续两集与真实外部精剪交接的 S3 机制验收；默认 60–120 秒连续内容及返工的目标工作室工作流试点。观察首次找到正确素材、采用后导出、不等长替换及他人接手意见时的求助与人工时间；不能以接口完成或模拟器通过替代真实制作。

UX-01 后续比较时保持生成、参考、版本能力相近；当前结构化工作台是实施选择，页面稿和 AI 评审不能证明用户效率已提高。本文件所有走查、模型与用户验收仍待运行。

替换预览前，声音／字幕影响区同时呈现台词绑定。载入完整现有绑定，要求用户处理已删片段、新声源区间、新台词版本；明确重新关联或删除后提交完整 dramaBindings。系统检查绑定有效性，实际说话内容与口型仍由制作人员审阅，不按相同文字自动通过。
