# 58 固定异步生成任务与取消恢复

2026-09-12，基线 `932103f`。依据 [07 供应商协议](07-provider-adapter.md)、[04 执行状态](04-state-execution-and-budget.md) 和 [38 当前首发范围](38-first-release-scope-review.md)，补齐已保留的 AI 长任务受理、查询与取消。后端、前端和 HTTP 故障验证由三个 agent 并行完成，主任务负责组合、交叉审查、真实 API／数据库／浏览器验证和远端集成。

## 用户行为

模型受理任务后，平台保存原供应商任务 ID；页面区分等待处理、正在生成、结果保存和最终可用。刷新、离开页面或执行器进程重开，都继续核对原任务，不重新提交生成。现有图片、视频、音频、分镜、提示与候选修改使用同一任务机制；媒体完成仍须经过原归档链路才能成为可用媒体。

取消框固定原 job／plan。排队任务可在首次提交前确认取消；提交未知时先保存独立取消意图，继续找回原提交；已受理后只尝试一次供应商取消。请求已记录、不支持取消、回执未知、确认已取消分别展示。取消尚未确认时继续占用执行限额；完成结果与取消请求竞态时，结果仍保留，供用户明确取回或采用。

本机先保存固定取消请求。平台取消响应丢失后，刷新只 GET 原任务；如确认请求尚未送达，用户可明确恢复同一请求。取消事实在服务端按 job 永久唯一，不依赖短期 HTTP 回执来避免重复供应商取消。新计划与跨镜头输入保持隔离，迟到响应不能污染另一份输入。

## 持久化与权限

`0092` 增加不可变 provider 绑定、观察租约、逐份证据投影记录及独立取消字段。原 attempt、输入摘要和 connection version 在 submit／recover／query／cancel 中固定；同一连接版本内冲突 provider ID、同一 attempt 多个 ID 或矛盾终态进入核对，不自动重提。完整原回执继续追加，重复投影不反复修改任务版本。

查询先提交60秒租约，再在事务外调用适配器，正常间隔5秒；异常采用带抖动的有界退避，上限300秒，调用提供30秒 AbortSignal。租约领取时持久增加失败计数，进程退出不会将任务恢复为排队；只有仍持有有效原租约的执行器能释放和调整调度。取消外呼前持久标记已尝试，丢回包或进程重开后改为查询。初次提交继续检查当前权限、固定能力及返工来源；提交之后的原结果恢复不会改用新来源或新连接。

`0093` 保持原身份不可变，同时允许一次经过当前权限校验的取消意图。runtime 对 job 的旧 UPDATE 权限被撤除；worker 只能调用受限函数，旧重命名输出入口不再直接暴露。新观察表不向 API／worker 开放任意写入。

交叉审查发现，同一结果补发 `usage` 会因完整 JSON 不同被误判终态冲突。追加 `0094` 将终态比较与可选用量观察分开，完整原回执仍都保存；分镜、提示和媒体旧输出函数一起修正。两个回执先到后投影与结果完成后补发均只生成一份产物；不同 ID、输出或终态仍需核对。没有增加商业计费或费用运营功能。

三个迁移均在首次实际应用后冻结；所有修正通过追加迁移完成。真实供应商尚未启用，适配器能力仍是显式 `test_fixture`。
