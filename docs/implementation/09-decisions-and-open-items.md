# 09 已裁决设计、实施准入与后续验证

当前设计状态（2026-09-10）：[核心布局和导航已确认](../design/approved-baseline-2026-09-10.md)，四项专项暂时收口；用户随后确认[技术评审方向](../design/technical-direction-confirmation-2026-09-10.md)。任务调度、未完成剪辑恢复、画布协作及保存历史已按[21](21-technical-baseline-closure.md)完成协议同步，候选集成与运行验收待执行。当前仍按用户要求暂停正式工程，不把 G／EV 清单当作开工批准。

本页记录原自主评审及后续用户确认的决策。原评审裁决按当时授权形成；后续组件与视觉讨论遵循用户最新要求，区分已确认和研究建议，不将相邻候选自动视为接受。下表已定项作为实施基线；外部账号、真实媒体、测试预算和用户效果仍必须有事实证据，不能用裁决代替。

## 1. 用户确定的边界

长期支持短剧和广告，当前短剧优先；面向中小工作室、不设10人上限；偏AI写实、优先Seedance等领先模型；初版内部简单协作、暂不做外包；首版每场次包含分镜／自由画布，价值与默认呈现继续通过试点验证。广告未来面向商家／教育机构营销人员，内容工厂为候选，不提前增加第三条产品线。

### 2.1 后续技术方向确认

用户已同意最新技术评审的方向判断。保留架构主干和组件体系；成熟队列优先，pg-boss 是首个验证候选；编辑草稿与可渲染版本分开；补齐自动保存历史、前端状态所有权和画布异步协作边界。具体决定、尚未锁定的选项及文档同步顺序以[技术方向确认](../design/technical-direction-confirmation-2026-09-10.md)为准。用户随后授权继续收尾，契约已同步实施包1.3／OpenAPI1.3.0；候选组件集成仍待执行。

## 4. 明确后置

| ID | 后续问题 | 进入依据 |
|---|---|---|
| UX-01 | 画布在哪些探索、比较、关系表达任务上有净收益 | 用同等素材/生成能力完成可比任务，比较遗漏、人工、理解和交接；不按竞品截图投票 |
| UX-02 | 镜头组／长段在真实团队中的频率和最佳交互 | 已支持人工多区间，不把长段模式未经验证的效果视为已上线 |
| PM-01 | 更深NLE、自动口型/分轨、专业工程往返 | 13记录外部修复耗时，反复出现高损耗再前移 |
| PM-02 | 第二模型或模式、自动连续性提醒 | 同质量下降低总人工/成本/周期，不能只增加模型数量 |
| PM-02 批量方法 | **已决策（2026-09-18）**：批量生成按“多选 → 查看所选节点的生成计划 → 批次确认屏内显式确认”落地；批次只是分组，不做第二套调度，不引入多选工具条一键付费执行。规则见画布交互契约的多选与批量生成两行 | 落地后按“能否横向判定场次连续性”复核，不按省下的点击数复核 |
| AI-02 | 已制作内容的自动拆合/重写提案 | 先完成一次人工可追溯重拆，再验证自动化不会丢句或错误继承 |
| AD-01 | 广告独立业务入口与业务候选/采用/最终资格 | 公共闭环稳定且有重复营销任务，不强制等待短剧V2 |
| ORG-01 | Guest、客户链接、工作组、自定义权限 | 实际外包/隔离需求出现才扩展，默认无权不继承内部共享 |

已确认方向、新增裁决与待验证效果分别管理，避免把后置研究默认为本期承诺，也避免把已能确定的行为反复留成讨论题。
