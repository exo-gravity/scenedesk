# 真实模型前的工作区收尾

## 交付边界

当前保留的用户路径是：外部初稿导入与阅读 → 固定选文和参考进入画布 → 同一草稿中创作、比较、继续修改 → 按需整理镜头并明确选用 → 原片交接。无剧本、无场次时仍允许先在项目画布探索；镜头整理沿用既有场次归属。

Word 和飞书仍采用“预览 → 确认导入 → 当前稿”。历史、下载原件和兼容编辑在次级入口；没有新增分支、发布或审批系统。固定引用、任务与结果留在内部，导入新稿不会改变旧任务依据。

连续创作沿用已有图片／视频草稿、固定任务、结果与比较表示。本轮补助手应用后的“继续编辑此草稿”、被画布边缘遮挡时的完整编辑入口，并把普通路径中的旧分镜台入口收敛到镜头列表。显式旧深链仍保留，不迁移或删除用户已有画布、镜头与候选身份。

镜头交付使用本场当前明确选用的完整原视频，并附有序清单；它不是剪辑渲染。下载前展示清单，准备后再次核对权限、选用与顺序，失败不能交出被当作完整成功的半包。详细契约和边界随[镜头列表](76-shot-list-workspace.md)记录。

- 本地 Word 样本与受控飞书文档不是团队真实剧本的版式验收。当前承诺为受限 `.docx`，不宣称任意 Office 格式、分页或复杂排版完整保真。
- 本机工作台升级、隔离备份恢复与容器部署检查分别记账；它们不能替代外部生产服务器、真实 OIDC、云权限和团队试用。

本机完整媒体回归没有通过：在 16 GiB 主机、接近用满的 swap 和高负载下，Docker 的容器创建／清理出现精确 15 秒超时。原先怀疑的嵌入音频用例在独立运行中通过；重跑实际通过生成音频、PCM WAV 等阶段后，又在 `docker create` 被超时终止。保留原失败证据，不放宽生产资源与超时限制。后期音频加工／标准化按当前 MVP 已后置，不能把它作为新增功能，也不能把本轮完整媒体写成全绿。

数据库与核心浏览器用例转到本机已有的 PostgreSQL 16，以单独创建的合成数据库和随机 schema／受限角色运行。该测试实例与用户 4311 工作台的 PostgreSQL、MinIO 完全独立。
