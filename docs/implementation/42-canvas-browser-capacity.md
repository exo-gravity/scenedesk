# 画布浏览器容量验证（300 / 2000 节点）

日期：2026-09-11。范围：文档 18 §8 / AT-61 的本地真实浏览器容量证据。基线为 `dc5f3d00179f6f01e9269ff8f072430cab5045cc` 的生产构建；优化为本提交中的 CanvasBoard 折叠面板懒挂载及 editing-json-v1 字段比较器等价优化。没有部署或真实模型验收结论。

## 环境和数据

- MacBookPro18,3，Apple M1 Pro（8 逻辑核）、16 GiB RAM，arm64；macOS 26.0.1（25A362）。Chrome 152.0.7977.83 headed，1512 × 982，DPR 1，无 CPU/网络节流。浏览器通常约 120 Hz RAF；RAF 间隔不是显示器呈现时间或 Web Vitals INP。
- 独立 `scenedesk-canvas-capacity` 浏览器和 4318 Vite production preview。API 4310、OIDC 4320 共用，本地测试身份明确可见。300 与 2000 不同时运行；主任务完整数据库回归在两组之间完成。API 在两组之间升级 SQL 23–27，Canvas API 未变；此后仅有其他小项目浏览器操作。
- 这是共享开发机器。记录的 load average：19:53 为 20.21 / 25.37 / 34.48，20:01 为 9.39 / 14.19 / 24.51，20:13 为 12.11 / 13.87 / 18.94。其他进程和 OS 调度未隔离；不能据此承诺独占或线上性能。
- 创建了独立技术项目、两场及两个画布，未改现有 AI / UI 夹具。真实 API 保存 300 节点 / 500 边 / 30 组，及 2000 / 5000 / 200。20 列布局、320 宽节点、380 × 280 间距；一半文字/素材来源，一半尚未生成的创作草稿；全部参考边保留其方向、用途和顺序。
- 初始 UTF-8 保存请求为 259,755 / 2,069,785 字节，均低于 4 MiB；编辑后的对应请求为 259,781 / 2,069,811 字节。字节数来自真实请求体，不把单次保存延迟当作 P95。
- 技术素材由浏览器生成，经真实上传/验收：PNG 320 × 180（1982 字节）、约 1 秒 WebM（1353 字节）、1 秒 48 kHz PCM WAV（96044 字节）。300 / 2000 有 8 / 50 个素材呈现节点，重复使用这 3 个媒体；其余为文字和草稿。没有真实模型调用。这不代表数百个不同大型视频的带宽、解码或模型验收。

## 测量方法

1. 每组 20 次完整重载，使用已有缓存的构建资源。以导航 timeOrigin 起算，到真实画布节点及“已保存”状态出现后再经过两次 RAF 为首屏可操作时间。没有将 hash 变化当作页面重载；该指标包含页面、API、IndexedDB 及布局读取。
2. 各 40 次真实点击/文字输入。从浏览器原生 capture 事件起计，到目标节点 `data-selected` 或可见文字匹配后下一次 RAF；不计 CLI 往返。文字通过真实受控输入更新，明确保存后再 GET 验证节点/边数量与文本，并重载核对。此指标是本任务的交互观测，不冒充 INP。
3. 搜索、首尾节点定位各 20 次。输入过滤到唯一结果，再点击该结果；定位确认目标已选中且边框与画布可视区相交。计时到目标可见，不包含后续视口偏好持久化；截图不用于计时。
4. 平移每组 3 轮，每轮 12 段往返、每段 20 次鼠标移动，实际按住鼠标操作手形工具。局部从 80% 缩放开始；全览先点“适应内容”。RAF 同时记录实际 viewport transform 的变化（每轮 240 次），不是闲置页面 FPS。缩放另测 3 轮，每轮 60 次 Ctrl+滚轮，实际缩放范围受 10%–400% 限制；原始数据保留每轮起止视口及所有帧间隔、长任务。
5. P95 使用 nearest-rank：排序后第 `ceil(n × .95)` 个样本。表中平移/缩放是各轮 P95 的范围，并保留每轮 n、最大值；没有把一张截图、一次 API 或少数动作称作性能分位数。操作间的 RAF 仍可能受共享主机负载影响。
6. 内存使用可得的 `performance.memory` 和 CDP `Memory.getDOMCounters` / `Performance.getMetrics`。主动 GC 只用于单独内存观测或离开模式后，未插入交互/帧时采样。JS heap 不是整个浏览器进程 RSS，也不包含全部 GPU / 解码内存；单次回收不是长期无泄漏证明。
7. 8 次文字修改的 CPU profile 使用 CDP 1 ms 采样，前后保持相同画布结构和文字输入。其自采样占比用于定位热点，不直接当作墙钟百分比。

### 独立端口适配与测量边界

服务器允许的本地 Origin 是 4311。测试浏览器中，4318 的 API 写请求使用 `route.fetch` 将 Origin 映射为 4311，真实响应原样返回；CSRF、会话、CAS、数据库约束均继续生效。MinIO 同样只允许既定 Origin，因此媒体请求用相同 Origin 别名，并仅向该测试浏览器返回匹配 4318 的 CORS 头。未改 API / MinIO 配置，未伪造媒体响应或访问凭据。

未适配时播放器的 format error 已区分为 CORS 拒绝：代理 ready、浏览器支持 H.264 / VP8；适配后真实代理可解码。另丢弃了首版诊断采样器重复 RAF 回调产生的 0 ms 间隔，修复采样器后重新完成三轮；提交的结果仅含有效样本。原始 console / 运行清单可能含临时签名地址，未进入提交证据。

## 实测结果

单位为毫秒。所有数值来自已保留的样本，不作插值。

| 指标                      |  300 基线 | 300 优化后 | 2000 基线 | 2000 优化后 |
| ------------------------- | --------: | ---------: | --------: | ----------: |
| 首屏可操作 P95（20 次）   |    1409.2 |     1421.5 |      2771 |      1514.8 |
| 选择 P95（40 次）         |      39.1 |       23.6 |     110.4 |        72.7 |
| 文字编辑 P95（40 次）     |      79.1 |       30.7 |     785.9 |       269.1 |
| 列表搜索 P95（20 次）     |      17.1 |       16.5 |        47 |        26.7 |
| 首尾定位 P95（20 次）     |        63 |       58.9 |       176 |       156.7 |
| 80% 局部平移每轮 P95 范围 |  9.8–10.1 |     9.6–10 |  9.9–10.2 |      9.8–10 |
| 滚轮缩放每轮 P95 范围     | 10.3–10.4 |  10.3–10.3 | 10.2–16.8 |   10.3–10.3 |
| 全览平移每轮 P95 范围     | 33.1–33.7 |  26.5–32.5 | 83.3–84.8 |   81.9–83.6 |

本轮 300 节点选择、文字编辑、搜索和定位的 P95 均低于文档建议的 100 ms；局部平移和三轮全览平移的 P95 也低于 33 ms。全览最大一轮 P95 为 32.5 ms，距离建议值仅 0.5 ms；共享环境下不能将它解释为稳定生产余量。

2000 节点能够进入、选择、搜索、定位、编辑、保存及刷新恢复，但编辑 P95 269.1 ms、全览平移 P95 81.9–83.6 ms，仍明显卡顿。文档 18 没有为 2000 单独规定毫秒门槛，本记录将其作为容量边界证据，不声称其具备与 300 相同的流畅度。未靠减少节点上限或跳过权限、错误、结构校验获得结果。

300 全览实际显示 300 节点 / 500 边，fitView 约 12.06%；2000 的高长宽比布局触及 10% 最小缩放，测量结束视口实际约 440 节点 / 1240 边，并不意味着能在一屏展示全部 2000 节点。局部通常显示 15 节点，300 / 2000 对应约 59 / 94 边。缩放及全览仍有长帧，完整最大值和 long-task 数量保留于原始 JSON，P95 通过不代表没有卡顿。

## 原因与改动边界

实际输入的 CPU profile 把主要成本定位到 `editingCanonical` 的键排序比较器：旧实现对每次比较的两个键分别 `Array.from`，在 8 次文字修改的 4296 个自采样中占 1744 个（40.60%）。优化后同场景共 1470 个自采样，比较器为 13 个（0.88%）。这是输入变慢的直接采样证据；剩余成本主要仍在完整 canonical 编码、Unicode 标量检查和持久化相关流程。

比较器现在按码点宽度直接前进，保留 BMP / 补充平面的码点顺序、前缀、相等及 lone-surrogate 的比较语义，后续 scalar 检查继续拒绝非法字符串。没有改变 hash 版本、canonical 格式、校验次数、保存协议或服务端授权。冻结 canonical / Python UTF-8 hash 用例继续通过，新增混合 Unicode 键和共同前缀的公共行为回归。前后实际 40 次编辑最终保存的文本逐字相同，引用数量完整保留。

CanvasBoard 在桌面折叠状态下不再挂载节点列表及分组表单；展开后仍可搜索所有节点、键盘定位和修改分组。2000 节点末次首屏采样的页面 DOM 元素从 8660 降至 1047，未以移除业务内容减少文档容量。文字/数值缓冲和文档状态仍由既有 controller 管理；窄屏自动保留列表，无效分组缓冲恢复后展开，关闭/再开列表保留查询。

没有修改 SceneProductionWorkspace、AI、SQL、provider、契约生成器或后期模块。没有做视觉重设计。2000 全览的密集渲染成本仍存在；下一步应先独立分析可见节点/边的绘制与低缩放表现，再决定视图细节或渲染策略，不能把这次 canonical 优化当作解决了全览性能。

## 内存、媒体与恢复

| 优化后观测（GC 后 JS heap）      |      300 |     2000 |
| -------------------------------- | -------: | -------: |
| 选中文字、搜索仅一结果、分组折叠 | 14.1 MiB | 21.9 MiB |
| 切到分镜后                       | 11.1 MiB | 14.1 MiB |

表中的模式切换观测均为播放器数 0。两组均实际打开并播放视频，观察到一个 readyState 4、paused=false、currentTime 前进的播放器；定位远处声音节点后旧播放器数变为 0，再播放声音仅有一个实例，切换分镜后再次为 0。声音展示沿用项目播放器的 `<video>` 音频模式；不能以 `<audio>` 标签数量误判。播放器首次点击后才挂载，未播放时均为缩略呈现。媒体完成加载后另点击“定位当前内容”使播放器完整入框，截图与实例计数记录这一明确操作后的状态。

正常编辑保存经真实 PUT、读回和页面重载核对；分组空名称输入没有进入服务端文档，刷新后通过产品已有的“恢复本机修改”动作恢复原缓冲，再填写合法名称完成保存。键盘 Enter 展开节点列表、关闭/再展开查询保留、390 × 844 窄屏列表和无横向页面溢出均单独检查。这是本地技术夹具证据，不是商业数据或模型输出验收。
