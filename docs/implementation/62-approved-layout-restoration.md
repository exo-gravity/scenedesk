# 已确认设计的业务页面还原

日期：2026-09-12。用户指出视觉设计、页面结构与布局偏离已确认方案，并要求严格按计划实施。本轮是把已经确认的方案落实到真实业务页面，不重新选择视觉方向。

## 偏差及原因

业务页面此前独立组合了宽侧栏、较大页边距、通栏表单和重复卡片，没有把 v0.3 原型的空间关系同步到真实工作区。根主题已经使用中性明暗色表，因此只替换颜色不能解决问题。此前的 `ui:check` 检查组件库、主题 token 和部分对比度，浏览器检查偏重业务行为与溢出；这些都不等于已确认布局的视觉验收。进度报告漏列了这项未完成工作。

本轮依据：[已确认基线](../design/approved-baseline-2026-09-10.md)、[核心体验 v0.3](../design/scene-walkthrough-review-v0.3.md)、[专项 v0.4](../design/production-detail-design-v0.4.md)、[共同视觉语言](../design/shared-visual-language-v0.1.md)。已后置的剪辑、交付、完整团队及运营能力不恢复到首发入口，保留能力的结构与视觉要求继续适用。

## 还原与验收范围

| 页面／状态 | 按已确认方案实现和检查的关系 |
|---|---|
| 全局与项目目录 | 34px 顶栏、76px 工作室导航、56px 上下文栏；项目目录在上下文栏下，宽196px；制作页释放项目目录空间 |
| 项目首页／我的工作 | 项目画面与名称构成入口，没有图片时明确空态；我的工作读取当前账号的真实创作任务，使用平行行，不重新开放团队管理 |
| 场次目录 | 单集分组、平行场次行、制作入口；编辑与排序就近展开，避免把全集镜头要求常驻堆满目录 |
| 剧本与设定 | 正文是主区域；历史和固定原文可查；分镜建议、修订与明确采纳使用按需辅助区域，原持久草稿和冲突保护保留 |
| 分镜 | 当前镜头大媒体预览、中央有界提示输入、底部缩略分镜条；候选与素材按需打开，和助手协调占用空间 |
| 自由画布 | 全场空间、平移缩放与全览、局部工具与有界输入；节点坐标与镜头顺序分离，保留视口与编辑恢复 |
| 助手 | 非模态停靠，明确上下文与固定目标，默认收起；保留建议修订、生成确认、未知提交与结果恢复 |
| 资产／素材 | 固定版本与引用可扫描，媒体占主体；详情恢复专项左右关系，避免重复导航和层层卡片 |
| 明暗与紧凑视口 | 同一中性色表和结构；使用媒体6px、工具8px、浮动输入12px语义圆角；明暗不改变媒体颜色 |

## 验证记录

整合验证进行中。提交、截图、实际交互及检查结果在最终验收后补入；此处不以局部类型检查或单张截图宣称全站还原完成。

真实模型 transport、真实部署／身份验收以及模型执行恢复门禁的既有缺口独立保留。视觉修正不把本地模型 fixture 等同于真实 AI，也不把布局还原等同于整个 MVP 已完成。
