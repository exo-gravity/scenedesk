# 创作依据与项目默认确认

2026-09-10。此切片落实 [14 的创作确认规则](14-scene-mvp-closure.md#5-主创确认与自由试作)中来源快照、项目默认确认与历史核对；固定稿限定确认随编辑／审阅切片继续实施。

## 已实现行为

- 保存剧本、剧目设定、场次设定或镜头台词时，同一数据库事务生成不可变 `CreativeBasisRevision`。保存失败一并回滚，不要求先有确认记录。
- 新建且无内容的剧目／场次／台词不制造空依据；已有内容被清空时保留真实的新空版本。剧本和镜头来源固定到不可变修订，剧目／场次来源保留当时根版本及快照。
- 正式确认只接受明确的依据 ID、用途、前次确认 ID 和说明。负责人／管理员获授权后追加确认，再切换该对象的正式指针；首次前次 ID 为 null，并发不一致返回 412。同一幂等键重放返回原结果。
- 可明确选择历史依据作为正式版本。新草稿不覆盖旧确认，确认旧内容也不回退当前编辑稿。确认者、时间、说明、前次指针及固定内容持续可查。
- 集场镜页面进入“创作依据”，按类型与历史版本筛选，查看当前草稿来源、固定依据序号及正式状态。详情并排呈现所选内容和当前正式内容；确认冲突保留说明，需核对最新正式记录后明确继续。未提交说明按用户／项目／依据／标签页存入 IndexedDB，刷新后手动恢复。

`listCreativeBasisRevisions` 补齐未确认依据的查找入口；支持 `subjectId`、`kind`、搜索与游标。`number` 是同一对象的依据保存次序；不可变对象自身的 `revision` 为 1。`isCurrentSource` 和 `currentConfirmationId` 是读取时状态，不修改固定快照。确认历史返回说明。所有输入和输出继续由同一 OpenAPI 生成契约验证。

## 内容摘要 creative-v1

摘要是受保护字段规范 JSON 的 SHA-256，不使用模型判断相似性。JSON 无多余空白，声明的 ASCII 属性名按 C 排序，文本逐字保留；资产版本集合按规范小写 UUID 去重排序。

| 类型 | 纳入摘要 | 保留在快照、但不作为摘要内容 |
|---|---|---|
| 剧本 | 正文 | 来源剧本修订 ID |
| 剧目 | 创作简述、默认资产版本集合 | 剧目标题与根版本不进入摘要 |
| 场次 | 摘要、连续性状态、默认资产版本集合 | 标题、序号、显示时间地点标签不进入摘要 |
| 镜头台词 | 每句稳定身份（明确的来源对白 ID 优先）、说话人、准确文本；按规范内容排序 | 来源镜头修订、表演备注、声音试作引用、来源摘录与显示次序 |

镜头修改构图或表演备注会保存新的实际来源，受保护台词不变则摘要一致。明确继承对白身份的拆镜可保留相同摘要；换身份、换说话人或改单字均改变摘要。页面“正式内容一致”只表示这份依据与该对象当前正式记录的受保护字段一致，不能表示影片已实现它。跨对象确认复用及冻结稿实际使用关系将在生成／编辑／审阅模块落实。

当前连续性中的人物／道具资产引用仍由内容入口拒绝，直到资产切片建立真实引用；`creative-v1` 对连续性 JSON 保留其数组顺序，未来规范化规则变化需明确新 hashVersion，不能重写旧摘要。

## 数据与迁移

迁移 `0006_creative_bases.sql` 创建类型明确的主体、依据、确认及当前指针表，使用 tenant／project 复合外键、强制 RLS 与不可变触发器。来源捕获函数仅以类型和真实来源 ID 读取数据，不接收客户端快照或摘要；函数为调用者权限，固定 schema 查找路径，运行角色无提权。

每次来源写入由触发器捕获，因此手工写入和 CSV 采纳使用相同规则。项目写锁串行化应用写入与确认；作用域由业务内核授权，按钮显隐不构成权限保护。

升级仅回填真实存在的剧本／镜头修订，以及当前剧目／场次值；无法重建的旧可变设定不伪造。已有本地验收数据实际回填 1 份剧本、4 份台词来源、1 份场次及 1 份剧目依据，未自动生成确认。既有迁移校验值保持不变。

## 验证与边界

- 全套 PostgreSQL 集成测试 37 项通过；新增创作测试覆盖捕获与回滚、规范摘要、继承对白、并发首次确认、请求重放、旧稿确认、新稿保持、跨项目外键、不可变记录、权限及 CSV 来源。
- `npm run check` 通过：14 项单元测试、类型检查、构建和 33 个迁移 UI 文件／20 组色彩检查。数据库使用真实 PostgreSQL 与独立受限角色。
- [浏览器验收](../../output/playwright/creative-bases/verification.md)使用本地身份模拟器与持久化业务 API，覆盖两标签页竞争、刷新恢复和窄屏确认。没有模型调用费用。

本切片没有实现固定剪辑稿，因此 `usage=cut_revision` 明确拒绝，不保存无对应稿件的 ID，也不切换正式指针。固定稿依赖、审阅批准、资产引用和实际影片质量属于后续工作；此状态不能视为完整 MVP 完成。
