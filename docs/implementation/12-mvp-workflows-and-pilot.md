# 12 MVP 工作流、制作交接与试点执行

本页将本期体验确定到可实现的操作。MVP 默认采用结构化分镜工作台；UX-01 继续验证后续画布是否值得引入、服务哪些任务。当前选择是本轮授权下的实施裁决，不声称已由目标用户验证，也不锁死长期交互形态。

## 1. 核心用户与首发任务

首发聚焦已有剧本、参考素材和后期习惯的工作室内部制作人员，负责人同时承担质量与成本决策。首个完整任务是“把一个对白场次从已有资料做到可审稿、完成一次指定返工并交接成片或精剪素材”。不是从空白输入一句话全自动完成整剧。

试点默认内容为普通话、竖屏、现代人物的双人对白与少量道具动作，单集 60–120 秒，并安排连续两集检验复用。它是收敛首发测试的选择，不是平台只支持该题材或集长。46 秒《旧钥匙》F0用于内部竖向贯通；S3必须完成F0/F1连续两集工程夹具、F2返工和一次真实内部后期交接F3；S4才用代表集长与真实工作室验证价值。详见10/13，工程两集仍不能代替真实试点。

## 2. 本期页面与主要动作

| 工作区 | 常驻内容 | 主要动作／完成后的去向 |
|---|---|---|
| 项目首页 | 项目与当前集、负责人、最近草稿／审稿、待处理作业、预算摘要 | 继续上次场次；新建集／录入剧本；配置缺失时由管理者完成连接和预算 |
| 分镜工作台 | 左侧集场镜；中间当前场次镜头卡；右侧当前要求、参考、候选与作业 | 编辑要求、准备生成、查看候选、采用、加入剪辑或导出精剪包 |
| 生成计划抽屉 | 选定镜头、确切文本与参考用途、模式、预计费用、输入缺口 | 按此计划生成；返回修改则新建计划；明确未知提交时进入核对详情 |
| 候选播放器 | 候选及其源要求、原视频、入出点、声音状态、与当前采用的差异 | 从本候选继续、设置区间、采用；采用后进入指定草稿更新预览 |
| 剪辑区 | 一条主视频轨、显式音轨／字幕、当前草稿版本和总时长 | 重排、裁切、调整声音／字幕、固定审稿；不要求先完成整剧 |
| 审阅区 | 固定版本播放器、版本序号、时间码意见、正式决定 | 通过／需修改；从意见回到原候选或手动定位；不能在播放器上改原稿 |
| 交付区 | 精剪素材包、平台审稿／成片、外部回传与批准依据 | 导出原素材及清单；回传外部新版本；批准后建立最终交付 |

进入当前场次首先显示未完成或最近操作的镜头，历史候选折叠；不要将所有素材和高级模型参数同时展开。镜头卡的“有候选／当前采用／已进入哪个稿”分别显示，生成状态不能替代这些制作事实。

## 3. 关键交互的确定规则

### WF-01 已有资料进入制作

剧本文本可粘贴或导入受支持的 UTF-8 文本；已有镜头清单可用规定 CSV 字段导入并预览映射。CSV 至少包含 episode、scene、shot_label、intent，可带 dialogue、duration_seconds 和 notes；首版按当前项目生成待确认提案，不能由编号相同就覆盖原镜头。复杂排版 Word/PDF 解析后置，用户可先转文本，产品不伪装已支持所有文件格式。

默认一位制作人员主责当前场次，其他人按需协助，主创在方向和完整场次结果处确认。人工新建和编辑始终可用。AI 分镜建议或 CSV 导入呈现可编辑 create 提案；可直接追加当前场次，或明确新建结构并检查父子依赖；复杂 AI update/archive 后置。已有内容可人工拆分、合并、移动和归档，保留原文与旧镜头映射，不自动清空素材。

### WF-02 从要求到实际模型输入

从当前场次选择一个或多个镜头，系统呈现来源要求和参考建议。用户确认最终媒体、用途及文本，生成计划固定这一份实际输入。上下文说明与模型参数分开；不支持的动作／声音参考必须解释原因。不得把所有角色参考统一套为“首帧”，也不得静默只保留一个人物。

提交前变更了有关来源要求，重新生成计划并显示差异；无关镜头重排不应导致整个项目所有计划失效。已执行计划永久指向当时输入，新要求只让旧结果显示“依据已变化”。

### WF-03 采用并更新指定草稿

先保存采用决定，再让用户选择草稿和其中的具体片段。替换预览显示旧／新源范围、时长差，以及受影响的对白、字幕和后续片段。

首版默认“保持该片段在时间线上的时长”，用户选择足够长的源区间，不能自动变速；不足时阻断并给出明确调整入口。若用户选择“改变片段时长并顺延”，服务器按确定的时间政策计算预览，并要求用户确认被影响的声音／字幕；预览所对应草稿版本过期则重新计算。不存在隐式 ripple edit 或替换所有项目引用。

### WF-04 声音进入剪辑

视频的原生混合音轨默认保留。加入替代对白时，先明确是否静音该片段原轨；系统不能保证保留混合轨中的背景音乐同时只去除对白。独立音频和字幕可以关联到时间线片段／台词，用于替换时提示影响；不因同一角色或同一台词文字自动覆盖旧轨道。

首版允许导入配音、环境声、音乐和字幕，自动转写、口型修复、分轨分离不是闭环前提。字幕按实际采用声音人工核对；计划台词仅提供草案，不直接当作实际说出的内容。

### WF-05 外部精剪交接

制作人员可在候选已采用后导出精剪素材包，不必先在平台完成全片渲染。包内提供去重后的原始媒体、已选区间、镜头／台词对应、已知声音和字幕、固定版本及清单，明确是否存在平台时间线。首版不承诺自动生成任何剪辑软件工程文件。

外部精剪回传 MP4 可附 SRT，归入同一外部稿的版本历史；媒体与字幕均验收后独立审阅。只有实际导入了对应工程映射才可声称知道外部切点，单靠 MP4＋SRT 不推导逐镜映射。

### WF-06 评论到返工

负责人可从评论创建关联返工任务，协作者可提交处理意见，保存 review/comment、目标 take 或 cut revision、负责人和说明，不能只靠自由文本复制一个镜头编号。已知平台映射时显示相关镜头与源区间；外部映射未知则显示外部版本和时间码，让制作人员明确关联目标。任务完成只表示执行人员完成处理，原审阅仍需要新稿和正式决定。

## 4. 试点方法与成功标准（09-09 收尾裁决）

首期目标是承接目标团队实际工作流。先由一家代表团队完成一次场次任务，再到连续两集、指定返工和内部后期交接；默认招募目标仍为 3 家，尽量覆盖超过 10 人的团队。未招募时可以做内部走查，不能称作客户验证。时间、金额和样本集长在实际任务开始前固定，避免事后改变完成定义。

| 验收维度 | 首期要求 | 证据 |
|---|---|---|
| 能完成 | 制作人员从已有资料完成场次；整集编排、下一集复用、指定返工及后期回传可完成 | 实际任务、操作记录、媒体与交付包；不能依靠研发改库或拼请求代做 |
| 质量可判断 | 主创确认正式创作依据；场次连续性、正确台词、基本音画及必要字幕达到预先约定标准，整集再确认 | 固定版本审阅、质量记录及例外理由；关键错误不能用平均分抵消 |
| 交接正确 | 交接者能取得正确版本、真实源区间和实际声音字幕，旧意见和新结果可追溯 | 一次未参与原制作的内部后期接手与回传；无错版本、无静默替换、无恢复重买 |
| 费用可信 | 已确认消费、未决费用和预占分开，遵守授权预算 | 真实账单与作业对应；未知不填 0 |
| 后续打磨依据 | 找到反复卡住、绕出工作台或需要人工解释的环节 | 按环节记录主动人工、等待、失败、外部工具和帮助 |

人工减少 20%、费用增幅不超过 10% 不再是 MVP 门槛；不要求首期证明差异化。成熟后如要评价效率改善，再单独设定同质量、可比难度、交替顺序的配对研究，不把该研究的样本负担加到第一轮可用性验证。

保留每家和每项任务的实际结果，失败、未完工和未决费用均报告。样本不足时只输出问题发现。画布 UX-01 另用同素材、同生成能力验证定位、比较与交接的净收益，不按界面喜好投票。质量判断与实验停止规则继续按 10／13；下一阶段 Skills 沉淀、更广 Agent 自动化以这些重复任务为依据。
