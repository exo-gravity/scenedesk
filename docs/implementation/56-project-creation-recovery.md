# 56 新建项目的持久恢复

2026-09-12。处理 [54](54-content-creation-recovery.md) 留下的项目创建缺口：旧表单在刷新后丢失请求身份，项目又没有内容版本前提，重新发送可能创建第二个项目。本片基于 `279d59c`，后端、前端及独立审查并行推进；下列为实施约束，实际验证与合入状态在取得证据后记录。

## 服务端边界

`CreateProject.creationRequestId` 是可选 UUID；新页面每次明确新建都固定一个身份，未携带字段的旧客户端保持兼容。服务端以工作室、原创建用户和该身份记录原输入摘要与项目 ID，绑定与项目、负责人、剧目及内容版本根在同一事务创建。绑定不随通用 24 小时 HTTP 回执过期，项目归档不清除绑定。

携带此身份的请求仍校验通用 HTTP 幂等键。同一有效键改变任何正文（包括创建身份）先返回 `409 IDEMPOTENCY_CONFLICT`；新的或已过期的 HTTP 键使用同一创建身份却改变原输入，返回 `409 PROJECT_CREATION_CONFLICT`。两种冲突均不创建项目。有效回执命中不直接返回旧密文结果，也不延长原有效期，而由持久绑定读取同一个项目的**当前表示及版本**；更名、规格调整或归档后恢复不会覆盖这些后续操作。

当前身份与 owner/admin 权限始终先核验；身份本身不授予访问权，不跨工作室或用户定位结果。租户写锁与唯一约束共同约束并发，运行角色不能更新或删除绑定。决策依据见 [ADR-0009](../adr/0009-project-creation-identity-outlives-http-receipts.md)。

## 页面边界

未提交表单保留在本机。首次发送前，完整原输入、创建身份和 HTTP 幂等键必须先耐久写入；未知结果期间不允许把输入改写成另一次创建。关闭窗口或刷新只恢复本机记录，用户明确恢复时才重发原请求。收到成功回包还需要完成本机回执保存／清理，才能结束恢复并进入项目；本机存储失败不解释为业务失败，也不自动再创建。

恢复记录按当前用户和工作室隔离。不同标签页、会话切换或晚到回包不能覆盖另一份已经固定的请求。仅首次发送收到可证明没有创建的业务拒绝才可回到编辑；代理错误、未知后的拒绝以及身份冲突保持原请求。

## 验证与限制

本片的数据库、生产构建浏览器、组合检查和远端 CI 尚待完成，不能用设计描述代替通过记录。验证目标是未知回包、显式原请求恢复、跨回执有效期、并发、当前权限、归档后恢复，以及本机存储和窄屏行为。

持久绑定只保护仍保有原创建身份的请求。旧版本已经丢失身份的历史提交、用户主动清除浏览器数据或在另一设备重新填写表单，不能凭项目名称推断为同一次创建。集场镜创建超过 24 小时的结果定位限制仍按 [54](54-content-creation-recovery.md) 保留；工作室初始化继续使用 [55](55-private-owner-bootstrap.md) 的未知后不重发规则。本片不扩展这两个协议，也不改变模型、后期或团队范围。
