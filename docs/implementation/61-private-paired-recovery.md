# 61 私有数据库与固定媒体的成对恢复演练

2026-09-12。本片补齐私有首发的数据恢复证据：实际数据库和媒体原版本能否一起恢复、恢复后权限和历史是否仍成立。入口见[隔离恢复工具](../../deploy/recovery/README.md)，执行与断言见[独立验收说明](../../deploy/recovery/smoke/README.md)。

## 能力与边界

提供backup、restore、verify三个CLI命令，显式指定带随机演练标签的PostgreSQL 16／MinIO容器与卷。先停写再封存数据库逻辑备份和存储冷快照，记录全表摘要、角色与迁移、固定对象和全部对象版本。独立密钥的HMAC与文件摘要校验完整性；配置和密钥必须位于备份目录之外，所有私密文件限制权限。

目标必须为空且与源不同。恢复保持原对象key／VersionId，随后核验字节数与SHA-256、全部版本和删除标记；不使用重新上传产生的新VersionId替代。已完成的重复恢复只做只读核验，部分恢复或身份不符不会自动覆盖重试。

工具仅操作受控合成演练资源，不发现或连接用户部署。临时容器绑定本次身份，超时后按确切ID结束并删除；PGDATA用tmpfs避免镜像隐式匿名卷。它不启动API或模型执行器，保留queued和unknown事实，输出明确的执行关闭及modelRestartSafe=false。

## 验证

独立实际演练最终11项通过（10子项与父项，169.708秒）：公共API创建的项目、镜头及画布历史，真实PNG上传／probe／poster，七份公共表示与受限权限、原VersionId下载和完整对象清单均在恢复后成立。queued没有新增attempt，unknown保留原提交事实。篡改摘要、密钥打包、缺失半份备份、同源或非空目标被拒；只删除原固定对象版本时精确报RECOVERY_FIXED_OBJECT_MISMATCH。

实际超时测试观察到临时容器start／destroy及正确挂载，最终本轮记录的容器与named volumes清理通过。较早版本的匿名卷归属已无法从Docker事件确认，没有按猜测删除；这项历史清理限制及测试等待失败均保留在验收说明，不用最终结果覆盖。没有模型外呼或用户数据。

独立恢复测试加入GitHub部署工作流的并行job，与既有配置／HTTPS／容器检查分别执行。两个工作流保留所有PR检查和main合入后的检查，feature分支push不再重复启动同一套检查，测试内容不减。私密配置、备份、密钥与原始运行目录不上传为CI工件。

## 尚未证明的生产条件

本片不是通用生产备份、云存储迁移或PITR。真实宿主、OIDC、HTTPS、对象权限、异地保留及RPO/RTO需要在实际环境验收。恢复数据库后重新启用真实模型还需按[11 恢复协议](11-transaction-and-implementation-blueprint.md)落实epoch与隔离核对，防止恢复点之后已被供应商接受的旧queued作业再次提交；本工具保持执行关闭，不授予这种放行能力。商业计费和后期功能继续后置。
