# 精确制作副本：实施记录

本记录对应 [11 §6](11-transaction-and-implementation-blueprint.md#6-tx-04-采用规范化草稿与冻结) 的内部媒体阶段。当前在 `feat/cut-normalization` 实施；工作稿归一、确认、固定渲染和页面尚未接通，不代表 E05 已完成。原片、预览代理和制作副本继续保持不同身份。

## 视频时间与实际内容

`packages/media/src/source-timing.ts` 读取固定 FFmpeg 9.0.1 构建的逐帧 PTS 和 duration。compact 数字字段直接转 BigInt，不经过 JSON Number，也不读取平均帧率推算边界。首个解码画面 PTS 是逻辑零点；中间区间以后一帧 PTS 结束，末端必须有正的解码帧 duration。缺失、重复、回跳或不可解释的末端明确失败。原始 PTS、time base、末端依据均进入映射。

每个原帧保存对应输出帧的半开区间，包括没有输出帧的被跳过项。对于约分后的目标帧率 P/Q，输出数是 floor(DP/Q)，第 k 帧的来源由 kQ/P 落在哪个原帧显示区间确定。相接时刻选择新帧，合法长帧可以重复，片尾不足一帧不补满。这个区间表示可以无歧义地还原每个 k 的原始 PTS。

`makeVideoProduction` 使用 `native-ffv1-nut-v1` 内部 profile：源解码输出原精度像素，宿主按映射选帧，再通过另一受限容器编码为 FFV1／NUT。rawvideo 输入的尺寸、像素格式与整数帧率全部显式指定；FFmpeg 使用 passthrough，选帧规则由平台执行。该 profile 不是最终交付视频的编码或色彩策略。相关参数含义见 [FFmpeg 时间与同步选项](https://ffmpeg.org/ffmpeg.html#Advanced-options)、[rawvideo 格式](https://ffmpeg.org/ffmpeg-formats.html#rawvideo) 与 [NUT](https://ffmpeg.org/nut.html)。

支持的目标帧率与当前项目选项一致：24、25、30、24000/1001、30000/1001。制作保持原尺寸和位深；原色彩标记、色度位置、透明度解释、像素比例与显示矩阵进入 source map。原始显示矩阵由后续渲染依据读取；raw 解码禁用自动旋转。NUT 不携带完整色彩标记，渲染必须读取固定 source map；raw 流重新编码前使用 setparams 恢复已核验的色彩解释，并保持自动色彩转换关闭。无法保持的像素格式、隔行素材、片中规格变化，以及未验收的 HDR／ICC 附加元数据明确拒绝，不默认降为 8 位 SDR。

编码完成后再次探测并完整解码。必须同时满足实际帧数、每个 PTS、精确末端和所有画面像素摘要与源映射一致，且原片前后 SHA-256 与字节数相同，才返回工件。JSON 映射固定源摘要、构建、profile、原时间区间、原帧像素摘要与副本校验结果；本地目录或临时文件名不进入其内容。结果文件和映射均有独立 SHA-256。

## 隔离和失败恢复

解码和编码之间使用带背压的有界流，不将整段原始画面装入内存，不开放网络或可写宿主挂载。进程原有 3 分钟、768 MiB、2 CPU 等约束保持；原片限额沿用媒体导入规则。制作额外限制 1,728,000 帧、256 MiB 探测报告、每个工件 8 GiB 和每段 raw 流 256 GiB，超限明确失败。这些是资源上界，不承诺所有上界组合都能处理完成。

stdin 必须声明字节上限。异常输入、输出阻塞、超限、取消和超时均终止相关流；Docker 子进程已经结束而宿主输出尚未完成时仍保留取消能力。正常执行及受控失败的 finally 均清理所属容器。制作 Worker 另在创建前持久记录 UUID 和宿主归属，并保留延迟创建的清扫记录；实际运行与中断验证见下文。制作工件写入本次独有临时目录，任一步失败清理整个目录；不删调用方原片或其他任务目录。

## 音频样本与呈现区间

实际 Worker 的碎片 MP4 验证发现首个 AAC 帧有 1,024 个解码样本，但 duration 为 4,000 个源采样刻度，下一帧 PTS 为 4,000。声明区间跨过了实际音频样本后的间隙。现在只有后续 PTS 不早于声明末端、且 duration 能精确表示源样本数时，才保留这些真实样本并把后续空隙记录为静音；不拉长声音，也不从最后一帧的过长 duration 推测片尾静音。缺少后续边界及相互冲突的时间戳继续失败。FFmpeg 对 [AVFrame 样本数、PTS 与 duration 的定义](https://ffmpeg.org/doxygen/trunk/structAVFrame.html)是字段依据；上述间隙处理是平台的明确解释规则，原始字段和段映射均保留。

`audio-timing.ts` 读取解码帧的原始整数 PTS、time base、样本数、格式和声道。解码器已经应用的 skip／discard 元数据不再裁第二次。细于或等于一个样本的时钟中，只有明确、精确、短于解码样本数的最后一帧 duration 才允许剔除尾部编码填充；中间短区间、不整样本的 duration 和不可解释的重叠失败。没有已知起始裁剪信息时，不能猜出 AAC 或 MP3 的编码延迟并擅自去掉内容。

粗时钟不能直接把每个 PTS 当成新的音频片段：48 kHz、每帧 1,024 样本的连续 Matroska 夹具实际给出 5,000、5,021、5,043、5,064、5,085 毫秒。实现以样本数保持连续节奏，并要求整个连续段存在同一个可行的最近时钟刻度相位区间；区间交集逐帧收紧，不允许每帧重新放宽误差。细时钟没有此容差。无法共享相位且至少领先完整一个刻度的时间戳才能开启新的间隙段，无法解释的其他不连续失败。原 PTS、样本区间和相位约束同时保存，可检查这项平台解释规则。

`makeAudioProduction` 生成 48 kHz 双声道 `pcm_f64le`，保持浮点幅度，拒绝非有限样本；单声道逐样本复制，双声道保持左右身份，多于两声道或未确认的声道布局拒绝。内部 raw PCM 不带时间戳，其固定 source map 是位置依据。原片先解码成原采样率 PCM，实际字节数必须符合逐帧解码报告，并保存每帧样本摘要。

每个连续段独立使用固定 swr 参数：double 内部精度、滤波尺寸 32、10 位相位表、exact_rational、linear_interp、0.97 截止比例、Kaiser beta 9、不抖动、async=0；禁止通过时间补偿拉伸声音。含义见 [FFmpeg 重采样参数](https://ffmpeg.org/ffmpeg-resampler.html)。CPU 优化标志固定为 0，记录实际 Linux 架构、镜像身份与版本；固定构建身份不能仅用多架构镜像地址代替。

实测 44.1 kHz 的单个输入样本直接经过固定 swr 得到 0 个输出，无法作为合法的最短音频。为明确提供滤波所需边界上下文，平台在每段末端扩展至少 256 个源率零样本，并把输入总量 L+C 对齐到 `R/gcd(R,48000)` 的整数倍；规则固定，实际 C 进入每段映射，它们在原呈现区间之外。192 kHz 的实测也显示，未经周期对齐的 257／258 个输入分别输出 64／65 个样本，因此不能假设重采样器的上下文尾端总是 ceil。先核对完整扩展输入实际生成精确整数 `(L+C)×48000/R` 个样本，再只保留原呈现区间内的 `ceil(L×48000/R)` 个采样时刻。上下文长度、完整重采样摘要与实际数量均进入映射，不能把滤波上下文当作新增内容时长，也不能遇到任意输出长度错误就补齐或截短。

视频调用方传入第一张有效视频帧的 PTS／time base 作为零点；独立音频以第一份有效解码音频样本为零点。正偏移 roundHalfUp 到输出采样位置。负偏移先按 ceil 剔除所有位于零点之前的重采样时刻，再将首个保留样本的位置 roundHalfUp；分数偏移可能留下一个明确的起始静音样本。每个间隙在最终固定位置补静音，不延伸素材末端，不混入代理声音。全部音频都在零点前时允许产生显式空 PCM，后续原生音频静音补足属于剪辑归一与渲染。

输出 PCM 按映射组装，复查有限值、单声道左右逐字节一致、实际字节数和摘要；源文件前后摘要必须不变。每个临时文件上限 8 GiB、连续段最多 128、源样本与相对零点的末端均不超过两小时。使用受控本地临时文件；制作 Worker 的总体写入预算、租约及宿主资源清扫见下文。

## 内部工件存储

`ProductionStore` 使用独立、启用版本管理的私有 bucket，键为调用方预先保留的 `productions/{artifactId}`。身份固定工件类型、实际字节数及完整 SHA-256；视频和音频工件上限 8 GiB，映射上限 256 MiB，显式空 PCM 可以是 0 字节。原片导入继续保持 256 MiB 上限，公开媒体签名仍不接受制作工件键。

小工件使用带完整 SHA-256 和不存在前提的 PUT；大工件以 64 MiB 分段。每个分段核对实际文件内容、服务端分段 SHA-256 和 ETag，并通过调用方 journal 记录上传身份、分段及完成阶段。未知创建结果从预留的精确键发现，已传分段只有摘要和大小均匹配才复用。发起 multipart 不盲目重试；已提交但完成回执丢失时查找固定对象版本。多个对象版本、删除标记或截断的发现结果均明确失败，不猜测应采用哪个结果。

multipart SHA-256 是组合校验，不能当作完整文件摘要。上传或恢复后均以显式 VersionId 完整流式读取对象，独立验证类型、元数据、实际字节数及完整 SHA-256；校验成功后才记录 verified。下载失败删除本次新建的文件，保留调用方原有文件。相关语义见 [S3 分段校验](https://docs.aws.amazon.com/AmazonS3/latest/userguide/checking-object-integrity-upload.html) 和 [条件写入](https://docs.aws.amazon.com/AmazonS3/latest/userguide/conditional-writes.html)。

只有已校验或已退出的工件才能清理其精确键下的 multipart；清理前重新检查归属，保留调用方 tombstone 以便后续再扫迟到的创建。传输有取消信号及 20 分钟总时限，分段内存有界，不将整个大文件载入内存。journal 的数据库实现及独立崩溃验证见下一节；原存储套件仍用故障注入适配器隔离验证存储行为，不能用它单独证明数据库持久性。完整 Worker 调度及宿主崩溃后的资源清扫已进入实际验证。

API 身份没有内部 bucket 权限。Worker 的 multipart 枚举权限只在独立内部 bucket 生效；原片 bucket 不授予该枚举权限，对象版本枚举限于 `productions/`。实际测试发现固定 MinIO 版本把 GetObjectVersion 隐式匹配为 GetObject，且缺失版本参数在权限上下文中表现为空字符串。权限因此显式排除缺失、空串及 `null` 版本；原片和预览的固定读取权限也采用此限制，staging 的受控快照读取保持独立。依据见固定版本的 [动作匹配代码](https://github.com/minio/pkg/blob/v3.1.3/policy/actionset.go)、[请求条件代码](https://github.com/minio/minio/blob/7ced9663e6a791fef9dc6be798ff24cda9c730ac/cmd/bucket-policy.go)；使用小写条件键兼容该服务，AWS 的[条件键名不区分大小写](https://docs.aws.amazon.com/IAM/latest/UserGuide/reference_policies_elements_condition.html)。本地兼容服务的验证不替代生产存储部署验收。

## 持久任务与故障恢复

迁移 `0015`／`0016` 为制作副本、实际来源、处理尝试、工件、分段和清理记录建立独立表。去重按租户／目标项目、源 SHA-256 和完整内部 profile；profile 固定目标帧率、视频或独立音频零点、制作 recipe、renderer／normalization 版本与实际镜像／架构。数据库统一 JSON 表示再计算摘要，字段顺序不同不产生新副本。每次请求，包括去重命中，都重新检查当前项目权限及实际 sourceMediaId，并用复合外键保存该来源和 SHA；其他私有项目中内容相同的文件不能因此被引用。归档原片的新制作请求仅接受目标项目仍保留的编辑历史引用。

`requestMediaProduction` 必须运行在调用方事务中，通过 savepoint 保证业务根和队列提示同时成功；即使调用方捕获入队异常继续提交，也不留下半份新根。队列载荷仍只有任务类型、业务 ID、步骤和 epoch。当前 queue parser 识别 `media_production`，原导入处理器显式拒绝该类型，防止误送入预览派生路径。实际制作 dispatcher 及其定时扫描已接入运行入口，行为见下一节。

处理尝试以数据库 60 秒租约和不可复用的 attemptId 限制写入；心跳、工件预留、分段回执、完成及失败均经过当前租约校验。失效租约不能续命或确认结果，新尝试复用同一步骤的固定工件及上传回执。自动尝试最多六次；暂时失败可以释放租约保留回执，显式恢复失败任务会重新授权、递增步骤并退出旧工件。并发显式恢复只推进一次步骤。仅当当前步骤要求的全部视频／音频及映射均有已验证固定版本时，才允许 ready；ready 的源身份和结果不可修改。

工作目录及容器资源记录绑定原尝试，名称将由预留 UUID 派生；清理任务只能认领已释放、已结束或租约失效的资源，宿主资源限定原 hostId。内部存储清理仅认领退出或完整 ready 的工件。清理自身也有租约，成功后保留 tombstone 并允许延迟再扫，不把迟到创建当作永远不存在。数据库归属与认领协议、解码容器创建前预留、宿主目录写入预算及清扫执行器均已接通，实际验证单独记录。

API、Worker 和调度器分别取得受限函数权限；API 不能读取原始工件存储回执或伪造租约，Worker 不能直接改表或调用调度扫描。所有新增 SECURITY DEFINER 函数均交给既有 NOLOGIN 授权角色，固定 search_path 并显式授予所需表权限。每个后台适配器方法独立使用短事务，存储及解码不会占着这些 SQL 行锁执行。

## 实际制作 Worker

`createProductionProcessor` 已接入运行入口的 `media_production` 分发，定时修复扫描同时补回制作任务提示。处理器核对固定 profile 的实际镜像／架构和当前内部 recipe，再以独立 60 秒 SQL 租约执行下载、逐帧／样本制作和固定对象发布；每 15 秒续约，失效或关闭即取消外部处理。已存储的完整结果可以直接验证恢复；重新计算的内容仍须与本步骤预留摘要相同。视频声音使用第一张有效视频画面的原 PTS 为零点，独立音频使用第一份有效样本。只有全部所需工件通过验证，业务根才进入 ready。

制作任务的队列总时限显式设为一小时，每次解码的三分钟限制保持。固定 pg-boss 的心跳只更新存活时间，不延长从任务启动起算的总时限；因此不能沿用导入任务的 120 秒总时限来运行完整制作。

每个制作目录和解码容器都先在 SQL 中取得资源 UUID，再实际创建。异步执行上下文覆盖制作内核中的探测、解码和编码；容器名称与标签固定资源 UUID 和宿主 UUID，清扫核对标签后删除实际容器 ID。目录位于私有工作根中，路径由资源 UUID 派生。宿主 UUID 通过完整文件原子发布并持久保存，同一宿主只能有一个持有数据库连接锁的协调进程；失去连接时停止处理。

每个制作任务默认最多累计写入 16 GiB，覆盖原片下载、中间 PCM、视频、组装音频和映射；在字节进入文件前记账，删除中间文件不重置预算。开始处理前按并发预留量检查可用磁盘，并留出 1 GiB 余量。超出写入预算明确失败，磁盘暂时不足保留恢复路径。宿主崩溃后的目录和容器由同宿主清扫器处理；未到期的尝试保持受保护，清扫成功仍保留迟到创建的再扫记录。内部存储清扫仅终止所属 multipart，不删除固定工件版本。

本地配置脚本创建独立、启用版本管理的制作 bucket，仅向 Worker 身份授予访问；已有生成配置可从精确匹配的旧内容原子升级，其他编辑保留。原导入 Worker 与制作 Worker 共用运行入口，API 的原媒体访问类型保持不变。内部制作 recipe 当前标识为 `production-worker-v1`，不表示最终交付编码、字幕字体或剪辑 RenderProfile 已完成。工作稿归一及页面确认仍须接通。
