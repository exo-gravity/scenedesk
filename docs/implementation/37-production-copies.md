本记录对应 [11 §6](11-transaction-and-implementation-blueprint.md#6-tx-04-采用规范化草稿与冻结) 的内部媒体阶段。当前在 `feat/cut-normalization` 实施；工作稿归一、确认、固定渲染和页面尚未接通，不代表 E05 已完成。原片、预览代理和制作副本继续保持不同身份。

## 视频时间与实际内容

`packages/media/src/source-timing.ts` 读取固定 FFmpeg 9.0.1 构建的逐帧 PTS 和 duration。compact 数字字段直接转 BigInt，不经过 JSON Number，也不读取平均帧率推算边界。首个解码画面 PTS 是逻辑零点；中间区间以后一帧 PTS 结束，末端必须有正的解码帧 duration。缺失、重复、回跳或不可解释的末端明确失败。原始 PTS、time base、末端依据均进入映射。

每个原帧保存对应输出帧的半开区间，包括没有输出帧的被跳过项。对于约分后的目标帧率 P/Q，输出数是 floor(DP/Q)，第 k 帧的来源由 kQ/P 落在哪个原帧显示区间确定。相接时刻选择新帧，合法长帧可以重复，片尾不足一帧不补满。这个区间表示可以无歧义地还原每个 k 的原始 PTS。

`makeVideoProduction` 使用 `native-ffv1-nut-v1` 内部 profile：源解码输出原精度像素，宿主按映射选帧，再通过另一受限容器编码为 FFV1／NUT。rawvideo 输入的尺寸、像素格式与整数帧率全部显式指定；FFmpeg 使用 passthrough，选帧规则由平台执行。该 profile 不是最终交付视频的编码或色彩策略。相关参数含义见 [FFmpeg 时间与同步选项](https://ffmpeg.org/ffmpeg.html#Advanced-options)、[rawvideo 格式](https://ffmpeg.org/ffmpeg-formats.html#rawvideo) 与 [NUT](https://ffmpeg.org/nut.html)。

支持的目标帧率与当前项目选项一致：24、25、30、24000/1001、30000/1001。制作保持原尺寸和位深；原色彩标记、色度位置、透明度解释、像素比例与显示矩阵进入 source map。原始显示矩阵由后续渲染依据读取；raw 解码禁用自动旋转。NUT 不携带完整色彩标记，渲染必须读取固定 source map；raw 流重新编码前使用 setparams 恢复已核验的色彩解释，并保持自动色彩转换关闭。无法保持的像素格式、隔行素材、片中规格变化，以及未验收的 HDR／ICC 附加元数据明确拒绝，不默认降为 8 位 SDR。

编码完成后再次探测并完整解码。必须同时满足实际帧数、每个 PTS、精确末端和所有画面像素摘要与源映射一致，且原片前后 SHA-256 与字节数相同，才返回工件。JSON 映射固定源摘要、构建、profile、原时间区间、原帧像素摘要与副本校验结果；本地目录或临时文件名不进入其内容。结果文件和映射均有独立 SHA-256。

## 隔离和失败恢复

解码和编码之间使用带背压的有界流，不将整段原始画面装入内存，不开放网络或可写宿主挂载。进程原有 3 分钟、768 MiB、2 CPU 等约束保持；原片限额沿用媒体导入规则。制作额外限制 1,728,000 帧、256 MiB 探测报告、每个工件 8 GiB 和每段 raw 流 256 GiB，超限明确失败。这些是资源上界，不承诺所有上界组合都能处理完成。

stdin 必须声明字节上限。异常输入、输出阻塞、超限、取消和超时均终止相关流；Docker 子进程已经结束而宿主输出尚未完成时仍保留取消能力。命名容器始终强制清理。制作工件写入本次独有临时目录，任一步失败清理整个目录；不删调用方原片或其他任务目录。

## 验证与接入状态

新增单元用例检查半开区间、NTSC 片尾、合法长帧、超过 Number 安全整数的正负 PTS、缺失或异常时间戳及不合法帧率。真实容器测试使用每帧亮度编码原帧序号的信号，独立读取输出像素，覆盖 VFR／非零 PTS、全部五种目标帧率、重复执行工件摘要、10 位样本、色彩与像素比例。流测试覆盖背压、输入超限、输入不结束、容器结束后宿主输出阻塞、上游异常与容器清理；另验证已经建立制作目录后的取消不留下半份工件。

最初完整视频测试触发了套件 360 秒总时限，不能计为通过。已减少重复帧率运行，将套件总时限设为 720 秒并把测试取消信号传入媒体执行；媒体进程自己的资源时限未放宽。随后通过了 VFR、五种帧率、重复摘要和制作目录取消检查，但 10 位夹具的色彩断言失败：NUT 未保留源标记。改用携带真实色彩信息的 HEVC/MP4，并修复 raw 流编码前未恢复色彩解释的问题后，10 位样本／色彩／像素比例的专项重测通过。H.264 B 帧原片也已通过完整像素比较。当前最终完整媒体回归仍在执行，结果以通过后的更新及 CI 为准。

下一步继续完成 48 kHz 双声道 PCM 制作及正负音画偏移、间隙和采样转换映射，再接通内部工件存储、持久去重、受限任务角色、来源依赖、归一结果、双版本确认和固定渲染。现有 `publish`／导入文件限额不能直接当作制作工件存储协议；接入时需独立验证大工件、不可变对象版本与崩溃恢复。当前函数仅返回 Worker 本地工件，不创建假 productionCopyId，不增加公开媒体 access variant，也不把队列成功当作业务成功。
