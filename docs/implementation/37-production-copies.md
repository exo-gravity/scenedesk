## 视频时间与实际内容

`packages/media/src/source-timing.ts` 读取固定 FFmpeg 9.0.1 构建的逐帧 PTS 和 duration。compact 数字字段直接转 BigInt，不经过 JSON Number，也不读取平均帧率推算边界。首个解码画面 PTS 是逻辑零点；中间区间以后一帧 PTS 结束，末端必须有正的解码帧 duration。缺失、重复、回跳或不可解释的末端明确失败。原始 PTS、time base、末端依据均进入映射。

每个原帧保存对应输出帧的半开区间，包括没有输出帧的被跳过项。对于约分后的目标帧率 P/Q，输出数是 floor(DP/Q)，第 k 帧的来源由 kQ/P 落在哪个原帧显示区间确定。相接时刻选择新帧，合法长帧可以重复，片尾不足一帧不补满。这个区间表示可以无歧义地还原每个 k 的原始 PTS。

`makeVideoProduction` 使用 `native-ffv1-nut-v1` 内部 profile：源解码输出原精度像素，宿主按映射选帧，再通过另一受限容器编码为 FFV1／NUT。rawvideo 输入的尺寸、像素格式与整数帧率全部显式指定；FFmpeg 使用 passthrough，选帧规则由平台执行。该 profile 不是最终交付视频的编码或色彩策略。相关参数含义见 [FFmpeg 时间与同步选项](https://ffmpeg.org/ffmpeg.html#Advanced-options)、[rawvideo 格式](https://ffmpeg.org/ffmpeg-formats.html#rawvideo) 与 [NUT](https://ffmpeg.org/nut.html)。

支持的目标帧率与当前项目选项一致：24、25、30、24000/1001、30000/1001。制作保持原尺寸和位深；原色彩标记、色度位置、透明度解释、像素比例与显示矩阵进入 source map。原始显示矩阵由后续渲染依据读取；raw 解码禁用自动旋转。NUT 不携带完整色彩标记，渲染必须读取固定 source map；raw 流重新编码前使用 setparams 恢复已核验的色彩解释，并保持自动色彩转换关闭。无法保持的像素格式、隔行素材、片中规格变化，以及未验收的 HDR／ICC 附加元数据明确拒绝，不默认降为 8 位 SDR。

编码完成后再次探测并完整解码。必须同时满足实际帧数、每个 PTS、精确末端和所有画面像素摘要与源映射一致，且原片前后 SHA-256 与字节数相同，才返回工件。JSON 映射固定源摘要、构建、profile、原时间区间、原帧像素摘要与副本校验结果；本地目录或临时文件名不进入其内容。结果文件和映射均有独立 SHA-256。

## 隔离和失败恢复

解码和编码之间使用带背压的有界流，不将整段原始画面装入内存，不开放网络或可写宿主挂载。进程原有 3 分钟、768 MiB、2 CPU 等约束保持；原片限额沿用媒体导入规则。制作额外限制 1,728,000 帧、256 MiB 探测报告、每个工件 8 GiB 和每段 raw 流 256 GiB，超限明确失败。这些是资源上界，不承诺所有上界组合都能处理完成。

stdin 必须声明字节上限。异常输入、输出阻塞、超限、取消和超时均终止相关流；Docker 子进程已经结束而宿主输出尚未完成时仍保留取消能力。正常执行及受控失败的 finally 均发出命名容器强制清理命令；宿主中断或 Docker 延迟完成创建时仍可能留下容器，持久任务接入时必须补齐按实际任务归属恢复清扫，不能把该情形计为已覆盖。制作工件写入本次独有临时目录，任一步失败清理整个目录；不删调用方原片或其他任务目录。

## 音频样本与呈现区间

`audio-timing.ts` 读取解码帧的原始整数 PTS、time base、样本数、格式和声道。解码器已经应用的 skip／discard 元数据不再裁第二次。细于或等于一个样本的时钟中，只有明确、精确、短于解码样本数的最后一帧 duration 才允许剔除尾部编码填充；中间短区间、不整样本的 duration 和不可解释的重叠失败。没有已知起始裁剪信息时，不能猜出 AAC 或 MP3 的编码延迟并擅自去掉内容。

粗时钟不能直接把每个 PTS 当成新的音频片段：48 kHz、每帧 1,024 样本的连续 Matroska 夹具实际给出 5,000、5,021、5,043、5,064、5,085 毫秒。实现以样本数保持连续节奏，并要求整个连续段存在同一个可行的最近时钟刻度相位区间；区间交集逐帧收紧，不允许每帧重新放宽误差。细时钟没有此容差。无法共享相位且至少领先完整一个刻度的时间戳才能开启新的间隙段，无法解释的其他不连续失败。原 PTS、样本区间和相位约束同时保存，可检查这项平台解释规则。

`makeAudioProduction` 生成 48 kHz 双声道 `pcm_f64le`，保持浮点幅度，拒绝非有限样本；单声道逐样本复制，双声道保持左右身份，多于两声道或未确认的声道布局拒绝。内部 raw PCM 不带时间戳，其固定 source map 是位置依据。原片先解码成原采样率 PCM，实际字节数必须符合逐帧解码报告，并保存每帧样本摘要。

每个连续段独立使用固定 swr 参数：double 内部精度、滤波尺寸 32、10 位相位表、exact_rational、linear_interp、0.97 截止比例、Kaiser beta 9、不抖动、async=0；禁止通过时间补偿拉伸声音。含义见 [FFmpeg 重采样参数](https://ffmpeg.org/ffmpeg-resampler.html)。CPU 优化标志固定为 0，记录实际 Linux 架构、镜像身份与版本；固定构建身份不能仅用多架构镜像地址代替。

实测 44.1 kHz 的单个输入样本直接经过固定 swr 得到 0 个输出，无法作为合法的最短音频。为明确提供滤波所需边界上下文，平台在每段末端扩展至少 256 个源率零样本，并把输入总量 L+C 对齐到 `R/gcd(R,48000)` 的整数倍；规则固定，实际 C 进入每段映射，它们在原呈现区间之外。192 kHz 的实测也显示，未经周期对齐的 257／258 个输入分别输出 64／65 个样本，因此不能假设重采样器的上下文尾端总是 ceil。先核对完整扩展输入实际生成精确整数 `(L+C)×48000/R` 个样本，再只保留原呈现区间内的 `ceil(L×48000/R)` 个采样时刻。上下文长度、完整重采样摘要与实际数量均进入映射，不能把滤波上下文当作新增内容时长，也不能遇到任意输出长度错误就补齐或截短。

视频调用方传入第一张有效视频帧的 PTS／time base 作为零点；独立音频以第一份有效解码音频样本为零点。正偏移 roundHalfUp 到输出采样位置。负偏移先按 ceil 剔除所有位于零点之前的重采样时刻，再将首个保留样本的位置 roundHalfUp；分数偏移可能留下一个明确的起始静音样本。每个间隙在最终固定位置补静音，不延伸素材末端，不混入代理声音。全部音频都在零点前时允许产生显式空 PCM，后续原生音频静音补足属于剪辑归一与渲染。

输出 PCM 按映射组装，复查有限值、单声道左右逐字节一致、实际字节数和摘要；源文件前后摘要必须不变。每个临时文件上限 8 GiB、连续段最多 128、源样本与相对零点的末端均不超过两小时。当前使用受控本地临时文件，生产任务的总体磁盘配额、租约及宿主崩溃清理仍须在持久 Worker 接入时落实。
