## 用户行为

图片、视频、音频草稿均可从当前项目的场次中选择镜头及确切历史版本。浏览候选不会改变选择；明确加入、替换版本、移除和调整顺序后，来源引用跟随原有节点／媒体类型／用户与会话分区的生成草稿保存。旧草稿缺少此可选字段时仍代表零来源。来源不写入画布文档，也不创建镜头绑定或自动采用结果。

准备计划前先复制本次选定的来源顺序，再等待画布保存。异步保存期间的操作不会改变原请求；已保存的计划请求继续使用原正文、幂等键及版本前提。刷新和来源读取失败不会将原选择悄悄清空。镜头后来产生新修订时，原选择不自动升级；新的计划可以明确更改来源。

固定计划和历史详情读取计划自身的镜头快照及实际参考顺序。原草稿删除之后，已提交任务仍保留来源、执行和结果证据，结果通过现有入口明确取回。

## 数据库约束

公开接口原本已经支持有序固定来源、跨场次的同项目来源、历史修订和类型化音频引用；本片复用这些接口。准备和执行前仍要求来源镜头及父级处于有效状态。执行后保存的历史文本继续按既有协议使用；没有加入会使已提交固定任务因后来归档而失效的额外限制。当前权限及实际媒体、声音版本可用性仍按原规则检查。

独立 SQL 负例发现原约束只核对来源关联及部分镜头规格，未完整约束解析后的镜头数量、身份与起止状态。追加迁移 `0095_fixed_shot_snapshot_projection.sql`，将每个有序解析条目与选定不可变修订生成的完整对象核对；额外镜头、替换身份和改变起止状态均被拒绝。原样输入仍可保存。既有触发器和角色权限保持适用，不增加接口或执行器分支。0095 在首次实际应用后冻结。
