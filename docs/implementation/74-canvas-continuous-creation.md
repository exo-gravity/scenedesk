# 固定剧本选文与连续画布创作

本片基于 Word 导入与项目画布，交付 PR-5 的第一条主路径。用户从当前稿或历史稿选择一段原文，添加到项目画布；选中文字继续创建图片、视频或声音草稿。画布的生成动作组合已有保存、固定计划与执行命令，正常路径不再要求先打开内部计划再确认执行。

## 固定来源与恢复

- 复用 `ScriptExcerpt`（固定剧本修订、Unicode 码点范围、原文）；UI 不要求填写修订或范围。Word 的段落、表格与 emoji 使用保存后的规范正文选文。原有纯文本的 CRLF/CR 经文本框显示归一后，选择位置映射回保存的精确原文，不修改固定来源。
- `CanvasTextContent.sourceExcerpt` 可选；有引用的原文不可原地改写。节点标题、位置可调整，用户在相连创作草稿中写新的生成描述。
- 仅新增迁移 `0111_canvas_script_excerpts.sql`：扩展永久 `canvas_node_index`，不新增业务聚合。SQL 依据同项目固定剧本验证范围与原文，节点删除后仍保留引用身份；复用原标识不能去掉或改指引用。
- 添加选文使用现有画布修订 CAS，服务器只追加这一节点。客户端在提交前保留原文与节点身份；回包丢失后读取原节点回执。相同请求不重复追加，原节点已经被移除时不自动恢复。导入新稿不升级旧引用。
- 当前权限及活动项目门禁在幂等缓存之前执行；固定回执读取仍允许归档项目历史查阅。接口重放读取当前节点状态，避免缓存旧的“仍在画布”状态。

## 生成与下一稿

`AssistantSession.generateFrom` 在一次明确点击内保存并核对点击时的画布输入，再持久化计划请求、取得固定计划并提交执行。执行请求仍先持久化再发送。画布保存/CAS 失败或期间内容改变时，不继续准备或执行。恢复页面仅读取；用户明确继续时才恢复原计划请求或原执行身份。

已有回执且处于排队、模型已接收、正在生成或归档阶段的任务可放入既有历史，继续编辑下一稿。原任务、旧计划与结果仍独立；结果进入画布仍需明确操作，新增结果节点不替换草稿，不自动采用镜头候选。提交未知、丢回包尚未核对以及需要对账的状态不能通过“下一稿”放弃原提交。

进入下一稿前重新读取原任务，核对固定任务及计划身份，再判断当前状态；轮询缓存不能授权放下原提交。读取失败、返回错任务或状态已变为提交未知时，原输入与执行身份保持不变。

节点编辑器按视口限制高度并滚动内容；空间不足时保留可见“专注编辑”入口。专注模式沿用原有编辑树和保留屏障。

## 第三批收尾：复用同一草稿与收敛入口（2026-09-16）

重新审查生产实现后，图片参考创建视频草稿、固定任务读取、结果就地预览、明确添加、同类型结果比较、准备下一稿，以及助手以 CAS 修改原节点提示的业务能力均已存在。本片不新增创作聚合或第二份助手草稿；补齐入口与验收：

- 场次画布不再常驻“画布／分镜台”双主切换，整理镜头使用既有镜头列表。“本场镜头与探索”的“查看镜头”也打开列表并定位确切镜头，保留画布编辑。`mode=storyboard` 旧深链仍读取原工作区，并提供经过编辑保留屏障的“返回画布”。旧制作和后期实现不删除。
- 助手建议成功应用后提供“继续编辑此草稿”。先核对助手输入和原应用回执已本机保留，再沿用画布和生成参数的保留屏障；目标仍是原固定节点标识。目标消失、权限或保留失败时留在原处，不创建新节点、不执行生成。
- 节点编辑器在左右边缘被裁切时也保留可见的“专注编辑”入口；打开辅助区不会强行移动画布或创建另一个编辑会话。
- 新增专项浏览器场景：图片参考→两次视频生成→明确加入→比较→刷新查回固定历史；助手应用丢回包→读取原回执→继续同一草稿；默认镜头列表和旧分镜深链兼容。

专项 fixture 只在独立本机 `drama_e2e_*` 数据库及 `PROVIDER_MODE=mock` 启动；生成调用的是注入的受控 adapter，视频为库内蓝／橙样片、图片为合成 PNG。固定计划、任务、应用回执与画布写入使用真实业务接口和受限角色；媒体归档使用受限 SQL fixture，不冒充生产媒体解码或真实供应商验收。浏览器手工与自动执行证据须在验证后追加，本段的测试构造不构成通过记录。
