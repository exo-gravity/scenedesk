# 场次主责与人工任务

2026-09-11。落实 [14 的场次主责规则](14-scene-mvp-closure.md#6-场次主责与整集闭环)及 AT-29／AT-50 的人工分派、资格变化与历史保护部分。

## 已实现行为

- 项目负责人、工作室所有者及管理员可新建一般任务、协助任务或场次主责；普通协作者只更新自己有效任务的状态与处理说明，不能修改标题、分派、范围、阶段或期限。
- 受派人须为当前有效且可访问项目的成员；管理员和所有者具有隐含项目资格。撤销项目资格或暂停成员后保留原受派人和历史，读取时显示待重新分配。资格变化不伪造任务修订。
- 每场永久只有一项主责任务，已完成也不能新建第二项。改派与重新打开均修改原任务；类型及主责场次不可更换。任务状态不代表生成作业进度或审稿批准。
- 一般／协助任务可以不绑定场次或镜头。显式同时绑定场与镜时必须确为同场；有这种任务的镜头跨场移动会被拒绝，负责人须先明确调整任务范围。仅绑定镜头的任务可按镜头当前场次筛选。
- 每次实际任务修改在同一事务追加不可变修订，保存当时完整分派、状态、说明、截止时间、操作者及时间。无修改的请求不增加修订。当前根版本必须有对应历史，失败写入整体回滚。
- 场次首页显示主责与处理状态，“查看本场分工”进入相应筛选。列表支持类型、状态、场次及“只看分配给我”；详情可核对历史。编辑输入在本标签页本地保存，刷新后手动恢复；CAS 冲突呈现服务器内容，明确核对后才能继续保存。

## 数据与接口

迁移 `0007_production_tasks.sql` 创建 `production_tasks` 与 `production_task_revisions`。tenant／project／场镜采用复合外键，场次主责采用永久唯一索引；根版本指向历史的延迟外键阻止遗漏修订。历史不可更新／删除，任务身份受触发器保护，业务角色只有必要的列更新权限，两个表均启用强制 RLS。

`getTask` 返回当前任务和 ETag；`listTaskRevisions` 返回不可变快照。历史自身 `revision=1`，`number` 对应任务当时根版本。当前 `assigneeAvailable` 是读取时权限事实，不存入历史快照。列表游标绑定用户、项目、全部过滤条件，历史游标额外绑定任务 ID。

请求继续使用业务内核的身份校验、Origin／CSRF、幂等、授权锁与 CAS。项目写锁和成员变更锁保证受派资格在写入事务期间稳定；同键重放重新授权，并由唯一主责约束防止换键重复创建。归档项目只读；已归档场次原有任务可在活跃项目内处理收尾，但不能向归档内容新派任务。

本地已升级既有持久化数据库，应用 0007 并重新验证受限角色，没有改写既有迁移。
