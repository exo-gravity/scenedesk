# 画布节点主体拖动与创作导航保留

2026-09-14。分支 `feat/canvas-node-body-drag`，基于 PR #37 合入后的 `42cfb812c91a9e2a0da6cfe2ad3ed60dc3f6d2be`。本说明记录当前工作树修复、最终本地检查与浏览器验收；提交及远端集成状态另由整合任务记录。

## 问题与实现

真实浏览器复现了图片主体拖不动：节点仅允许从标题区域拖动，媒体和文字预览又被标为 `nodrag`。现在 `CanvasBoard` 移除标题专用拖动句柄，让图片、文字、生成草稿及未播放的视频海报主体使用原 React Flow 拖动流程；原生图片 `dragstart` 被阻止，避免拖出浏览器图片。多选移动、原保存协议和 Undo 不变。

预览与编辑仍有不同交互：播放按钮和已展开播放器保留 `nodrag/nopan`，编辑 portal 中输入、选字不变；节点只读、手形、专注编辑期间不允许拖动。代码同时在按住 Space 时关闭 `nodesDraggable`；**Space 组合本轮仅代码审查，未计入真实浏览器通过项**。

切换镜头、场次或模式之前，仍须保留项目内当前身份的助手与创作输入。本轮修复以下生命周期边界：

- 已保存的旧编辑器卸载时会进入清理用 `checking`；不能把这个过期状态当作当前权限失败，永久阻止后续导航。注册记录区分挂载与卸载，已保留且空闲的旧记录可释放。
- 卸载不等于保存成功。`hasUnretainedDraft()` 同时检查可见和暂时隐藏的输入；未保存残留、失败写入或未结束操作继续阻止切换，重新挂载同一 controller 不能用重复旧注册覆盖新状态。
- 导航失败保留目的地，提供「留在当前页」及「重新核对并切换」。后者是用户明确触发的权限/固定记录读取与本机重存；最新内存输入优先于旧存储副本，不自动重发计划、执行、采用或意见提交。
- 正在核对时等待**已经启动**的 `settleAccess()`，不另启请求，也不取消原请求；权限拒绝、存储失败或等待超过 15 秒仍停留当前页。真实快速切换进一步发现：等待中后来挂载的编辑器没有参加原等待，造成误拦。最终屏障动态纳入这些编辑器，共享原 15 秒截止时间，不能漏检或重置预算；修复后已完成针对性测试与实际快速切换复验。
