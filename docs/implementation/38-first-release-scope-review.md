# 当前 MVP 范围与上线顺序

日期：2026-09-11。用户要求优先尽快上线可用版本，并连续明确了范围：完整团队管理、对外注册和运营暂不需要；后期剪辑可以移出 MVP；**画布和 AI 能力整体仍按原计划推进**。

本文件是当前发布范围的覆盖说明。此前提出的“暂不做画布”“轻量画布＋纯文本助手”“第二步必做单场剪辑导出”建议已经被最新决定取代。已确认的画布与 AI 设计继续适用，不再重新询问是否只做其中一种助手任务。

## 保留与后置

| 范围 | 当前决定 | 实施边界 |
|---|---|---|
| 项目、剧本、集场镜、资产、素材导入预览、候选与明确采用 | 保留 | 复用已合入能力，保留实际来源与固定版本 |
| 分镜／自由画布双模式 | 按原方案保留 | 每场一张画布，文字／图片／视频／音频、引用边、分组、镜头关联、个人偏好、固定生成输入、结果取回、保存冲突与有限恢复历史；按18／21及CX01–06实施 |
| AI 辅助与媒体生成 | 按原方案保留 | 分镜建议、提示准备、按意见准备修改及原定媒体生成流程；明确上下文与目标、固定输入／能力版本、建议修订与确认应用、异步任务与结果归档；不缩成普通聊天或仅文本提示词 |
| 模型执行的可靠性与基础安全限制 | 保留 | 任务／attempt、幂等、未知提交核对、取消语义、并发和用量上限、结果归档恢复仍是实际模型调用的必要条件 |
| 商业计费与费用运营 | 后置 | 不做客户收款、套餐／充值、完整费用后台和运营核账；供应商任务身份及实际返回用量可记录，不用缺少证据的“0费用”替代未知状态 |
| 登录与基本项目访问隔离 | 保留 | 使用真实身份，限制私有试用者访问；复用已有权限约束 |
| 完整团队管理、开放注册、运营后台 | 用户已明确暂不需要 | 预先配置试用访问；不重新建设组织运营流程 |
| 时间线剪辑、混音、字幕、归一、冻结和成片渲染 | 移出 MVP | 已有后期代码和历史保留，停止将这些功能作为当前发布依赖；用户在外部工具完成后期 |
| 完整后期审阅／交接、整集编排、跨集制作流程 | 后置 | 不要求渲染成片、完成两集或后期工作包才能发布当前创作工作台 |
| 多家工作室和连续两集试点 | 后续阶段 | 首次上线以实际创作任务验收；画布原定容量、保存恢复和模型异常验证不因此取消 |

“按原方案”同时保留原有边界：引用边表达当前输入，不是任意可执行工作流；无整图自动运行、复杂 Agent 编排或无确认付费重试。AI 结果、候选、采用和画布呈现是不同事实。画布和 AI 的原能力验收不以减少可见按钮或只跑 mock 替代。

按意见准备修改保留原设计；涉及已移出首版的剪辑／固定审阅对象的动作，只能在实际来源可用时开放，不伪造来源，也不借此把完整后期系统重新加入首发门槛。独立的镜头与生成输入处理沿原契约实施。

## 当前 MVP 的可用闭环

登录 → 创建项目和场次 → 整理剧本、参考和镜头 → 在分镜／画布中准备创作输入 → 使用 AI 辅助并明确采用建议 → 确认并执行生成 → 查看和取回结果 → 比较、形成候选并明确采用 → 下载素材，在外部工具完成后期。

分镜和画布共用制作事实。用户切换模式、浏览其他镜头、关闭页面或遇到保存冲突时，不能把建议目标、生成输入或已选素材偷偷替换成最新对象。旧结果和原片保持不变。

现有素材／分镜工作台可先部署供用户试用和整理资料，但这是提前试用切片。画布和原定 AI 流程尚未完成时，不宣称当前 MVP 已全部完成。应用入口应移除后期、费用运营和原型演示的使用路径。

## AI 实施计划与实际状态

实施顺序先打通“当前场次剧本 → 可编辑分镜提案 → 明确采纳 → 镜头与画布”，复用现有 CSV 提案的持久化、人工修订、逐项选择及基线冲突处理。随后接通提示准备、固定生成计划、媒体生成与结果回到画布；依此逐项完成原定辅助能力。这是交付顺序，不是把原定 AI 范围缩成一个文本功能。

助手沿原设计以非模态侧栏服务明确的场次或镜头，显示实际选定上下文和目标。建议可以编辑、保存、重新打开和明确应用；生成执行使用已经固定的输入，避免浏览位置或参考变化改变正在执行的任务。

当前事实：项目、镜头、素材及 CSV 提案的业务接口已实现；`packages/provider` 目前只有故障模拟器。真实 AI 供应商、助手业务面板、AI 输出到提案、生成计划及画布生成结果接入均待实现。已有聊天样例、Schema 或 mock 测试不计为助手／生成可用。

真实 AI 需要实际可用的模型服务、能力验证和必要凭据；付费调用还需要费用授权。保留导入素材路径可以继续工程和页面工作，但不能以“无模型也能打开页面”代替 AI 验收。首个真实接入按原方案选择并验证指定服务，不因为保留多种能力就同时接所有供应商。

## 上线顺序与验收

1. 保留已做的后期分支和验证记录，停止追加归一／渲染功能；后期 PR 不再阻挡此次发布。
2. 同步当前范围与应用入口；复用已合入基础、现有主题与组件，不重做已验证业务。
3. 按原方案完成画布持久化、交互、引用、结果取回、冲突和有限历史；完成原定 AI 辅助与生成切片。
4. 同时准备可复现的部署、真实登录、持久化数据及对象存储、HTTPS、备份和恢复。
5. 使用实际场次和真实模型完成创作闭环，核对异常恢复；部署后从干净浏览器复验。后期处理和商业运营不作为发布验收项。

仓库当前只有本地 PostgreSQL compose 和开发启动脚本，没有完整生产部署交付。不能把本地预览或某条 CI 通过称为上线。不作缺少模型与部署条件的日期承诺，先消除当前发布所需的实际缺口。
