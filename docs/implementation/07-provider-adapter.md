# 07 模型接入、能力配置与验证规程

目标是接入一条稳定的写实短剧主路径；Seedance 优先评估。模型品牌、网页端体验、API 服务、账号权限和执行模式不是同一个概念。此处不承诺某个尚未核验的版本支持所有参考、对白、声轨、取消或幂等。

## 1. 本轮核对得到的工程约束

- 官方火山方舟 Python SDK 在本轮查阅版本中的默认重试为 2，创建任务也会经过请求层。客户端关联 ID 不能自动证明供应商创建幂等；适配器需要关闭创建端隐式重试，并检查自身实际使用的客户端与代理配置。[固定版本 SDK](https://github.com/volcengine/volcengine-python-sdk/blob/bd7d94433803d213a85f918ff2eb049067655eff/volcenginesdkarkruntime/_constants.py)
- 官方 SDK 具有内容生成任务的创建、读取、列表与删除接口；类型存在不代表指定账号、模型和模式具备全部能力。[官方任务资源定义](https://github.com/volcengine/volcengine-python-sdk/blob/bd7d94433803d213a85f918ff2eb049067655eff/volcenginesdkarkruntime/resources/content_generation/tasks.py)
- BytePlus LAS 的特定区域文档存在任务与结果有效期、真人参考访问条件及不同算子收费规则。它们不能直接迁移为中国区方舟或所有 Seedance 接口的统一规则。
- 本轮未找到足以把所有相关回调都视为已认证、严格有序且恰好一次送达的依据。默认把回调当查询提示，费用和媒体状态以可信查询／账单证据确认。

详细访问记录、适用范围与原始链接见 [模型接入证据](../research/2026-09-07-implementation-model-evidence.md)。本包中的“默认禁重试”是据此做出的系统设计，不是对供应商实现的推断。

## 2. Capability Profile

每条启用能力固定 connectionId、`connectionVersionId`、供应商服务、地区、账号、模型版本、模式、计价版本、验证时间和证据。连接版本的 service、region、providerAccountIdentity 不可变；不同账号或地区不可共用一次通过结论。plan／job／attempt 均固定连接版本，恢复不跟随连接当前配置。公开 API 返回界面需要的脱敏身份和限制；内部配置额外保留恢复、计费、文件期限与验证用例结果。

| 配置组 | 必须说明 |
|---|---|
| 输入 | 文本；图／视频／音频类型；用途映射；每类数量、尺寸、时长、大小；真人参考条件 |
| 模式 | 文生、图生、多参考或其他实际支持模式；不能由一个宽泛 supportsReferences 布尔值替代 |
| 输出 | 时长、画幅、分辨率、帧率限制；是否原生音频；混合轨还是分轨；是否允许首尾帧同时使用 |
| 生命周期 | 创建与查询地址、状态映射、轮询间隔、任务保留期、结果链接有效期、取消及恢复语义 |
| 消费 | 估计公式和输入、定价版本、基础估计／余量、币种、费用来源、分笔完整性证据、失败／取消计费、内部重试是否产生多笔费用 |
| 可靠性 | SDK／代理重试设置、已测试的幂等或找回能力、回调校验、限流和错误分类 |
| 数据处理 | 输入上传路径、供应商保存期限、地区和适用协议；实际采购确认后填写 |

未验证项使用 unknown／未启用，不能以 false 隐含“不可能”或以 true 推断可用。管理者可停用连接，但不能自行把未验证的能力勾成已验证。首版由受控配置发布能力，无需建设面向用户的通用适配器管理平台。

秘密绑定使用明确 secret reference／version，轮换先核查供应商账号身份。只有同账号、同服务／地区的已验证后继秘密版本可用于旧连接版本查询；保存后继关系、验证时间与证据。跨账号凭据不构成普通轮换，必须新建连接并重新验能力。若供应商无法提供可自动读取的稳定账号身份，启用前用受控人工证据记录与核查，不按密钥字符串相似或查询失败推断同账号。停用连接阻断新分派，但不抹掉旧身份与必要恢复能力。

## 3. 接口边界

以下为模块接口设计，供应商完整 TypeScript 类型在 S2 落地，S0 contracts 包仅生成平台 OpenAPI 类型；不是可直接调用的供应商 SDK。

| 操作 | 输入 | 返回与责任 |
|---|---|---|
| prepare | 固定创作输入、连接版本／能力配置、已验收媒体清单 | 完整 resolvedInput、实际来源版本清单、语义输入摘要、估计公式／计量输入／余量或明确阻断；不执行付费生成 |
| stageInputs | 已保存 plan、媒体读取授权、connectionVersionId | 必要的供应商上传引用及期限；逐项保留 mediaId／媒体版本／用途映射；只有已核验安全性才可恢复上传 |
| submitOnce | 持久化 attempt、已完成 staging 的 PreparedRequest、绑定秘密版本 | Accepted(providerJobId, receipt)／Rejected(evidence, billingState)／Unknown(correlation)；不吞未知为普通失败 |
| query | 固定连接版本及其可用同账号秘密、已知 providerJobId | Pending／Running／Completed(outputs)／Failed(evidence)／Cancelled(evidence)／Unavailable(reason) |
| recoverSubmission | attempt 证据、具备已验证找回能力的原连接版本 | Found(providerJobId, evidence)／ConfirmedNotAccepted(evidence)／Unresolved；unsupported 直接 Unresolved |
| requestCancel | 已知 ID、原连接版本、已核验能力 | Requested／ConfirmedCancelled／Unsupported／Unknown；均不自动产生退款 |
| readCostEvidence | 固定连接版本、作业回执或官方账单定位信息 | CostEvidence(costStatus=pending/partial/final/unavailable, entries, completenessEvidence?, observedAt)；仅 final 可带明确完整性结论，unavailable 转受控人工核账 |

媒体归档由 AssetMedia 负责，供应商 Adapter 只返回来源定位与期限。文本同步 API 可以返回直接完成的分镜提案或提示／返工建议源数据，由 Generation 按 purpose 和 assistance.kind 进行结构及范围校验；不能伪造一个可查询的 providerJobId。所有调用记录 correlation；秘密与签名 URL 不进入可见快照或语义 inputHash。staging 完成后持久保存 actual request hash／受限请求证据和 media→provider reference 映射，标识提交过什么；这不改变用户已确认的创作输入。若 staging 必须改变实际素材内容、用途或参数，阻断并重新形成计划，不能只换一个 hash 后继续提交。

prepare 的实际输入必须可回显：使用了哪一版角色和造型、哪些媒体、每项用途、文本如何形成、哪些条件不受支持。由 DramaPlanning 提供实际参与解析的 Production／Scene／Shot 与固定资产／造型版本清单，Generation 保存该清单和完整 resolvedInput；提交时只检查这些明确依赖与策略，不因另一个未使用造型变化而重解旧输入。估计保存定价版本、计量输入、基础金额和余量，显示预占从何而来。不同模型路径可以有不同必填项。支持直接多参考时，不强制先生成首帧；只支持首帧时，界面明确需要准备该输入。无法映射的声音／动作参考返回阻断或由用户明确移除，不能静默忽略。

stageInputs 若使用会计费的预处理算子，必须成为显式计划与预算项，不能隐藏在“上传”里。首版优先选择免费媒体上传或授权 URL 输入；如必须采用付费预处理，先更新计划和费用契约再启用。

### 3.1 迟到回执与权威状态分开

内部 `recordSubmissionEvidence(attemptId, receipt)` 接收追加式不可变证据，以 attempt、来源和证据摘要去重。受信 Worker 即使 lease_token 过期，也可保存自身请求的迟到回执；该入口没有“设置 job.status／金额”参数。原 lease 失效不能成为丢弃唯一 providerJobId 的理由，旧 Worker 也不能借追加证据回滚权威状态。当前持有者／核对任务按 connectionVersionId、request hash、provider task 唯一关联验证后推进状态。同一 attempt 出现冲突 ID 时进入 reconciliation_required。普通用户、未经核验回调不得直接写入可信证据；未知回调仍只唤醒查询。详见 [11 TX-02](11-transaction-and-implementation-blueprint.md#4-tx-02-一次分派与迟到证据)。

### 3.2 费用终局性与预算投影

Adapter 的 entries 是本次观察到的可识别条目，带 charge key、币种、金额和证据；Budget 去重并累计 `confirmedCost`，不能把每次拉取的数组当作整项累计金额直接覆盖。状态含义如下：

| costStatus | 可认定的事实 | 对预占的影响 |
|---|---|---|
| pending | 暂无完整账单，仍可继续核查 | 保留未决金额，不记录 0 元实际消费 |
| partial | 已有一项或多项可靠费用，但尚不能证明完整 | `reservationRemaining=max(原预占估计−confirmedCost,0)+K`，K 为单列控制预留 |
| final | 有覆盖该作业全部已知收费分项／尝试的完整性证据，或有确定无费用证据 | 在同一结清事务释放基础剩余预占和K；可为 0 元 final，但不能由失败状态推断 |
| unavailable | 当前服务没有可靠自动取证路径或证据已不可取得 | 转受限人工核账；已有 confirmedCost 保留，remaining 不因 unavailable 释放 |

pending／unavailable 若此前已有部分确认，同样按既有累计金额保留基础 `max(原预占估计−confirmedCost,0)`，API另加K；不得因后续查询失败清空确认记录。每笔已确认消费只记一次。原估计含预占余量；project 作业约束工作室和项目，shared 作业仅约束工作室。若尚未 final 而 confirmedCost 已达到或超过原估计，基础remaining=0 只表示原预占耗尽，并不证明没有未知费用：阻断该连接的新提交，直至核清或经受控命令明确增加有限敞口预留并审计。该控制预留与 job 的原估计剩余分列，API reservationRemaining为两者之和，同样减少可用额度，不篡改原计划。final 后更正继续追加；可信证据推翻既有完整性结论时重新标记未决并阻断核查。

完整性证据须指明覆盖范围、来源、时点及对应服务／账号／作业；调用成功、第一笔账单到达、任务取消或等待超时都不充分。供应商无法给出该结论时只接受有证据的人工核账，保留未决亦是有效结果，不宣称所有账号均能自动结清。

## 4. 作业输出与候选

| purpose | 成功后的平台对象 | 失败边界 |
|---|---|---|
| video | 原媒体、必要元数据；单镜头可形成候选，多镜头由人映射区间 | 无法验收文件为 archive_failed；画面不好可仍 succeeded，由人不采用 |
| image | 图片媒体，可用于角色、造型、场景或实际生成输入 | 成功返回与角色设定确认分离，不自动替换资产当前版本 |
| audio | 音频媒体，可显式编入时间线 | 不因文本相同就自动覆盖镜头原生音轨 |
| script_analysis | 通过 schema／作用域／父子关系校验的 Proposal | 非法提案为 failed，不写入剧本结构；费用照实核对 |

一项视频任务可能包含多个镜头，也可能只完成某个镜头的一部分。Provider 输出的段落描述或台词时间不是精确剪辑依据；候选区间由验收媒体及人的选择确定。模型提供结构化切点时也要先校验再呈现。

## 5. 连接验证清单

在所选账号上执行并保留请求摘要、实际回执、文件参数、费用和结论，密钥与私有内容脱敏。真实调用需要已确定的采购账号与测试预算；文档静态校验和模拟器均不能代替本节。

| ID | 必须验证 | 可启用条件 |
|---|---|---|
| MV-01 | 最小输入到可播放输出 | 原文件及时归档、参数与报价依据可解释 |
| MV-02 | 同人物多参考／所选造型，或该模式替代输入路径 | 支持的输入角色确实送达；效果由行业评审记录 |
| MV-03 | 双人对白与短动作 | 明确原生音频是否可用、音轨形式、常见返工路径 |
| MV-04 | 创建超时、进程中断、租约过期后回执到达 | 实际调用栈不自动重 POST；迟到 ID 被追加保存但不能回滚现状态；未知能被显示和核对 |
| MV-05 | 已知 ID 查询、限流与暂时错误 | 重查可恢复，错误和过期状态映射正确 |
| MV-06 | 输出 URL 过期／下载中断 | 可以恢复或明确不可恢复；未再次购买 |
| MV-07 | 取消与成功竞态 | 保存真实结果并核对消费，无“取消即退款”假设 |
| MV-08 | 用量、分笔／乱序账单与终局性核对 | 部分确认不提前结清或双占；final 有完整性证据；非 final 超估计阻断并核对；无自动取证时保留未决 |
| MV-09 | 真人素材与所选服务访问条件 | 指定账号确实允许预期输入，输入资料符合该服务约定 |
| MV-10 | 同账号秘密轮换、误填跨账号秘密、停用及旧任务查询 | 原 connectionVersionId 不变；同账号后继有验证；跨账号需新连接，不能继承能力；停用不丢旧任务身份 |

主路径入选以约定质量下的可采用率、人工修改分钟数、实际成本和交付周期共同评估。若直接音画路径对白不可控，可以采用原生视频静音加外部配音／补镜头，但新增步骤计入成本。不能只比模型返回成功率或单次报价。

## 6. 首版与演进

S0 先做有限模拟 Adapter 验证接受、明确拒绝和响应丢失；查询延迟、取消竞态、过期文件及完整费用核对仍是 S2 验收要求。S0/S1 同期核实真实主路径账号、模式和文档，在预算与账号落实后尽早做独立接入试验，避免到界面完成后才发现能力缺口。图像和文本能力只做到样片所需，独立语音在主路径需要时接入。实现第二供应商时再检验接口是否过度贴合第一家，不提前实现大量空适配器。

长期新模型接入只应修改能力配置和 Adapter，以及确有不同输入需求的计划表单；不应改变镜头、采用、冻结审阅和租户费用规则。若未来供应商提供长段自主创作，仍保存明确输入与输出版本，由业务模块决定如何拆成镜头或广告创意；不让供应商任务结构成为全平台数据模型。
