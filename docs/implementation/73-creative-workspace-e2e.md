# 创作工作区端到端与设计验收

2026-09-16。用户要求核心设计与页面做端到端测试。本规范落实在[重构计划](70-creative-workspace-refactor.md)的每个业务切片，沿用[已确认设计](../design/creative-workspace-approved-2026-09-16.md)，不等最后一个 PR 才回归。测试不是新增产品功能；未实现的用例不能用假页面标记通过。

## 合并条件

每个核心页面 PR 同时提供以下证据：

1. **实际业务流程**：浏览器操作正式构建，连接实际 API、受限数据库角色及适用的存储／队列。断言用户可观察的结果，并通过刷新、另一个会话或公开读取接口验证持久化。不能把全部业务接口替换成成功响应再称为端到端。
2. **故障恢复**：覆盖本次修改涉及的响应丢失、冲突、刷新、退出、权限和归档边界。局部故障注入必须注明；恢复后确认没有重复业务效果、草稿丢失或固定引用漂移。
3. **设计与交互**：查看生产构建的真实截图和操作，对照已确认页面的层级、工作区占比、工具位置、状态反馈及上下文连续性。类型检查、DOM 存在、无横向溢出和截图文件生成都不能单独证明设计验收。
4. **自动回归**：稳定主路径进入仓库 E2E 套件并在 CI 执行；后端权限／事务／供应商状态的组合边界继续由数据库和媒体测试覆盖。自动回归尚缺失时明确记录，不用一次手工检查关闭其缺口。

由负责该 PR 的实现者记录用例、提交和结果，集成时核对真实差异及证据。失败需要修复或明确缩小交付范围；不能通过删断言、盲目更新截图或改成始终成功的 mock 解除门槛。会产生费用的真实模型验收按已授权服务和额度独立执行，CI 默认不访问付费供应商。

## 共用负例与设计检查

这些检查随影响范围选取，不要求每个小改动重复执行无关组合：

| 范围 | 必须保留的断言 |
|---|---|
| 访问与权限 | 当前 tenant/project 权限决定读写及原件下载；跨项目 ID、撤权、只读和归档有明确结果；幂等命中仍检查当前权限 |
| 冲突与确认 | 第二会话更新后原确认不能静默覆盖；保留当前草稿、原目标／版本和重试所需信息；失败弹窗可退出但不误报成功 |
| 本地恢复 | 网络不可用、保存回执丢失、IndexedDB 保留失败及刷新；不在业务效果和本地恢复状态不一致时显示保存完成 |
| 执行与媒体 | 固定输入／供应商任务／归档结果分开；unknown 不触发新付费提交；原件、预览、正式结果不混用 |
| 桌面视觉 | 在约 1440px 和 1280px 宽度核对主次层级、侧栏、画布可用面积、节点输入和助手占位；真实长标题及长模型名不挤坏布局 |
| 窄屏与键盘 | 约 820px 与 390px 检查入口、抽屉、滚动、错误和确认；Tab 焦点可见、弹窗焦点管理正确；不能靠裁剪隐藏功能 |
| 状态与主题 | 明暗主题、加载、空白、只读、失败、运行中和完成状态；状态名与真实业务事实一致，不以颜色作为唯一提示 |

新 E2E 基础设施使用隔离合成项目和测试身份，测试启动和清理不会重置现有本机项目。测试专用身份引导不能进入生产部署。fixture 媒体／供应商必须明确标识；测试产物不得包含真实客户文档、可用会话令牌或私有存储凭据。
