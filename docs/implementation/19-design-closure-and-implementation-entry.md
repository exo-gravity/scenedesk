## 2. 工程应遵守的当前基线

1. **一个场次，两种制作模式。** 每场唯一画布，多个镜头与共用参考可并存。分镜详情与节点编辑只是当前焦点；不创建每镜头独立工作区。首次默认分镜，之后恢复个人选择，明确链接优先。
2. **共同事实只有一份。** 素材、生成计划／任务、候选、采用、剪辑和固定审阅版本共用。模式切换不生成、不自动绑定、不采用、不重排镜头，也不改变旧剪辑或固定稿。
3. **画布保存自身文档。** 文本、媒体引用、生成草稿、位置、引用边和可选分组属于画布；成员视口属于个人偏好。节点类型与媒体身份固定，换素材创建新节点；异步任务只更新任务事实，结果由明确操作取回。
4. **先保护修改，再增加协作复杂度。** 首版整文档 CAS，冲突保留本地修改并停止自动覆盖。没有实时共同编辑、任意执行图或后台智能合并承诺；同伴可以查看，冲突可识别可恢复。
5. **生成有确切输入与采购边界。** 保存输入后准备固定计划，展示引用、模型与费用，再明确执行。画布位置不使计划过期；实际提示／参考改变会。未知提交查原任务，不重新购买。
6. **首个场次闭环不能代替完整 MVP。** 完整交付仍需真实生成、声音与轻量剪辑、固定审阅返工、整集交付、第二集资产复用与内部后期接手；每场双模式同时在验收范围内。
7. **通用内核复用，业务入口分阶段。** 通用画布、媒体、模型执行、版本、审阅及组织权限不写死短剧层级。当前只接短剧；广告之后接营销任务／品牌与商品语境，不创建假场次。广告画布默认交互还需分别验证营销人员与制作团队。

## 3. 明确开工后的执行顺序

**第一步：E01、T01、E02–E03。** 完成可信身份和项目权限、集场镜与固定要求、实际媒体上传验收及私有访问。先交付真实 API／数据库和最小可操作页面。模型账号能力调查 V01 同时推进；不等待模型采购才做通用工程。

**第二步：E04、E05A、E05–E06与CX01–03／CX06。** 用导入素材完成候选采用、明确组接、声音字幕、冻结、审阅与素材包；同时实现唯一场次画布、保存恢复、局部输入和镜头关联。导入片段也必须走不可变媒体和真实区间校验。

**第三步：G01–G04 与 CX04。** 接入经账号验证的一个 Seedance 正式服务。固定计划、预算、一次提交、未知恢复、媒体归档、核账和画布结果取回形成同一条链。第二供应商由实际缺口触发。

**第四步：C01–C03、CX05、U01。** 完成连续两集、真实内部后期交接、冲突／撤权／容量／恢复演练及工作室任务试点。按失败点修复后，再扩大工作室规模。

工作包逐项同时包含数据、接口、UI、异常恢复及验证，不拆成“先写完全部接口，再做所有页面”。岗位责任及依赖见 20；实际人手、金额与日历需要真实组织信息后填写，本文不虚构上线日。

本轮可自主完成的设计准备已给出。真实服务账号、实际测试金额、素材授权事实、云资源、人手投入、试点客户和软件收费约定尚未取得，集中在 [20 的 EV-01–09](20-external-validation-and-launch-plan.md#4-外部条件清单与最晚关口)。它们在对应动作前核实；明确开工后，可先推进不依赖这些条件的身份、媒体、工作区和事务工作包。
