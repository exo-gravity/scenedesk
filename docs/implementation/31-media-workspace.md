# 素材工作台与浏览器恢复

2026-09-11。接通[素材导入服务](30-media-import-service.md)的项目素材与工作室共享素材页面。此切片包含导入、查询、预览、下载、来源编辑及归档；资产固定版本、共享发布、候选采用和剪辑继续实施，完整 E03–E04 尚未完成。

## 可操作行为

从项目设定或集场镜进入项目素材；工作室导航提供共享素材。列表按名称／原文件名／标签查询，支持类型、状态筛选和分页。详情可直接定位；查询失败显示错误和重试，不伪装为空列表。权限和项目归档状态决定可用操作，服务端继续负责每次实际授权。

文件由浏览器计算 SHA-256，经签名表单直接传入私有存储。页面显示真实传输进度、等待验收、处理结果和公开错误。开始前先保存声明与创建请求标识；创建回包丢失时，刷新后仍重放同一请求身份。重新选择的文件须匹配大小与摘要，不能把另一份内容塞入旧上传。恢复记录按用户及范围隔离，仅保留声明、意图 ID 和传输确认，不保留 File、上传表单或私有 URL；最多显示 20 项，读取时清理当前用户超过 7 天的本机记录。权限失效后清除对应本机记录。

上传使用单文件有限体积的完整校验，当前不是分片上传；中断于字节传输时可能重新发送同一文件。意图或创建确认过期须明确新建导入。原文件拒绝与派生失败分别显示；派生恢复不会新建或改写原文件。

图片使用海报，视频与音频使用代理，文档下载原文件。私有访问每次明确指定变体，没有静默回退。[Media Chrome](https://www.media-chrome.org/docs/en/react/get-started) 4.19.2 按[组件选型](17-frontend-component-selection.md)作为共享专业播放器，使用中文控件；音频隐藏全屏入口。专业组件独立延迟加载，页面持有业务状态和签发请求。签名过期后的读取失败重新签发一次；其他错误提供明确重载。重载保留播放位置，以暂停状态重新就绪。原文件下载走 attachment，仍保留原始文件名和摘要。

名称、标签和来源说明采用素材 revision 保存。草稿同时保存原基线与当前输入；冲突显示原值、服务器新值和本机输入。核对后，仅将本机没有修改的字段带入服务器新值，双方均修改的内容由成员手工核对。保存期间表单禁用，避免提交成功清除更新中的输入。归档保留原文件和既有引用，仍可修订人工元数据；归档项目整体只读。已有来源证据 ID 随编辑保留，证据选择入口随资产引用继续接入。

共享草稿机制增加 Web Locks 所有权：复制标签页即使复制了 sessionStorage，也必须取得独立身份；刷新仍恢复本标签页草稿。浏览器不支持独立锁或本地存储失败时，明确提示本地保存不可用，不能假装已保存。

## 实际验证

以下在本机受限 API、PostgreSQL、私有存储和独立 Worker 上执行。测试身份及数据均为夹具，不代表真人试点。

- 页面导入四秒视频，原文件、海报和代理均就绪。实际播放、跳转及代理 Range 请求通过（206，64 字节）；原文件下载与输入的 SHA-256 均为 `d9d0cd34cb56eb77ea259eef96fb5d053100b99a218210377a711fc116f458b1`。
- 在创建上传的真实响应前注入断网，刷新后选择错误文件被拒绝；选择原文件后只重放一次原创建身份，最终媒体仍指向原意图 `5c9826d8-6628-4445-af47-1de4f6680ecd`，原文件与海报已就绪。本机记录没有上传凭证。
- 复制标签页取得不同草稿身份，刷新恢复自己的输入；连续两次真实 412 冲突后，保留本机名称与手工核对的来源，也保留同伴新增标签和用途说明。最终素材 revision 为 5，原文件摘要未变。
- 凭证过期时间及首个存储读取故障由浏览器拦截注入：自动重新签发并播放。随后注入播放器错误事件，明确重载后恢复到第 2 秒；零页面脚本错误。此为恢复路径测试，不声称进行了五分钟墙钟等待。
- 页面导入三秒 48 kHz 单声道 PCM WAV，代理实际播放，音频控制器不显示全屏。早期调试文件的 WAV 长度头未闭合，被严格解码拒绝，页面显示明确错误。
- 图片归档后仍能下载，输入及下载 SHA-256 均为 `0d172aa5d602e1af7ff3ba0c7baee8ef00ad476f153358a6ebbc68eca76970bc`。归档禁止新引用的服务规则不等于禁止修订来源说明。
- 实际生产构建在本地授权来源 4311 运行：1366×768 无横向溢出，播放器控件底边在 691 px；320×740 下播放器与导入区均无横向溢出，控件可滚动到达。共享设计样例播放器可用，零页面脚本错误。检查完恢复开发服务器。
- `npm run check`：契约一致、类型及构建通过，14 项单元、45 文件 UI 规则、20 项对比度检查通过。本切片没有服务端或数据库变更；服务端的 51 项数据库及 25 项媒体验证和两组 Linux CI 见 PR #8。
