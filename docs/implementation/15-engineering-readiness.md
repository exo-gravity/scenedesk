## 2. 运行版本和选型调整

官方静态核查见 [版本证据](../research/2026-09-09-engineering-stack-evidence.md)。实际选择以 package.json、package-lock.json、.nvmrc 和 Compose 为准：

- Node 22.23.2，npm 10.9.8；不改动主机全局 Node，通过明确版本的命令执行本轮复现。
- React/react-dom 19.2.8，Vite 7.3.6 与插件 5.2.0，Fastify 5.12.3。
- **TypeScript 5.9.3**：原研究建议 6.0.3；实际安装发现 openapi-typescript 7.13.0 的 peer 限制为 5.x。选择满足交集的版本，不使用 force/legacy-peer-deps 跳过检查。后续 TypeScript 6 升级需先验证契约生成链。
- PostgreSQL 16.15 服务端；本机 psql 16.13 只作为客户端。镜像实际信息在验证结果中记录。
- Ajv 8.20.0 + formats 3.0.1；配置不强制类型、不删除额外字段、不补默认值，以免改变用户请求语义。

类型生成工具的传递依赖将 js-yaml 固定在已报告问题的 4.3.1；本轮仅对 @redocly/openapi-core 下的该依赖覆盖到 4.3.2，重跑生成一致性与全部检查。待上游解除旧固定后移除覆盖，避免长期掩盖依赖关系。

Fastify 默认的 Schema 编译器不被直接视为 OpenAPI 3.1 的完整实现。本轮先以独立 Ajv 2020-12 验证相同请求／响应 Schema；S1 路由使用这条规则链，并显式校验输入及输出，暂不使用另一套默认响应 Schema 变换字段。权限、金额和跨字段媒体事实仍由业务模块校验。

场次页用于让下批前端工作有一个可操作起点，不代表最终视觉方案或用户验证。可走查：选择 SH-04 的另一个候选→确认草稿未变→明确用于草稿→剪辑冻结 v1→写意见／模拟决定→返回制作尝试新候选→建立 v2→检查 v1 未改→追加分镜仅进入当前场次。
