# 54 集场镜创建回包恢复

2026-09-12。基于 `cc0a14b` 的独立前端修复，处理 [53 中的 P2 创建恢复缺口](53-creative-workflow-recovery.md#待处理创建回执未知时的重复创建)。范围为 `StructureEditor` 新建单集、场次和镜头，不改变创建接口、数据库、生成任务或后期功能。

## 原问题与协议依据

服务端已创建对象但响应丢失后，旧编辑器仅留下字段草稿。刷新丢失 `useCommand` 的内存幂等键；重新核对基线后，编辑器从最新内容树重新计算 position，发送新的 key／body／If-Match，导致第二个对象。原 `onCommitted → draft.complete()` 只处理已收到成功回包后本地清理失败，不能识别这次未知提交。

现有后端已经提供所需边界：`apps/api/src/kernel/routes.ts` 在当前会话／scope 权限核验后，按 actor、scope、operation、path、key 获取回执，并校验 body／query／If-Match 的摘要；相同请求在业务 CAS 之前返回原回执。`modules/content/routes.ts` 对三类创建先核对内容版本，再插入并递增内容版本。没有新增后端接口或修改权限检查。

## 当前行为

- 创建发送前，先把完整原请求（目标路径、POST 正文、内容版本、幂等键）与原用户字段一起提交到现有 IndexedDB 草稿。存储失败或本机写完成前编辑器已离开，都不发送创建请求。
- 请求未知后保留原输入和原插入位置，普通创建、编辑字段、重新设基线及放弃未知请求入口不可用。关闭／刷新只读取并明确恢复本地记录，不自动 POST。
- 用户点击“恢复原创建请求”才发送同一 key、body、If-Match。服务器当前权限仍重新验证。原请求已成功时读取原回执；原请求未到服务器且旧版本仍有效时，这次明确操作可完成原创建。
- 只有本页面第一次发送直接收到明确的 400／409／412／422 拒绝（排除幂等身份冲突）才允许“保留输入，返回编辑”，随后按原流程核对新基线。响应丢失后的任何恢复都不走此解除路径。
- 已收到成功回包仍沿原 mutation-owned `onCommitted` 和 `draft.complete()` 写清理回执。清理失败只重试本机清理；刷新读取该回执后也不会还原旧创建意图或再 POST。

`useCommand` 仅新增可选调用者提供的 `idempotencyKey`，原调用者的生成方式、CSRF、If-Match 和成功回调保持原行为；`DraftNotice` 只为未知创建提供不可丢弃的恢复文案。

## 验证

`npm run check` 92/92 通过；新增 4 项公共行为测试覆盖先耐久存储再发送、提交后丢回包并以原请求恢复、存储失败／编辑器离开零写入、首次明确拒绝与未知恢复 412 的区别、恢复权限失败与目标不可替换。

生产构建在独立 4316／`scenedesk-ai-ui` 的受控 transport 验证实际页面、Query、IndexedDB 与刷新行为：单集／场次／镜头每类先改变受控服务状态并缓存回执，再中断响应；刷新已读取包含原创建结果的新内容版本，自动 POST 为零，明确恢复仍使用原请求，每类 2 次 HTTP 请求、1 次创建。另验证本地 stage 失败零 POST、首次明确 412 后保留输入并显式改基线、服务器成功后清理失败重试与刷新恢复不重复创建。1512／390 px 截图已检查。见[证据和结果](../../output/playwright/2026-09-12-content-creation/verification.md)。

这些是受控服务故障注入及真实浏览器行为验证，**不是实际 API／PostgreSQL 或生产环境业务验收**。没有写主线程真实项目、调用模型或启动媒体任务，实际服务整合由主线程继续核验。

## 范围与限制

现有幂等回执有效期为 24 小时。未知提交超过有效期后，原创建若成功已经递增内容版本，同请求重放将返回 412，界面继续保留未决记录且不解除原身份，不能猜测同名对象就是原结果。无限期读取原回执／凭请求标识定位业务对象需要另行明确后端耐久结果查询；本次不把它伪装为已完成。旧版本已丢失原 key 的历史草稿也无法事后推导该身份。

`Projects.tsx` 的 `CreateProject` 使用非耐久表单及内存 key，没有内容 CAS；本次按分配范围未改创建项目。该入口若需跨刷新恢复，应独立处理项目创建意图和回执有效期边界，不能直接套用本次依赖内容版本的恢复结论。普通已有内容的 PUT／剧本版本编辑没有扩大改动。
