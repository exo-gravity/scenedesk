# 导入视频候选与明确采用

2026-09-11。依据 PR-09、E04、AT-20／21 和已确认核心体验 v0.3；完整 MVP 仍按 [22](22-implementation-progress.md) 继续实施。

## 实际实现

新增迁移 `0011_takes_and_selections.sql`，候选固定到一份镜头要求和验收视频内的连续微秒区间。唯一键跨请求去重；不同镜头或不同区间保持各自身份。固定外键保留视频、要求及同媒体来源候选。数据库验证实际操作者、可见范围、视频种类／可用状态、父层归档、要求归属和来源，运行账号不能修改或删除候选与决定。

采用／清除各追加一条决定，镜头指针由数据库投影，镜头修改版本与内容根版本同时推进。CAS 冲突不追加事实；改要求不清除旧采用，也不自动把旧候选视为满足新要求。显式沿用建立新候选并保留 sourceTakeId，再单独采用。决定有顺序、实际操作者和上条记录；读取状态、固定候选及决定历史三个补充接口同步到了生成器与 OpenAPI。正文不可变版本与镜头 ETag 的区别见 [06](06-api-contract.md)。

场次目录可进入真实镜头制作页：当前镜头大预览、底部分镜顺序、候选／素材非模态面板。导入的项目视频与共享视频可直接选区间建候选；旧候选可以核对沿用或另选区间，查看／归档／采用分开。候选草稿按用户、标签页、镜头及媒体／来源分开保留；采用理由在冲突后保留，明确核对最新修改版本才重新提交。成功回执先记录，再清理本地草稿，清理失败仅重试清理。离开镜头后收到成功回复不会把用户导航拉回原镜头。

十进制秒通过 BigInt 精确转换为安全整数微秒。代理播放器按区间限制播放；浏览器会量化媒体时钟，因此定位纠偏允许 1 毫秒显示容差，防止 0.250001 秒量化为 0.25 秒后无限触发 seeking。该容差不改变候选区间，不代替 E05 的精确归一与制作副本。

## 验证记录

数据库集成测试覆盖重复／并发归档、同视频两镜两段、游标范围、错误媒体／时长／来源／操作者、同时采用只有一个成功、要求变化与沿用、清除及过期重试、受限账号不可改写、媒体归档保留、移除成员后旧幂等回复不可再取回。最终全库 79 项通过，20 项单元、UI 规则、类型检查与生产构建通过，媒体全套 25 项通过。文档校验通过：147 操作、113 路径、222 Schema、157 正反样例。

首轮媒体回归发现旧隔离测试只轮询等待创建 3 秒，短于运行层的独立创建期限（15 秒）。测试改为等待 onCreated 或实际执行结束，继续核对容器的网络、用户、内存、CPU、只读挂载、取消清理及超时；没有放宽解码限制或把超时改为成功。

生产构建完整流程已验证：0.250001–2.000001 秒精确保留，代理在出点停止；切镜头后可恢复未提交草稿，非法区间无法提交；真实 412 保留采用理由，明确重核后提交；采用成功但 IDB 删除失败，仅清理重试且没有第二次成功采用。更换镜头要求保留旧采用，沿用生成有来源的新候选，再明确采用；清除追加第三条决定。两个镜头可以关联同视频的不同区间。另一个脚本在草稿编辑时更新真实镜头要求，刷新后明确绑定新要求，区间与说明保持；随后延迟已提交归档的网络回复，切镜头后释放，确认留在新镜头且旧草稿已清理。1366×768、1512×982 和 320px 无横向溢出，笔记本采用操作与分镜条同时可见，实际截图已检查。

浏览器脚本与截图位于 [候选验收目录](../../output/playwright/candidates/README.md)。这里使用已验收的四秒技术测试片和本地身份，验证业务事实及恢复，不代表模型画面质量或真实工作室试点。
