# 46 单图生成前端切片

2026-09-11。基于 `51cad31` 的独立分支 `feat/image-generation-workspace`。本记录只声明生产构建页面、行为测试和明确受控传输的验证；实际 API、worker、存储和模型验收由主线程整合后完成。本片没有调用真实或付费模型。

## 用户路径

- 分镜的“本次创作输入”增加“生成图片”。当前手工提示、固定镜头修订、人工选择的参考与 `assistanceSource` 一起成为新计划的输入；准备提示的建议不会隐式替换原文。固定计划后继续编辑手工提示不会影响原计划或被结果覆盖。
- 自由画布增加可折叠的“画布图片生成与结果”，由现有画布编辑器负责配置和保存。用户明确选择图片草稿及实际可执行能力，完成画布保存后，沿原 `prepareCanvasGeneration` 固定该节点、画布修订和引用。未完成保存、存在冲突或恢复中的画布不能准备操作。
- 模型、尺寸、宽高比和 seed 来自实际 Capability。`target_profile_fixture` 仅描述提示目标，不能作为可执行模型。首片本地能力仅接受显式 `image_fixture_v1 / test_fixture`；具备已验证执行标记的其他图片能力才进入选择。默认没有可执行能力时禁用准备，并说明实际缺少条件。
- 用户先查看固定计划中的模型、尺寸、提示和参考，再明确执行。测试能力和计划始终标注“受控测试”；Job 成功后才展示独立图片 Media。结果不自动创建 Take、替换原媒体或改变采用。
- 未知提交只读恢复原计划和 Job。刷新及模式切换不重发执行；恢复原提交必须由用户明确触发，并保留原计划与请求身份。归档失败沿原 `recover-archive` 恢复，只保存原结果，不再次调用模型。
- 已归档图片通过实际媒体访问 API 获取授权。poster 未就绪时读取 ready original；画布节点的通用 MediaPreview 也支持同样回退。未通过原件验收的素材不能借此显示。访问 URL 不进入本机恢复记录。
- 镜头生成结果可明确打开素材页取回原图。画布生成结果可查看添加位置并确认，经原 `materializeCanvasResults` 新建独立结果节点，保留原草稿。确认绑定 canvas/job/media/revision/position；丢失回执后保留原幂等键、正文和版本，刷新不自动 POST，显式恢复同一次添加。画布已变更时重新核对位置；本机记录先保存成功回执，再刷新父画布，避免组件卸载丢失结果。
- 画布计划历史沿服务端 `listCanvasPlans` 读取。原草稿删除后仍可明确打开固定任务与原图。`reconciliation_required` 即使带有先前 Media 身份，也不会把冲突结果展示为确定成功或允许添加。

## 生命周期与实现边界

复用原 `AssistantSession`、IndexedDB 写队列、会话 epoch 和 editing-lifecycle。扩展泛型请求以保存原 canvas 计划意图；没有新增平行授权协议。每次恢复先核对当前 session、项目／画布／镜头和已知 Job/Media 访问，权限提示立即隐藏；确认 401/403/404 后销毁自有恢复记录，断网保留隐藏副本。旧会话晚到读取、保存和后续操作不能复活数据。

异步 `prepareFrom` 在源画布保存完成后再次检查 epoch，退出或撤权后不创建计划；`commitDraft` 的完成守卫保护后续动作，画布添加回执须先持久化再通知父组件。本片保留既有脚本分析和提示准备的默认请求类型与行为。

只修改前端图片组件、原助手会话扩展、ShotPromptComposer、SceneProductionWorkspace 组合和 MediaPreview。没有修改 BusinessApp、CanvasBoard、canvas controller、纯领域代码、SQL、生成器或 provider。
