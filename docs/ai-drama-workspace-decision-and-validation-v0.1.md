# 短剧主创工作区：第一性原理、待验证假设与决策方法

> 历史讨论／背景材料（2026-09-10 标注）：研究方法仍可参考；“画布是否纳入首版”已决定，当前为每场分镜／自由画布双模式，后续验证操作收益。本文原日期与正文记录当时判断，不再决定当前范围或待办；以[当前完整方案](ai-drama-workbench-product-design-v1.1.md)、[实施包](implementation/README.md)及[设计确认记录](design/approved-baseline-2026-09-10.md)为准。

日期：2026-09-07。状态：讨论与验证准备，尚无目标用户研究结果；未决定画布为主界面，未冻结相关 MVP 范围。

用户最新方向：将画布选择的目标用户验证列为后续 TODO，现阶段继续推进产品设计。画布主界面未定；可以先完成核心行为规格和用于内部检查的低保真流程稿。本文前八节保留后续研究方法，第九、十节记录当前推进安排。市场事实仍见 [画布市场复核 v2](research/2026-09-07-canvas-market-review-v2.md)。

## 1. 收回过早的结论

竞品证据支持把画布纳入候选，不能独立证明它应成为我们的主工作区。此前“提升为主要工作区重点设计方向”的表述回到待验证假设；场次画布、结构化工作台、主画布与按需关系视图均未胜出。

目标用户无需先表达界面偏好。我们负责解释取舍、识别不确定性、准备有区分力的验证，并根据证据提出建议。受访用户提供真实工作行为、材料和约束，不承担替产品团队选择界面的责任。

## 2. 从最终产出反推，而非从界面反推

当前已确认服务对象是中小工作室内部团队，优先 AI 写实短剧，不设 10 人上限，长期复用制作核心支持广告。日常主操作职责暂定为主创／AI 制作人员；负责人、剪辑、经营决策者分别影响质量、交接与采用，一人可以兼任。

建议将工作台目标表述为：**帮助团队在可接受的预算和周期内持续交付达到约定标准的叙事作品，并能在修改和交接时保留正确的内容、上下文和版本。**

评价先约定相同任务的质量和交付要求，再分别记录：

- 人工时间：构思、准备输入、制作操作、比较、整理、沟通、返工、后期与学习；避免将同一段返工时间重复计入。
- 日历耗时：等待、队列与关键依赖造成的交付延迟；多人并行时不能把所有等待简单相加。
- 现金支出：包含失败和未采用结果的调用费用，以及必要的外部工具和后期费用。
- 可靠性：错误引用、错误采用、丢失制作上下文、意外改变已审版本、交接后无法继续等事件。

未采用候选可能帮助发现正确方向，不能一律视为浪费；减少点击也不自动等于提高交付效率。不能用较低质量或较窄交付范围换得的速度优势证明方案更好。

## 3. 我们需要理解的是哪些决定，以及决定如何改变

以下是用于组织讨论的分析框架，不是已观察到所有团队的统一流程。

| 工作问题 | 制作人员正在决定什么 | 需要看到或控制什么 |
|---|---|---|
| 表达 | 这段戏要让观众理解什么、产生什么感受 | 故事上下文、动作、对白、表演和节奏 |
| 约束 | 哪些设定要保持、哪些可以尝试 | 人物、造型、场景、声音与当前剧情状态 |
| 实现 | 用什么输入和制作步骤得到需要的素材 | 参考用途、模型能力、生成范围、处理步骤 |
| 取舍 | 哪个候选可用，缺陷是否值得继续修 | 可比较的结果、来源、成本和修改范围 |
| 组接 | 素材怎样组合才成立 | 片段顺序、长度、声音及相邻镜头衔接 |
| 交接 | 别人怎样继续做，并知道什么已被确认 | 当前采用、未解决问题、来源和审阅版本 |

必须区分三类成本：有价值的创意探索、模型实现受限、可避免的组织与交接损失。工作台可能通过不同能力改善它们；自由空间本身不能保证模型质量。

首要未知是：**关键创作决定通常在什么时候、由谁、针对多大范围作出和修改。** 这比先确定画布是场次级还是项目级更基础。剧本／分镜先定再执行，与边生成边形成拍法，可以出现在同一团队的不同阶段；不能强行把工作室分成互斥类型。

## 4. 分开评价三个层面

| 层面 | 例子 | 决策方式 |
|---|---|---|
| 要具备的业务能力 | 复用参考、生成候选、局部返工、采用、交接 | 由真实任务与问题决定 |
| 底层执行和记录 | 输入快照、版本、依赖、运行状态、费用、剪辑引用 | 由可靠性和已验证制作路径决定 |
| 向用户呈现与操作 | 表格、卡片、画布、对话、时间线、局部关系视图 | 由当前任务中需要表达的关系决定 |

示例：如果两种界面都具备参考引用，但画布减少了比较和关系理解成本，才是画布带来的收益。若画布版本多了自动输入、批处理和素材管理，就不能将全部提升归给空间布局。

## 5. 优先验证的假设及反证

| 假设 | 支持它的真实行为 | 会削弱它的证据 | 可能的产品方向 |
|---|---|---|---|
| H1：跨材料和分支的关系理解，是频繁且昂贵的问题 | 用户不断并置多组参考、解释来源、比较多个制作分支 | 大多数操作围绕单个镜头，材料能通过检索和列表快速找到 | 关系视图、分支比较或画布；是否为默认界面仍需测试 |
| H2：主要损失来自素材搬运和重复输入 | 同一参考被反复下载、上传、命名或复制提示 | 工具已集成，但用户仍难以理解和修改关系 | 统一资产与执行入口可能比自由布局更优先 |
| H3：大量创作决定在生成过程中形成 | 看到结果后调整表演、拍法、场景乃至镜头计划 | 稳定按明确分镜执行，变化主要来自验收返工 | 需要探索空间；不自动要求任意流程编排 |
| H4：采用与交接比探索更难 | 用户无法解释哪个结果可用、谁确认、剪辑用了哪一版 | 单人工作居多且追溯顺畅，主要时间消耗在获得合格素材 | 版本、采用与任务交接优先，画布价值另证 |
| H5：重复工艺需要由普通成员使用 | 一套稳定方法跨场次／项目重复，仍需作者反复操作 | 每次路径差异大，模型或方法尚不稳定 | 模板／批处理先验证；开放图编辑和发布平台后判 |
| H6：Agent 需要人与其共用的上下文空间 | 用户需要指向多个已有对象、纠正取材范围并接手中间结果 | 自动化可用明确表单输入完成，开放空间增加噪声 | 显式上下文选择与结果回流；画布只是候选呈现 |

先定位发生频率、影响和可改善程度，再选择最值得验证的一两个假设。不将上表默认全部转为需求。

## 6. 先做一次不依赖原型的真实项目回看

首轮建议从能够接触的 3—5 家工作室开始，覆盖实际制作、主创／审片、剪辑／交接职责，并单独了解付费决策者。数量是便于开展的初始安排，不保证饱和或统计代表性。优先已交付或正在返工的写实短剧项目；不以团队人数或是否喜欢节点工具作为唯一筛选条件。

记录会改变使用方式的差异：主要职责、制作经验、当前工具、生成路径、项目阶段、创作决定权、已有画布熟练度和实际任务规模。不要把未来广告营销人员混入当前短剧样本后计算一个平均偏好。

首次会话约 60—90 分钟，先不展示我们的画布方案。让对方用最近项目的剧本、素材、生成记录、剪辑与反馈重建一个真实片段的制作过程；若能观察正在发生的制作，优先观察。回忆叙述与现场观察分开记录。[方法参考：NN/g 情境研究](https://www.nngroup.com/articles/contextual-inquiry/)

推荐主持顺序：

1. 确认这段戏的交付要求、职责分工和最终验收者。
2. 从当时最早拿到的材料开始，回看一个已交付片段是怎样形成的。
3. 找一次实际发生的修改：修改要求是什么、由谁提出、当时拿哪些材料作决定。
4. 看被保留及被放弃的候选，追问选择理由、下一步和相关证据。
5. 看素材如何进入剪辑，另一位成员如何知道采用哪个结果。
6. 看一次顺利完成的过程作为对照，避免只研究极端失败。
7. 最后讨论哪些步骤重复、哪些需要熟练人员判断，以及替换工具的学习和迁移代价。

避免以“无限画布能否帮助你”“你是否需要版本管理”开场；这些问题已经暗示解决方案。应询问最近实际发生的动作、原因、结果和补救，而不是只收集未来使用意愿。[方法参考：NN/g 避免诱导性提问](https://www.nngroup.com/articles/leading-questions/)

记录模板：职责／任务 → 当时输入 → 当前决定 → 实际动作与工具 → 产物 → 出现的问题 → 人工时间／等待／现金证据 → 补救 → 交接对象 → 研究者推断 → 相反证据。

时间和成本需注明来自日志、现场计时、账单还是回忆估计；未知留空说明，不能填 0。材料不足时只能形成待验证假设，不能补造已完成案例。

## 7. 根据观察选择最小的交互对照

只有在首轮确认主要问题后，才制作与该问题对应的原型。候选不是必须同时开发的三套产品：

- A：以内容列表／卡片和就地操作为主，资料与结果集成。
- B：以空间并置、引用关系和分支展开为主。
- C：默认结构化操作，在有需要时展开局部比较／关系空间。

先选择最有区分力的两种。相同素材、生成能力、版本规则、候选数量和操作范围下比较；布局、关系呈现与操作方式才是主要差异。

任务描述表达结果，不使用界面术语。例如：“让人物这个反应更克制，保留当前外形和对白，交给剪辑继续使用。”不要指定“复制节点、连接参考、运行分组”，否则测试只是检查用户能否照提示点击。[方法参考：NN/g 任务场景](https://www.nngroup.com/articles/task-scenarios-usability-testing/)

先用少量代表用户检查任务是否自然、原型能力是否足够，再扩展。使用难度相近的任务并交替顺序，避免第二次因熟悉剧情而天然更快；画布经验不同的用户分别解释结果，不把经验差异当界面优劣。

原型可使用预先准备的相同素材和生成候选，先隔离交互变量。这种验证只能判断找参考、比较、修改表达、采用和交接，不能据此证明实际模型成功率、等待、生成质量或真实支出更好。后续通过真实项目小范围试用验证完整价值。

## 8. 怎样从证据走到产品决策

| 观察到的结果 | 应做的决策 |
|---|---|
| 核心高频任务中，空间和关系操作持续有帮助，学习及整理代价可接受 | 将画布作为该职责／阶段的默认工作区候选，进入真实制作试用 |
| 收益集中在探索、候选比较或某类复杂返工 | 在这些任务中提供画布／关系视图，默认生产入口继续对照 |
| 两种界面都因集成、引用、版本能力而改善，布局差异收益小 | 优先公共能力，选择实现和学习负担较低的主界面 |
| 主要瓶颈是模型无法达到目标质量 | 优先验证模型制作路径；不要用界面重构掩盖产品价值瓶颈 |
| 用户喜欢展示效果，但任务耗时、错误或整理负担增加 | 继续调整或暂缓画布，不以偏好票数代替任务证据 |
| 不同职责或经验层出现相反结果 | 分析任务及默认入口；先选当前主要用户，避免直接建设两套完整系统 |
| 证据混合且无法解释 | 保持可逆，不冻结主界面；针对分歧补一个有区分力的任务 |

先约定质量、原稿保留和交接正确性等基本要求；效率收益应在覆盖学习、整理和后期的范围内解释。小样本用于发现和解释机制，不宣称统计显著的市场普遍提升。阈值需在看结果之前根据真实基线和业务经济性设定，当前不杜撰统一的百分比。

每条决策记录：范围（谁／哪个任务）→ 证据 → 反证 → 结论 → 尚未解决的问题 → 复审触发条件。当前所有候选状态均为“待验证”。

此处是项目设计待办，不是定时提醒或已安排的用户访谈。

### 当前推进工作

| 顺序 | 现在做什么 | 具体产物 | 仍保留什么不确定性 |
|---|---|---|---|
| 1 | 完成一个场次的制作与返工行为规格 | 谁操作、需要什么输入、产生什么结果、改变哪些状态、失败后如何继续 | 不据此证明代表全部工作室；镜头数量和集长不固定 |
| 2 | 细化 MVP 深度与交付要求 | 必需动作、例外情况、外部精剪分工、可检验的完成标准 | 样片质量门槛和首发规格仍需校准 |
| 3 | 明确对象、版本和核心操作契约 | 镜头／生成／媒体／采用／剪辑／审阅分别记录，操作影响范围明确 | 不提前设计任意节点引擎或所有业务的通用元模型 |
| 4 | 用低保真界面检查流程 | 内容导航、当前制作对象、参考、候选、采用、剪辑和审阅的可走查稿 | 可暂用分镜卡片＋详情；这不构成最终主界面或用户效果结论 |
| 5 | 准备模型技术验证与开发拆解 | 主生成路径和重做路径样例、输入限制清单、模块依赖及实施任务 | 指定服务／模型／账号、成本和真实质量需实际试作；当前未调用付费服务 |

第七节“先有观察再做原型对照”仍适用于证明哪种交互更好。这里的低保真稿只用来检查自己的流程是否完整，允许在用户研究前开展；不能用内部走查代替用户验证。

开发顺序在行为与技术路径明确后细化，当前不承诺日期或人日。若提前进入实现，优先范围明确的资产、生成记录、候选和版本操作；前端只做一条简单可替换的制作路径，不为保留未来可能性同时实现多套界面。

### 现阶段采用的设计工作假设

1. 用户可以从当前场次或选定镜头继续操作；不要求总从全剧首页开始。
2. 为讨论流程暂用内容导航和分镜卡片，参考与候选就地查看；支持选定多个内容对象。该选择只是低保真载体。
3. 明确的业务操作不依赖画布坐标。连接参考、开始生成、继续尝试、采用结果、更新剪辑和提交审阅分别有规则。
4. 稳定对象身份、媒体版本和制作来源先明确；节点位置与空间分组作为以后可附加的展示信息，不作为唯一业务记录。
5. 公共生成执行接收明确输入与使用范围，不要求一定存在短剧场次，也不要求一定存在画布节点；未来广告按自己的业务流程调用。

这些约束降低更换呈现方式时重复设计核心规则的成本，但不承诺未来增加自由连接、大规模媒体布局或实时共编无需额外研发。

## 10. 当前具体产物：一个场次的制作与返工行为规格 v0.1

以下为供详细设计使用的样例，不是用户研究结果。示例是一段双人对白戏，有可用剧本、人物和场景参考；用一组镜头完成表达。镜头数、时长和题材不构成首发限制。

| 步骤 | 操作与输入 | 应产生的结果／状态 | 关键约束 |
|---|---|---|---|
| 开始制作 | 选择场次，查看／补充已有分镜与参考 | 能识别当前制作范围和缺少的必要输入 | 不要求先填完全部剧目设定或为每镜创建人工任务 |
| 准备一次尝试 | 选择镜头或镜头组，声明动作／对白与参考用途 | 可查看本次实际输入、模型模式、参数和费用估计 | 不支持的输入明确提示，不能静默忽略 |
| 提交制作 | 在有权限和预算的范围提交 | 记录固定输入的一次作业并显示状态 | 不强制一个作业对应一个镜头 |
| 接收结果 | 作业完成并归档可用媒体 | 形成候选，保留来源、参数与执行记录 | 供应商完成与媒体可用分开；新候选不改变采用或剪辑 |
| 比较与继续 | 查看候选；需要时从选定版本修改输入再制作 | 新作业、新候选；原有结果继续可用 | 重做选定范围是基础路径，局部编辑按实际模型能力提供 |
| 采用 | 选择完整媒体或其中一段，关联计划内容 | 保存当前选用版本与使用区间 | 采用不等于已审通过；结果可供多个计划镜头使用 |
| 组接 | 将采用结果加入可编辑剪辑，调整顺序、长度和声音 | 场次／整集剪辑草稿，可预览 | 顺序由剪辑记录决定，不能从卡片摆放或生成顺序推断 |
| 审阅 | 提交具体剪辑版本，由负责人查看 | 对版本及时间点记录问题或确认决定 | 修改中的草稿与已提交版本区分；不要求每次尝试都审批 |
| 指定返工 | 从意见定位媒体和相关制作输入，准备一次修改 | 保留旧结果，新候选等待比较和采用 | 已确认的外形／对白等要求显式保留，模型效果仍需检查 |
| 更新与交接 | 采用新结果，选择要更新的可编辑剪辑；对已审稿形成新版本 | 接手者能找到当前采用、来源、反馈和新稿 | 不自动覆盖历史审片和交付；反馈时间点随具体版本保存 |
| 交付 | 确认输出版本及规格，渲染并导出 | MP4、必要素材／字幕／清单与交付记录 | 外部精剪回传作为独立版本，不能从成片还原未登记工程 |

首先检查五类异常：提交结果未知时不重复付费；生成完成但媒体未入库时恢复归档；输入修改后仍在运行的旧作业可辨识；新采用结果不静默替换已审稿；另一成员更改同一对象时提示冲突而不是覆盖。
