# 09 设计决策与待落实事项

本页区分用户确认方向、当前实施默认值、启动／上线所需事实和延后研究。尚未核验的外部事实不会因写进方案而自动成立。

## 1. 已确认方向

| 事项 | 约束 |
|---|---|
| 产品范围 | 长期支持短剧与广告，当前优先短剧，核心能力尽可能复用 |
| 客户 | 中小工作室团队，不设 10 人上限；广告未来主要面向商家／教育机构营销人员 |
| 内容与模型 | 先偏 AI 写实；优先 Seedance 等领先模型；不预先限定剧情题材 |
| 组织权限 | 首版内部协作、简单管理；外包长期可能需要，当前不做 |
| 画布 | UX-01 后续验证，现阶段不选择最终主界面，不阻塞业务规则和技术准备 |

## 2. 当前实施默认值

这些选择用于减少研发时自行补规则，遇到具体相反证据可修订；不要求用户逐项再确认才能做可逆工程准备。

| 选择 | 为什么／何时复审 |
|---|---|
| 同一平台、两个业务工作台、公共制作模块 | 当前短剧独立跑通；广告出现正式试点时检验复用边界 |
| 一个项目一个剧目，剧目下集／场次／镜头 | 保持短剧语义清晰；广告使用自己的业务结构 |
| 固定 Owner／Admin／Member，加项目 lead／collaborator | 覆盖内部工作室日常权限；真实外包／部门隔离需求出现时扩展 |
| 新候选不自动采用，采用不自动改剪辑 | 保护并行制作与已审稿；详见 ADR-0002 |
| 引用固定版本，媒体不可变，审阅和交付冻结 | 支持返工、责任与费用追溯；不能为同步方便破坏历史 |
| 视频主路径一个已验证模式起步 | 验证真实可用性和成本；样片需要时前移图片／声音补充或第二模式 |
| 模块化单体 API、独立 Worker、PG 事务与 outbox | 当前减少部署和一致性负担；有实际吞吐或团队边界时拆分 |
| OIDC 会话、邀请链接、内部项目访问 | 避免首版自建完整身份平台；S0 选定适合首发客户的身份提供方 |
| 成本预算先做，充值／售价后按商业模式确定 | 供应商成本不同于客户收费，不能把消费记录直接当扣费订单 |
| 当前低保真用内容导航、卡片、就地参考／候选 | 仅验证制作行为；UX-01 的界面选择仍开放 |

长期且代价较高的决策记录为提议状态：[ADR-0001](../adr/0001-production-records-independent-of-views.md)、[ADR-0002](../adr/0002-freeze-review-and-explicit-adoption.md)、[ADR-0003](../adr/0003-uncertain-provider-submission.md)。阶段复审时以证据更新状态，不补写不存在的审批历史。

## 3. 启动与上线前需要落实的事项

负责人列使用岗位表示尚待实际团队认领；不是已派发任务。每项有当前可做工作，避免把信息缺口变成整体停工理由。

| ID | 需要的事实或决定 | 责任岗位／最晚阶段 | 当前可推进 |
|---|---|---|---|
| G-01 | 首发代表样本：剧种、语言、画幅、集长、质量基线 | 产品负责人＋主创／S0 样片前 | 使用 10 的 46 秒夹具验证规则，不能把夹具当完整市场样本 |
| G-02 | 具体 Seedance 服务、地区、账号、接入授权和能力版本 | 技术负责人＋采购／真实请求前 | 模拟 Adapter、契约、归档和预算实现；准备 MV 用例 |
| G-03 | 真实调用预算与费用承担方式、账单可获取性 | 工作室经营者＋产品负责人／真实请求前 | 估计与账本采用单币种；不代用户开通或充值 |
| G-04 | OIDC、部署地区、对象存储和秘密管理服务 | 技术负责人／S0 结束 | 保持接口边界；用开发环境搭建路径 |
| G-05 | 研发人员配置、实施节奏和试点支持责任 | 项目负责人／排期前 | 按 S0–S4 工作包估算，不先承诺固定日期 |
| G-06 | 媒体保存期限、备份成本及可承诺的恢复指标 | 技术负责人＋经营者／S4 前 | 默认保留被引用内容；跑恢复演练并核定成本 |
| G-07 | 试点工作室、现有方式基线、质量与改善目标 | 产品负责人＋试点主创／S4 前 | 设计可比任务和记录表，不编造访问或访谈结果 |
| G-08 | 自带模型账号或平台统一采购，软件收费方式 | 产品负责人＋经营者／商业试用前 | 当前连接按工作室隔离；保留成本／客户订单分离，不实现自动扣款 |

G-02／G-03 未满足时不能执行真实付费调用；这不阻碍界面、内部流程、数据库和模拟集成。当前文档交付没有启动任何采购或付费任务。

## 4. 后续验证与重要迭代

| TODO | 要验证的问题 | 触发与判断方法 | 当前影响 |
|---|---|---|---|
| UX-01 | 哪些工作需要空间摆放、多候选并看、关系表达；收益是否大于操作和维护成本 | 目标工作室完成同一场次探索、生产和返工任务；对照结构化视图与画布原型，记录时间、遗漏、理解和重复输入；先小样发现问题，再按差异补样 | 不承诺无限画布为主界面；对象、版本和明确采用规则先落地 |
| UX-02 | 日常工作单位是镜头、镜头组还是场次，模型输出如何对应 | 观察样片和真实任务；区分创作意图、生成单元、剪辑片段 | 一次任务可关联多镜头，首版人工选区间 |
| PM-01 | 平台轻量剪辑能承担多少后期，何时必须进外部工具 | 记录外部精剪工时、缺失操作与回传次数 | 首版支持素材包和独立成片回传，不实现全部 NLE |
| PM-02 | 第二视频／图像／声音模式在哪类返工上有净收益 | 以同质量下人工、总费用和周期比较 | 按任务前移，不按模型数量追 KPI |
| AD-01 | 营销人员从推广事实到多个可投放版本的实际闭环 | 短剧核心稳定后独立广告试点；与内容工厂需求分开记录 | 共用核心，不提前建立广告全套入口 |
| ORG-01 | 外包是否需要项目参与、单素材访问还是只交付文件 | 出现实际外包项目后再设计最小授权与撤销 | 当前无 Guest、匿名审片链接或自定义权限 |

UX-01 沿用 [原决策与验证框架](../ai-drama-workspace-decision-and-validation-v0.1.md)。本包没有完成用户访谈，也没有将任何市场研究建议升级为最终 UI 决定。
