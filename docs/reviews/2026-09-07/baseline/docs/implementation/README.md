# AI 短剧工作台：实施设计包 v0.1

更新日期：2026-09-07。用途：下一阶段产品、设计、前后端、模型接入和测试共同使用的实施基线。当前已完成文档与契约设计；尚无已运行产品、已通过真实模型验证、用户试点或生产验收。

## 1. 先读结论

长期采用同一平台内的短剧、广告两个业务工作台，共用资产媒体、生成执行、版本、编辑、审阅交付和费用能力。当前 MVP 完成中小工作室内部的 AI 写实短剧制作闭环，不设 10 人上限，不同时开发广告入口或外包协作。

核心流程是：已有剧本 → 集场镜与创作依据 → 明确生成计划 → 候选与人工采用 → 轻量剪辑和声音 → 冻结审阅 → 指定返工 → 固定交付。Seedance 等领先模型优先，但只启用指定服务／地区／账号实际验证过的模式。首次实现以一条视频主路径贯通，补充能力按样片需要引入。

画布仍是 UX-01 待验证项。现阶段固定的是制作对象、输入版本、费用边界和交接规则；内部低保真可以用内容导航与卡片验证流程，不据此选择最终主界面，也不建设通用节点工作流。

## 3. 这次补齐的关键规则

- 角色身份、并存造型、造型修改历史和场次状态分开；引用固定版本，实际模型输入可核查。
- 计划先固化实际输入与费用估计，再以一次平台事务建立作业、预占和 outbox；提交未知不自动重发供应商创建请求。
- 媒体归档与模型生成分离；上传验收后使用不可变内容，旧上传 URL 不得改写已审稿。
- 一个生成结果可以按区间供多个镜头使用；新候选不自动采用，采用不自动更新剪辑。
- 评论绑定具体候选或冻结版本；新的审阅轮次不能借用旧批准建立最终交付。
- 轻量剪辑保留原生音轨／外加声音的明确选择；外部精剪回传为独立版本，未知时间线不伪造来源。
- 工作室、项目预算共同约束同一笔消费；取消、失败和下载失败均不自动意味着无费用。

## 4. 下一阶段如何开始

S0 先锁定工程版本与契约，建立数据库事务、模拟 Adapter 和媒体路径，同时落实首发样本、具体模型账号／测试预算、身份与部署服务。S1–S3 按“准备场次 → 可靠生成 → 剪辑审阅返工交付”逐段贯通；可以先用导入素材并行验证后半程。S4 再执行恢复、容量与真实工作室试点。

现在可直接做工程初始化、迁移、模拟集成和低保真行为验证。真实付费调用需要 G-02／G-03 的账号与预算事实；产品价值仍需 AT-35／36 的样片及目标用户证据。UX-01 不阻碍这些工作，也没有被提前判定。

用户最新明确方向优先；完整产品主稿负责定位与总范围，本实施包负责当前行为、数据和接口细节。字段结构以 openapi.json 为准，跨字段业务规则以 03／04／06 为准；若发现矛盾，应修正文档与契约并复检，不能任选一种实现。旧专项和市场资料保留背景，不自动扩大首版范围。

## 6. 重跑静态检查

建议使用独立 Python 虚拟环境，安装 [validation-requirements.txt](validation-requirements.txt) 中固定的验证依赖。依次执行：

```sh
python docs/implementation/build_contract.py
python docs/implementation/check_design.py
```

检查包含 OpenAPI 结构、Schema 引用、权限与版本头、需求覆盖、有效／无效结构样例、本包相对文件链接和生成结果可复现性。报告不会将 DB、浏览器、真实供应商、媒体处理或用户验收标记为通过。
