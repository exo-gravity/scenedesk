# 连续创作与返工：独立设计评审

日期：2026-09-10。视角：以专业创作工具／影视制作 UX 的判断方法，检查一个 AI 写实短剧团队连续完成一场戏的工作。本文不是行业访谈，也不声称作者拥有被验证的制作履历。

状态：只评审，未修改 UI、依赖或后台；建议未替代用户已确认的产品边界。

## 结论

这套原型已经把“选候选 → 采用 → 剪辑使用 → 固定审阅”串起来，且保留了每场双模式和审阅来源。应保留这些事实与导航关系。最需要调整的不是再增加入口，而是给创作判断一个持续可用的工作位置：用户正在看什么、为什么需要改、拿什么作依据，以及修改后是否真的更好，必须能在同一工作片段里核对。

我推荐**分镜以当前镜头精修为主要工作状态，全场网格作为总览；画布保留全场自由组织；两者拥有同一套可固定目标的局部制作区。助手非模态停靠，素材按任务短暂展开或固定参考。1366 宽度不默认同时展开完整素材库、完整编辑栏和完整助手栏。** 这里的“媒体优先”首先是让要判断的候选足够大，而不是所有镜头一直平分屏幕。

最紧急的行为问题是返工入口覆盖现有提示词；最紧急的布局问题是助手遮罩阻断直接编辑；最影响后续方案判断的缺口是尚无足够大的候选比较状态。

## 最严重的五项问题

### 1. 助手把依赖的画面和编辑区变成不可用背景

**已验证：** 助手截图中整个画布变暗，420px 抽屉覆盖右侧制作区；TSX 第 22 行把场次切换、资产、作业和助手放在同一个单选 `drawer` 状态，第 149 行起共用 Drawer。助手的“填入提示词”操作随后关闭面板。现状无法在保留助手内容的同时直接调整提示词或继续浏览资产。

**推断：** “这个手指应该怎样接触钥匙”通常需要看目标动作、指出接触问题、检查参考，再精确改写。遮罩使这些动作被人为串行化。只把 Drawer 的遮罩去掉也不够：覆盖原编辑区的几何关系依然存在，焦点约束也需一并核对。

**推荐：** 持续助手使用参与布局的非模态停靠区；打开时主区中的候选、已引用参考与直接编辑仍可操作。一次性的提示词建议可以贴近输入展开，不必总开聊天区。把建议转为可编辑草稿后，助手保持原对话位置，不能用关闭助手作为“应用成功”的必要反馈。

**待验证：** 用户能否边看 SH-04、边改两个动作词、边回看建议；至少完成一次“看建议 → 手改 → 补充引用 → 再修订”，不能只测一次点击填入。

### 2. 全场展示面积充足，当前候选的判断面积不足

**已验证：** 分镜主区是六镜头网格；候选在右侧仅宽 61px、高 72px（CSS 第 87–89 行）。分镜主卡始终呈现镜头示意媒体，选择候选并未引入一个独立的大幅当前候选／对比状态。画布虽放大当前节点，但仍是一镜一张代表图，候选切换主要依赖右侧缩略图；本轮未演示独立候选分支。所有候选复用静帧是已说明的原型限制，不应把它误判成真实候选内容相同。

**推断：** 大网格适合找 SH-04，不足以支持决定 C 是否值得采用。接触点、手指结构、钥匙形状、拿离桌面的时序与表演节奏，不能从 72px 静帧缩略图可靠判断。“媒体很多”不等于“判断对象可看清”。

**推荐：** 选中后可直接进入当前镜头工作状态：主区大预览、候选条、前后镜头定位、局部输入；全场网格由明确的“全场”入口打开。对比把 A 与 C 提到主区；静帧可并排，视频按现有 MVP 先切换播放，保留各自暂停点与明确候选身份。需要比手部细节时有主动放大入口，不能只靠扩大卡片。放大检查不改变实际输出画幅。

既有双模式契约 §2 已写“主区预览当前镜头、底部分镜条，全场总览按需展开”，本轮导航提案改成三列网格。两者存在待收口的布局分歧；我的独立判断支持前者作为连续精修状态，但不能据此直接宣布新提案被否决。

**待验证：** 用确实不同的 A／C 示意帧或本地短片测判断路径。当前共图原型只能验证布局、身份和操作，不能验证创作质量判断。

### 3. “按意见继续制作”把意见直接写成新提示词，破坏已有工作依据

**已验证：** TSX 第 63–65 行的 `beginRework` 将该镜头的 `prompt` 直接替换为意见正文加“保留当前人物、造型和场景参考”。原来的完整提示词没有合并、差异预览或显式取代步骤。此操作不仅是定位。再次从旧稿进入返工时也会这样覆盖当前草稿。

**推断：** 用户本来只想回到 SH-04 处理接触点，却可能丢失之前修正过的运动、光线和表演要求。更严重的是，审阅意见是对固定 v1/A 的观察，当前草稿可能已经来自 C；不能假定两者可以直接互相覆盖。

**推荐：** 返回制作只固定返工来源并定位镜头，保留当前输入。局部显示“来源 v1 / SH-04 / A / 00:24”和“保留／待改”摘要。“按意见准备修改”再提出建议，显示对当前输入的差异，供用户接受全部、局部采纳或手改；不自动采用、不替换剪辑，也不解决原评论。若当前已采用 C，要明确“原意见针对 A，当前采用 C”，让人决定本次从哪个候选继续。

**待验证：** 先手改提示词，再从旧 v1 进入返工，原文应完整保留；连做两次返工并切换镜头，不应把后一次意见误写到前一次草稿。

### 4. 参考被表现为“已加哪些附件”，尚不能说明本次判断依赖什么

**已验证：** 当前参考标签只显示小图、名称和移除按钮（TSX 第 84 行），资产版本在浏览器条目中可见，在已引用标签中不显示。画布取 `picked.refs.slice(0, 2)`：初始为林夏与咖啡厅，随后添加的旧铜钥匙是第三项，不会自动进入这张画布的参考呈现。镜头入／出状态在制作区底部折叠详情中；SH-04 的实际要求是“钥匙在桌面中央 → 钥匙握在林夏右手”，SH-05 的入镜则是“钥匙已在林夏手中”。

**推断：** 本次最关键的钥匙参考可能添加成功但仍无法与手部并看。创作者也不易分清某图是人物身份依据、道具外观依据、动作示意，还是仅供灵感浏览。抽屉列出版本并不能代替生成前对实际使用依据的核对。

**推荐：** 已引用条目保持轻量，至少能展开确切版本与作用；本次需要比较的参考可“固定查看”，不受添加先后顺序限制。浏览某资产、把它放在画布、加入本次生成、交给助手讨论是不同动作；后两者明确显示目标。返工时把本镜头相关连续性摘要提前显示，例如“右手；桌面 → 手中；接 SH-05”，详情仍可展开，不把全部剧本永久铺在输入旁。

这不是要求本轮发明新参考系统：现有画布契约已经区分待选参考关系与实际输入、保存确切参考版本与用途。本轮应把这些事实做成用户看得懂的工作状态。

**待验证：** 添加第三项钥匙参考后，用户能在保持 SH-04 输入和助手的情况下看清它；能说清哪两项给模型，哪一项只用于讨论。资产是同项目正式版本时，不增加逐镜重复批准。

### 5. 返工来源有了，但“这次修改处理了什么”缺少收尾位置

**已验证：** `scene.rework` 只保存一份场次级来源。顶部返工横条不按当前镜头过滤（TSX 第 142 行）；切到其他镜头仍可呈现这份来源。固定 v2 时 `notes: []`，说明默认仅写“根据 v1 的意见调整 SH-04”（第 60 行）；旧意见不会改变，也没有展示它与候选 C／v2 的处理对应。

**推断：** 不自动解决旧意见是正确的，但缺少对应关系会让接手的人难以判断“谁以什么改动回应了哪条意见，应该去哪个版本复核”。一个场次的负责人可以兼任多个角色，但不能据此假设工作永远由一个人记在脑中。

**推荐：** 当前镜头局部显示本次返工来源；切到 SH-05 时收成“本场有 SH-04 返工”可定位提示，不能看起来像 SH-05 的要求。提交 v2 前给出简短的人工修改说明及来源链接，例如“用 C 调整接触与拿离，保留 9 秒；请复核 v1 的 00:24 意见”。原意见可保留“已回应，待复核”的可追踪呈现，但只有明确审阅操作才改变处理判断，固定版本确认仍独立。MVP 不需要借此扩成工单管理系统。

**待验证：** 另一位成员不听口头讲解，能从 v2 找到原意见和改动说明，并返回 v1 看 A；继续改当前草稿后，旧对应仍然稳定。

## SH-04 拿钥匙返工：完整 walkthrough

以下是推荐验收脚本，不是宣称当前原型已全部实现。示例从 v1 使用 A、当前采用 A、剪辑用 A 开始。v1 的 00:24 在现有 6+8+7 秒前序镜头之后，落在 SH-04 的镜头内约 3 秒；界面应同时清楚区分整场时间和镜头内时间。

| 步骤 | 创作者正在判断什么 | 必须可见与可做 | 事实变化 |
|---|---|---|---|
| 1. 打开 v1 的意见 | 是手指没有接触，还是节奏或道具变化？ | 固定 v1/A、00:24 原意见、对应画面；能查看 SH-03 到 SH-05 的固定稿上下文 | 只查看固定稿 |
| 2. 按意见回制作 | 现在的草稿与被审版本是否一致？ | 定位 SH-04；原意见作为来源；保留当前提示词，显示当前采用／剪辑使用 | 不改输入、不改采用、不解决意见 |
| 3. 明确保留与待改 | 保留人物、衣服、9 秒节奏；只改接触与拿离 | 精简连续性：“钥匙桌面中央 → 林夏右手；接 SH-05”；展开可读原镜头要求 | 用户可编辑本次修改草稿 |
| 4. 找到钥匙依据 | 要保留哪把钥匙、磨痕、尺寸和朝向？ | 搜索旧铜钥匙 v1，固定看图；加入明确的 SH-04 生成参考；人物与场景依据保持可核对 | 引用变化明确，不因浏览就替换 |
| 5. 与助手讨论 | 如何使动作有接触感且不破坏节奏？ | 助手列出 v1 意见、目标 SH-04、当前输入和选定参考；用户可继续看画面、修改输入 | 助手先返回建议，不执行生成 |
| 6. 手工修订建议 | “靠近、接触、收拢、拿离”是否符合这场戏？ | 在主区接受或改写相应句子，保留原文与建议出处；助手仍在旁边 | 只改本次输入；不要求让 AI 再重写整段 |
| 7. 查看生成计划 | 本次真的用了哪些参考、时长与能力？ | 实际提示、参考版本与用途、输出参数、执行及费用信息按已有计划规则回显；不把聊天引用自动当模型输入 | 明确执行后建立新尝试 |
| 8. C 返回并比较 | 接触是否自然，是否出现人物／道具副作用？ | 主区看 C，对照 A 和钥匙参考；静帧可并排，视频切换看；能回到问题点，检查首尾状态 | 正在看 C；采用 A；剪辑用 A；v1 用 A |
| 9. 必要时继续尝试 | C 解决接触但拿离太快怎么办？ | 保留 C 的来源与讨论，继续改局部输入产生 D；不要把失败尝试从比较历史抹掉 | D 是另一候选，原采用与用片不变 |
| 10. 明确采用 C | 本镜头当前推荐哪份素材？ | “采用 C”及简短理由可选；显示剪辑仍用 A | 采用 C，剪辑仍 A，v1 仍 A |
| 11. 用于剪辑并看接续 | C 与 SH-03／SH-05 的实际用片是否接得上？ | 明确替换，保留使用区间核对；在剪辑预览前后连接、节奏与已有声音／字幕影响 | 剪辑用 C，固定 v1 仍 A |
| 12. 固定 v2 并交回复核 | 是否完整回应了这条意见？ | 说明修改内容、链接 v1 意见，固定当前剪辑；审阅者看 v2，还能返回 v1 | v2 待审阅；生成 v2 不等于评论已解决或场次已确认 |
| 13. 确认与整集使用 | 整场是否达到进入整集的条件？ | 主创明确确认 v2；整集再明确引用 v2 | 当前草稿以后可继续改，v1/v2 与整集所用版本不被覆盖 |

这段流程不要求把所有工具同时铺满。它要求**当前观察目标和本次编辑目标始终清楚，辅助内容收起后不丢失，任何关键判断都能取回依据**。完整场次验收还包括声音、台词、字幕、交接和恢复；这些不在本轮截图内，不代表取消。

## 我推荐的布局与面板规则

### 主区优先服务观察与编辑

分镜模式默认恢复用户的当前镜头工作位置：主区大预览，候选条、相邻镜头导航与连续性摘要轻量附着；“全场”进入有序网格。新进入场次可先展示全场帮助定位，第一次选镜头后进入精修，并记住状态。模式名称只有分镜／画布；总览、精修和比较属于分镜内部工作状态，不新增第三种数据模式。

自由画布保留同一场的全部素材和探索，不以“只看当前镜头”替代它。选中对象后，短动作就近展开；长提示词固定到主区边缘的制作区，有明确目标标签，不跟随鼠标或拖动节点漂移。未选中不保留假定的上一镜头输入。进入比较是主动的临时聚焦，返回恢复原画布视野与节点位置。

两种模式的直接输入只有一份，拥有相同草稿、目标、参考与计划语义；采用、剪辑使用、固定稿确认不放进画布布局状态。邻接判断默认采用实际剪辑的前后片段并标明版本；故事顺序与剪辑顺序不一致时可切换查看，不能根据画布距离推断前后。

### 助手、素材和直接编辑怎样共存

| 内容 | 推荐呈现 | 联动规则 |
|---|---|---|
| 直接编辑 | 主区内稳定的局部制作区；可展开、收成摘要 | 始终可恢复，不与助手共用一个互斥页签；生成入口靠近当前输入 |
| 持续助手 | 右侧非模态停靠，默认关闭，可调整宽度 | 不盖画面或编辑器；保留会话、输入和滚动位置；打开不自动缩小到全场 |
| 已用于判断的参考 | 主区内可固定的一至数张媒体，或可展开参考条 | 不因素材库收起而消失；明确“仅查看／本次生成参考／助手引用” |
| 快速加参考 | 当前引用附近的搜索／最近使用选择器 | 选择前固定目标 SH-04；选中资产只浏览，明确添加才变更引用 |
| 持续素材浏览 | 按需左侧停靠或主区的浏览状态 | 搜索、位置、待选内容保留；小屏与完整助手不强行双开 |
| 候选比较 | 主区临时聚焦 A/C，保留目标、状态和返回入口 | 预览与采用分开；高倍查看可让编辑区暂时收起，但草稿不丢失 |

三种能力应能在同一工作片段并用；不要求三个完整面板永久同时展开。特别是“素材可用”与“整个素材库常驻”不同。1366 宽度下，助手＋直接编辑＋已固定参考可以同时使用；若需要持续全库浏览，默认收起助手为可恢复入口，用户选好参考后回到讨论，编辑草稿和会话都保持。该取舍比把中心画面挤到六百像素以下更适合这次手部判断。

助手请求的目标由显式引用确定：切到 SH-05 浏览时，已发出的 SH-04 请求和返回建议保持原归属；新消息发送前显示本次目标。用户可以明确“把 SH-05 作为接续参考”，但它不应因此变成修改目标。将建议应用回原对象也要清楚显示 SH-04，不依赖当前屏幕恰好选中了什么。

### 1366 宽度的具体取舍

以下是下一版的**尺寸试验起点**，不是已测试过的像素结论。先保留现有 76px 全局栏，避免把是否缩窄导航与创作布局捆绑。

| 状态 | 横向预算 | 中央使用方式 |
|---|---|---|
| 无辅助面板 | 1366 − 76 = 1290px | 全场、画布组织或当前镜头工作状态 |
| 助手展开 | 1366 − 76 − 360 − 16 = 914px | 直接编辑归入这 914px；预览与参考同在主区；不再另扣 356px 编辑栏 |
| 素材浏览展开、助手收起 | 1366 − 76 − 260 − 16 = 1014px | 搜索、比较资产并引用；主区保留目标预览和输入 |
| 素材与助手完整双开 | 1366 − 76 − 260 − 360 − 32 = 638px | 不作为 1366 默认精修状态；不以缩小当前媒体勉强达成“双开” |

助手状态下主区再留 24px 两侧内边距，约 866px 可用：足够试验两张 230–260px 的完整竖画幅和一项参考，但实际细节判断仍需主动放大。并排的宽度不是唯一约束：在 1366×768 下，即便压到约 96px 的上下文与模式栏，扣除返工摘要、约 180px 输入、候选与控制条后，媒体高度仍可能只有约 350px。此时必须提供“比较／放大”让输入收成约一行摘要，不能承诺三张全高画面、长输入和聊天全部舒展。

在 1366×900 优先保留长输入与图像并看；在 1366×768 优先给比较状态足够高度。滚动只发生在输入或助手各自区域，执行按钮和当前目标不随长聊天跑远。具体最小高度、参考固定数量和面板切换成本待用中文长输入测试。

模态可以用于独立的生成计划执行核对、固定稿提交等完整决策；大图精看也可进入专用状态。是否模态取决于该步骤是否已经包含决策所需内容，不能用“低频”作为唯一理由。

## 对主代理待挑战建议的判断

对照文件：[导航与核心创作页面：独立设计复核](../../design/journey-independent-review-2026-09-10.md)。以下是在独立判断形成后对照所得。

| 建议 | 我的判断 | 补充或不同替代 |
|---|---|---|
| 淘汰持续助手的模态遮罩 | 同意 | 必须同时取消覆盖编辑区与焦点阻断；仅去遮罩不算完成 |
| 中央内容与当前对象制作，右侧持续助手 | 同意 | 长输入需要稳定位置与明确目标，不追随画布节点；已发请求目标不能随新选择变动 |
| 快速引用与持续素材浏览分开 | 同意 | 增加“固定看这份参考”，解决素材库收起后仍需判断钥匙的问题 |
| 左素材、中央制作、右助手，约 690px 中央待验证 | 有条件同意，反对作为 1366 默认 | 我选择完整素材库与完整助手默认互斥展开，保留已固定参考和直接编辑。并非能力互斥，也不是只有一个共用抽屉 |
| 六镜头网格适合总览，精修要聚焦 | 同意并加强 | 应拍板总览／精修的主次，不能只在现有网格上添加放大按钮后就认为已解决；既有双模式契约与新提案需统一 |
| 大图／比较是创作判断入口 | 同意 | 明确静帧并排、视频先切换；不能顺势要求 MVP 同步多路视频 |
| 按对象附近呈现当前操作 | 同意原则，不把“附近”理解成所有输入贴节点 | 稳定的主区边缘编辑区能降低目标移动和视野漂移，更适合长中文提示与持续对话 |
| 下一轮只验证 SH-04 | 同意作为最小修订切片 | 必须增加从旧稿二次返工、跨镜头查看、第三项参考和返回原上下文四个变体，否则容易漏掉本次最严重的问题 |

该报告关于“打开助手阻断背景”的浏览器测量与我的截图／源码检查相符，但我没有复做其 DOM 命中测量。它未充分讨论返工入口覆盖输入、第三项关键参考在画布消失和返工回应的收尾，这三项应进入综合方案。

## 至少一个看似合理、但不建议的替代

**“把右侧改成制作／助手／素材三个页签，用户切着用就行。”** 这能快速去掉遮罩，也能节省宽度，但把当前正在编辑的文本与用来判断它的建议继续分离。用户要接受一句、保留一句、再加一张参考时，仍需要依赖记忆反复切换。它可用作短暂过渡，前提是直接编辑已经保留在主区；不能作为最终连续创作方案。

**“所有辅助面板都非模态，因此可以左素材＋中间网格＋右编辑＋右助手同时展开。”** 非模态只解决阻断，不解决媒体尺寸。按现有宽度，1366 − 76 − 240 − 356 − 360 只剩 334px，尚未扣间距。即便把输入挪到中心，两个完整辅助栏仍让近距离候选比较受限。应按当前任务保留需要持续可见的内容，而不是以全部面板可见证明功能完整。

**“采用后顺便自动用于剪辑，减少一个步骤。”** 两步确实增加点击，但这不是可合并的同一事实。制作人员可能推荐 C，剪辑还需要保留 A 的节奏或与已录声音的配合。应通过差异提示与明确的下一步降低操作成本，不能用省点击取消已确认的边界。

## MVP 与后续边界

下一轮设计原型应先补：不覆盖输入的返工定位；助手与直接编辑并用；可看清的当前候选与 A/C 比较状态；第三项钥匙参考固定查看；四种事实的差异呈现；v1 意见到 v2 修改说明的可追踪路径。全部可以用现有 Mantine、CSS 与本地样例完成设计验证，无须新增依赖或接后台。

完整 MVP 仍须覆盖现有承诺：实际生成与计划核对、参考的确切版本、可找回的候选与来源、场次双模式／未归镜头探索、基础音画字幕与内部后期交接、整集和第二集复用、保存冲突与恢复、成员协作。当前示意图没有演示它们，不能把它们归为取消或可任意后置。

助手首期继续受现有三类有限 AI 入口约束。改善讨论与建议编辑的承载方式，不等于引入跨项目自由 Agent、自动改剧情、任意工具执行或循环付费重试。多人团队也不等于首期实时共同编辑；至少要让接手者看得懂来源、改动和当前版本，不用每镜头工单来替代创作空间。

可后续研究：多视频同步播放比较、任意浮窗布局、自动诊断连续性、完整创作讨论知识沉淀、通用 Agent 工作流、广告的专用工作对象。底层保持媒体、引用、尝试、候选与固定版本的通用性；广告接入自己的上下文，不把“集／场／镜头”硬塞进通用画布。

## 给主代理的简短结论与必须拍板项

主线保留，先修连续判断：**返工保留原输入，当前候选进入主区，助手不遮挡直接编辑，关键参考可固定，回应旧意见有可追踪出口。** 对助手非模态和中央局部制作，我与待挑战稿一致；对 1366 默认左右完整辅助栏同时展开，我持保留并推荐取舍；对“分镜网格是主要工作状态”，我推荐改为总览／当前镜头精修分工。

需要拍板的冲突点：

1. 分镜进入或选中后的主要状态是全场网格还是当前镜头精修？建议首次定位可总览，实际制作以精修为主，并收口与既有契约的分歧。
2. 1366 下是否要求完整素材库与完整助手同时展开？建议不作为默认要求；保证助手＋直接编辑＋固定参考同时可用。
3. “按意见继续制作”是纯定位还是直接改变提示？建议纯定位保留原输入，准备修改另作可审查建议。
4. 返工上下文跟随当前所选镜头，还是绑定原意见对象？建议原意见／请求固定归属，浏览选择独立；切镜头时明确提示和显式应用目标。
5. 下一轮是否用不同 A/C 素材验证判断，而非只验证按钮与标签？建议至少换成确有差异的示意帧；视频质量与真实制作效率继续标待验证。

上述推荐是基于任务与原型证据的设计判断。没有目标团队试用数据，尚不能证明它是全局最优布局或节省多少制作时间。
