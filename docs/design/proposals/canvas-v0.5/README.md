# 自由画布 v0.5：结构与状态样例

这是一次性设计原型，回答“日常创作输入属于哪里、何时打开”的问题，不是可用业务画布。对应[研究后推荐方案](../../canvas-redesign-v0.5-2026-09-14.md)。原型保留在 `feat/canvas-interaction-redesign` 分支，不加入生产构建或直接合入 main。

在仓库根运行：

```sh
python3 docs/design/proposals/canvas-v0.5/serve.py
```

打开 [本地设计样例](http://127.0.0.1:4318/?variant=A)。服务器仅绑定回环地址，只提供 HTML 和两张已有演示图；不暴露仓库目录，没有 API、存储、鉴权信息或模型调用。

| 结构 | URL | 需要判断的问题 |
| --- | --- | --- |
| A：节点就近编辑，推荐日常使用 | `/?variant=A` | 浏览与编辑分开后，目标和上下文是否更连续？ |
| B：固定对象侧栏 | `/?variant=B` | 固定输入位置是否值得持续占用宽度、与助手争用空间？ |
| C：显式专注创作 | `/?variant=C` | 长输入与大预览是否适合作为有意进入的局部状态？ |

底部箭头和输入区之外的左右键切换结构。先点草稿，再点“编辑输入”，观察单击选择与明确编辑的差别。文本只在本页内存中保留；刷新重置。切结构保留同一文本用于比较，重置选中／编辑／辅助状态；URL 记录结构。

可检查的交互：选择、局部输入、固定确认阅读态、专注进入／返回、助手或材料／结果／镜头说明区切换、并排静帧检查、明暗和小屏列表。真正执行与写入入口没有接通；带“预演”“样例”的动作只切展示状态。“新建视频草稿样例”打开同一示例草稿，不持久创建节点。

样例是固定坐标的结构验证，未实现 React Flow 的平移缩放、完整碰撞避让、100 份参考管理、键盘全链路、生成任务与错误恢复。底部显式展示相关状态，不能用它证明这些工程要求已经完成。正式实现需使用现有 Mantine、Phosphor、React Flow、主题和 controller，不把本 HTML 移进生产代码。

两张图片直接读取仓库已有的 `apps/web/public/demo/workspace-v2/` 演示静帧；没有为比较伪造两次生成结果、视频动作或采用事实。画布节点上下文进入助手是新增接入设计，现有产品仍要求镜头来源，必须先补对应服务契约。

## 本轮观察结果

推荐 A 作为默认、C 作为长任务补充。B 的输入位置稳定，但开启助手后需要明确处理两者对同一个侧区的竞争。普通选中不展开表单，局部输入与画布容器分离，能消除本轮测得的底部布局挤压；真实创作者是否更容易操作仍待任务验证。

实际浏览器检查及图片见[验证记录](../../../../output/playwright/2026-09-14-canvas-research/README.md)。这是原型状态检查，未宣称生产业务 E2E 或用户效率验证通过。
