# Mantine UI 执行规范：Agent 用稿 v0.1

初稿：2026-09-09；同步：2026-09-10。状态：**当前 UI 执行规则**。Mantine 唯一通用 UI、Form／Splitter、共同语言与核心工作区已确认，四项专项暂时收口。正式业务工程仍暂停；[早期样板记录](mantine-visual-sample-v0.2.md)只说明当时实现，当前页面与状态见[设计基线](approved-baseline-2026-09-10.md)。

适用：AI 视频平台的短剧优先 MVP。业务范围以 [14 场次收口](../implementation/14-scene-mvp-closure.md) 为准；库的接受状态以 [17 组件选型](../implementation/17-frontend-component-selection.md) 为准；视觉原则见[共同语言](shared-visual-language-v0.1.md)，布局见[核心体验 v0.3](scene-walkthrough-review-v0.3.md)。本稿不扩大画布、剪辑或自动执行范围。

## 1. 实现边界

- 通用按钮、表单、菜单、弹窗、选择器、标签页使用 Mantine；不引入 Tailwind、Kumo、HeroUI、shadcn/ui 或其他通用 UI 库。
- 允许语义 HTML、CSS Grid/Flex、CSS Modules、现有 Phosphor 图标及单独确认的专业组件。“唯一通用 UI”不要求所有布局都写成 Mantine 组件。
- 一处根 MantineProvider、一套集中主题。页面不另设局部主题改品牌或密度；样板展示如确需隔离，须明确标记，不能复制到业务页面。
- 使用公开 Styles API、组件 CSS 变量与有作用域样式；不修改第三方源码，不依赖生成类名或内部 DOM 层级，不用全局 button/input/svg 规则覆盖组件，不以堆积 `!important` 修补冲突。
- 用户最新决定将每场次自由画布纳入首版，见[场次画布交互](scene-canvas-interaction-v0.1.md)。React Flow 12.11.6 已完成隔离验证并选定；播放器采用 Media Chrome，排序采用 dnd-kit，服务端状态采用 Query，Virtual按需使用。主应用按组件选型文件和CX任务接入，不以隔离样例替代完整业务。视觉规范不能替代这些选型决定。

## 2. Theme、语义变量与密度

用户已确认[共同视觉语言](shared-visual-language-v0.1.md)：媒体优先、轻包装、全局紧凑与局部舒展、工具就近展开、形状分层及克制用色。核心制作使用中央有界输入、底部分镜条／全场自由画布，助手与持续素材浏览占布局空间。

当前独立原型的明暗样例由 `apps/web/src/theme/shared-language-study.ts` 集中提供；根主题 `theme.ts`、`tokens.ts` 仍服务早期页面与通用组件。两者尚未完成全站归一，后续迁移应将已确认语言纳入统一语义主题，不复制散落的色表，也不回退到早期暖杏色方向。

| 系统项 | 当前执行规则 |
|---|---|
| 表面与文字 | 沿用当前中性浅／深色语义变量；画布、面板、输入、文字、边界分别表达，不从旧截图手抄色值 |
| 关键动作 | 采用当前低饱和动作色与主题配对文字；暖杏色仅属于早期样板，不能作为新增页面品牌要求 |
| 字体与密度 | 系统中文无衬线；全局紧凑、当前编辑舒展。必要文字不靠缩小维持列数；具体字号复用主题 |
| 间距与尺寸 | 沿用既有 4px 步长和紧凑／常规／表单控件尺寸；按内容需要使用已定义变体 |
| 形状与层次 | 媒体、短工具、输入与弹层分别复用当前语义圆角；描边和表面区分为主，弱阴影只用于必要层次 |
| 媒体与字幕 | 工作台明暗、选中和焦点不改变影片内容；字幕使用固定媒体颜色，不能随按钮文字反色 |
| 动效 | 简短颜色／透明度反馈，尊重减少动态效果；选镜不缩放媒体、不挪动卡片 |

实施要求：

1. `createTheme` 集中定义色阶、字体、字号、行高、间距、圆角和阴影。产品语义变量至少包含 surface、text、border、accent、status、focus，区分装饰分隔与可操作输入边界。
2. 通过 `theme.components`、组件 `extend` 的 `defaultProps`、`classNames` / `vars` 统一各控件。**相同 `size="sm"` 不保证不同控件的像素高度相同**，按每个组件的公开 API 映射并检查 Button、ActionIcon、TextInput、Select、NumberInput、Textarea。
3. 原始色阶由主题维护；业务 CSS 引用语义变量。自定义变量可由 `theme.other` 配合 `cssVariablesResolver` 导出；不在 CSS 中再手抄另一份色表。
4. 页面不硬编码新的品牌色、字号、圆角和阴影，也不使用 Mantine 任意色名创建新的状态语言。动态宽度、媒体比例、拖拽位移、进度和时间位置等业务计算值允许动态样式，不必伪装成设计 token。
5. 自定义 CSS 用 CSS Modules；Mantine 的间距等 style props 可以使用已定义 token。公共组件外观改动回到主题或组件定义，页面只负责布局。

以上机制对应 Mantine 官方 [Theme](https://mantine.dev/theming/theme-object/)、[默认属性](https://mantine.dev/theming/default-props/)、[Styles API](https://mantine.dev/styles/styles-api/)、[CSS 变量](https://mantine.dev/styles/css-variables/)。默认属性可被页面 props 覆盖，故 Theme 本身不是强制一致性的检查器。

## 3. 通用组件用法

| 对象 | 规则 |
|---|---|
| 按钮 | 全局默认使用中性次操作；区域主操作显式使用强调色 filled，常规次操作 default，弱操作 subtle，危险操作使用危险语义。每个独立操作区域最多一个强调色主按钮；不用颜色装饰所有动作 |
| 图标按钮 | 使用 ActionIcon；提供可访问名称与必要 Tooltip，保留 focus-visible。必要操作不能仅靠 hover 才能发现 |
| 输入 | label 常驻，placeholder 只作示例；错误在字段附近说明原因；只读可复制，disabled 明确原因；提交或冲突不清空已输入内容 |
| 卡片 | 媒体、摘要、使用状态、操作位置稳定；按内容角色组合，不为每段文字再套一个带边框 Card。卡内多操作时避免嵌套 button |
| 面板 | 稳定的标题/工具区与内容区；用 Splitter 管理可调整面板；折叠和尺寸为视图偏好，不与镜头排序或业务状态混存 |
| 弹窗 | 短表单和明确确认用 Modal；持续提示词编辑、参考选择等优先在工作区完成。标题、主操作、关闭/返回和焦点恢复一致，避免嵌套弹窗 |
| 通知 | Toast 只补充即时反馈；可持续的任务、错误和恢复入口保留在对应对象附近，不能只显示几秒后消失 |

各组件样板必须展示 normal、hover、focus-visible、disabled 及适用的 loading、error。输入只读、加载中和不可用是不同状态，不共用一个灰化效果。

## 4. 生成与制作状态

业务状态映射来自现有契约，不新增一个覆盖所有含义的 `status: success`。用独立状态展示组件集中维护图标、文案和颜色；页面不得自行给状态换名字或上色。

| 状态维度 | 必须表达的含义 |
|---|---|
| 交互状态 | hover、选中、键盘焦点相互独立；选中不代表采用或通过 |
| 生成任务 | 区分排队、执行、结果处理中、结果可用、失败、已取消和提交状态待核对；具体枚举映射既有契约。没有供应商真实百分比就只显示实际阶段 |
| 成功 | 生成成功表示产物已达到契约规定的可用条件；“已生成”与主创“已通过”使用不同明确文案 |
| 失败/待核对 | 失败显示可理解原因及允许的恢复操作；未知提交显示“待核对”，不能当失败再购买；页面刷新或通用重试不得发起新收费任务 |
| 当前采用 | 显示“已采用 A”及稳定候选身份；新生成结果不自动采用 |
| 剪辑使用 | 显示实际候选、版本及使用区间；采用 B 不自动将剪辑 A 替换为 B |
| 审阅 | 通过、返工意见绑定明确固定版本；场次通过不代表整集通过，新稿不继承旧稿通过 |

颜色只作辅助，必须有文字，必要时加图标。绿色可用于成功/正式通过的相应反馈，但不能据绿色推断对象已经获批。界面可同时展示“B 已采用、剪辑使用 A、v1 已通过、v2 草稿”。

## 5. 业务组件边界

优先按真实场次页面需要实现，不一次建设全量组件平台，也不为每个 Mantine 控件创建透传包装。

| 组件 | 责任与边界 |
|---|---|
| WorkspaceShell | 项目/场次上下文、视图切换、面板槽位、折叠及尺寸；不持有生成、费用或批准事实 |
| PromptComposer | 提示词草稿、明确参考与编辑状态；区分准备提示、保存和提交生成，切镜头不丢草稿；费用与执行由业务层驱动 |
| ModelSelector | 展示实际可用的服务/模型能力、输入要求及不可用原因；模式和参数来自能力描述，不写死所有模型都要求首帧或支持音频 |
| GenerationCard | 一次生成任务的阶段、输入摘要、结果入口和恢复动作；不承担镜头是否完成或已批准的判断 |
| CandidateCard | 单个结果/候选版本的预览、身份、选择与采用入口；允许一次任务有多个产物，避免将任务与候选混为一个对象 |
| AssetCard | 资产及引用版本、类型、预览和选择；资产引用与生成结果候选保持各自语义 |
| ShotCard | 镜头要求摘要、媒体、当前采用、实际剪辑使用和相应入口；以稳定 shotId 定位，排序后身份不变 |
| MediaViewport | 统一媒体周边背景、比例、加载/错误/空态与播放器集成位置；素材比较默认完整画幅，不通过滤镜改变图像；不设计庞大的通用播放器框架 |
| 状态展示组件 | 根据任务/采用/使用/审阅各自的明确输入渲染，必要时用多个小组件；不从颜色、数组位置或本地选择推断业务事实 |
| NodeShell | 场次画布工程接入时实现；包装节点选择、端口与内容槽位，不持有镜头、任务或收费事实；示意脚本不是生产组件 |

UI 组件接收明确数据与操作回调；不可将 API 查询、购买重试、批准权限和画布内部 store 隐藏在卡片中。服务端仍负责授权和状态校验。

## 6. 约束 AI Coding 的最小落地闭环

仅给 Agent 一段“简洁、专业、深色”的提示不足以约束结果。后续迁移按以下顺序推进。早期样板已有主题、组件页和有限检查；**已确认核心／专项仍是隔离原型，不能据此声称统一生产组件与全站迁移已经完成**：

1. **一套主题实现。** 在 `apps/web/src/theme/` 集中主题、语义变量和公共组件覆盖；收窄旧全局 CSS。复用已有图标，不新增第二套图标体系。
2. **一个可运行样板入口。** 复用现有设计页入口，展示通用组件全部适用状态及上述业务组件。直接渲染实际生产组件，以确定性数据展示，不复制一份只供演示的实现；本期无需另搭 Storybook 服务。
3. **一个真实场次样板。** 在 1366×900 和 1512×982 核对镜头、候选、参数、媒体预览和错误/返工状态。样板确认后再逐步迁移其他页面，保持既有业务行为。
4. **一份 Agent 入口规则。** 当前 `apps/web/AGENTS.md` 已链接本规范、当前设计基线与历史样板，明确已确认／暂时收口的边界；规则保持一份。要求“先查已有组件 → 组合使用 → 需要新变体先补公共定义和样板 → 验证实际页面”。AGENTS 中的工程规则已启用，不将视觉评审状态偷换为最终品牌批准。
5. **少量可执行检查。** lint 检查禁止依赖及导入、主题外新增原始色值/外观 token；运行期计算值和主题测试夹具使用明确例外。对已迁移范围检查，避免让尚未迁移的旧原型产生大量噪声。固定数据和视口保存必要的截图基线，变更不能以自动重录基线代替审阅。

Agent 不得为单页“更好看”绕过主题、复制 Card/Modal 的一套新样式、偷换业务状态，或为通过检查禁用焦点。公共变体确实缺失时，补定义、用例和规则，再在页面复用；不要求每次小改都重新请用户批准。

## 7. 完成标准

- 同一控件和同一业务状态跨制作、剪辑、审阅视图保持一致；长中文、空结果、多个候选和错误提示不破坏布局。
- 媒体内容没有被选择态改色，必要文字可读；普通文本对比度目标 4.5:1、大字按适用定义 3:1；操作边界和焦点单独检查，装饰分隔不用一概加重。[W3C 对比度](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)
- 键盘可到达操作、关闭弹窗并恢复焦点；分隔可键盘调整。排序在引入拖拽后仍保留可用的键盘/明确移动操作。
- 截图变化、主题检查、类型/构建及适用交互检查分别报告。token 检查或截图相同不等于业务正确，也不等于所有可访问性要求通过。
- 不虚报已安装、已迁移或已验证；本轮只完成实现记录列明的本地样板范围。播放器已经选定；明确开工后按 [F00 接入计划](../implementation/17-frontend-component-selection.md) 推进。
