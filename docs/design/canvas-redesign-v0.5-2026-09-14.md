# 场次自由画布重设计 v0.5

日期：2026-09-14。状态：**用户已确认方案，正在实施。下面的研究和原型证据不替代生产代码与业务验收；实际完成状态见实施进度。**

本轮先执行 `git fetch origin --prune` 和 `git pull --ff-only origin main`，确认最新代码为 `f4f005c981ea195dbca56c1c5d570de66470f994`。随后并行完成 TapNow 官方交互研究、LibTV 一手来源研究、SceneDesk 结构审计，并实际打开本地保留演示项目检查布局。最新用户要求重设计，因此重新评估 v0.3 的中央长输入和 9 月 13 日底部面板方案；原有业务定位、固定输入和恢复要求继续成立。

## 1. 推荐结论

**保留同一场次的自由创作空间，以节点附近的短编辑为主，复杂编辑显式进入可返回的专注视图；助手使用独立的右侧辅助区。移除画布底部常驻的公共编辑／生成面板。**

用户在画布上的主路径应当是：

> 看材料 → 选材料 → 作为参考新建 → 就近写本次要求 → 核对并明确生成 → 查看结果 → 继续尝试或用于镜头。

这里最需要改变的是操作状态和空间归属。单击一张图片只是选中它；不应随即改变画布高度、打开镜头关联与生成记录。固定任务也不应挤在另一个草稿的输入下方，让用户靠读小标题判断正在操作哪个对象。

### 当前问题不是简单“没照设计图”

上轮确实遵循了旧 v0.3 的中央稳定长输入方向，并补了就近工具、参考条和折叠参数。但把这一方向泛化为所有节点的公共底部面板，是方案本身需要修正的判断：**分镜模式的一次单镜头编辑，与自由画布的跨对象浏览、比较和探索，需要不同的空间安排。** 给底部表单继续加折叠不能解决这一点。

本轮也没有把竞品研究不足掩饰为“完全理解”：TapNow 已观察六段官方动态图；LibTV 看到了官方演示的部分画面和官方操作文档，但登录内完整链路仍未实测。本文对两者使用不同证据强度。

## 3. 本地真实页面暴露的问题

本轮新开保留演示“旧钥匙 · 完整演示 / 咖啡厅”，默认浏览器视口为 1280 × 720，确认页面加载 `/assets/index-l_bRDbIN.js`。只查看、适应内容和选中，未修改节点、媒体、候选或生成任务。

1. **未选中也占编辑空间。** 页面底部仍显示“生成记录 0 项”和选中提示；这不是开始创作所必需的常驻内容。
2. **选中参考图即展开大面板。** 实际选中“林夏 · 固定参考 v1”，底部显示镜头关联、节点属性和生成记录；此时 React Flow 区域只有 1212 × 343.53px，从 y=134 开始。用户想看的参考仍缩在全览中，属性表却占据显著空间。[本轮截图](../../output/playwright/2026-09-14-canvas-research/current-reference-selection.jpg)
3. **浏览与编辑目标可能不同，却被装进一个容器。** 当前 `historyId` 与选中节点独立，这种业务保护应保留；视觉应拆出只读的固定尝试，不能让它看起来属于上方新草稿。
4. **动作未按内容状态分流。** 草稿上仍显示“继续创作”，而创建逻辑拒绝草稿作为参考；用户到点击后才得知。应先显示“编辑输入／准备生成”。
5. **节点不能清楚表达已有尝试。** 草稿统一写“尚未生成”，真实历史任务却在另一处。新版用“草稿”和“最近尝试 · 状态”分别表达，不能把旧成功结果标成当前新输入已成功。
6. **模式与关系说明过重。** 镜头关联、生成来源、画布引用、助手上下文相邻出现，但用途不同。需要以“本次使用什么”和“成果用于哪里”重组入口。

“适应内容”把 19 个节点缩成全景是合理导航，不是视频画质故障。但它不能作为首次进入和所有选择操作的默认可用构图。已有视口优先恢复；没有历史视口时，聚焦入口明确指向的对象，若无对象则先全览并提供可辨识的节点索引，不能自动改动节点布局。

工作室轨道 │ 项目 / 第1集 / 咖啡厅  [分镜 | 画布]  已保存  任务  AI助手
           ├─────────────────────────────────────────────────────────┐
           │ [+]                                                     │
           │ 材料     参考图       文字想法                            │
           │ 查找       ╲          ╱                                 │

### 四类区域各有单一职责

| 区域 | 默认内容 | 展开规则 |
| --- | --- | --- |
| 场次栏 | 路径、分镜／画布切换、保存、任务、助手 | 合并重复的“镜头制作”标题和多排按钮；场次目录按需打开 |
| 左侧画布工具 | 新建／导入、材料、查找、镜头索引、结果 | 入口有 tooltip 和键盘名称；浏览面板一次一份，关闭保留最新选择和视口 |
| 左下视口工具 | 选择／手形、缩放、定位／适应内容 | 节点数量和容量进入信息层；接近容量限制时提升可见度 |
| 对象局部区 | 当前对象短工具，明确编辑后的局部输入 | 没有选择时不显示；多选只显示共同操作；普通媒体不挂输入表单 |
| 右侧辅助区 | 助手、长结果详情、镜头交接、完整材料浏览择一 | 显式操作打开；保留各自草稿；不能因选中别的节点自动换内容 |

右侧区作为屏幕覆盖层，常规桌面建议 360px，较大屏可到 400px。它改变可用安全区，不改变 React Flow 容器尺寸或 transform；当前对象被遮挡时提供“定位对象／专注编辑”，不默默执行 fit。短菜单与参考详情 popover 可就近打开，不另起第二根完整侧栏。

普通辅助区是非模态的：打开后仍可在画布选 B 或平移，关闭时保留这些新状态，只把键盘焦点还给仍存在的入口。不得恢复旧选区 A 覆盖用户后续导航。焦点目标不存在时回到稳定的画布工具入口。

画布模式不常驻整条分镜胶片、不强制一个镜头一个大框。镜头索引显示 01–06、摘要、候选状态和“未关联探索”，点击只定位；分组是空间整理，不代表镜头绑定或播放顺序。

## 5. 对象状态与动作矩阵

| 当前状态 | 单击后 | 明确编辑／下一步 | 不产生的副作用 |
| --- | --- | --- | --- |
| 文字／便签 | 选择边界；编辑、作为参考新建、更多 | 双击或编辑进入正文；长文本可专注编辑 | 不自动发送助手、不准备模型任务 |
| 已有图片／视频／声音 | 轻标题、预览／播放、作为参考新建、更多 | 双击打开大预览；编辑图像等工具只按已接通能力显示 | 不展开镜头属性表、不改媒体、不自动采用 |
| 未提交草稿 | 类型、摘要；编辑输入、更多 | 双击／编辑打开局部输入；新建草稿后可直接进入输入 | 不能作为已经完成的媒体继续引用 |
| 草稿有历史尝试 | 可编辑草稿与最近尝试状态分两层 | 编辑当前稿；或明确打开某次固定尝试 | 旧任务不因当前文字修改而改写，不给新文字显示旧成功 |
| 任务排队／运行／待核对 | 真实阶段和查看任务 | 查询、实际支持的取消、恢复原任务 | 不以等待超时启动新的收费尝试 |
| 已就绪成果 | 媒体、类型、来自哪次尝试 | 预览、明确取回、作为参考新建、用于镜头 | 不自动形成 Take 或替换当前采用 |
| 多选 | 数量、分组／移动、更多 | 全部可用时“作为参考新建”；有不合法来源时解释并让用户明确排除 | 不静默丢弃草稿／不可用媒体，不同时打开多份输入 |
| 未选中 | 仅画布与全局入口 | 双击空白打开类型菜单 | 菜单打开不新建节点，无全局生成空表单 |

短工具默认最多三个显著动作：主要动作、查看／编辑、更多。删除和复制放更多；保留快捷键。任务失败、输入失效或保存冲突在对象旁持续可见，不以“高端简洁”隐藏异常。

## 6. 局部输入：一份草稿、一份可读工作面

建议初始宽 400px，可在 360–480px 内适配安全空间；短编辑高约 220–280px。数值是原型起点，须根据 1366 × 768、1440 × 900 和长中文任务验证，不是竞品测量值。

```text
视频草稿 · 咖啡厅 / 钥匙动作             展开  收起
参考 [钥匙 v1 · 细节] [人物 v1 · 外观]   + 添加
本次要求
保持右手和袖口，先碰到匙环，再缓慢拿起……

模型 ▾   9:16 ▾   5秒 ▾   更多          准备生成 →
```

- 正文是主区域；名称、x/y、宽高和分组进入更多属性，不与本次要求并列成后台表单。
- 图片／视频／声音是草稿类型；只展示该类型和实际服务需要的参数。声音保留台词、声音固定版本等具体角色，不能全部变成通用图片 chips。
- 参考条显示缩略、短名、用途；展开可读固定版本、顺序、启用与移除。超过可读数量时展示“另 N 项”，在同一参考浏览器管理全部 0–100 项；不能只保留前几张。
- 模型与必要输出规格常显；seed、负面提示和其他实际支持参数进入更多。服务未配置时保留输入，主动作说明缺少服务，不把演示标签写成可调用模型。
- “准备生成”得到一份固定确认，原区域进入阅读态；常显目标、参考数量／版本及输出规格，长正文可展开；按钮明确“确认生成”。确认仍绑定原计划，其他选区不改变它。
- 当前稿与上一份固定尝试不相等时，显示“输入已修改”；可以查看旧尝试，但不能在旧计划按钮旁同时放一份貌似可修改的正文。
- 本机保留、服务器保存和任务受理分别呈现。异步返回只更新原对象会话，不替换后来输入。

### 避让与离屏规则

1. 输入以当前编辑对象屏幕包围框为锚，优先保持上次仍合法的位置，再按下、右、左、上寻找位置；与节点留约 12px 间距。
2. 在正常展开编辑态，标题、操作区和当前媒体主体应同时可见。优先级是保留输入与世界 transform → 有安全空间才展开完整输入 → 无空间时转为有名称的压缩提示，由用户定位或专注；不能为强行满足可见性偷偷 fit。可见且已启用的参考是软避让目标；100 份参考不能全部同时保留在屏幕上，输入内缩略条补足核对能力。
3. 浮层不参与节点大小、文档坐标、fit 包围盒和 React Flow 容器布局；输入、选中、收起不会重排节点或自动平移缩放。
4. 输入和中文组合期间锁定浮层方向。长文字内部滚动，不每次换行翻边；用户结束平移／缩放、打开辅助区或调整窗口后才重新判定。仍合法的位置保留约 24px 余量，避免来回跳动。
5. 缩小总览时，输入保持屏幕可读尺寸。编辑对象被辅助区遮住或移到视口外时，用“正在编辑 X · 位于视图外”的轻提示与定位／专注编辑／收起，不在邻近对象上伪造工具归属。
6. 若安全空间无法同时放下当前媒体和输入，不硬挤长表单：提供显式“专注编辑”。进入时保存本页视图状态并暂停底层画布的指针和键盘交互；退出仍在同一场次且权限有效时恢复原视口、仍存在的选区和同一份草稿。对象／入口已消失则回到稳定工具入口，告知原因，不复活已删除对象或越权显示恢复副本。

### 选择与编辑目标分离

选中 B 只是浏览 B；正在编辑的 A 保留清楚的名称及细边标记。明确“编辑 B”时，先完成 A 的本机写入队列交接，再把同一个输入容器切到 B。本机保留失败时保留 A 输入和恢复入口，不无声覆盖。点空白取消选择、收起短输入；有写入失败时保留命名的恢复提示。关闭 UI 不丢弃草稿，不取消任务。

专注编辑是同一对象的视图状态，不是第三个顶层模式或新路由。常规结构是左侧大预览及可查看参考、右侧长输入与固定尝试摘要。它服务长文本、大量来源、精细检查和恢复；普通改一句提示无需进入。退出按钮始终可见，Esc 先关闭内层菜单，再退出；中文输入法优先。

### 固定尝试的切换矩阵

| 动作 | 编辑输入区 | 固定尝试详情 | 不能发生什么 |
| --- | --- | --- | --- |
| A 准备出计划 P | A 的固定确认阅读态 | 原 P 可找回 | 不把此后改稿写进 P |
| 此时选择素材 B | 仍为 A／P，名称常显 | 不自动改变 | 不把 B 当成执行目标 |
| 明确编辑草稿 B | A 的输入先耐久交接，编辑区切 B | P 留在任务／尝试入口；若已打开，独立只读区明确写 A／P | 不能在 B 正文下拼入 P 的执行按钮 |
| 明确查看 A／P | B 的未提交输入保留 | 在辅助区或专注详情查看 A／P，执行只作用于 P | 不能用 B 的参数执行 A，也不能为了查询新建计划 |
| 关闭尝试详情 | 回到仍有效的 B 编辑会话，保留最新画布导航 | P 状态独立保持 | 不恢复较旧的 selection 覆盖用户选择 |

专注视图中切换草稿需要同样的耐久交接；详情与编辑区竞争唯一辅助空间时，提供明确的返回入口并保留双方会话。以上是呈现状态，实际执行与幂等仍归原 controller。

## 7. 助手、参考和镜头交接

### 助手操作同一批对象，但不会隐式读取所有内容

**当前能力差距必须单独处理。** 现有 `SceneAssistant` 的准备提示入口要求明确镜头来源，并说明“仅画布内容暂不支持此入口”；当前创作助手协议也要求至少一份 `shotSources`（[页面](../../apps/web/src/business/SceneAssistant.tsx)、[协议生成器](../../docs/implementation/build_contract.py)）。所以任意画布节点加入助手、建议写回独立草稿，不能只换 UI 就宣称可用。这是本方案提出的新增接入设计，需要在切片 3b 补固定来源与应用契约；不是已经具备的功能，也不是要扩成全自主 Agent。

目标体验：右侧助手顶部说明当前场次和本次明确上下文；底部是独立的本次要求输入。选中节点后提供“加入助手上下文”，发送前可移除和检查固定版本。普通选择不自动加材料，也不默认读取整场全部节点。新契约接通前，真实产品只展示已支持的场次／镜头建议入口，并明确其来源限制，不先放一个无法工作的任意节点聊天按钮。

画布助手接入至少需要：将文字／草稿内容固定到节点身份、画布修订和内容快照；将媒体／资产固定到已有准确版本；服务端核验真实归属、权限和模型支持的输入；建议产物记录这些固定来源；应用时明确目标草稿、基线修订、差异及耐久恢复。纯画布内容允许零镜头来源，不能为绕过旧协议虚构 Shot。来源被删除或修改不静默换成最新，过期应用保留用户稿；需独立验证接口、权限和中断恢复，再开放相应入口。

助手返回的提示建议、结构提案和返工建议按现有有限能力显示。对草稿建议先看差异，再“应用到草稿 X”；用户后续手改与过期版本保留。生成相关操作继续走相同固定计划和明确执行，不加入 Auto，不把一段对话当成真实模型产物。

打开材料选择可以在助手里进入一个带明确“返回对话”的临时浏览状态，返回时保留输入；不能再铺第二根完整材料侧栏。节点输入与助手空间确实冲突时，明确选择收起局部输入或进入专注编辑，不能悄悄关闭一边。

### 两种关系分开表达

| 本次使用什么 | 成果用于哪里 |
| --- | --- |
| 图片／文字／声音参考、固定资产版本、明确选入的历史镜头来源 | 关联到某镜头作为待选参考或视频候选 |
| 输入附近的参考条与完整来源浏览 | 结果上的“用于镜头”动作及独立交接面 |
| 调整用途／启用／顺序会影响下一次准备 | 明确目标、版本与视频区间后建立候选；采用是后续独立操作 |

来源显示“用于本次生成”；镜头标签显示“用于镜头 SH-04”并带真实关系。没有镜头关联的结果保持“自由探索”。拖进分组、移动到某镜头旁、切换分镜都不建立关系。

### 结果与历史

“结果”以缩略、类型、日期和真实阶段浏览；“画布修订”属于保存详情，二者不叫同一个“历史”。固定任务详情有明确只读标题和目标，不复用当前草稿编辑标题。

成功任务先显示“成果已就绪”。首次放入画布时，在来源草稿附近的空位建立结果呈现，保留输入与原素材；已经移除过的结果取回沿用原 `(canvas, job, media)` 对应的节点身份，不为找空位重新分配。若来源草稿已删除，先显示“放到当前视野”的明确落点预览，确认后放置；不假设每次尝试仍有可定位的空间节点。放置不自动 fit，不改旧节点位置；对象已在画布则优先定位，不反复复制。多产物可展开逐项检查，不能只留第一个。

比较两份结果时，提供临时并排大预览及清楚的 A/B 名称、来源和镜头采用状态；视频分别可播放，同时最多一份有声，不虚称首期已有同步对齐播放。比较期间暂停底层画布交互；退出按同场次／对象存在／权限有效的条件恢复画布；比较不触发采用。镜头交接打开后如果目标修订、权限或可用媒体已变化，保留用户范围选择，展示差异重新确认，不能把旧确认静默应用到最新镜头。

## 8. 指针、键盘、响应式与视觉

### 事件和定位

- 选择工具：空白单击取消选择，空白拖动框选；Shift 调整多选。手形／空格拖动／中键平移。输入内空格正常输入。
- 普通滚轮／触控板双指平移；组合键或捏合缩放；提供可见缩放、100%、适应内容。显示实际缩放百分比。
- 节点标题和非交互区域可拖；媒体播放、文字选区、输入、端口和菜单不拖节点。给键盘用户同等的新建、添加参考、定位路径。
- 双击空白只开类型菜单；选择类型后创建，菜单取消不留空节点。导入验证、上传中和失败留在明确对象上。
- 连线显示方向；未启用来源有不同线型与可读标签。选中时突出当前输入关系，默认降低无关线的权重，不能藏掉当前重要引用。
- 撤销仅作用于当前焦点域：文字编辑／画布修改各自处理；不撤销模型消费或正式采用。Delete 在输入内删字。
- 初次进入、切模式、开侧区和点媒体均不自动 fit。明确定位可以平移／适当缩放，且其按钮名称说明定位目标。

### 尺寸策略

| 可用宽度 | 行为 |
| --- | --- |
| 大桌面 ≥1440px | 局部输入可与一根辅助区并用，仍遵守目标可见和避让约束 |
| 普通桌面 1100–1439px | 一根 360px 辅助区按需覆盖；局部输入放不下时显式专注，不缩字号挤满 |
| 小桌面 760–1099px | 优先画布浏览和单个操作空间；复杂输入进入专注视图，避免同时展示长输入与助手 |
| <760px | 保留现有节点列表定位承诺；直接进入对象详情／编辑页，隐藏无效的空间缩放工具，不把桌面画布缩成手机后台表单 |

阈值按实际可用安全空间判断；不是仅靠 CSS 宽度保证局部浮层一定能摆下。既有极端坐标、缩放范围、节点容量和离屏媒体释放继续保持。

### 视觉语言

沿用已确认的中性明暗、媒体优先、轻包装。媒体原比例 `contain`，不染色、不裁切来做选择效果。选中靠细外框、工具和文字状态；生成／失败辅以图标和标签。必要动作和编辑文字保持可读，不把“高级”做成小号低对比灰字。

全局轨道和工具紧凑；画面周围有呼吸空间；内容节点、短工具、编辑浮层采用不同层级，避免所有东西都套一样的卡片。建议节点边缘约 6px、工具约 8px、编辑浮层约 12px，最终复用主题 token，不逐组件硬编码另一套色板。阴影只用于浮层高度，避免当前大面板的广泛浓阴影。

节点选择立即反馈；只有主动定位可用短过渡，尊重 reduced motion。取消选择不以动画改变媒体尺寸。明暗模式保持相同布局。

## 9. 为什么选择这条结构

| 选项 | 适合什么 | 结论 |
| --- | --- | --- |
| 继续压缩当前底部公共面板 | 分镜中的单镜头、固定输入位置 | 放弃作为自由画布默认。仍改变高度，且无法消除跨对象目标混合 |
| 所有编辑放一根稳定侧栏 | 长表单、复杂参数、固定检查目标 | 作为长任务可用；全量默认会与助手争位置，持续损失横向比较空间 |
| 节点就近短编辑＋显式专注视图 | 多材料探索、快速试作，必要时认真检查 | **推荐。** 需要更多避让和焦点设计，但能同时守住空间浏览与完整编辑 |

独立反向评审指出的风险已纳入：局部输入会挡参考；缩小全览不能让字体一起缩；离屏工具不能误指邻近对象；输入时不能翻边；选中不能改执行目标；专注编辑不能复制会话。不能只把底部原表单整体搬到节点旁就宣称完成。

## 10. 实施切片与验证

先冻结 `selectedIds`、`editingTarget`、`inspectedAttempt`、`auxiliaryView` 四种界面状态的关系，以及同一草稿的耐久交接。切片 1／2／3a 复用现有固定来源和任务协议；切片 3b 单独扩展画布助手来源／应用契约，不能混成纯布局改动。现有 `CanvasBoard` 管浏览交互，生成 controller 管原会话，场次接入管镜头关系。普通布局调整不新增后端状态机。

| 切片 | 具体交付 | 进入下一步的条件 |
| --- | --- | --- |
| 1. 空间与动作 | 移除常驻底部区；稳定 canvas 容器；按对象类型分流动作；场次栏与工具重组 | 单击浏览不改容器和 transform；草稿不提供不合法参考入口；旧操作可达 |
| 2. 局部编辑 | 一份 composer、参考管理、参数、固定确认、避让与专注返回 | 输入和切换不丢稿；不同选中／编辑／确认目标不混淆；长中文与边缘状态可操作 |
| 3a. 结果与现有助手 | 单辅助区、现有镜头／场次助手、任务摘要、缩略历史、结果取回与镜头交接 | 原任务可找回；结果身份和采用不混；无配置模型状态真实 |
| 3b. 画布助手接入 | 新的节点固定上下文、零镜头场景、建议差异与精确草稿应用契约，再接对应 UI | 服务端归属／权限、固定快照、过期应用与耐久恢复通过；不靠伪造镜头兼容旧接口 |
| 4. 联合验收 | 隔离真实 API 的完整链路、错误恢复、响应式和人工视觉检查 | 下表通过，才更改“已落地”状态；真实模型质量另需真实服务条件 |

### 必须补充的体验验收，不能只截图通过

| 场景 | 可验证条件 |
| --- | --- |
| 连续选择三个媒体节点 | 画布容器尺寸、transform、节点坐标不变；不弹输入；只显对应短工具 |
| 从两份参考新建视频草稿 | 原来源保留，局部输入就近可读；生成调用为 0，直到明确执行 |
| 打开草稿 A，浏览 B，再编辑 B | A 输入先耐久交接；B 身份明确；未知任务仍可从 A 原身份找回 |
| 长中文、中文组合、20 个参考 | 标题与主动作可见；正文独立滚动；完整来源可查；输入时不翻边、不抢删除／撤销 |
| 总览缩放、节点在边缘／离屏、开助手 | 输入不随世界缩小；不自动 fit；有名的定位或专注入口；当前主体不被硬盖 |
| 执行中关闭、刷新、切场次 | 不重复提交；状态属于原计划；取消未知与终态按真实证据显示 |
| 原草稿已删除，查历史取回成果 | 找回同一媒体；不重跑模型；不自动新增候选或采用 |
| 结果送入 SH-04 候选，切分镜再回来 | 目标与视频区间明确；原采用保持，直到用户明确采用；返回布局保留 |
| 保存 412、本机写失败、权限撤回 | 输入按原协议保护；错误动作可见；无“已保存”误报、无越权显示 |
| 纯画布内容交给助手，再应用到指定草稿 | 零镜头来源合法且固定；不猜最新内容；过期草稿先看差异；跨项目来源／撤权拒绝；关闭和刷新后原建议仍可找回 |
| 1440×900／1366×768／1280×720，浅深色；390 列表 | 真实媒体和主操作可见、可点；无无意义大空表单；窄屏不叠多份面板 |

第一轮同时找 3–5 位实际创作者执行“从两份材料试作、比较 A/B、恢复中断、用于指定镜头”四项任务，记录第一次错误动作、目标判断和是否需要解释。目标是无需讲解即可说清“正在看谁、改谁、用什么、结果到哪”。这些是待验证指标，不宣称本轮已经证明效率提高。

## 11. 本轮交付边界

研究底稿、此方案及[独立研究分支的可点击状态样例](https://github.com/exo-gravity/scenedesk/blob/134a8c1/docs/design/proposals/canvas-v0.5/index.html)用于检验信息组织和状态切换。样例使用已有演示静帧，仅模拟选择、编辑、助手、专注和结果状态；不接服务，不生成、不保存到真实项目，也不是新画布已经实现的证据。原型保留在研究分支，不直接合入业务页面。

LibTV 仍需补证：完整节点输入／参数布局、单击到编辑的手势、历史与结果选择、Agent 展开对视口的影响、边缘避让。获得可访问的官方教程或合法登录环境后应补看；本方案不把这些未知行为当复制依据，也不因此推迟已由自身问题和 TapNow 一手证据支持的结构判断。
