# 项目列表与创作台位置导航

状态：2026-09-25 已确认，按第二版轻量导航实施。基于 `ddab43d`，本决定更新创作区左上角的项目入口与项目列表；其他创作区导航职责不变。验证记录见[实施进度](../implementation/22-implementation-progress.md)。

## 1. 项目列表服务什么

帮助创作者辨认作品、进入创作台和找到项目设置。保持现有工作室导航与创作台内的「剧本／创作台／镜头整理」视图，不新增首页仪表盘。

改动前，`Projects.tsx` 每个项目查询一份可用图片作为预览，不是指定封面。340 × 300 的容器中，媒体组件自己的 contain 样式让竖版素材出现大片侧边留白；封面的视觉尺寸随原图比例变化。名称下面只有分辨率与帧率，缺少明确入口，全部项目还混有归档项目。

## 2. 版式与内容

- 顶部保留「项目」和右侧「新建项目」，删除口号副标题。没有新建权限时不留占位按钮。
- 次行放「进行中／已归档」与各自真实数量，右侧放搜索；默认进行中。空归档与无搜索结果分别说明，并保留清空搜索动作。
- 正文使用统一 3:4 海报框。桌面卡宽约 216–248px，列间距 24px，行间距 32px；1440px 屏幕配现有左栏通常为四列，1024px 为三列，窄屏按实际可用宽度变两列或一列。宽屏不把三张卡拉伸到铺满整行。
- 卡片仅封面有 8px 圆角和细边界，信息区不再加一层白盒或重投影。封面悬停轻微提亮边界，不位移、不自动播放。
- 封面下第一行：项目名（16px，中等字重，最多两行）与常显的「更多」。次行：`竖屏 · 9:16 · 24 fps`，12px 次级文字；精确像素进入项目设置。
- 封面与标题打开创作台；底部安静地显示「进入创作台 →」，归档项目为「查看项目 →」。更多菜单第一版只给已存在的「项目设置」入口，管理和归档继续在设置页处理。
- 不显示没有依据的完成率、待处理数量、协作头像、上次编辑者或「最近更新」。当前 Project.updatedAt 不能代表剧本、画布、镜头或生成内容的最后活动时间。
- 未来若增加继续工作信息，优先是当前用户实际记录的「上次打开的视图／画布」。明确标为个人打开记录，不伪装成团队活动；失败或目标无权访问时回到有效项目入口。

### 封面规则

第一版可以复用现有图片预览，以海报裁切统一构图，只影响入口缩略图，原图与素材详情仍完整显示。框的比例是项目识别设计，与交付画幅分开；宽幅项目也不把一行卡片撑成不同高度。裁切中主体不合适时，应进入后续可指定封面方案，不按新生成结果不断换成「最新版」。

「指定项目封面」更合理，但当前 Project 契约没有封面引用。若实施此能力，需独立确认固定媒体引用、权限、归档后的读取、主体位置及 schema／契约变更，不能把 localStorage 中的任意图片当作团队封面。第一版不把自动选出的首张图片称为人工封面。

无图片时，海报框显示项目名与小号「暂无预览」，使用中性底色和简洁的排版，不用一大块图标暗示故障，也不编造风格图。无图片不代表无剧本或无制作成果；封面查询失败单独显示「预览暂不可用」，整卡依然可以打开。

加载时用同尺寸骨架；列表或权限读取失败时不展示旧缓存名称和媒体，呈现重试／返回入口。

## 3. 左上角组件的职责

它是位置导航，包含两个不同范围的选择器，另加一个返回入口。

`四格图标 │ 旧钥匙 ▾   项目画布 ▾`

| 部位 | 原实现 | 确认后的职责 |
|---|---|---|
| 四格图标 | 原为 SceneDesk 项目菜单 | 直接返回当前工作室项目列表；提示「所有项目」，可访问名称「返回项目列表」 |
| 项目名 | 纯文本 | 成为项目选择器；切换项目和项目设置放这里 |
| 项目画布／场次名 | 独立画布菜单 | 保留职责；选项目画布或按集分组的场次画布，底部新增场次与场次目录 |
| 中间视图切换 | 剧本／创作台／镜头整理 | 保持；不再塞进上述菜单 |
| 右侧账号 | 账户、主题、退出 | 保持；不把项目管理塞到账号下 |

整体去掉外层胶囊边框。只有返回图标后保留一条细分隔线；项目名是主层级，画布名用次级颜色。各个可点击片段独立呈现 hover／focus，保留焦点框。创作区不常显品牌文字或「所有项目」返回文案；项目列表的品牌与工作室入口保留。

### 项目选择器

272px 宽，直接展开项目列表，去掉二级悬停菜单。可切换项目超过 6 个时出现搜索；少量项目直接点选。当前项目带勾选与名称，其他进行中项目按名称、编号稳定排序。同名项目补充项目编号；读取失败不显示旧缓存条目。每行左侧用中性的首字标记，不请求额外媒体。

底部单独一组「项目设置」「所有项目」。「项目设置」替代冗长的「项目设置、成员与归档」，因为当前实际只跳到项目设置页面，并没有三个独立快捷动作。需要成员功能时再按现有真实路由与权限呈现，不能承诺菜单里没有的能力。

只有一个项目时仍可打开，显示当前项目与两个底部入口。没有匹配项目则显示无结果与清空搜索；查询中用骨架，查询失败就地重试。点击当前项目只关闭菜单，不刷新工作区。归档项目仍能表达当前上下文，标注「已归档 · 只读」，其他归档项目从列表页进入。

### 画布选择器

顶部搜索项目／场次画布；项目画布固定第一项，与后面的按集分组场次分开。当前项有勾选；场次名称保留完整内容，集名保留在分组标题。没有场次时显示轻量空态，底部「新增场次」「场次目录」保持可发现。只在创作台视图显示，剧本和镜头整理保留各自现有范围选择。

切换项目／画布必须走既有草稿、上传、助手及保存恢复屏障；菜单不直接绕过。未保存、请求处理中和恢复失败时沿用真实状态，不能提前显示「已保存」。刷新、浏览器返回与旧深链继续保留具体项目／画布身份；不得把最近访问偏好覆盖深链。

### 键盘与窄屏

用 Mantine 的焦点与弹层能力；打开后可搜索，方向键浏览，Enter 选中，Escape 关闭并回到触发器。点击外部关闭，不依赖鼠标悬停才能进入子菜单。

返回图标在所有尺寸保持一致。窄屏优先保留项目名及当前位置，超长名称省略但菜单保留全名。弹层宽度不超出视口，不与右侧保存／任务／账号重叠。项目与画布触发器、项目菜单的触摸操作保持至少 44px 高度。焦点框与选中标记分开。

## 4. 第一版范围与验收

第一版只改项目列表的布局、状态过滤、现有字段呈现，以及项目菜单触发器与平铺列表。保持现有路由、权限、画布切换和生成行为；不新增依赖、不改数据库或公开契约。封面指定、团队活动聚合与项目成员管理扩展单独定范围。

验收覆盖：有图／无图／预览失败／长名称；零个、一个、多个项目；搜索与归档；项目列表打开创作台；项目切换、画布切换、设置与返回；只读和撤权；草稿保留、键盘焦点、窄屏与深色。通过生产构建的实际页面截图确认比例，不把本提案示意当成生产验收。

## 5. 独立修正：全局模型提示

`/health/live` 当前仍返回历史 `providerMode: mock`，它并不反映租户能力记录和独立真实供应商执行器。BusinessApp 不再据此显示全局「未连接真实模型」，覆盖登录、工作室、Studio 和账户菜单。本地测试身份仍根据 identityMode 显示；助手中明确的 test_fixture 能力改写为「本地测试模型」，原有测试产物标识保留。不把旧提示替换成同样缺乏全局依据的「已连接」。

本次未更改健康接口契约或执行门禁，也未执行付费调用。真实模型逐项验收事实仍以[86](../implementation/86-verified-provider-runtime.md)为准。
