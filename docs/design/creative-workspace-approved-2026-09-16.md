## 产品与主路径

SceneDesk 是独立 Web 的短剧视觉创作工作台。主要路径为：外部剧本初稿 → 导入并阅读 → 引用内容和参考进入画布 → 生成、比较和继续修改 → 整理为镜头并明确选用 → 下载／导出给外部后期。也允许不导入剧本直接开始创作。

- 项目内左侧可折叠导航按「剧本、画布、项目资产」排列；顶部仅表达当前工作区与相关操作。画布为主要创作区。
- 剧本首先承载本地文件与飞书文档的导入和阅读。先支持 `.docx`，其他格式按实际样本增加；不以“支持 Office”承诺任意格式。正文编辑尚无独立确认需求，本次默认不新增富文本编辑器；原有编辑与版本历史在替换期间保留。
- 一次导入建立固定版本。记录来源、时间、原件与可阅读内容；外部更新由用户明确重新导入。项目权限控制共享阅读，飞书链接不能代替实际正文读取授权。
- 从剧本引用到画布保持确切版本和原文范围；导入新版本不静默改变已有生成依据。
- 项目可以拥有不关联场次的画布。生成不要求先建立集场镜；整理为镜头时沿用既有场次归属，不在本轮全面迁移 Shot 的父级。
- 草稿、参考、任务进度与历次结果在同一创作区域呈现。默认一个明确的生成动作，内部固定输入并创建持久作业；新结果可见与正式采用独立。
- 镜头列表与专注预览保留顺序、播放、比较和采用。具备这些能力后再移除完整分镜台的重复创作入口。
- 助手保持现有对话界面，与直接操作指向同一草稿和业务命令；不建设第二套创作状态。
- 复用统一资产库、真实媒体归档、下载和既有历史；交付不依赖剪辑或渲染。

## 实施与兼容

保留 React / React Flow、Mantine、Phosphor、Fastify、PostgreSQL、私有存储和 Worker。复用当前主题，不重做品牌系统。不新增万能工作流或统一“创作单元”聚合根；通过小接口集中提交、恢复和读取组合，逐步替换暴露过多内部阶段的调用方式。

必须保留项目授权、不可变修订、CAS、幂等、提交前持久 Attempt、未知提交核对、独立归档重试、草稿保留与明确采用。图片输出不能直接冒充视频 Take；旧媒体、任务、镜头和画布身份不变。

本方向覆盖 2026-09-14 的双完整工作区安排、2026-09-15 的「剧本／场次／资产」主导航顺序；既有可靠性规则继续有效。分批交付期间旧场次工作区仍可使用，新的替代路径完成并验收后才切换；旧链接保留定位能力。

原型源留在 `feat/core-flow-prototype-20260916`，参考提交 `8d4fdac`。原型内存状态、固定样例、虚拟生成与单一示例项目不移植为生产事实。

## 首版验收与后置

用实际剧本与一组镜头分别验证导入阅读、反复图片／视频生成、比较采用与导出，以及刷新、断网、丢回包和归档失败恢复。接口/模拟通过与真实文档、真实模型、实际团队试用分开记录。不得在服务、凭据和消费授权不具备时执行付费模型调用。

后置完整正文创作、多人文档编辑、飞书双向同步、自动完整分镜编排、全图执行、通用工作流、全模型覆盖、公共 API 产品、商业运营、完整团队管理及成片剪辑渲染。
