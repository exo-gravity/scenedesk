# LibTV 画布：一手证据与 SceneDesk 设计依据

研究日期：2026-09-14。范围仅为公开可访问的 LibTV 官方资料；没有登录、创建画布、调用生成、安装插件或修改产品。本文不把第三方教程、同名克隆或网页脚本中的组件名称当作已验证的交互。

## 结论与证据强度

可以确认的设计方向是：LibTV 将画布、媒体节点、显式引用关系和 Agent 工作接到同一作品上下文；官方操作文档要求保存准确项目、节点、引用顺序与任务身份，再核对实际产物。它值得借鉴的部分是**让创作材料、生成输入和结果关系留在同一个可见工作面**。不能根据目前取得的材料断言它的选中浮层、输入框布局、多选快捷键或历史界面已经如何实现。

本文区分三类证据：

- **页面事实**：公开网页实际返回的文字、链接及图片地址；未观看图片时只证明资源存在。
- **官方操作规范**：官网直链的官方技能分发仓库；证明作者规定的工作方式，不等于线上所有接口和 UI 的实测结果。
- **待观察**：找到原始入口但未取得可观察的内容；保留 Unknown，不用镜像或克隆填空。

当前公开访问限制：研究工具访问 B 站正文返回 412；飞书指南无法正常抓取。主任务实际打开官方 share 路由后出现“登录失败，请重新登录”，没有进入画布。因此下面没有声称完成登录内交互实测。

## 对 SceneDesk 方案的具体启示（研究判断，非 LibTV 产品事实）

1. **把节点当作创作对象。** 默认显示画面或文本摘要，保留状态和明确来源；选中时就近呈现主要输入与动作。模型和输出参数可渐进展开，但已有值、错误和未决任务不能随面板收起消失。需要通过 SceneDesk 原型验证位置，而不能声称复制了尚未看清的 LibTV 浮层。
2. **让输入关系可读。** 显示上游参考缩略图、用途、顺序和固定版本；连线帮助理解依赖，运行前的固定输入仍以准确对象集合为准。移动节点不能改变输入或镜头顺序。
3. **让 Agent 和手工编辑共用同一上下文。** 选中节点可以形成明确的助手上下文，但不能自动读取未选内容；助手返回内容和媒体结果回到原计划／任务／产物链，并由用户决定放入画布或采纳。
4. **分开叙事结构与空间。** 场次、镜头和确定的镜头来源保留显式顺序；自由布局用于探索与比较。无需为学习另一产品恢复剪辑时间线或后期渲染范围。
5. **把结果管理放到创作现场。** 在节点附近给出生成中、未决、失败及可取回结果；比较多次输出时保持原输入与历史版本。新结果不会自动替换来源节点或成为已采纳 Take。

上述建议与现有固定计划、耐久任务、独立媒体和人工采纳规则相容。真正需要下一轮设计决策的是节点内容、就近编辑、选择上下文和结果分支的空间安排；没有证据支持为了接近 LibTV 而重建底层业务模型。
