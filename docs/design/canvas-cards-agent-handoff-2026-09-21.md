## 3. 调研最重要的结论

**SceneDesk 已有相当多生成和恢复能力，主要差距在默认卡片呈现、编辑器尺度、参考操作和结果迭代路径。** 不应把本次重设计做成重新实现生成系统，也不能降格为简单白板。

| 观察点 | LibTV／即梦现场 | SceneDesk 审计基线 | 应解决的问题 |
|---|---|---|---|
| 默认卡片 | 图片／视频或对应占位是主体，标题与操作围绕内容出现 | 已有媒体节点已经以媒体为主；生成草稿默认主要显示提示摘要 | 优先修改生成草稿，让作品在收起态也可辨认 |
| 输入区 | 独立面板出现在卡片附近，在较低画布缩放下仍可读 | 就地编辑随画布缩放，低缩放依赖定位或专注模式；进入编辑会扩宽／撑高卡片 | 卡片几何稳定，输入区采用屏幕尺度 |
| 模型和参数 | 底部紧凑一行；模型与规格分别展开浮层 | 模型下拉和规格浮层已存在，但仍有明显表单感 | 重做控件呈现与布局，复用真实能力和校验 |
| 参考与派生 | 两家均实际验证过图片右侧＋新建视频、建立引用与连线，不直接生成 | 已有「继续创作」及有序引用，端口与操作入口分散 | 统一来源旁的继续入口和输入区参考呈现 |
| 结果迭代 | 已有结果可在卡片附近预览、回看输入或进入后续工具 | 成功结果主要在编辑态预览；历史、比较、放置分布在不同入口 | 结果持续可见，历史和比较按需打开 |
| 边缘体验 | 实际观察过 LibTV 工具条越界，以及即梦长输入和助手遮挡 | 当前有定位条、专注编辑等兜底 | 学习结构，同时实测避让，不能默认竞品细节都正确 |

另外四点值得保留：

1. **即梦存在两套画布**：`/ai-tool/ai-canvas` 是节点工作区，`/ai-tool/canvas` 是另一套 Agent 中心工作区，不能混成一个产品能力清单。
2. LibTV 脚本有独立的分镜、资产、提示词工作面；即梦有主体、时间线、导演台等专用对象。它们证明复杂对象可以有专用编辑面，不代表 SceneDesk 本轮要新增这些功能。
3. LibTV 助手可浮动或停靠，并非永远固定宽度抽屉。SceneDesk 本轮沿用现有助手位置，仅处理与输入区的空间关系。
4. 结果自动展示与镜头正式选用是两个独立事实。可以改善作品可见性，同时保留明确选用。

### 证据边界

- 两家都使用真实登录页面，分别创建了独立研究项目，操作空节点、手写示例、编辑器和图片到视频的派生；没有上传项目素材、发送 Agent 对话、运行生成或付费后处理。
- 多选建组、竞品多结果历史、实际生成后的落点规律、多人协作、断网恢复和真实 AI 效果没有完整验证。
- 本轮亲见的即梦失败是媒体播放失败，不能泛化成生成失败。
- SceneDesk 审计中「已实现／有测试」是代码事实，不表示本轮已经重新运行这些业务验收。

### 不要再沿用的旧判断

SceneDesk 并非只有场次画布；也不缺模型参数、前置校验、批量计划、重命名、撤销或比较。它们已经有实现。LibTV 快捷键文字提取遗漏了 macOS 的 ⌘ 图标，旧报告里的单键 G／L／Enter／Z 判断已纠正。看到菜单、类名或连接状态不等于对应操作已完整验收。

## 4. 后续设计方向

用户明确要求模型与参数对标竞品；方案选择 **LibTV 为主要控件参照**。下面是本轮形成的实施提案，具体细节以完整修改计划为准，不把每个建议描述成用户逐项批准。

1. **卡片保持稳定。** 默认展示标题、内容与必要状态；打开编辑不拉宽、拉长卡片，不推动邻居。图片／视频、声音、文字和固定摘录保持各自类型特征。
2. **选中与编辑分开。** 单击只选中并显示简短操作；明确编辑后展开输入；新建草稿直接进入编辑。已有媒体双击仍是预览。
3. **独立输入区。** 卡片附近显示一个输入面板，字号不随画布 zoom 缩小；全画布同时一个；靠边避让、长内容限高、助手开合后仍可操作。
4. **LibTV 式生成控件。** 参考在上，提示词直接输入，底部一行模型、适用模式、合并规格和提交。去掉重复标题、内层文本框、大块下拉框和全宽生成按钮。
5. **参考换入口，能力保留。** 去掉「参考材料」折叠栏；缩略图／图标直接呈现引用，点开调整用途、启停和移除；失效和未就绪仍清楚显示。
6. **节点属性回到对象操作。** 标题改名、拖拽位置、调整宽度、更多菜单的精确位置／尺寸、选择工具条的分组。替代入口齐备后删除原折叠栏。
7. **继续创作贴近来源。** 可用文字／媒体旁的＋与现有继续创作共用同一命令；新建独立草稿并建立引用，不直接运行生成。
8. **结果留在原处。** 有有效成功结果时，收起草稿也可见；重新生成或失败时保留上次可用画面；记录和比较按需展开，不自动采用。
9. **保持空间和输入连续。** 生成完成不抢焦点、不自动移动画布；关闭、切换、刷新和错误时保留草稿；菜单、键盘、中文输入法与画布手势分别处理。

### 效果图必须按真实能力修正的地方

| 图中细节 | 正式实现要求 |
|---|---|
| Seedance、全能参考、4K、耗时等样例 | 只展示实际接入、已核验能力；官方模型名称不随意改写，不硬编码图中列表或时长估算 |
| 1个／2个／4个 | 当前 OutputOptions 无单次输出数量字段；现有多节点批量不是这项功能。数量扩展单独设计契约、费用、作业、部分失败和幂等 |
| 空视频草稿右侧＋ | 隐藏。当前仅允许文字／媒体作为来源，不能因为效果图有按钮就允许草稿互连 |
| 成功草稿直接继续生成下一张 | 首轮沿用明确添加为媒体后再继续创作。更短的直接派生路径需独立处理来源固定、写入原子性与幂等 |
| 深浅、尺寸和真实内容 | 图仅表达结构；使用实际数据、既有主题和不同视口实测，不把示例媒体作为产品结果 |

## 5. 推荐实施节奏：两轮、五个切片

完整范围属于中等偏大的前端改造。最新建议先完成效果图对应的操作，再做结果常显；这是一种实施拆分建议，不表示后半部分已取消。

| 轮次／切片 | 工作内容 | 主要完成标准 |
|---|---|---|
| 第一轮 · 1 | 稳定卡片、独立编辑器、屏幕尺度与避让 | 编辑前后节点几何稳定；50%／100% 下能正常输入；关闭和切换不丢草稿 |
| 第一轮 · 2 | LibTV 式模型列表、规格浮层、紧凑底行，覆盖图片／视频／声音 | 模型参数来自真实能力；摘要与值一致；原提交和锁定规则有效 |
| 第一轮 · 3 | 参考缩略图、节点属性迁移、＋继续创作 | 两个旧折叠栏移除后无功能丢失；引用、尺寸和分组能保存、撤销与恢复 |
| 第二轮 · 4 | 收起态结果、历史／比较入口、任务状态、预览读取调度 | 旧结果和新尝试区分清楚；未知提交不重复生成；不展示未授权预览 |
| 第二轮 · 5 | 整页性能、可访问性、主题和窗口回归、证据与清理 | 生产构建走查及相关回归通过，剩余未验能力明确记录 |

每个切片都要完成本次涉及的保存、失败恢复和页面验证；第一轮本身也要生产页面验收，不能等切片 5 才首次检查界面。多个切片涉及相同主文件，优先按依赖推进，不能未经协调让多个实现同时改同一区域。

单次多结果数量、新模型／新模式、@ 解析扩展、富文本全面升级、小地图、自动排列、吸附、可视组框、复制继承所有连线、图执行、时间线、3D、多人共编不混进第一轮界面修改。

## 7. 必须保留的业务行为

- 输入在关闭、切换、冲突、失败和刷新后可恢复；完成保留前不能假报已保存。
- 固定引用不静默更新；历史输入不覆盖正在编辑的草稿。
- 供应商请求沿用持久尝试与幂等；未知提交核对原请求，归档失败只恢复归档。
- 服务端权限继续覆盖读取、重试与缓存幂等响应；撤权／切项目／切会话不残留可见预览。
- 预览可见、创建素材节点、关联镜头、正式选用和交付分别成立，不能自动合并。
- 保留已有多选、批量计划、媒体预览、助手上下文、撤销和分组路径；重设计不能让 AI 画布退化为白板。
