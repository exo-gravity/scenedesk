# 核心工作区：三方评审后的最终推荐 v0.2

设计推导留档（2026-09-10 整理）。本文的核心推荐已落实到[当前核心体验 v0.3](scene-walkthrough-review-v0.3.md)并获用户确认，不再处于“页面尚未修改／等待选择”状态。保留三方取舍与备选比较；当前页面行为与确认边界以 v0.3 和[确认记录](approved-baseline-2026-09-10.md)为准，四项[专项 v0.4](production-detail-design-v0.4.md)暂时收口，正式业务工程仍暂停。

## 1. 最终判断

我推荐：**以当前创作对象为中心，场次提供分镜／自由画布两种模式；直接输入在中央稳定呈现，助手非模态停靠，参考按需选择并可固定查看。**

默认让画面和直接创作占据工作区。分镜用当前镜头主预览＋底部分镜条，自由画布保留多个镜头、独立素材与探索分支。助手默认收起；展开后可以继续看图、选对象和修改输入。完整素材浏览只在持续搜索时展开，已选的关键参考可以留在中央，不要求整个素材目录一直可见。

这是我在当前产品目标、桌面空间与 MVP 约束下认为最合适的方案。它解决的是连续判断、目标明确和草稿保持；尚无真人用户测试，不能宣称所有团队都最适合它。精确尺寸需要下一版原型验证，但没有必要因此推迟对默认结构和行为边界的决定。

## 2. 三方评审怎样改变了我的判断

本轮由三位独立 AI 评审代理分别模拟专业创作工具设计师、信息架构设计师、桌面视觉与交互设计师。先各自形成判断，再阅读我上一轮提案，最后由我综合。原始评审完整保留在[评审入口](../reviews/2026-09-10-workspace/README.md)，不把 AI 评审写成真人专家访谈。

| 视角 | 最有价值的发现 | 我的裁决 |
|---|---|---|
| 连续创作与影视制作 | 候选小图无法支撑手部／道具判断；返工入口直接覆盖提示词；第三项钥匙参考没有进入当前画布示意；已选参考应能固定看 | 先保证候选大预览与不破坏输入的返工；增加固定参考；取回旧意见到新版本的关联 |
| 信息架构与认知负担 | 当前镜头被用作制作、审阅、资产添加和助手目标；审阅文字与送审说明未按对象隔离；非模态开放后会暴露目标漂移 | 明确浏览与修改的边界，按对象保留草稿和返回位置；目标固定与面板改造一起设计 |
| 视觉与交互系统 | 共同语言部分成立，但横向窄栏与纵向输入都缺空间预算；候选判断面积不足；还缺完整焦点和无选择规则 | 恢复聚焦分镜；中央输入限高；面板按实际可用空间展开；补键盘、视野、空态契约 |

我明确修改了前一轮的两项判断：

- **不再把完整“左资产＋右助手”作为所有桌面宽度的默认。** 1366 宽度优先保留助手、实际输入和固定参考。完整目录与助手同时可见不是创作连续性的必要条件。
- **右侧“详情／助手”互切可以长期成立。** 前提是正在修改的提示词与必要参考留在中央；需要互切的是完整详情，不是实际创作输入。把它一概视为过渡方案过于绝对。

对视觉评审提出的 1366 双栏试验，我保留为对照状态，不作为默认：更小的完整画幅可能适合整理，却不一定适合判断写实人物的动作接触。这里优先采用创作任务的约束，而不是按评审人数折中。

## 3. 判断“更好”的顺序

1. **先能判断作品。** 当前候选、关键参考和前后关系需要看得清；缩略图只承担找候选。
2. **明确作用目标并保留已有工作。** 看 SH-05、讨论 SH-04、编辑 SH-04 是可以同时存在的行为，不能互相误改。
3. **连续动作少被打断。** 查看建议、改一句提示、核对参考应在同一工作片段完成。
4. **空间和位置可预测。** 工具开关不突然缩放全场，不让长输入挤掉媒体，也不要求用户管理多个漂浮窗口。
5. **首期能收口，后续能复用。** 维持有限 AI、场次双模式及已有生成／采用／剪辑／审阅事实；未来广告可以复用通用画布和创作工具。

不以“一屏显示多少功能”“少几次点击”单独判断最优；采用与用于剪辑之类独立决定仍需明确操作。本轮没有用缺乏依据的分数、权重或效率百分比包装判断。

## 4. 共同视觉语言：保留方向，纠正任务中的偏差

| 已确认原则 | 当前审计结论 | 推荐设计的落实方式 |
|---|---|---|
| 媒体优先、轻包装 | 部分符合；完整画幅正确，候选过小，辅助工具遮住工作内容 | 当前候选进入主区；参考可固定；助手不遮罩；选择不加媒体滤镜 |
| 全局紧凑、局部舒展 | 部分符合；项目目录收起有效，顶部三行与窄编辑栏不匹配 | 产品顶部压为两行；当前对象输入展开，其他对象保持摘要；网格仅总览 |
| 工具就近展开 | 部分符合；按需入口已有，但当前操作被辅助抽屉阻断 | 节点附近短工具，中央稳定长输入；辅助工具与直接编辑并用 |
| 形状表达层次 | 基本语言已出现，部分停靠区像漂浮卡片 | 停靠面板用表面与细边界；短选择器适度抬升；避免整栏再套有阴影的大卡片 |
| 中性底色、克制用色 | 基本符合，实际对比度未完整验收 | 延续灰阶、排版与状态文字；保留独立焦点；主题与品牌色另行评审 |

专业感来自稳定的空间关系、恰当的判断面积、清楚的对象身份和一致的细节。当前不重新选择视觉风格，也不把默认明暗与品牌色偷偷定下来。

采用、剪辑使用等状态一致时可压缩成简短摘要；出现差异时展开说明，例如“正在看 C；采用 A；剪辑用 A”。必要失败、冲突、来源过期和返工信息持续留在对象附近，不只依赖短暂提示。

## 5. 全局导航与场次顶部

保留工作室 → 项目 → 场次的组织层级，集作为项目下定位场次的上下文。工作室以项目为默认入口；“我的工作”处理人的负责事项与意见，生成作业处理模型任务。项目默认显示按集组织的场次；进入场次收起项目目录，保留清楚的返回与场次切换。

资产名称保持范围一致：完整入口用“工作室资产／项目资产”；全局窄栏可简写“资产”，工具提示与页面标题明确“工作室资产”，不再混用“共享资产”表示另一个范围。制作中的“参考”是就地使用入口，不是第三个资产管理层。

产品顶部建议两行，约 100px 为原型起点：

- 第一行：项目／集／场次与返回；右侧审阅稿版本入口、生成作业、成员。
- 第二行：左侧“镜头制作／剪辑”；制作时同一行的工具区域提供“视图：分镜／自由画布”，以及参考与助手入口。用分组和标签体现从属，不把四项画成同级页签。

当前原型额外的设计预览横条单独计算，不把它误当正式产品导航冗余。

审阅仍是固定版本入口；可展开版本列表，分别显示版本与状态。最新 v2、已确认 v1、整集当前使用 v1可以同时成立。进入旧稿后突出“固定审阅稿 vN”，分别提供返回刚才制作、返回当前剪辑的明确路径。无效版本不静默跳到最新稿。

## 6. 核心页面的最终布局

### 分镜模式

已有镜头时，默认恢复当前镜头；没有最近位置则定位第一个可用镜头。没有镜头时显示建立分镜的引导，不伪造选中对象。

~~~text
场次身份、固定稿入口、生成作业
镜头制作／剪辑                  视图：分镜／自由画布   参考   助手
┌──────────────────────────────────────┬─────────────────┐
│ SH-04 · 当前候选 C   候选切换／比较    │ 创作助手        │
│                                      │ 当前辅助动作    │
│       当前候选大预览   固定钥匙参考    │ 明确来源与目标  │
│                                      │ 建议／修改依据  │
├──────────────────────────────────────┤                 │
│ SH-04 的创作输入 · 参考 · 模型／计划  │                 │
├──────────────────────────────────────┤                 │
│ 01   02   03   [04]   05   06   全场 │                 │
└──────────────────────────────────────┴─────────────────┘
全局窄导航始终在左侧；此图省略。助手关闭后中央扩展。
~~~

底部分镜条负责顺序、定位和必要状态；它不是制作页里的完整剪辑时间线。全场总览以有序网格呈现缺口与全局状态，选镜头返回主预览；不要求六镜头在精修时一直占据同等面积。

候选切换作用于主预览。图片可并排；视频首期切换播放，分别保留身份与暂停点，不顺势增加多视频同步播放。需要判断接触细节时主动放大；完整画幅可随时恢复。比较状态可暂时把输入收为目标＋草稿摘要，返回后恢复文字、光标和位置。

固定参考占中央预览的明确位置，不浮在作品上。首期保证一张关键参考持续查看；其他参考仍可切换和展开。固定查看不等于加入模型输入或助手引用。

### 自由画布模式

~~~text
同一场次身份与工具行                         视图：自由画布
┌──────────────────────────────────────┬─────────────────┐
│  角色参考       未归镜头的探索素材    │ 创作助手        │
│        ↘                             │ 当前动作的目标  │
│       草稿 → 结果 A     结果 B        │ 与明确引用      │
│                  已关联 SH-04        │                 │
│  场景参考       其他镜头／分组        │                 │
├──────────────────────────────────────┤                 │
│ 当前草稿的唯一创作输入 · 引用 · 计划 │                 │
└──────────────────────────────────────┴─────────────────┘
仅选择可编辑对象时出现输入；短工具靠近节点，底部输入预留空间。
~~~

画布操作整个场次空间，包含多个镜头、共同参考、未归镜头内容与候选分支。节点代表明确内容；选择变化不更换另一个节点的媒体、不移除第三项以后参考、不重建画布。空间位置和连线不表达播放顺序。

镜头候选与画布媒体节点的身份保持分离：浏览 B 不让 A 的节点变成 B；新结果保留独立来源，按既有“添加到画布”规则取回。媒体节点只查看和呈现短工具；选择可编辑草稿恢复其输入，明确“继续创作”才准备后续草稿。未绑定镜头合法，不自动归到上个镜头。

长提示词固定在中央底部，不跟随节点或鼠标漂移；开启时占用布局空间。若当前对象因可用区域收缩而不可见，最小平移保持目标；用户设置的缩放不自动改成“适应全场”。对象本来过大时提供主动定位／放大入口，不承诺同时显示全部大节点。

未选中时隐藏对象输入，只保留添加、选择、平移、缩放和可检索的内容入口。多选只显示移动、收纳、引用等共同操作，不出现多份提示词，也不引入一键付费批量执行。

### 三个辅助区域的职责

| 区域 | 默认状态 | 使用规则 |
|---|---|---|
| 中央直接输入 | 有明确创作目标时显示 | 唯一一份正在编辑的生成输入；简短要求、已用参考、模型与计划入口；完整要求可展开 |
| 右侧辅助区 | 收起 | 助手非模态停靠；完整镜头详情可在同一区域切换。提示词本体不随右侧页签消失 |
| 左侧参考浏览 | 收起 | 搜索大量素材时展开；已知参考用中央附近的快速选择；管理资产仍去完整页面 |

助手首期只承载“分镜建议、准备本次提示、按意见准备修改”三类已有辅助动作。场次制作里展示适用动作、来源与建议历史；分镜建议从相应剧本入口发起。辅助要求与实际生成提示分别命名，避免出现两个都叫“输入”的文本框。不因新的侧栏形态承诺通用自主 Agent。

## 7. 空间分配与响应规则

默认两侧辅助都收起。最常用的辅助状态是“主预览＋直接输入＋固定参考＋右侧助手”。完整资产浏览与助手并开是宽屏可选状态。

以下是**下一版原型的试验预算**，不是已验证的视觉尺寸标准。保留现有全局栏 76px；素材约 256px，助手约 360px；两条分隔各按 1px 估算。

| 窗口宽度 | 仅助手时中央宽度 | 完整素材＋助手时中央宽度 | 推荐行为 |
|---|---:|---:|---|
| 1366 | 929px | 672px | 默认最多展开一个完整辅助栏；关键参考可继续固定看，直接输入始终保留 |
| 1512 | 1075px | 818px | 可试验左右同时停靠，仍以当前预览与输入为主，网格不常驻 |

中央宽度包含内边距；实图还受画幅与高度限制。以中央约 760px 作为初始双栏门槛，后续用真实判断任务调整。评审中的 680px、706px 等更紧值只说明可能排得下，尚不能证明适合精修；我选择更保守的默认。

1366 下快速“加参考”不必收起助手。用户主动进入完整素材浏览时，可暂收起助手，保留全部内容，明确显示可恢复入口；返回讨论时恢复原会话。若窗口缩窄导致无法并排，优先保留正在输入的区域，收起另一辅助栏并说明原因；不能立刻关掉用户刚主动打开的工具。无论怎样变化，都不删除引用、清空草稿或修改场次数据。

中央输入默认约 208–224px，包含目标、参考摘要、可编辑正文和计划操作。长文在输入内部滚动，参考过多时可展开列表，不让整块无限长高。在正文高度足够的窗口试验上限 min(300px, 正文高度−480px)，同时核对扣除分镜条、候选控制后的**实际媒体高度**。不能将剩余区域高度全部宣称为实图高度。

低高度窗口使用紧凑输入与用户主动的“专注比较／展开编辑”状态；草稿保留。这里的上限公式不直接套用于所有小窗口。助手自己的要求输入只在助手栏内增长，建议约 96px、上限约 160px；只压缩建议历史，不影响中央媒体。

## 8. 行为规则比面板位置更关键

| 行为 | 明确规则 |
|---|---|
| 浏览候选 | 只改变正在看的候选，不改变采用或剪辑使用 |
| 浏览资产 | 只改变资产预览；“引用到 SH-04”才变更相应引用，固定查看不自动作为生成依据 |
| 查看助手建议 | 展示发起时的场次、镜头／节点、参考及来源版本；不默认读取整场或所有可见节点 |
| 切到另一镜头 | 保存原目标输入；新目标显示自己的草稿；旧建议仍归原目标 |
| 应用建议 | 按钮写清“应用到 SH-04”；显示改动或可选文本。若目标内容已改变，核对差异，不盲目整段覆盖 |
| 从旧稿返工 | 只定位并附带原意见、版本、时间点和来源候选；不自动改写提示词，不自动解决评论 |
| 切模式 | 同场共享草稿与制作事实；各自恢复视野／位置；不创建第二份场次数据 |
| 浏览旧审阅稿 | 保留独立播放位置与评论草稿，不覆盖当前制作焦点；返回恢复原位置 |
| 切场次 | 助手记录、未发送要求、提示词、审阅意见、送审说明各留在原对象；新场显示自己的内容 |
| 生成结果返回 | 固定在原目标，可从生成作业找回；不抢当前焦点、不自动采用、不改剪辑 |

添加参考的会话在打开时固定接收目标。若之后选择 SH-05，仍标“引用到 SH-04”，并提供明确的“改为 SH-05”；不把按钮里的“当前”解释成随时改变的指针。浏览媒体与向助手添加引用也不等于授权修改该媒体。

采用、剪辑实际使用与固定稿确认保留现有独立事实。返工回应以原意见链接、修改说明和新候选／新稿来源承接；首期不因此新增每镜头工单体系，也不凭生成成功自动判定问题解决。

键盘和焦点需遵循：面板没有背景焦点锁；关闭返回有效入口；切模式恢复合理位置；输入法组合态与输入框的空格、删除、撤销不操作画布；选中圈和焦点圈分开；未显示区域不可被 Tab 进入。视口外节点通过搜索／列表定位，不要求遍历数百节点。真实浏览器验证后才可宣称通过。

## 9. 用 SH-04 说明完整体验

1. 在固定 v1 的 00:24 查看“手与钥匙接触不自然”的意见，能看清 v1 实际用的 A。
2. 点“前往 SH-04 制作”：定位当前镜头，保留已编辑提示；旁边显示意见来自 v1/A。如果当前采用已是 C，明确呈现差异。
3. 从“加参考”找到旧铜钥匙的确切版本。固定看这张图，并明确是否用于本次生成。第三项参考同样可见，不受列表前两项限制。
4. 打开助手的“按意见准备修改”。发起前看见来源意见、目标 SH-04 与选定参考；任何收费文本辅助仍按已有费用／执行规则处理。
5. 建议与实际输入并排。用户接受有关“靠近、接触、收拢、拿离”的句子，手工调整节奏，不替换无关的人物与光线要求。
6. 查看生成计划里的实际输入、参考版本、模型能力与费用，明确执行。助手引用不会静默变成模型输入。
7. C 返回，主区查看 C 并切回 A；对照钥匙，检查首尾与前后镜头的关系。没有采用前，A 仍是当前采用和剪辑用片。
8. 明确采用 C，再明确用于剪辑。到剪辑检查连接、使用区间以及声音／字幕影响；画布位置不决定连接顺序。
9. 固定新的场次版本、附修改说明与原意见链接，再按既有提交／审阅操作交回复核。v1不变，主创另行确认新稿，整集另行选择要引用的版本。

关键收益是这条链路中的“看、改、对照、决定”有持续可用的位置；同时没有把草稿、候选、用片和批准混为一件事。

## 10. 为什么优于几个合理备选

| 方案 | 它的优势 | 这次不作为最终默认的原因 |
|---|---|---|
| 现有遮罩抽屉 | 实现简单，关闭时省空间 | 助手依赖的候选与输入在它打开时不可操作；去掉遮罩但保留遮挡／焦点锁仍不够 |
| 右侧整份制作输入／助手互切 | 改动少，省宽度 | 看建议和改实际提示仍要反复切换；本方案仅允许低频详情与助手互切 |
| 所有栏常驻 | 所有入口可見 | 1366 下当前媒体被压小；长期看参考不需要长期看完整目录 |
| 所有工具都贴着画布节点浮动 | 对象关联直观 | 长中文提示会遮图、随平移漂移，多对象时还要管理层级；本方案仅保留短小就地工具 |
| 全场网格始终为主 | 扫描与发现缺口方便 | 当前候选与动作细节需要聚焦；本方案保留网格作为可直接到达的总览 |
| 一种自由画布承载全部流程 | 表达自由，表面统一 | 已确定用户可选择有序分镜；团队用片和固定版本也不能由节点位置表示 |

这套推荐仍有代价：底部输入占用媒体高度；小屏完整素材浏览与助手可能需要切换；更多独立草稿要求更严谨的上下文设计。限高输入、固定关键参考、可恢复面板和明确目标分别应对这些代价。若后续验证发现底部输入显著损害真实素材判断，应保留右侧编辑布局作为对照，而不是为维护结论继续挤小作品。

## 11. 与既有方案的关系及下一步

继续保留：中小工作室、不设 10 人上限、短剧优先且偏 AI 写实、场次主责、每场双模式、简单内部权限、Mantine 通用 UI、既有专业组件裁决、生成计划与费用边界、场次和整集独立确认、声音与字幕等完整 MVP 承诺。

本轮恢复：第 18 文档已有的聚焦分镜＋底部分镜条、总览按需、无选择／自由节点、单一输入和明确引用身份。journey 的常驻网格、强制当前镜头与参考集合随选择变化是原型偏差，不据此推翻已定领域模型。

本轮提出的新布局：把原定右侧直接输入移到中央底部；助手非模态；固定参考；窄屏辅助栏规则；顶部行数收紧。这些布局已获确认；2026-09-10 文档维护已同步 02／14／18／19 的当前规则。

以下是当时提出的原型与验证变体。原型已交付，实际覆盖及未验证项以 v0.3／v0.4 的验证记录为准；此处保留测试设计依据，不代表全部已通过：

- 不同 A/C 示意帧或真实可用短片；当前共图只能测身份与操作，不能测画面判断。
- 1366×900 与 1512×982，补 1366×768 压力状态；明暗、3／10／30 行输入、2／6 项参考。
- 编辑后从旧 v1 再次返工；SH-04 发起辅助后浏览 SH-05；应用旧建议时当前内容已变。
- v1 留评论草稿后切 v2；两个场次各有未发送内容；异步结果在用户离开时返回。
- 无选择、自由节点、多选、切模式、第三项参考、视口外节点、键盘与中文输入。

先检查误引用、草稿丢失、误应用、目标辨认、候选细节能否看清，再记录面板往返与任务用时。后续邀请目标团队做相同任务的观察，才能讨论效率收益；本轮三方专业视角一致不等于市场验证。
