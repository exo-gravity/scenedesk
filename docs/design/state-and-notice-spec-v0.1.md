# 状态与提示设计规范（State & Notice Spec）

日期：2026-09-18。**状态：提案,待确认。** 来源：剧本页一致性规则（[2026-09-18-script-status-consistency-rules.md](../research/2026-09-18-script-status-consistency-rules.md)）在抽查全仓后的**泛化版本**。

## 1. 为什么应该成为规范（实测证据）

| 维度 | 现状 | 结论 |
|---|---|---|
| **载体数量** | `ErrorNotice` 238 处 · 原生 `<Alert>` **141 处** · `DraftNotice` 56 处 · `<Badge>` 34 处 | 已有两个"统一"雏形,但 141 处绕过了它们 |
| **语义词汇** | 同一件事「归档」在 **9 个页面有 9 种写法** | 用户每页要重新学一遍 |
| **标题词** | 归档场景里标题混用 **「项目已归档」「只读项目」「只读场次」「资产已归档」** | 连"这是什么状态"都不统一 |
| **动作强度** | `ErrorNotice` 的标题写死「操作未完成」,重试按钮位置固定 | 好的部分:应当保留并推广 |
| **文案** | 混用 `·`、`：`、`，`;句尾时有时无;`读取中…` 与 `已保留` 时态不一致 | 需要句式与标点约定 |

**判断:适合成为规范,但不能原样照搬。** 剧本页那套里,"通知轨位置"与"页宽"是**页面结构相关**的,不适用于数据密集页;而"语义四种""文案句式""同物同名"是**跨页通用**的。

## 2. 规范分三层（通用 → 局部）

| 层 | 内容 | 适用范围 | 强度 |
|---|---|---|---|
| **L1 语义层** | 四种语义、同物同名、标题词 | **全仓所有页面** | **强制** |
| **L2 文案层** | 三类句式、标点、时态、否定 | **全仓所有页面** | **强制** |
| **L3 布局层** | 位置（通知轨／页级横幅／就地）、宽度、动作对齐 | 阅读型页面（有单一阅读列的页面） | 推荐;数据密集页可另行约定,但**同一页内必须唯一** |

## 3. L1 语义层（强制）

### 3.1 只有四种语义

| 语义 | 何时用 | 例 |
|---|---|---|
| **中性 info** | 例行告知:状态已保存、草稿已保留、有说明可展开 | 文件已保留,离开后可继续导入。 |
| **提醒 warn** | 需要留意但不阻断:外部改动、本机与云端不一致 | 本机有一个未完成的导入,与当前稿不一致。 |
| **失败 danger** | 动作失败:读取失败、提交失败、版本找不到 | 剧本正文读取失败。 |
| **受限 readonly** | 能力被关闭:归档、权限不足、只读版本 | 项目已归档。 |

**不用第五种。** 若一个状态看似不属于任何一类,先判断它是"告知／留意／失败／受限"中的哪一个,而不是新增颜色。

### 3.2 标题词统一（解决 9 种写法）

| 场景 | **统一标题** | 统一说明句式 | 现有反例 |
|---|---|---|---|
| 项目归档 | **项目已归档** | 可{保留的读能力}。恢复项目后可{恢复的能力}。 | 「只读项目」「只读场次」 |
| 场次/剪辑归档 | **场次已归档**（若与项目不同层级,正文说明层级） | 同上 | 「当前场次或剪辑已归档」 |
| 资产归档 | **资产已归档** | 固定版本与已有引用仍保留。不能{被禁的能力}。 | — |
| 无权限 | **只读** | 你没有{动作}的权限。 | 「无权」「受限」 |
| 版本非当前 | **历史版本** | 仍可{可做的}。 | 「历史稿」「旧稿」 |

**规则:标题只说"是什么状态",动作影响写在说明里。** 现在的「只读项目」把状态（归档）和能力（只读）混在标题里,导致同一状态两种标题。

### 3.3 术语表（同物同名）

| 概念 | 只用 | 禁用 |
|---|---|---|
| 正在用的版本 | 当前稿 / 当前版本 | 最新稿、现行稿 |
| 非当前版本 | 历史版本 | 旧稿、历史稿（二者择一,全仓统一为**历史版本**） |
| 本机未提交的导入 | 未完成的导入 | 草稿导入、待提交文件 |
| 带段落进画布 | 带入画布 | 引用到画布、选文进画布 |
| 能力被关闭 | 已归档（数据）／只读（权限） | 已停用、受限 |

## 4. L2 文案层（强制）

### 4.1 三类句式

| 功能 | 句式 | 例 |
|---|---|---|
| 告知状态 | `{对象}已{结果}。` | 文件已保留,离开后可继续导入。 |
| 说明原因 | `{现象}。{可做什么}。` | 文件无法完整解析。已选文件仍保留在本机。 |
| 需要决定 | `{情况},需要你决定{什么}。` | 本机有一个未完成的导入,与当前稿不一致,需要你决定保留哪一份。 |

### 4.2 硬约定

| 项 | 约定 |
|---|---|
| 标点 | 全角 `：，。`;代码标识符与英文串内保持半角 |
| 句尾 | **告知与说明类都带句号**;按钮、标签、菜单项**不带** |
| 分隔 | **不用 `·` 连接两个句子**;`·` 只用于同一行的并列字段（如版本行） |
| 时态 | 进行中 `正在{动作}`;已完成 `已{动作}`;不得混用（现状反例:「读取中…」与「已保留」并存） |
| 否定 | 用 `不会`／`未`／`需要你决定`,不用「无需担心」这类安抚语 |
| 人称 | 不出现「系统」「平台」;面向用户时用「你」 |
| 长度 | 说明**不超过两行**;超出则改为「摘要 + 展开」 |

## 5. L3 布局层（推荐;同一页内必须唯一）

### 5.1 三个合法位置

| 位置 | 用于 | 约束 |
|---|---|---|
| **通知轨** | 内容级状态（导入、保存、读取、冲突） | 固定在**页头与主内容之间**或**版本行与正文之间**;**同一页只选其一** |
| **页级横幅** | 项目级状态（归档、权限） | 在**页面最顶部**;整页可见 |
| **就地** | 与某个字段/对象绑定的状态（某条记录失败、某个字段校验） | 紧贴该对象;不参与前两者 |

**禁止第四处。** 现状反例:同一页把归档提示放页头之上、导入警告放版本行下、草稿提示放版本行上——用户每次都要重新定位。

### 5.2 宽度与动作

- 通知轨宽度:**同一页唯一**。阅读型页面对齐阅读列;数据密集页对齐内容区。
- 动作:**最多两个**（一主一次）;位置在同一页内统一（右对齐或跟随文字,择一)。
- 语义只用**左色条 + 底色**表达;**不用图标区分语义**（图标留给动作,避免混淆）。

## 6. 落地方式（建议）

| 步 | 动作 | 说明 |
|---|---|---|
| 1 | **在共享层提供 `Notice` 组件**,支持 `tone: info\|warn\|danger\|readonly` + 可选 `title` + 最多两个 `actions` | 位置与宽度由页面容器决定,组件不写死 margin —— 现有 `ErrorNotice` 的 margin 是页面级耦合,应拆开 |
| 2 | **`ErrorNotice` / `DraftNotice` 改为 `Notice` 的薄封装** | 保留现有调用点(238+56 处)不炸,内部统一 |
| 3 | **141 处原生 `<Alert>` 收敛**:归档类、权限类、失败类各改 `Notice`;纯装饰性的保留 | 按 §3 的标题词与句式改文案 |
| 4 | **在 `npm run ui:check` 增加门禁**:业务目录内禁止直接 `import { Alert } from "@mantine/core"`,必须走 `Notice` | 与现有硬规则同一机制,防止回退 |
| 5 | 补一份**样例页**(设计预览下可达)列出四种语义与三个位置 | 供后续页面照抄 |

**不建议一步全改**:先做 1–2（组件与封装,零风险),再按页面逐个把归档/权限类文案按 §3.2 对齐,最后才加门禁。
