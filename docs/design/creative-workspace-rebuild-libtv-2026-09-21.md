# 核心创作区重建：参考 LibTV 模式（设计决定）

日期：2026-09-21。状态：**已确认**（用户 2026-09-21 确认；基于对前后端整体代码的三路审查）。本决定是核心创作区的产品与视觉基线，取代 [创作工作区方向](creative-workspace-approved-2026-09-16.md) 与 [画布导航与场次目录](canvas-navigation-approved-2026-09-16.md) 中关于页面分工与导航的条款，以及 [画布重设计 v0.5](canvas-redesign-v0.5-2026-09-14.md) 中关于卡片、输入面板与工具条的条款。主路径不变：外部剧本导入 → 创作台连续创作 → 整理镜头并明确选用 → 交付原片。

## 1. 决定

核心创作区（创作台、资产面板、剧本、镜头整理、助手、任务）的**界面层从零新写**，放在新目录 `apps/web/src/studio/`；后端与前端引擎按原样复用；页面组织参考 LibTV：

- 创作区顶栏一排**视图切换：剧本 | 创作台 | 镜头整理**；没有项目左栏。
- **创作台**（英文标识仍为 canvas）是全屏主工作面：顶栏切项目与创作台，底部一条工具条，左下拉出资产侧面板，助手可浮窗可停靠。
- **剧本**是独立视图（导入、阅读、选文入创作台），创作台上不做「剧本卡」；创作台上与剧本的联系是只读的固定摘录卡。
- **镜头整理**是独立视图（表格式镜头列表、候选、选用、交付）。
- **项目资产**是创作台左下拉出的侧面板（列表、搜索、拖入），完整资产库页面保留为独立路由，从面板「管理资产」进入。
- **项目设置、成员、归档**在左上角项目菜单里，不占常驻位置；工作室切换、项目列表、我的工作在创作区之外，不在本次范围。
- 配色用 SceneDesk 自己的主题变量（结构、密度、交互照 LibTV，颜色是自己的）；浅色为准，深色只保证可读不坏。
- 画布引擎库保留 React Flow。

## 2. 审查结论（2026-09-21，三路审查）

**后端**：创作台、生成、媒体、能力、偏好、镜头绑定的全部操作已在契约与 `apps/api` 中；写操作统一校验来源、CSRF、If-Match、幂等键；未知回执只能对账不能重发；归档恢复不重呼模型。**界面重建不需要任何后端改动。** 能力记录里没有模型的展示名、厂商、图标、说明、费用、预计耗时；费用只在已准备好的计划上有估算。接真实模型时要做的是：实现 `AssistanceAdapter`、插入 `verified_provider` 能力记录、放开受控测试的门。

**前端引擎**：`use-canvas`／`canvas-controller`（文档、保存、换基线、恢复）、`use-generation-session`（会话、幂等、回执）、三种生成的能力过滤与请求构造、引用与用途、固定来源、结果放置、编辑交接、继续创作规则、视口约束、偏好、上传规则、结果预览、节点动作、规格归一、引用状态、画幅、放置算法——**没有一个依赖 React Flow、Mantine 或旧界面文件**，可以原样接入新界面。生成工作区把 21 条流程规则和界面写在一起（附录 A），新面板必须逐条重现。

**页面与外壳**：现在的核心创作区是「工作室栏 + 项目左栏（剧本／画布／项目资产／项目设置）+ 画布顶栏挂镜头列表、任务、素材、助手」；最大文件助手 2,710 行、画布 2,514 行、场次工作区 1,658 行、生成工作区 1,392 行；`CutWorkspace`、`TaskWorkspace`、`Members` 已无人引用。e2e 18 个文件中 15 个触及画布界面。

## 5. 卡片与面板的复刻清单

依据 `docs/research/assets/2026-09-21-canvas-cards/` 的六张 LibTV 截图。

- **卡片**：标题在卡片外（小类型图标 + 名称，灰色小字，双击改名）；本体白底、细浅边、圆角；空态只有居中浅灰图标，没有说明句、没有底栏；图片／视频按画幅比例定高；新卡等面积（基准边 360，宽 = 360 × √画幅，16:9 得 480×270、9:16 得 270×480；文字 320、音频 360 固定），已保存宽度照旧渲染；每张卡右下拉伸角只改宽，高随画幅（2026-09-22 用户决定，取代原「一期不改宽」）；选中细边变深，两侧边缘中点出现细圈端口；键盘焦点另有描边；生成中／失败在卡内左下小标签，结果铺满本体；文本卡就地编辑纯文本、右下拉伸角，不做富文本；媒体卡被引用时缩略图左上角小标签为用途；固定摘录卡只读并可回看来源。
- **选中后的动作**：不做浮动工具条；右键菜单（重命名、复制、删除、关联镜头、多选时「查看 N 项的生成计划」）+ 快捷键。
- **输入面板**：选中生成卡后出现在正下方、左对齐、约 660 宽（受画板限制，四边不空时按放置算法换边或裁边；右上角拖动把手可把面板拖到别处，本次选中期间跟卡走，换卡即回到算法，2026-09-22 用户决定）、白底细边轻阴影、高随内容；右上角一个展开图标即专注编辑；行 1「＋参考」胶囊；行 2 参考缩略图（约 48px，用途角标，异常状态另有角标）；行 3 提示词大字；底行胶囊 `模型 ▾`、`比例 · 清晰度 · 时长 · 音频 ▾`，右侧黑色圆形 ↑；空提示或未选模型时禁用并说明原因；文本卡不出面板。
- **模型列表**：行 = 图标、名称、状态小字（已接入／受控测试），选中浅灰底；无耗时。未接真实模型前列出的是本地夹具模型，不改名；一个都没有时显示「暂无可用模型」而不是空按钮。（2026-09-23 起由 [创作区底部：模型、模式与规格](studio-model-and-specification-2026-09-23.md) 取代。）
- **规格浮层**：比例是带图形的方块 tile，清晰度两列格子，时长滑杆 + 数字 + s，生成音频开启／关闭；只列该模型允许的项；无生成数量。（2026-09-23 起由 [创作区底部：模型、模式与规格](studio-model-and-specification-2026-09-23.md) 取代。）

## 8. 组件策略与规范优先级

- Mantine 只做基础设施（浮层、菜单、焦点圈、滑杆、提示、对话框、无障碍），一律无样式变体接新目录的样式；主题的默认变体（`Button` 默认 `default`）不进创作区。看得见的表面用语义元素加 CSS module。图标 Phosphor。
- SceneDesk 统一规范管颜色变量、字体阶梯、焦点、状态与提示规范、领域含义；LibTV 管结构、尺寸、密度、交互。数值冲突时加 `--ws-studio-*` 变量并记入共享视觉语言，规范被扩展不被绕过。
- 配色已定为 SceneDesk 自己的；日后若要照抄 LibTV，只是改一组变量值。

- 附录 A 的 21 条流程规则是最容易漏的地方，第 ③ 片必须逐条对照并有 e2e。
- 镜头整理视图（⑦）是本计划里最大的一片：它同时承载候选、选用与交付的领域事实；表格式只改外观，不改事实。

## 附录 A：生成面板必须重现的流程规则（来自现有 `MediaGenerationWorkspace` 画布模式）

1. 会话身份 = 会话 · 类型 · 画布 · 节点 ·（检视时的计划 id），任一变化即重建。
2. 打开面板时向画布登记「保留草稿」检查：关闭前会话已落定且草稿已保存，否则阻止并说明。
3. 检视固定尝试时只打开一次，并校验项目与用途。
4. 能力读取遇 401／403／404 → 挂起会话并重新核对权限。
5. 草稿的模型与规格保存在**画布文档**里（`configure`），不是会话里。
6. 已有计划或原请求时，模型与规格全部冻结。
7. 不活跃、会话忙、无草稿时禁用输入。
8. 生成前：先固定镜头来源快照，再**保存画布**，保存后画布 id 或文档变化则拒绝，再构造请求。
9. 画布未保存（脏、待定、未就绪）时显示「生成前会先保存」，并禁用结果放置。
10. 结果放置评审：任务成功且有媒体，先再保存画布，算出放置位置，进入评审态。
11. 放置提交：412 版本冲突 → 冲突态；成功后回调 `afterPlacement`。
12. 放置回执未知：只给「恢复本次添加」；冲突则重新评审；已放置则定位到新节点。
13. 归档失败：两步「核对／继续原归档恢复请求」，不重呼模型。
14. 继续原计划：以原计划为种子修订；放置未知或评审中时禁止。
15. 提交回执未知：只能恢复提交，刷新不会重执行。
16. 计划未就绪或已过期时禁止执行。
17. 切换模型：只保留新模型接受的输出项，补齐唯一可选项。
18. 镜头来源选择只在画布、有草稿、未冻结、非检视时出现。
19. 权限未就绪时整个面板换成重新核对提示。
