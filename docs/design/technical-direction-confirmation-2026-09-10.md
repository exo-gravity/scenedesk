状态：**技术方向已确认；用户随后授权继续，三项协议及前端状态规则已完成[设计收尾](../implementation/21-technical-baseline-closure.md)。候选组件集成及运行验证未执行，正式业务工程仍暂停。** 此次确认不改变已定产品范围，也不将评审中的所有候选方案视为选定。

## 1. 已确认的方向

| 议题 | 当前决定 | 仍需落实的细节 |
|---|---|---|
| 架构主干 | 保留 TypeScript／React／Vite、Node／Fastify 模块化 API、独立任务及媒体 Worker、PostgreSQL、私有对象存储与 FFmpeg | 模块接口、运行身份、实际部署配置与验证 |
| 任务执行 | 优先复用成熟调度组件，pg-boss 为首个集成验证候选；平台继续拥有 job／attempt、未知提交、费用与供应商在途额度 | 同事务入队、最小权限、故障恢复验证通过后再锁定具体组件；不默认继续自研通用调度器 |
| 前端状态 | 保留现有组件体系；服务端快照、本地编辑草稿、视图偏好分别管理 | 编辑 store 与 Query 的同步、撤销、断网与恢复协议 |
| 画布协作 | 首版仍按场次主责、异步协作设计，有条件保留整文档 CAS，明确编辑者提示与冲突恢复；不新增实时共同编辑承诺 | 双人同场编辑的验证；若持续共同编辑成为核心需求，重审保存粒度 |
| 保存历史 | 当前工作状态、近期恢复历史、周期检查点、业务固定快照分别管理；业务引用保护继续保留 | 保留期限、容量目标、压缩清理及旧基线恢复规则 |
| 剪辑保存 | 未完成编辑也能可靠保存与恢复；与经过校验的可渲染 CutDraft／固定版本分开 | 工作草稿的具体对象、API、权限、CAS、保存状态与验收；本轮已选择每Cut一份共享CutWorkDraft，详见21 |
| 媒体处理 | 保留精确时间边界、归一缓存与固定稿渲染；正式审阅依据固定渲染文件 | 实际素材、浏览器预览与 FFmpeg 输出的验证 |
| 模型与 Agent | 优先贯通一个真实视频服务；补齐模板、输入和应用关系的追踪；未来 Agent 复用受控业务操作 | 具体服务／地区／账号、追踪字段与接入验证 |
| 契约 | 保留 OpenAPI 单一公开契约源，按业务切片接通请求校验、授权、事务及响应 | 待修订协议及真实端点验证；不按接口数量判断完成度 |
| 部署与身份 | 保留容器、托管数据库、私有存储和成熟身份提供方方向 | 云与地区、登录渠道、账号归属、预算、实际商业接入条件；不据此认定具体供应商或价格已获确认 |

## 3. 与现行文档的关系

本记录确认的是方向和调整要求。原实施包v1.2／OpenAPI1.2.0为上轮快照；本次已更新为**实施包v1.3／OpenAPI1.3.0**，用于后续实施。组件集成和运行门槛不由文档更新代替。

尤其是自研 `worker_tasks` 的实现安排、唯一可渲染剪辑保存路径、画布全量历史保留细节，已按21完成协议修订；不得由工程人员自行补造字段或同时实现两套相互冲突的机制。与此次调整无关的授权、费用、制作身份、明确采用和固定版本审阅规则继续保留。

原技术评审和队列研究保留当时的论证与证据；本记录更新其确认状态，不将“候选符合文档要求”改写为“已验证可用”。
