## 1. 推荐方向与设计目标

推荐“中性深灰、媒体优先、适中偏紧凑、少量暖色强调”的专业创作工作区。优先让制作人员持续看清画面、读懂镜头要求、识别当前对象和执行下一步。技术实现使用Mantine，视觉身份由本产品规范决定。

设计判断依据：

- 主场景是一个人持续完成一场戏，频繁在分镜、参考、候选、剪辑和意见之间切换。
- 团队内部使用，需要在同一页面理解版本和状态，不能只追求单张截图的整洁。
- AI写实涉及脸部、道具和空间细节，图像的可辨认面积与完整画幅很重要。
- 工作台需要兼顾中文剧本阅读与多镜头浏览，信息密度不等于缩小所有文字。
- 长期广告场景可复用相同的工具语言，不把整体品牌限定为影视海报或某种剧目风格。

深色是本次工作场景的建议，不宣称它普遍更护眼，也不宣称网页预览可以代替校准监视器进行最终调色。

## 2. 对现有原型的评估

依据：[现有制作页截图](../../output/playwright/2026-09-09-visual-mvp/01-scene-production.png)、[原型说明](mvp-visual-prototype-v0.1.md)与实际CSS。

建议保留：

- 深色连续工作区和少量暖杏色主操作。
- 制作／剪辑／审阅共享同一场次上下文。
- 中央镜头、右侧当前对象的结构，完整展示9:16画幅。
- 明确的镜头编号、时长、候选与剪辑使用提示。

建议改进：

1. 中和大面积背景和辅助文字中的绿倾向，形成中性灰层级；暖色保留在操作强调。
2. 减少10–11px的必要信息，重要辅助字段至少按12px起点设计。提高小字可读性优先于维持四列。
3. 收紧上方重复标题/路径/元信息占用的高度，给镜头和预览增加纵向空间；不新增更多标题层。
4. 统一选中、悬停、键盘焦点和业务状态的视觉语法，避免同一个高亮同时表示“当前镜头”和“已经通过”。
5. 镜头卡分为稳定的媒体区、信息区和实际使用状态区，减少卡内边框和重复标签。

以上是对当前截图的设计判断，尚非用户测试结论。

## 3. 第一轮需要讨论的整体选择

### 3.1 主题

**建议MVP默认统一深色。** 创作、资产、审阅和管理页保持同一套中性色与状态含义，剧本页通过字号、行高和行宽改善阅读。以后根据真实阅读环境增加浅色主题或独立阅读模式；现在以语义token保留实现空间，不一次承诺两套完整主题验收。

候选变化：如果目标团队主要在明亮环境长时间编写戏文，可优先给剧本阅读/编辑区域增加浅色纸面。这个判断需要任务与环境依据，不仅是个人偏好。后续切换主题时，审阅媒体周边仍应有稳定中性背景。

### 3.2 强调色

**建议保留原型暖杏色，但降低使用面积。** 用于当前区域的主要动作、当前导航或明确选择反馈；灰色承担大多数容器和常规按钮。警告状态使用图标和文本区分，不能因为主色接近琥珀就把主操作解释为警告。

尚未确定品牌名称、Logo或最终主色数值。确认方向后再固定完整色阶和各交互态，不直接套用Mantine默认orange色阶当作全部品牌规范。

### 3.3 密度

**建议适中偏紧凑。** 常规操作可快速到达，媒体内容拥有主要面积，阅读文字保持清晰。先做一套默认密度；是否增加“紧凑模式”由真实镜头规模与屏幕测试决定。

桌面创作优先，目标走查包括1366×900和1440/1512宽屏。窄屏采用折叠、抽屉与顺序阅读，不把多面板等比缩成手机上的小字，也不在当前阶段承诺手机完成全部剪辑操作。

## 4. 规范起点：待确认的具体建议

| 项目 | 建议规则 | 原因 |
|---|---|---|
| 画布底色 | 中性深灰，起点`#141414` | 降低周边色彩存在感，保持内容优先 |
| 工作面板 | `#1B1B1B`，浮起/输入层`#242424` | 主要用明度、留白与必要分隔表达层级 |
| 文本 | 主文字`#EAEAEA`，次文字`#B8B8B8`，辅助文字`#9C9C9C` | 必要信息即便次要也应可读，禁止整块降低opacity |
| 主强调 | 暂以`#EDB878`为起点，按钮配深色文字 | 延续原型方向，最终确认不同状态与相邻背景对比 |
| 常规正文/控件 | 14px起点，正文行高20–22px | 中文可读与工作区密度兼顾 |
| 必要辅助信息 | 12px起点，行高16–18px | 避免镜号、版本、时长变成难以辨认的小字 |
| 戏文阅读编辑 | 16px起点、26–28px行高，限制行宽 | 与参数表单区分，适应连续阅读 |
| 标题 | 场次标题20–24px；区域标题14–16px | 清楚分层，避免标题挤占预览面积 |
| 间距 | 4px基本步长，常用8/12/16/24px | 同时支持紧凑控件和清楚的分组 |
| 控件高度 | 默认32px；表单可36px；紧凑操作28px | 保持一致的点击与阅读节奏，不缩小到图标本身 |
| 图标 | 沿用Phosphor，常规16–18px，统一字重 | 视觉一致；仅图标按钮提供可访问名称及必要提示 |
| 圆角 | 常规控件4–6px，内容容器6–8px | 轻量区分边界，不把所有区域做成圆角卡片 |
| 分隔 | 装饰分隔轻；需要辨认的输入边界、焦点单独保障对比 | 不用低对比美学掩盖交互位置 |
| 动效 | 常用100–160ms颜色/透明度过渡；稳定媒体位置 | 防止操作时内容跳动；尊重减少动态效果设置 |

这些数值是讨论起点；后续已按用户授权进入可评审样板，并展示hover、focus、disabled、loading和error等状态。生产规范仍以样板评审及后续测试为准。

## 5. 业务状态的视觉语义

| 事实 | 建议视觉表达 | 必须避免的混淆 |
|---|---|---|
| 当前选中镜头/候选 | 明确选择边框或标记，必要时使用强调色 | 不代表采用或批准 |
| 键盘焦点 | 可独立识别的焦点环，跟随实际焦点 | 不只复用选中样式 |
| 当前采用候选 | 带文字的“已采用 A”标签和稳定候选身份 | 不代表剪辑已经换成A |
| 实际剪辑使用 | 在使用区明确显示版本/候选/区间 | 不由当前采用标签推断 |
| 固定稿已通过 | 正向语义色+“v2 已通过”等确切文字 | 不让整张镜头卡变绿后省略版本 |
| 需要返工 | 警示图标+原因/意见数量+可到达的修改入口 | 不只用色点表达问题 |
| 生成中 | 进行中标记与明确阶段 | 无真实百分比时不伪造精确进度 |
| 生成失败/提交状态未知 | 明确错误或“待核对”文本，操作按业务恢复规则提供 | 未知不能简单显示失败并诱导再次付费 |

绿色建议主要用于正式通过/成功反馈；采用、引用和剪辑使用可用中性标签表达。警告与危险色只用于相应语义，不用于装饰大片背景。任何状态都不能只依赖颜色。

## 6. 内容与交互的视觉约束

- 源素材与镜头比较默认保留完整画幅，清楚标识contain/cover等实际输出选择。项目封面的装饰裁切不等同素材预览规则。
- 图像本身不加改变亮度、饱和度或色温的悬停滤镜来表达选中；优先在外部边框和状态区表达。
- 同一区域明确一个主操作，其余为次级操作；全局动作与当前镜头动作在位置上区分。不能把“准备生成”“提交费用”“采用”“替换剪辑”合并成一个含义不清的彩色按钮。
- 必要操作始终可发现；仅悬停出现的辅助操作也要能通过键盘到达，必要时提供菜单入口。
- 弹窗适合短暂、明确的确认；持续编辑优先在当前面板完成，避免多层弹窗遮住参考媒体。
- 分镜网格列数服从媒体最小可辨认尺寸与可用空间，不为固定四列压缩文字；剧本、资产、制作、剪辑、审阅使用各自合适的布局，但共享视觉语法。
- 保留布局偏好和连续工作上下文，不能因为打开弹窗、切换候选或显示错误就让播放器跳动。

## 7. 可访问性与验收

普通必要文本的对比度目标至少4.5:1，大字按适用定义至少3:1。紧凑设计建议仍保持28–32px点击区域；WCAG2.2的目标尺寸标准及其例外需要按实际布局检查，图标尺寸不等于点击区域。技术控件、输入边界和焦点按各自适用要求验证。[W3C文字对比](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)、[W3C目标尺寸](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)

静态token检查不等于整个页面通过：还要检查透明叠加、不同容器、错误文本、禁用说明、缩放和键盘焦点。真实业务试用至少涵盖“选参考→填写参数→比较候选→采用与更新剪辑→定位固定版本意见”。

## 8. 确认后的交付顺序

1. 先确认整体方向：深浅主题、媒体优先程度、信息密度、强调色。
2. 形成一份视觉token与状态规范：颜色、排版、间距、形状、焦点和反馈。
3. 在一个真实场次页面内完成镜头卡、资产选择、参数面板和审阅状态样例，再共同评估。
4. 确认后映射到Mantine theme/defaultProps/CSS Modules，沿已有业务切片迁移其余页面。

本文保留视觉方向讨论依据。后续已推进本地样板，供用户实际操作评审；MVP范围未扩大，最终像素与色值仍可根据样板反馈调整。
