# 创作信息架构与资产、剧本流程审查

日期：2026-09-13。范围：现有私有创作工作区。用户最新要求是在批准设计基础上提升信息组织、布局与交互质量。本次只审查并提出实施切片，没有修改 UI、业务数据或运行中的浏览器。

代码审查基线：`585eb10df26bc7b1d32d8b67bb99a8ee7b596898`。主任务已按用户要求执行 `fetch origin --prune` 与 `pull --ff-only origin main`，确认最新 `main` 仍为该提交，无差异。本稿结论可用于下一轮分工；本次审查本身没有开始 UI 实现。

主要判断：当前问题集中在页面默认呈现的内容顺序。资产已有参考画面，列表却要求读长文字；剧本已有保存版本，进入后却直接呈现编辑控件；故事设定属于创作输入，却埋在项目设置中。应先让人辨认和阅读作品，再按明确动作展开编辑、引用与核对工具。保留现有中性色、系统中文字体、Mantine、Phosphor、媒体主区与固定版本语义，不靠更换字体库、装饰阴影或扩大导航解决这些问题。

## 七项高影响建议

### 1. P0：资产列表改为可辨认人物与道具的视觉索引

**当前证据。** `assets.png` 中四项资产均为名称、长说明与状态文字，没有展示已存在的参考画面。[AssetWorkspace.tsx](../../../apps/web/src/business/AssetWorkspace.tsx#L146)把三个带 label 的筛选控件常驻在顶部，列表项从约第 182 行开始仅渲染文字。下方空的“已引入共享固定版”区域继续占据正文。

**建议。** 首屏按“查找 → 看到对象 → 打开确切设定”组织。用浅包装的视觉条目或画册式网格显示主参考、名称、类别和短版本标记；两行长说明移到详情。人物/空间/道具用可点击分类，搜索保留可访问名称，归档筛选收进筛选面板。共享引入有内容时作为明确分组，无内容时保留一个弱入口即可。不要增加没有真实数据支持的使用次数、完成度或批准标识。

**实施边界。** `Asset` 只有 `currentRevisionId`，缩略图需读取该确切版本及其真实媒体。复用已有查询缓存与 `MediaPreview`，只请求当前可见/已分页条目，不为整库并发读取全部版本；请求失败显示稳定占位及可恢复状态。不能把任意搜索到的人像作为资产封面。

**示意。** `项目资产  [搜索] [筛选]  新建资产` → `全部 / 角色 / 空间 / 道具 / 声音` → `林夏参考图｜林夏｜角色 · v1`。条目点击是浏览，不是引用或升级。

**可分配文件。** `AssetWorkspace.tsx`、`assets.module.css`、必要的局部预览组件；查询复用 `asset-queries.ts` 与 `MediaPreview.tsx`。验收包含有图、无图、不可读参考、长中文、分页及窄屏。

### 2. P1：资产详情保留大预览，围绕固定版本和参考选择整理工具

**当前证据。** [AssetDetails.tsx](../../../apps/web/src/business/AssetDetails.tsx#L101)已经把浏览和编辑分开，历史与使用位置按需读取，方向正确。[AssetRevisionView.tsx](../../../apps/web/src/business/AssetRevisionView.tsx#L34)的身份/造型入口是下拉选择，底部参考切换却主要显示“用途 1/2”和说明文字；版本、确认、新修订及检索信息动作散落于左右两区。

**建议。** 保留“左侧参考大图、右侧当前设定”的结构。页头显示资产名与当前正在浏览的 `vN`，身份/造型改为紧凑可发现的切换，参考采用小图带用途标签。右侧依次是当前固定描述、声音/造型摘要、明确的新修订入口；历史和有权查看的使用位置继续按需展开。检索信息与归档进入低频菜单，确认设定仅在合法草稿与权限条件成立时显示。

**示意。** `返回资产  林夏 · v1 [版本]` → `参考大图 + 缩略图带` ｜ `固定设定摘要 / 灰风衣 / 声音未设定 / 新建修订`。历史版显式标记“正在浏览 v1；当前为 v2”，不自动跳回最新。

**实施边界。** 不把“新建修订”变成原版本原地编辑；引用目标只在已有明确接收目标时展示。保持版本与确认对话框绑定打开时对象，缩略图选中只改变查看对象。

**可分配文件。** `AssetDetails.tsx`、`AssetRevisionView.tsx`、`assets.module.css`。验收包括历史深链、造型切换、撤权、引用版本不同于当前版本以及确认期间出现新版本。

### 3. P1：资产编辑从纵向完整表单改为有焦点的设定编辑

**当前证据。** [AssetDefinitionEditor.tsx](../../../apps/web/src/business/AssetDefinitionEditor.tsx#L205)依次铺开描述、主参考、声音、固定声线、全部并存造型；[AssetReferenceFields.tsx](../../../apps/web/src/business/AssetReferenceFields.tsx#L104)每个参考又常驻用途选择与说明输入。参考或造型一多，媒体与本次正在改的内容很快离开视野。

**建议。** 编辑时仍保留当前参考画面，主列展示本次设定说明；“参考”“造型”“声音”作为局部分区，已有内容先显示可读摘要，选中某项再展开该项字段。新增角色先完成名称/类型，再进入首版设定，后续动作明确显示“建立首版”，减少“创建空壳后不知道下一步”的断点。保存动作固定在本编辑区底部，并显示基于哪一版及本机修改状态。

**示意。** `新建修订 · 基于 v1` → `固定描述` → `主参考 2项 [编辑] / 造型 1项 [展开] / 声音 未设置 [添加]` → `取消编辑 · 保存为新版本`。

**实施边界。** 收起分区不能卸载并丢失草稿；当前 `prepared/reconcile`、造型身份与版本、`useContentDraft`、完成回执清理必须保留。新建资产和首版设定仍是各自真实事务，不能伪装成一次已成功提交或为了串联页面自动再 POST。

**可分配文件。** `AssetDefinitionEditor.tsx`、`AssetReferenceFields.tsx`、`AssetWorkspace.tsx`、`assets.module.css`。验收包含多造型、局部修改、二次冲突、保存成功后读取失败以及刷新恢复。

### 4. P0：剧本页先呈现戏文，编辑与提案按意图展开

**当前证据。** `script.png` 中正文已保存为第 1 版，但主区处于 textarea 编辑态，常驻“保存为第 2 版”。右侧尚未选择目标场次，却占完整固定宽度。[ContentWorkspace.tsx](../../../apps/web/src/business/ContentWorkspace.tsx#L624)始终渲染助手；`content.module.css:81`默认采用 410px 侧栏。[ContentEditors.tsx](../../../apps/web/src/business/ContentEditors.tsx#L929)保存按钮的禁用条件没有区分正文是否已修改。

**建议。** 已有干净版本时默认呈现可选择文字的阅读纸面，页头保留版本与“编辑正文”“整理为镜头”。没有剧本或有合法待恢复草稿时进入相应编辑/恢复状态。只有明确开始整理、返回未决任务或打开具体提案时展开助手；展开后沿用已批准的停靠方式。把“CSV 与提案”拆成低频导入入口和提案历史入口，避免把文件格式作为创作主步骤。

**示意。** `重逢 · 第1版 [版本]  编辑正文  整理为镜头` → `完整戏文`。点击整理后：`已保存第1版的原文范围 → 明确目标场次 → 固定计划/提案`。没有目标只可准备选择，不能沿用上次场次或暗中发送全剧本。

**实施边界。** 阅读/编辑切换只是视图状态；固定来源仍使用真实 `scriptRevisionId/range/quote`。不将未保存文本当作提交来源，不合并“保存”“生成”和“采纳”。保留 `scriptMounted`、草稿控制器及保存完成后双根读回逻辑；不能为了切换阅读态重置 `scriptEpoch`。

**可分配文件。** `ContentWorkspace.tsx`、`ContentEditors.tsx`、`content.module.css`；必要时由助手负责人接 `SceneAssistant` 的显隐接口。验收包含干净进入、未保存离开/返回、旧版本深链、选区固定、提案历史、未知任务只读恢复、保存成功但 refetch 失败。

### 5. P0：把故事设定放回“剧本与设定”，与依据确认分开

**当前证据。** [Projects.tsx](../../../apps/web/src/business/Projects.tsx#L319)把 `ProductionSettings` 放在项目规格和样片设置之后；[ProductionSettings.tsx](../../../apps/web/src/business/ProductionSettings.tsx#L19)常态直接显示完整编辑器。“剧本与设定”页的“创作依据”会打开固定版本的核对列表，[CreativeWorkspace.tsx](../../../apps/web/src/business/CreativeWorkspace.tsx#L77)承担确认而不是故事 brief 编辑；当前入口容易让用户混淆“写设定”与“确认哪版作为依据”。

**建议。** 剧本与设定提供“正文 / 故事设定”两个明确内容入口。设定页先阅读故事 brief 与固定默认资产的缩略摘要，再点击编辑。依据确认保留为各内容版本附近的独立状态和核对动作，历史可展开。项目设置继续保留规格等低频配置；已有设定编辑地址可以导向相同编辑器，避免维护两个独立草稿。

**示意。** `剧本与设定：正文 | 故事设定` → `旧钥匙 · 重逢 / 故事与风格 brief / 默认角色、空间、道具` → `编辑设定`；旁边显示实际依据状态，只有明确动作才建立确认。

**实施边界。** `Production.revision` 与 `Project.revision`、`ContentTree.revision`不同。复用原 `ProductionSettings` 的保存与恢复语义，迁移入口不要改变 draft key。文字和缩略摘要来自实际 Production/固定资产版本，不能从原型生成角色关系或默认确认。

**可分配文件。** `ContentWorkspace.tsx`、`ProductionSettings.tsx`、`CreativeWorkspace.tsx`及对应局部 CSS；`Projects.tsx`的入口调整由壳负责人协调。验收保存后返回、旧依据保留、固定默认资产不自动升级、同时打开两个入口时草稿与 CAS 一致。

### 6. P1：素材库保持画面网格，把导入动作与恢复记录分开

**当前证据。** [MediaWorkspace.tsx](../../../apps/web/src/business/MediaWorkspace.tsx#L210)已经使用真实媒体网格，应保留。顶部仍是三个完整筛选字段，主动作叫“导入与恢复”，并把整个 `MediaImports`插在浏览内容之前（第 128–166 行）。创作者为了导入文件，先进入一个同时承担历史和异常处理的区域。

**建议。** 默认显示紧凑搜索与图片/视频/声音类型切换，额外状态进入筛选。主动作使用“导入素材”，导入过程使用明确的局部工作区；“导入记录”作为次入口，真实处理中或待恢复时显示持久数量/摘要。关闭面板不取消上传、不丢失原请求，不把异常隐藏成短暂 toast。媒体详情保持预览优先，尺寸/时长可见，完整来源声明和低频文件信息按需展开。

**示意。** `素材文件  [搜索] [筛选]  导入素材` → `全部 / 图片 / 视频 / 声音` → `媒体网格`；有真实异常时在工具区显示 `1项需要核对 → 原上传记录`。

**实施边界。** 不新增猜测的“最近使用”排序或假处理进度。视频/音频保留显式播放和最多一个有声实例的规则，缩略列表不自动请求所有原文件。页面导航状态与上传控制器分开；筛选、滚动与返回上下文应保持，但不能污染业务版本。

**可分配文件。** `MediaWorkspace.tsx`、`MediaDetails.tsx`、`MediaImports.tsx`、`media.module.css`。验收包括导入后继续浏览、未知上传恢复、切范围撤权、无海报原件可用、长文件名、分页与浏览返回。

### 7. P1：把状态解释收敛到对象附近，但保留所有真实恢复出口

**当前证据。** 各编辑器已有草稿、冲突和提交完成保护，不能为简洁删除；资产编辑在冲突时出现长段说明与服务器概览，剧本在保存成功但未读回时锁住继续编辑。这些是应保留的业务能力。另有一个具体表述问题：[MediaDetails.tsx](../../../apps/web/src/business/MediaDetails.tsx#L121)按媒体类型写死“海报预览/代理预览”，而 `MediaPreview.tsx:59`可能实际选择 ready original，应跟随真实播放源表达。

**建议。** 常态只保留对象级一句状态，如“本机有修改”“已保存第2版”“正在读取保存结果”；异常出现时在同一位置展开原因、受影响版本和允许动作。较长冲突对照进入局部分区，当前手工合并与保存按钮保持在视野内。历史来源、未配置模型、未知提交、撤权、无法读取媒体不能被收进无人发现的“更多”菜单。

**示意。** `林夏 · 基于v1 · 本机有修改`；冲突时变为 `服务器已有v2，修改已保留 [查看差异]`，展开后明确核对，不提供含混的“继续”或自动覆盖。

**实施边界。** 只收敛呈现，不把多个业务状态变成统一成功标记。`DraftNotice/useContentDraft/useCommand`继续拥有原事实与恢复规则；未知提交不重新买单，已提交但本机清理未完成不显示“全部保存”。播放器旁文案读取实际 variant，不根据 media.kind推断。

**可分配文件。** 各本次修改编辑器的状态区、`MediaDetails.tsx`与`MediaPreview.tsx`的窄展示接口。若需公共样式变体再交共享组件负责人，不直接重写恢复控制器。验收按已有故障用例重放，不能只审正常态截图。
