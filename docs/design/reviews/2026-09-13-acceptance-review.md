本文件是新一轮 UI、信息结构与画布改进的验收计划，不是已通过报告。审查基于 `main 585eb10df26bc7b1d32d8b67bb99a8ee7b596898` 的代码、脚本和既有证据；本次未运行浏览器、业务测试或服务，未读取私有演示状态。

用户要求提升真实业务体验并完成端到端测试。`AGENTS.md`、`apps/web/AGENTS.md` 的固定版本、权限、草稿和未知请求恢复要求继续适用。旧 v0.3/v0.4 是比较起点；本轮明确批准的体验变化应记录为新预期，不能仅因旧截图通过就判定改进完成，也不能把旧 dock 宽度、组件类名全部固化成不可改变的测试。

## 结论与缺口

1. **缺少一个覆盖改版后完整任务链的真实业务浏览器入口。** `package.json` 的 `check` 是合同、UI 静态规则、类型、构建和 `tests/*.test.ts`；标准 CI 另跑数据库和媒体套件。它们均不自动执行 `output/playwright/` 的业务脚本。部署 smoke 验证同源服务及浏览器合同编译，不等于完成导航、播放、编辑与恢复。通过 `npm run check` 后仍必须执行下面的浏览器链。
2. **关键可用性组合未由旧证据证明。** [上一轮整合报告](../../../output/playwright/2026-09-12-approved-integration/README.md) 验证了 1512、部分 1366 和 390；没有 1440 的整链，也没有系统的纯键盘路径。上一轮真实资产上传使用 PG/MinIO，而场次使用静态媒体 adapter，故不能将两份截图合并解释为同一真实上传视频在所有页面均可用。
3. **正常保存与故障恢复的旧脚本可以复用，但不能直接重跑。** 多份脚本硬编码 `4311`、旧项目与节点 ID，且会 PUT 画布、偏好或创建对象。例如 [画布恢复脚本](../../../output/playwright/scene-canvas/verify-page-recovery.js) 明确插入同伴笔记并修改草稿。此次应只移植行为步骤和故障注入方法，全部目标改为新隔离夹具，并使用新的证据目录。

这些是待补的覆盖范围，不是未经复现的产品缺陷。当前 `CanvasBoard.tsx` 已有选择/手形、缩放、撤销/重做、删除键处理和窄屏列表边界；新的布局不能令这些既有操作不可达。

## 本轮必须通过的真实 E2E 路径

每条路径以**真实 UI 操作 → 实际 HTTP 结果 → 授权 GET 读回 → 刷新后页面**为证据。不得只用 `route.fulfill` 的成功响应替代服务器保存，也不能直接 `evaluate` 修改组件状态来冒充用户操作。

| 路径 | 实际操作 | 完成判定 |
|---|---|---|
| A. 信息结构与返回路径 | 项目列表 → 场次目录 → 分镜 → 画布 → 剧本 → 资产 → 素材；含深链接、返回、浏览器前进/后退和空场次 | 用户能辨认当前项目/场次/镜头；返回不会落到无关对象；主要创建、浏览和恢复入口可见或可明确展开；没有重复相互冲突的主导航。空场次有实际可操作入口，页面不能以隐藏了主体内容来通过 overflow 断言。 |
| B. 播放与固定候选 | 从实际采用缩略图进入视频，点击播放、暂停、拖动时间控件；切换未采用候选，再回到已采用；检查参考版本与素材详情，实际下载原文件 | `currentTime` 实际推进、pause 状态正确、seek 到达选定区间且无 decode error；9:16 完整画面及播放控制不被遮住；切换候选不改变 adoption。下载的 bytes/sha 与原上传文件一致；深色模式不改变媒体颜色。只在确有两份可听媒体时另验播放互斥，不把无声视频当音频验收。 |
| C. 画布核心编辑 | 工具栏添加文字和创作草稿 → 选择 → 编辑标题/正文 → 拖动 → 多选 → 显式建立/调整参考边 → 撤销/重做 → 保存 → 离开 → 刷新返回；另验 pan、zoom、fit、定位 | GET 的节点、位置、边顺序与输入相符，刷新仍一致；拖动/选择/手形的行为可区分，不误触删除；被选择对象和属性区域一致。开启辅助区不会清空输入或自动改动文档；保存标识仅在业务结果与本机状态一致后出现。删去临时节点不能删除原 Take、已采用事实或固定历史。 |
| D. 资产与素材 | 搜索资产 → v1/v2 浏览 → 从当前版本打开编辑 → 输入长说明/固定引用 → 关闭返回 → 明确恢复 → 保存新修订；再看旧版本和使用位置 | 浏览历史不修改 current；未提交草稿恢复准确；保存新增一个不可变修订，旧引用不升级，确认版本与普通保存仍是不同操作。媒体主体与上下文均可达到，长编辑区能滚到末尾并操作保存/返回。另验素材加载失败的明确重试和原文件下载。 |
| E. 剧本与助手布局 | 编辑剧本未提交内容 → 切页 → 返回 → 刷新 → 明确恢复；打开助手、选择固定原文、展开/关闭来源和长输出区 | 本机文本不丢失，不把服务器旧稿当本机稿“自动保存”；助手没有依据或没有执行能力时如实显示。侧栏滚动不拖走主文档；焦点与原选中对象保持。对改动涉及的固定 plan/job/artifact，沿原任务检查一次恢复，不自动执行或采用。 |
| F. 键盘与焦点 | 从页面起点用 Tab/Shift+Tab 遍历导航、菜单、分镜、播放器、画布工具、编辑器；Enter/Space 操作；Esc 关闭；焦点回触发处；在文本内使用 Backspace 与 Ctrl/Cmd+Z | 全部主要操作有可达焦点和明确名称；隐藏 dock 内容不进入焦点序列；关闭浮层后不丢失焦点。CanvasBoard 会排除 input/textarea/select/contenteditable 的删除/撤销快捷键，本轮必须实际证明编辑文字不会删节点，画布焦点下撤销/删除作用于正确临时对象。键盘无法直接空间拖拽时，节点列表/属性等已有替代路径必须可达，不能只声明 React Flow 默认可访问。 |

## 最小故障链：仍在上述隔离数据上串行执行

| 场景 | 注入边界与证据 |
|---|---|
| 真实画布 412 | 第二个独立浏览器/授权 API 客户端改同一隔离画布；保留第一份草稿，展示明确冲突。比较后再次制造版本变化，旧选择不能直接覆盖。明确重新核对、应用选定修改后，原草稿及同伴不冲突内容均存在。 |
| 服务端已提交、响应丢失 | Playwright 对目标 PUT/POST 先 `route.fetch()` 让真实服务提交，再丢弃这一次响应。读回确认同一效果，并记录请求/对象或修订次数；刷新不得自行新建另一个对象。若用户需显式恢复，必须执行该按钮后才报告成功。 |
| 离线与授权失败 | 仅阻断夹具目标请求，输入持久后刷新；恢复网络后重新核对当前身份。另在隔离身份撤权，不能泄露旧正文或继续提交。迟到响应不能让已离开的编辑器重新导航、覆盖新对象输入。 |
| 本机持久化失败 | 复用真实 IndexedDB transaction abort：发送前写入失败应零业务请求；服务端已成功但本机清理失败时保留已完成回执，明确重试清理不能再次提交。正常关闭/打开不能丢掉已接受的排队输入。 |
| 媒体 URL/读取失败 | 仅针对夹具原 grant，模拟一次过期或下载中断，验证授权重新读取/明确重试；媒体文件和源 ID 不变。不要把派发一个 DOM `error` 事件等同于真实解码成功或真实失效鉴权。 |
