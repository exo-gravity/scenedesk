# 场次自由画布：首版交互设计 v0.1

日期：2026-09-09。用户已明确：每个场次的镜头制作同时支持分镜模式和自由画布，随时切换，共用剪辑与固定稿审阅。本稿将最新范围与 TapNow／LibTV 的参考机制落为交互设计；不是已实现声明。它替代旧文档中“首版画布后置”的范围判断。画布持久化、API、并发保护与验收设计现已补入[18](../implementation/18-canvas-workspace-contract.md)及OpenAPI1.2.0，真实业务仍待实现。

## 1. 设计依据与取舍

证据详见[独立核对](../research/2026-09-09-scene-canvas-interactions.md)。TapNow 以官方节点、图片工具、画布整理和快捷键说明为依据；LibTV 以用户提供的两张截图支持静态布局判断，未登录实测。以下“首版设计”均为我们的选择，不表示竞品完全相同。

| 借鉴机制 | 首版设计 |
|---|---|
| 选中对象后出现相关工具 | 在节点附近显示工具栏，开始编辑后显示本次参考、提示和参数；只显示该对象、账号和模型实际可用的操作 |
| 从结果继续创建 | 节点右侧 `+` 或“继续创作”创建下游草稿，带入明确来源；原结果保留，不直接触发收费 |
| 多份材料共同参考 | 多选后“用作参考”创建带多份输入的新草稿；连接与本次真实输入分别可核查 |
| 历史可以重新放回画布 | 删除节点仅移除该画布呈现；媒体和作业历史仍可查询，恢复不重购任务 |
| 空间整理与正式制作分开 | 分组、位置和便签用于自由整理；镜头归属、采用、剪辑使用有独立记录 |

参考：[TapNow 节点与连接](https://docs.tapnow.ai/zh/docs/canvas/understand-nodes-and-connections)、[图片工具](https://docs.tapnow.ai/zh/docs/canvas/generate-and-edit-images)、[画布整理](https://docs.tapnow.ai/zh/docs/canvas/organize-your-canvas)。

## 2. 页面结构

```text
旧钥匙 / 第1集 / 咖啡厅     [镜头制作 | 剪辑]       审阅稿 v1 · 待修改
                           [分镜模式 | 自由画布]
当前模式的制作区；素材和历史按需展开，助手可收起
```

首版每场一张画布，归属于该场次及项目；用户偏好记录上次使用的模式。完整画布保留当前场次的参考与探索，不因切换镜头而卸载其他内容。镜头切换只定位相关节点；一次来源可服务多个镜头，媒体不重复上传。

**用户已确认的范围与粒度：** 分镜模式与自由画布都是整个场次的制作方式。分镜模式以全场镜头顺序导航，主区域聚焦当前镜头；自由画布在同一张画布中组织多个镜头的参考、草稿和结果，当前编辑对象可以是一个节点或一组节点。选择镜头只改变编辑焦点或定位，不创建、替换或清空场次画布。人物／场景参考可跨镜头共用，也允许未归镜头的探索内容；不要求每个节点绑定镜头或每个镜头套一个固定容器。

当前高保真呈现以[已确认核心体验 v0.3](scene-walkthrough-review-v0.3.md)为准：分镜模式采用当前镜头大预览、中央底部有界输入和底部分镜条；自由画布采用独立节点、就近短工具与中央稳定长输入。助手和完整参考浏览非模态停靠，窄桌面不并列两个完整辅助栏。旧[双模式效果图](scene-dual-mode-visuals-v0.4.md)保留为历史，不再规定右侧输入布局；原型不替代真实工程验收。

“每场一张画布”是当前短剧业务的组织规则；通用画布能力不以集／场次／镜头作为存在前提。长期广告复用方向已由用户确认，见第 9 节。

### 画布区域

- 中间：节点可自由移动、框选和分组，连线表达来源与引用；无强制的“一个镜头一个大容器”。镜头标签和可选分组便于找回对应创作内容；拖入分组不自动改变镜头归属。
- 常驻工具：添加、选择／手形、缩放、适应内容；素材、历史、节点查找以可收起入口提供。节点数量增加后保留列表定位，缩略导航按实测需要加入。
- 单选节点：附近出现轻量工具栏；输入区域在清晰标明的当前创作草稿旁打开。原结果的参数属于来源记录，修改参数会形成新的尝试。
- 输入空间不足：调整视口或展开编辑面板，媒体保留完整画幅；不以永久遮住图片／视频的浮层换取工具面积。
- 多选：显示数量及共同操作，如移动、分组、用作参考；不同时展开多个提示框。
- 未选中：隐藏对象工具与输入面板，保留基础画布工具。

Chat 可作为辅助入口，使用明确选定的节点作上下文；直接节点操作应能完成基础创作。首版沿用有限的提示准备与返工建议，不由加入画布推导出任意 Agent 编排。

## 3. 基础交互契约

| 动作 | 首版行为 |
|---|---|
| 单击节点 | 选中并显示局部工具，媒体颜色不变；选中不是采用 |
| Shift＋单击 | 加入／移出多选集合 |
| 拖节点标题或留白 | 移动选中节点；输入框、文字选择、播放器及连线端口不触发拖动 |
| 选择工具下拖空白 | 框选；空白单击取消选择 |
| 手形工具／空格＋拖动 | 平移；中键拖动也可用；输入框内空格维持正常输入 |
| 滚轮／双指移动 | 平移；Ctrl／Cmd＋滚轮或捏合以指针为中心缩放。另提供缩放按钮、100%和适应内容 |
| 双击空白／添加按钮 | 在点击位置／当前视野创建文字、图片、视频或音频节点；也可上传素材 |
| 拖入文件 | 在落点创建上传状态，进度／失败留在对应节点；验证通过才可作为生成输入 |
| 右侧 `+`／继续创作 | 新建下游草稿并关联当前来源；用户选择目标类型，核查参考和参数后执行 |
| 多选后用作参考 | 一次创建下游草稿，候选参考逐项可检查、移除及设定用途 |
| 手动连线 | 合法来源连接到创作草稿；不能改写已提交作业的真实输入。重复、不支持及循环引用明确拒绝或解释 |
| 复制／粘贴 | 复制节点表现及可用草稿配置，沿用素材引用；不复制执行中的任务，不产生收费，结果副本不变成新候选 |
| Delete | 删除当前画布节点／连接；不删除底层媒体、候选、已提交作业或固定稿；输入框内正常删字 |
| 撤销／重做 | 撤销当前画布的布局／草稿编辑；不撤销已发生模型消费、正式采用或剪辑保存。相关业务操作使用各自明确命令 |
| 节点列表／查找 | 搜索名称及文本，选择结果后定位并高亮；不改变采用或执行状态 |

这些快捷键是我们的首版交互契约，官方来源只证明证据表中的对应项。浏览器原生输入、复制粘贴和可访问性操作优先；必要操作同时有可见菜单入口。

## 4. 引用、执行和新尝试

1. 连接先表示可用于本轮创作的来源；输入区明确列出实际选中的参考及用途。`@` 用于指明对应材料，未选中参考不会因距离接近自动进入请求。
2. 新草稿可以来自一个结果或多个参考。上游为结果节点时固定其当前具体产物，而非跟随以后“最新结果”；对上游做新尝试不自动更新下游。
3. 点击准备／生成入口，按实际服务显示模型、数量、规格、引用版本与预计消耗；模型不支持的节点类型、时长等在提交前说明。
4. 明确执行后共用现有 GenerationPlan／Job、预算、权限和幂等服务。UI 显示实际排队、执行、处理、可用、失败或待核对状态；不能用模型成功代替归档成功。
5. 新结果与来源并存；结果就地比较，再继续创建下一次草稿。批次多个产物可逐项展开，不为简化画布丢弃其他输出。
6. 已提交后断线、切模式或关闭画布不重发任务。删除节点也不等同于取消作业；取消和失败恢复由共享任务服务处理。

## 5. 与分镜模式互通

- 有镜头的素材：以稳定镜头／候选身份定位，画布上的镜头标签是可见关联，不从位置、名称或分组猜测。
- 自由探索结果：先保存为场次内可找回素材；人工“关联已有镜头／新建镜头”后按媒体类型建立参考或视频候选。图片不能被错误创建为仅支持连续视频区间的 Take。
- 未归镜头的文字、草稿和成果：画布继续自由放置；分镜模式使用可收起入口查看，不能在切换时丢失。
- 切换：恢复当前场次与最近相关对象，以及每种模式的视口、选中和未提交输入。无镜头关联的节点不会被强行归入最后选中的镜头。
- 已关联的结果改参数：新建尝试；不改旧候选、不自动采用、不替换剪辑，也不更新固定稿评论时间。
- 首次打开可为已有镜头建立初始摆放；以后不因排序或切换重新布局。新镜头按需加入可见区域，已有节点位置保持。

## 6. 共享与保存

画布的节点、连接、分组和草稿采用独立保存记录，引用统一媒体、任务、资产和镜头。访问继承项目权限；视口和上次模式为用户偏好。自动保存必须展示失败和未保存状态；不得以最后写入覆盖同伴操作。

首版多人共享但不预设实时共同编辑。首版选择整文档revision／If-Match版本冲突保护；冲突保留本地输入并明确选择重应用，详见18。不能用 React Flow 内部状态取代服务端授权、执行记录或保存协议。

## 7. 首版和后续范围

首版必需：基础移动与定位、四类内容节点、上传与引用、单次图像／视频生成、继续尝试、多选参考、草稿保存／撤销、结果历史恢复、模式互通和冲突保护。声音生成及局部加工仅开放实际已接通的能力。

后续：任意可编程节点、流程循环／条件／自动重跑、模板市场、全自主 Agent、多视频同步比较、实时共同编辑。镜头分组是整理能力，不把场次画布变成通用工作流引擎。

本次示意用于检查独立节点、局部工具、引用、新尝试、导航与模式关系；不验证真实模型、服务端保存、多人协作、完整上传或收费执行。工程组件仍需按 Mantine 通用 UI＋画布专用引擎边界实现，不将示意脚本作为生产画布引擎。

本轮浏览器已核对示意中的节点拖动、撤销、框选、多选参考新草稿、平移、缩放、切模式后提示与参考保留、来源保留及共用剪辑／审阅入口；736与360视口没有页面横向溢出。窄屏使用节点列表展示，不构成移动端自由画布验收。[桌面截图](../../output/playwright/canvas-basics-desktop.png)、[基础检查](../../output/playwright/verify-canvas-basics.js)、[导航检查](../../output/playwright/verify-canvas-navigation.js)。

## 8. 验收场景

1. 同一场次来回切换，草稿、选中镜头和视口可恢复，另一种模式看见同一候选身份。
2. 在任意位置从人物和场景参考继续创建；实际输入可见，不自动消费。
3. 从结果 A 创建 B，A 及正在使用 A 的剪辑、v1 审阅均保留。
4. 删除画布 A 后，原候选与审阅仍可读；历史恢复同一成果，不启动模型任务。
5. 多选、输入、播放、拖动及画布快捷键不争抢事件；键盘能完成主要动作。
6. 断网恢复、保存冲突和未知提交不覆盖内容、不重复购买；未归镜头结果可找回。
7. 同一场次存在至少两个镜头的节点及一份共用参考；在镜头间定位、切换制作模式后，仍是同一张场次画布，节点与草稿不丢失、布局不重排，镜头顺序和采用不被改写。

## 9. 已确认：通用画布与广告演进方向

日期：2026-09-09。用户认可：当前用短剧场次把画布做扎实，底层按通用创作空间设计；未来广告工作台优先评估“画布＋助手”作为主要创作空间。确认的是产品与架构方向，广告具体默认界面及营销人员需要看到多少节点／连线仍待目标用户验证。

### 不同用户的进入方式

| 场景／使用者 | 产品方向 |
|---|---|
| 当前短剧团队 | 同一场次内分镜／自由画布双模式，按偏好切换，共用镜头成果、剪辑和固定稿审阅 |
| 后续广告制作团队／内容工厂 | 从广告制作任务进入画布，组织品牌材料、创意分支、生成结果和多个版本；按产能需求进一步支持批量操作 |
| 后续商家／教育机构营销人员 | 从目标、Brief 和材料开始，由助手组织可观看、可修改的方案；画布承载成果，节点与连线操作按需展开 |

广告中的创意探索、卖点组合与渠道版本可能使画布成为主要空间，但不把“广告适合画布”当作所有营销人员愿意手动编排节点的证据。助手与直接编辑应处理同一批成果，便于用户接手。

### 现在应守住的架构边界

1. 通用画布拥有节点呈现、位置、连接、分组和创作草稿；引用统一素材与任务，不把一个节点定义为一个 Shot。
2. 短剧模块负责场次归属、镜头绑定、当前采用及连续性要求；“每场一张”的约束位于短剧接入层。未来广告模块提供广告任务、商品／课程、品牌、受众、卖点和渠道等上下文。
3. 通用画布模块不反向依赖短剧实体。业务上下文通过明确的接入边界提供；服务端验证实际归属及项目权限，不能将任意 contextType/contextId 当作授权依据。
4. 素材、生成执行、费用、播放、剪辑运行、审阅和导出按已有边界复用。镜头 Take／Selection 等短剧语义继续保留；广告立项时定义自己的制作目标与审批对象，再扩展需要的公共接口。
5. 当前落地场次画布所需的真实能力，暂不创建广告业务实体、广告入口、插件市场或任意节点执行框架。未来广告可以直接绑定广告任务，无需构造虚假的集、场次或镜头。

通用画布保存协议、短剧场次绑定及权限、媒体／作业引用、模式互通和冲突保护的设计已由18闭合；这些API仍待实现，广告具体业务接口后续独立扩展。模块责任同步见[技术架构](../implementation/05-architecture-and-operations.md)。
