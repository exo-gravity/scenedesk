# 国内外 AI 视频／短剧工作台：画布定位与使用设计复核 v2

调研日期：2026-09-07。状态：新一轮公开证据研究与设计建议；不自动改变当前短剧 MVP 的已定范围。

后续讨论更新：用户希望暂缓界面选择，先以第一性原理与目标用户验证推进。本文“主要工作区”的建议现保留为未胜出的候选，不能作为主界面已定依据；详见 [工作区决策与验证框架](../ai-drama-workspace-decision-and-validation-v0.1.md)。下文竞品证据与历史推论原样保留。

## 1. 结论与需要修正的原判断

**画布已经出现在多种产品的主创作空间中，承载创作上下文、素材操作与制作关系；把它仅定义为灵感板或分镜表的可选显示方式，不能充分解释这些产品的设计。** 但“无限”主要表示空间可以扩展，并不保证流程自动化、角色一致性或团队生产可靠性。

本轮对原建议作三处修正：

1. **定位上调。** 将“结构化创作画布”列为我们主创工作区的重点原型方向，比较它与卡片／表格工作台的净收益；不再预设只能做成附属视图。
2. **粒度开放。** 研究项目内创作板、单集组织、场次聚焦的组合，不提前把每张画布硬性限定为一个场次；也不把整部剧无限铺开。
3. **范围拆开。** 创作画布、专业节点流程编辑、像素编辑器、多轨剪辑和实时多人共编是不同投入项。画布进入主要交互设计，不代表这些全部进入首版。

以上为本轮设计建议。原有“短剧优先、写实优先、Seedance 等领先模型优先、长期复用底层支持广告、初版内部团队与简单权限”保持为讨论前提。

## 4. “画布”至少承载四类不同任务

这些是设计维度，不是互斥的产品类别；一款产品可能同时具备多类。

| 任务 | 用户要解决的问题 | 空间和连接的实际含义 | 典型对照 |
|---|---|---|---|
| 编辑一张画面 | 哪里修改、物体放多大、如何合成 | 图层位置、蒙版与区域会影响像素结果 | 即梦智能画布；FLORA 局部图片编辑；Weave Compositor |
| 组织探索与比较 | 多组参考和方案如何同时看、从哪一版继续 | 摆放、分组主要帮助理解；可能没有可执行边 | Morphic Sections；LTX Canvas |
| 保持可接手的创作上下文 | 讨论、设定、素材与结果如何持续积累，让人和 Agent 接着做 | 内容对象及明确引用提供上下文；不能只靠位置邻近 | Seko；Dreamina Octo；TapNow |
| 构建与复用制作流程 | 哪些输入经过哪些模型／处理，改哪里才需重做 | 带约束的连接、批次与执行状态决定实际处理 | LTX Flows；Runway Workflows；FLORA；Weave |

Agent 是操作入口，时间线是时序编辑空间，二者可与上述任一类组合。一个产品叫“AI Canvas”，不足以确认其拥有自由连线执行、自动化批次或同屏协作。

## 5. 六种有代表性的实际使用路径

以下是从操作文档／官方说明重建的路径，不是本轮操作录像。

### 5.1 从结构起步：Katalist

导入脚本 → 左侧场景／镜头结构 → 选场景加入画布 → 操作生成卡片 → 选视频进入时间线。

借鉴点：空白画布不是必须的起点。结构可以由脚本提供，画布负责就地操作与方案展开。其图像到视频教程不能约束我们所有模型路径。

### 5.2 从选择上下文起步：TapNow、Dreamina

放入参考或已有内容 → 明确选中／引用 → 与 Agent 提出下一步 → 结果留在创作空间 → 局部选中继续。

借鉴点：用户可以通过“选对象后表达意图”推进工作，不必先画完整流程。必须能查看实际输入，而不是假定 Agent 已读到整个画布。[TapNow 起步文档](https://docs.tapnow.ai/en/docs/canvas/explore-the-canvas)、[Dreamina 工作区](https://dreamina.capcut.com/ai-video/ai-creative-workspace)

### 5.3 从已验证工艺起步：Runway、FLORA、Weave

熟练创作者构建流程 → 试运行并调整 → 命名和限制输入 → 发布 App／Technique／Tool → 他人通过简化界面使用。

借鉴点：流程作者需要构建能力，执行者需要明确的任务入口。这个模式适合未来营销人员，但不能省掉广告自身的 Brief、品牌与交付设计。[Runway Apps](https://help.runwayml.com/hc/en-us/articles/47865876793747-Publishing-Workflows-as-Apps)、[FLORA Techniques](https://docs.flora.ai/nodes/techniques)、[Weave Tools](https://help.weavy.ai/en/articles/12267755-tools)

### 5.4 从流水线中途接手：纳米

系统推进剧本与素材制作 → 用户查看中间内容 → 回改分镜／提示词／风格 → 继续制作。

借鉴点：画布也可作为纠错、插入创意和局部返工的入口。当前公开证据未给出完整的重跑与费用规则。

### 5.5 从生成进入组接：TapNow、FLORA

选择／连接视频 → 打开画布内的剪辑对象 → 在时间线排序与裁切 → 渲染输出回画布。

借鉴点：画布组织素材来源，时间线决定片段顺序和长度。专用编辑器可以嵌入制作空间，不必把它的每一个动作摊成通用节点。[TapNow 播放列表](https://docs.tapnow.ai/zh/docs/canvas/use-playlists)、[FLORA Timeline](https://docs.flora.ai/editor/timeline-editor)

### 5.6 从探索进入稳定交付：需要主动选择版本语义

FLORA 官方文档明确动态连接跟随来源节点的 active output；重生成会替换对应片段并重置该片段裁切。它也提供从素材库加入独立片段以避免这种跟随。这个细节说明“保持制作联动”和“保留已审结果”需要不同引用方式。[FLORA 更新与排障说明](https://docs.flora.ai/editor/timeline-editor#connected-inputs-and-live-updates)

借鉴点：我们的新候选不能悄悄改变已采用片段和已审剪辑。更新应显示影响范围，由采用／同步动作触发，并为冻结审片稿生成新版本。

## 6. 画布真正带来的价值与代价

| 价值来源 | 适合发挥作用的情况 | 代价与设计要求 |
|---|---|---|
| 多个材料同时可见 | 同角色、多场景、多拍法参考，需要快速比较 | 缩略图太多会难读；候选需要收起、聚合与筛选 |
| 关系能被查看和操作 | 存在多输入、多输出、分支返工 | 连线不能含义不明；应显示输入用途与实际使用版本 |
| 上下文持续保留 | 人与 Agent 来回推进、别人中途接手 | 同处画布不等于已引用；需可检查的上下文和来源 |
| 多工具连续操作 | 图片准备、生成、编辑、组接之间反复搬运 | 很多收益来自工具集成；对照测试要保持底层能力相近 |
| 可复用制作方法 | 同一工艺用于后续场景或新项目 | 模板发布、依赖、参数和输入替换需要治理 |
| 共享讨论空间 | 团队一起定方向、定位某个结果 | 光标／评论不等于正式审片；必须绑定内容版本与反馈对象 |

这些价值与代价是根据产品设计作出的分析，不是已测得的收益率。写实短剧特别需要跨镜头与跨集连续性，因此自由探索产生的候选越多，资产状态、采用规则和成片审阅就越重要。

## 7. 对我们方案的具体调整建议

### 7.1 产品定位：将画布纳入主要工作区方案对比

建议命名仍围绕用户任务：项目内的“创作工作台”，其中可有“画布／分镜列表／剪辑”入口。“无限画布”适合描述交互特性，不必成为与剧本、资产、审片并列的新业务模块。

建议重点原型：**左侧内容导航，中间结构化创作画布，选中对象后就地操作，按需打开候选、生成详情与时间线。** 从剧本或所选场次形成初始布局；允许从已有素材直接开始，兼容模型直接视频生成，不强制所有镜头先生成首帧。

默认聚焦当前场次以控制信息量；能查看单集结构并引用跨场次资产。底层允许项目包含多个创作板，板内放的是既有内容对象的引用，避免以后要拆除“场次就是画布”的硬绑定。多板界面、复杂跨板操作是否首版开放，另行按任务验证。

### 7.2 用同一个例子确定关系与动作

某场双人对话戏有两个人物参考、一份场景参考和三个计划镜头。主创为第二个镜头尝试两种拍法。

- 导入／选定场次后自动出现所需对象，不要求用户手动搭建基础生成链。
- 从第二镜头“继续尝试”，保留已有输入并产生新候选；参考用途可检查。
- 两个候选就地比较；改变它们的摆放不会改变镜头编号、采用或剪辑顺序。
- 主创选择候选 B 后，系统显示哪些可编辑剪辑可更新；已冻结的审片稿继续指向原素材。
- 单个生成片段若包含多个镜头，能按使用区间接入不同剪辑位置，不能被迫等同一个分镜对象。
- 审阅意见绑定具体媒体版本与时间点；画布上的便签只作为创作讨论。

这是我们推荐的行为，不是声称任一竞品已经完整实现。

### 7.3 底层需要区分的对象和关系

| 项目 | 应表达什么 | 不应由什么隐式决定 |
|---|---|---|
| 画布布局 | 节点显示位置、大小、分组、视口 | 不决定正式分镜顺序、权限或批准状态 |
| 内容记录 | 剧本、集、场次、镜头及资产的业务身份 | 不因移动／复制一个显示节点就自动复制整个业务对象 |
| 输入引用 | 角色／场景／动作／构图等用途，所用媒体版本 | 不只记录无类型连线或“在附近” |
| 生成执行 | 输入快照、模型参数、状态、费用与输出 | 不把节点当前预览当唯一执行记录 |
| 候选与采用 | 从哪些结果继续、采用哪个版本 | 不把最新生成自动当最佳或已批准 |
| 剪辑片段 | 确定媒体版本、使用区间、轨道和播放顺序 | 不由画布横向排列或生成依赖顺序决定 |
| 审阅决定 | 对象、版本、时间点、意见与处理状态 | 不等同便签位置或实时光标 |

这支持原方案的公共核心：媒体／资产版本、引用、生成任务、结果、选择、组接、审阅、费用。画布是操作这些能力的重要入口；它的布局数据不应变成整个业务系统的唯一事实来源。

### 7.4 MVP 与迭代建议

| 阶段 | 推荐验证／建设范围 | 进入条件 |
|---|---|---|
| 当前原型 | 结构化创作画布与卡片工作台使用同一场戏；覆盖参考、生成候选、局部返工、采用和入剪辑 | 看任务完成情况、错误、人工整理时间与交接效果 |
| 短剧 MVP 候选 | 若原型有净收益，交付默认布局、平移缩放、分组收起、明确引用、候选就地操作；通过既有对象同步分镜与剪辑 | 控制为一条已验证的模型制作路径，不要求任意节点编排 |
| 后续重要迭代 | 多创作板导航、跨场次复用、选择性批处理、流程定义版本、进一步团队协作 | 真实项目出现容量、重复劳动或协作瓶颈 |
| 长期共用能力 | 熟练成员封装工艺，短剧与广告分别用业务入口调用；营销人员可用表单／对话式简化工具 | 先有稳定可复用方法，再建设开放编排和发布能力 |

暂不因本次调研新增首版承诺：任意通用节点图、复杂控制流、流程市场、全功能 NLE、实时多人光标、外包权限系统。将画布列为重点原型候选与将这些全部列入 MVP 是不同决策。

## 8. 还需要真实使用才能回答的问题

| 验证任务 | 看什么 | 为什么会影响决策 |
|---|---|---|
| 同一场戏两种拍法 | 准备输入、比较、返工、采用各自用时与错误 | 判断画布相对现有卡片工作台的净收益 |
| 两个场次复用角色 | 定位参考、确认版本、跨场引用与切换负担 | 决定场次、单集和创作板的默认粒度 |
| 修改已采用素材 | 下游是否变化、是否提示、能否回到原稿 | 决定版本和审片可靠性 |
| 两名内部成员交接／同时操作 | 谁能改什么、冲突、断线恢复和费用归属 | 决定首版异步协作是否足够及实时协作优先级 |
| 一集实际规模的镜头和候选 | 寻找、收起、搜索、布局整理、媒体预览性能 | 决定大画布是否可长期使用，而非只适合演示 |
| 图／视频输入的实际模型路径 | 哪些参考被使用，输入限制、失败与成本 | 避免用统一连线掩盖 Seedance 等模型的不同语义 |

建议后续先以 Katalist 的结构起步方式、TapNow 的引用与组接、LibTV 的制作关系，以及 Dreamina／Seko 的上下文模式制作同任务交互对照。账号可用性与付费执行需要在实际体验时核查；本报告不把未执行项目写成完成结果。
