# 影视与叙事工作台画布专项复核：LTX、Higgsfield、Katalist、Google Flow、TapNow

核查日期：2026-09-07。本轮重新读取官方资料，旧笔记仅作检索线索。与国内、即梦和国际工作流三份专档共同支持本轮市场复核。

证据等级：D = 官方操作文档；P = 官方产品定位；V = 本轮浏览器看到的公开页面；I = 设计推论；U = 尚未确认。D 不代表已登录实测。本轮未创建项目、上传素材或执行生成；浏览器实际查看的是 Higgsfield 官方落地页及其界面示意图。生成质量、执行稳定性与付费方案权益不在已验证范围。

## 1. LTX Studio：Canvas 与 Flows 是两个不同的空间

**P：Canvas 是共同探索视觉方向的无限空间。** 当前官方场景页将 Gen Space、Canvas、Storyboard、Video Editor 分别用于生成探索、集中反馈与比较、形成叙事结构、调整最终时间顺序。这证明产品主动区分视觉探索与叙事编排，不能把 Canvas 内的空间排列直接视为分镜或剪辑顺序。[广告代理商方案](https://ltx.io/studio/solution/advertising-agencies)、[创意总监方案](https://ltx.io/studio/solution/creative-director)

**D：Flows 是另一个项目页签中的节点执行空间。** 2026-05-07 官方教程明确它与 Canvas 等空间并存。它支持带类型约束的连接、提示词与素材迭代器、单节点或整条流程执行、取消运行、执行历史。缓存使未变动步骤可以复用结果，变动沿依赖传播。图片接到视频首帧端口具有生成输入语义，不是普通的视觉关联线。[Flows 官方教程](https://ltx.io/blog/ltx-studio-flows)

**D：资产能力也受使用路径限制。** Color Elements 可在多个创作空间的图片生成中引用；官方文档将直接视频使用与先形成图片再作为视频参考区分开。[Color Elements](https://help.ltx.io/hc/en-us/articles/35494322496786-How-to-use-Color-Elements)

典型路径（根据官方文档重建，非本轮实操）：生成视觉方向 → Canvas 汇集比较 → Storyboard 编排 → Editor 调整；需要重复制作工艺时，在 Flows 配置和复用。两条路径之间具体如何同步每个素材版本，本轮没有足够操作证据，不能画成全自动无损双向同步。

**I：对我们的启发。** 创作工作区与专业流程编排可以复用执行能力，但不必共享同一种界面。不能以“LTX 有画布”为由认定它强制用户用节点图完成全部制作。

## 2. Higgsfield：Canvas 是多模型链路、探索与团队共创入口

**P／V：定位非常明确。** 官方落地页以同一空间容纳 moodboard、工作流与团队分享；本轮浏览器看到了上传图片、文本、图像生成、视频生成的连接示意，以及评论和协作者标记。这是宣传页面的视觉证据，不能据此声称已体验编辑器或多人协作。[Canvas 产品页](https://higgsfield.ai/canvas-intro)

**D：帮助文档给出节点工作流用法。** 从新画布添加文本和媒体输入，连接生成节点，选模型，按节点或序列运行；比较分支并保存模板。官方将其与偏整项目生成的 Supercomputer、偏电影镜头控制的 Cinema Studio 区分。该文档的完整正文由本轮搜索抓取返回，直接打开两次超时，因此记为“官方已索引帮助正文”，不声称浏览器已进入该帮助页。[How do I use Canvas?](https://higgsfield.ai/creator-hub/help-center/tools/how-do-i-use-canvas)

**D：连接图片不等于明确了图片用途。** 同一帮助页说明，Seedance 的参考还需要在提示中说明角色／地点／产品用途；Kling 直接连接图片与使用 Element 引用角色的路径不同。这是模型适配对画布设计的约束，不能用一条无类型“参考线”掩盖。

**P／D：协作主张有对应的操作描述。** 产品页描述共享画布、节点评论与版本保留，帮助页描述邀请成员、同时增加节点和运行独立生成。未核查套餐、编辑冲突、审批与冻结成片规则，也不将自动保存等同于不可变审片版本。

**I：对我们的启发。** 参考上下文、生成链与团队沟通能在同一个空间中共同呈现；底层仍必须保存输入用途、执行快照与明确的采用动作。实时光标不是协作生产管理的替代品。

## 3. Katalist：脚本给结构，Story Canvas 给操作空间，Timeline 给顺序

**D：当前 Story Canvas 操作指南提供了完整的衔接过程。** 从脚本创建项目后，左侧形成场景／镜头结构；选择场景添加到画布会出现生成卡片。角色、地点与帧卡片配合使用，选中的卡片可分组；帧可以继续生成视频，结果可以加入时间线并导出。[Story Canvas 操作指南](https://help.katalist.ai/en/articles/16298583-how-to-build-your-storyboard-and-videos-in-story-canvas)

典型操作（对上述指南的归纳）：导入脚本 → 左侧选择场景 → 自动形成画布对象 → 生成／调整角色和画面 → 继续制作视频 → 加入时间线 → 导出。

**P：当前定位也覆盖效果广告团队。** 官网强调脚本、故事板、视频和产品内容制作；Story Canvas 的 early-access 页面则展示整体制作空间。页面存在不同代际的文案，具体操作优先参考当前帮助指南，不用早期宣传补齐未确认能力。[官网](https://www.katalist.ai/)、[Story Canvas 产品页](https://www.katalist.ai/story-canvas-early-access)

**U：本轮未确认** 任意有向图连线规则、画布与时间线的版本传播、正式镜头审批和细粒度团队权限。其教程采用图像到视频路径，不能将它泛化为所有模型必须先逐镜生成首帧。

**I：这是短剧工作台尤其值得借鉴的结构。** 用户先有脚本和内容对象，再在画布中操作；因此“主创作画布”不必意味着空白画布或完全手工搭建流程。脚本侧栏、画布和时间线各司其职。

## 4. Google Flow：不能因为官方说 Canvas 就归入节点图产品

**P：当前首页确实采用 Canvas、Agent 和自定义工具的产品叙述。** 但“Canvas”一词本身不能证明有任意端口连接或无限空间。[Flow 官网](https://labs.google/fx/tools/flow)

**D：实际可读帮助仍需按具体操作分类。** 项目文档描述 Grid／Batch 视图、媒体类型筛选、角色、嵌套 Collections，以及 Agent 辅助整理资产。它提供对多媒体资产与参考的管理能力，不应只因没有节点图证据就认为缺少工作台价值。[项目、资产和 Collections](https://support.google.com/flow/answer/16935308?hl=en)

**D：版本和编排存在明确动作。** 编辑保留原始版本与 History；Scenebuilder 接收片段后排列、裁切和预览，导出场景。旧版本进入场景前有保存到项目的操作。Agent 对话、素材版本与视频时间顺序不是同一种结构。[编辑视频与构建场景](https://support.google.com/flow/answer/16935718?hl=en)

**D：复用可以通过简化工具完成。** 用户用自然语言描述 Tool，系统生成可操作界面；工具产出保存在当前项目，分享链接对应分享时的工具版本。这提供了不依赖用户手工搭建节点图的另一种复用机制。[创建与管理 Tools](https://support.google.com/flow/answer/17104535?hl=en)

**U：本轮未确认** 与 FLORA 相同的无限节点空间、任意依赖图执行和专业短剧审批结构；这不等于确认产品没有这些能力。

**I：对我们的启发。** 评价维度应是参考复用、局部修改、候选和版本、制作复用与成片编排，不能只按有没有无限画布排名。未来营销人员可以使用简化任务界面，输出仍回到统一的项目资产与版本体系。

## 5. TapNow：引用、Agent、流程模板与剪辑分别有明确操作

**D：画布是主要创作空间。** 节点存放文本和媒体；可以从已有节点继续创建、手动连接或多选后创建下游。中文指南尤其明确：连线使上游成为可用参考，具体生成仍需检查 Prompt 中的 `@` 引用和用途，不能把已连接与已正确使用混为一谈。[节点与连接](https://docs.tapnow.ai/zh/docs/canvas/understand-nodes-and-connections)

**D：Agent 处理显式提供的上下文。** 官方描述从选择节点、交给 Agent 到新结果回画布的起步方式；来源节点继续保留。画布中的可见对象和实际被 Agent 引用的对象需要分别核查。[认识画布](https://docs.tapnow.ai/en/docs/canvas/explore-the-canvas)、[TapNow Agent](https://docs.tapnow.ai/en/docs/agent/tapnow-agent)

**D：复用有不同层级。** Library 保存可复用媒体，Element 汇集主体参考，Template 保存节点、连接及结构；套用模板向当前画布增加分组。分组可以运行并显示预计费用，估计暂不可用时有继续选择；这不等于所有执行都必有可靠报价。[素材库与模板](https://docs.tapnow.ai/en/docs/canvas/use-library-and-templates)

**D：播放列表是画布中的专用剪辑对象。** 选取视频建立播放列表后，在时间线上排序、裁切和切割，原节点保留；可以定位来源、下载原片段、导出合并 MP4 或送回画布。没有据此确认专业 NLE 工程导出或重生成自动替换规则。[播放列表](https://docs.tapnow.ai/zh/docs/canvas/use-playlists)

**D：团队共编与链接分享明确不同。** 团队空间支持同一画布同步编辑、在线成员和跟随视角；分享链接以只读打开，克隆形成独立副本。[团队创作](https://docs.tapnow.ai/zh/docs/projects/create-with-your-team)、[分享与克隆](https://docs.tapnow.ai/en/docs/projects/share-view-and-clone)

**D：评论不是正式审片状态。** 当前指南写评论作为节点存在，允许回复，但没有“已解决”状态。评论与画面并置有助沟通，不能据此认定具有绑定视频时间码、固定候选版本与审批决定的审片系统。[评论与反馈](https://docs.tapnow.ai/zh/docs/projects/comment-and-send-feedback)

**I：对我们的启发。** 创作空间可以集成引用、执行、模板、组接与团队沟通，但每类操作仍有明确对象和规则。不同的“线”和“顺序”必须解释清楚，通用评论与业务审片要分别验收。本轮未实际登录操作，亦未验证当前账号权益与稳定性。

## 6. 横向比较

| 维度 | LTX Studio | Higgsfield | Katalist | Google Flow |
|---|---|---|---|---|
| 起步方式 | 生成／探索空间；另有 Flows | 新画布、素材与生成节点、模板 | 脚本解析后按场景进入画布 | 项目、生成／Agent／Tools |
| 画布核心价值 | 视觉方向协作；执行图另设 | 多模型依赖、并行探索、复用与沟通 | 结构化脚本与视觉生产连接 | 不能仅凭名称认定节点图；已确认资产组织与场景组接 |
| 画布布局是否等于成片顺序 | 无此证据 | 无此证据 | 时间线独立定义顺序 | Scenebuilder 定义顺序 |
| 执行机制有何证据 | Flows 类型、缓存与执行历史明确 | 单节点／序列、模型输入用途明确 | 帧与视频卡片生成明确，通用图执行未确认 | 生成、Agent、Tools 明确，通用图执行未确认 |
| 最值得带回产品讨论 | 探索与专业流程可分开 | 连线用途必须适配模型 | 自动结构化起步与多视图协同 | 使用业务能力评价，不以画布外形排名 |

TapNow 则把主要入口设在画布，并通过显式引用、Agent、分组模板和播放列表承载制作。这五款都是影视／视频制作的直接或相邻参考；本轮没有证明它们全部具备面向中国短剧工作室的剧目、集、场次、镜头、审片和成本管理闭环。
