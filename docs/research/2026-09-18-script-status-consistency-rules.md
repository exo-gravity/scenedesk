# 剧本页：状态展示的一致性规则（"通知轨"）

日期：2026-09-18。**状态：设计规则，待确认。** 配套：[旅程与状态设计](2026-09-18-script-journey-and-states.md)、效果稿 `#/script-layout`。

## 0. 为什么要定这套规则

第一版效果稿在**位置、样式、宽度、文案**四处各写各的，同一类信息在不同状态下出现的位置和长相不同，用户每次都要重新判断"这是什么、要注意什么"。本规则把状态类信息收敛成**一个组件、一个位置、一套色义、一套句式**。

## 1. 规则一：位置固定 —— "通知轨"

**所有状态类信息只出现在一个位置：版本行之下、正文之上。**

```
剧本                                                        ⋯
────────────────────────────────────────────────────────────
当前稿 · 纯文本 · 旧钥匙_第1集_初稿.docx · 8 月 12 日更新
┌──────────────────────────────────────────────────────────┐
│ ▎（通知轨：所有状态信息都在这里，同一位置、同一宽度）        │
└──────────────────────────────────────────────────────────┘
        第 1 集 · 重逢
        01　咖啡厅 / 日 / 内
```

| 规则 | 内容 |
|---|---|
| 位置 | **固定一条轨**（版本行下方、正文上方）。不再出现"页头之上""版本行之上"等变体 |
| 宽度 | **固定对齐内容区**（左 250、右留 48）。不做"有的通栏、有的 1120" |
| 数量 | **同时最多两条**;多条合并为一条摘要（`导入时有 3 条说明`） |
| 顺序 | 固定优先级：**错误 > 警告 > 中性**。同类只出现一条 |

## 2. 规则二：一套色义（四种语义，只有四种）

| 语义 | 何时用 | 左色条 | 底色 | 图标 |
|---|---|---|---|---|
| **中性**（info） | 例行提示:草稿已保留、导入说明、只读状态 | 灰 | 极浅灰 | 无 |
| **提醒**（warn） | 需要留意但不阻断:导入有说明、本机文件与当前稿不一致 | 琥珀 | 极浅琥珀 | 无 |
| **失败**（danger） | 动作失败:读取失败、导入失败、版本找不到 | 红 | 极浅红 | 无 |
| **受限**（readonly） | 能力被关闭:项目已归档、历史稿只读 | 灰（同中性,但**带徽标**） | 极浅灰 | 无 |

**约定**：*不用图标区分语义*（左色条 + 底色已足够,图标会与动作图标混淆）;受限态用**徽标**而不是色条强度,避免与失败混淆。

## 3. 规则三：动作形态 —— 通知轨一律文字动作

**通知轨里的动作只有一种形态：文字动作。主选加粗 + 次选常规，跟在说明后面同一行。**

| 情况 | 形态 |
|---|---|
| 全部情况 | **文字动作**。主选 `font-weight: 600` + 下划线；次选常规 + 下划线；同一行、紧接说明之后 |
| 只需一个回应 | 只给主选（例：草稿恢复的「继续导入」） |
| 没有回应 | 不出现动作（例：归档横幅、只读提示） |

**为什么不用按钮**（2026-09-18 经五档对照确认,选定 **C**）：

1. **假层级**：实心 + 描边暗示"实心更推荐";若两个动作对等,该层级并不存在 —— **假层级比没有层级更难看**。
2. **按钮是"目标",通知里的动作是"回应"**：`Button` 的填充与最小宽度是给页面主动作用的。
3. **一屏按钮过载**：同页已有空态的两个平级按钮与工具栏按钮,通知轨再放按钮会互相抢注意力。
4. **一致性优先**：曾考虑"高影响确认才用按钮"（如确认导入）,实测后**取消该例外** —— 通知轨只有一种形态,读者不需要判断"这次为什么是按钮"。

**位置属性行的动作不受此限**：版本行里的「返回当前稿」是**版本属性**的动作（合法位置之「就地」）,用按钮可以。

**取舍记录**：曾评估"两个描边按钮"（消除假层级但仍重）与"只给一个文字动作"（最轻,但缺少"明确拒绝"的出口）。最终选**两个文字动作**:层级交给**字重**而不是填充,同时保留拒绝路径。

## 4. 规则四：信息密度 —— 一律一行

**一行说完「什么情况 + 要做什么」。**

| 情况 | 形态 |
|---|---|
| 全部情况 | **一行**。例：`本机有一个未完成的导入，与当前稿不一致，需要你决定保留哪一份。` **继续导入** 放弃本机文件 |
| 需要类别标签时 | 用**徽标**（11px 描边小字）,与说明**同一行**,不额外占一行 |
| 需要展开的说明 | 摘要一行 + `展开` 文字动作（不预先把细节铺成第二行） |

**不再有"标题 + 说明"两行形态**：曾允许"标题是类别标签且信息不同"时分行,实测后**取消** —— 标题在多数情况下只是复述下面的句子。

**反例（改前）**：标题「本机有一个未完成的导入,与当前稿不一致。」+ 说明「需要你决定保留哪一份。」—— 读者要读两段才知道是一件事。

## 5. 规则五：几何 —— 全部可推导，不逐块调

**内容列变量**（同一页唯一）：

```
--col-left  : 内容列左边界（与页头、正文、版本行同起）
--col-width : 内容列宽度（同页所有块同宽）
```

| 项 | 规则 |
|---|---|
| **位置** | 固定一条轨（版本行与正文之间） |
| **宽度** | 与同页内容列**同宽同起**（不得比邻列宽或窄） |
| **内边距** | `spacing.md × lg`（12 × 16）,用 spacing 步长,不用孤立像素 |
| **块间距** | `sm` / `md` / `lg` 三档 |
| **高度** | **由内容 × 统一间距推导**,不写死：单行 ≈ 42px、带标题 ≈ 62px、带动作行 ≈ 52px |
| **结构** | 纵向序列：徽标 → 标题 → 「说明 + 动作」行 |
| **色条** | **2px** 左色条 + **只圆左侧**（`--ws-control-radius`）;避免 3px 色条配 4px 圆角 |
| **语义** | 只改**左色条与底色**;四语义几何完全一致;**不用图标区分** |
| **字号** | 三档：标题 13/600 · 正文 12 · 徽标 11,靠字重与颜色分层 |

### 5.1 三个合法位置共用同一套几何

三个位置**只在语义范围上不同,几何同族**:同一内容列、同一内边距、同一色条与圆角。

| 位置 | 语义范围 | 位置要求 |
|---|---|---|
| **页级横幅** | 整页（项目归档／权限） | 与页头**同列**,出现在**标题之后**（不是页头之上,也不是全出血） |
| **通知轨** | 内容（导入／保存／读取／冲突） | 与内容列同列,在**版本行与正文之间** |
| **就地** | 某个字段或对象 | 紧贴该对象;可自带动作（如版本行的按钮） |

**禁止全出血或负边距**：那会让同一页出现两套视觉体系（曾出现:归档横幅跨满宽度并顶出页左边界）。

### 5.2 待补 token（主题的缺口）

主题的 `--ws-{success,warning,danger,info}` 是**暗色主题值**,且**只有前景色,没有底色与文字色变体**,浅色表面无法直接复用。建议补：

```
--ws-{info,warn,danger,readonly}-surface   语义底色（区分浅色/暗色两套）
--ws-{info,warn,danger,readonly}-text      语义文字色
```

在补齐之前,浅色表面需要显式声明这四组值（本轮效果稿即如此,并在 CSS 注明"补 token 后应改为引用"）。

**另一处静默失败（本轮由机器检查抓到）**：设计预览壳**不注入主题变量**,稿子里引用 `var(--ws-control-radius)` 会静默回落成 `0px`。注释里已写明变量值须在本稿声明。**未定义的 CSS 变量在浏览器里不报错** —— 这类问题只能靠机器检查发现。

## 6. 一个组件，一套结构

**所有通知都是同一结构，只有语义与内容不同：**

```
▎ [动作区]  标题（可选，一行）
▎          说明（一行）
▎          [ 动作按钮 ]  [ 次要动作 ]
```

| 规则 | 内容 |
|---|---|
| 组件 | **统一一个 `Notice` 组件**（不再混用 `Alert`、自绘 div、正文小字） |
| 标题 | 可选。**需要用户做决定时必须有标题**（冲突裁决）;纯告知可省略 |
| 动作 | 最多两个:**一个主/一个次**。中性态通常没有动作 |
| 高度 | 单行说明约 36px;带标题+动作约 72px。**不超过两行说明** |

## 7. 文案句式统一

### 7.1 三类句式（按功能固定）

| 功能 | 句式 | 例 |
|---|---|---|
| **告知状态** | `{对象}已{结果}` | `文件已保留，离开后可继续导入。` |
| **说明原因** | `{现象}，因为{原因}` 或 `{现象}。{可做什么}` | `文件无法完整解析。已选文件仍保留在本机。` |
| **需要决定** | `{情况}，需要你决定{什么}` | `本机有一个未完成的导入，与当前稿不一致，需要你决定保留哪一份。` |

### 7.2 统一约定

| 项 | 约定 | 反例（现状） |
|---|---|---|
| 标点 | **全角**（：，。）；代码标识符与英文串内保持半角 | 混用 `，` 与 `,` |
| 句尾 | **告知/说明类都带句号**;按钮与标签不带 | `尚未导入 · 请核对正文和显示说明`（无句号、用间隔号连接两句） |
| 分隔 | **不用 `·` 连接两个句子**;`·` 只用于同一行的并列字段（版本行） | `正在读取 · 文件名` |
| 人称 | **不出现"你"以外的第二人称**;不提"系统""平台" | `项目已归档：仍可阅读与引用` |
| 时态 | 进行中用`正在{动作}`;完成用`已{动作}` | `读取中…` / `已保留` 混用 |
| 否定 | 用`不会`/`未`;不用`无需`以外的书面否定 | `不会自动覆盖` → 统一为 `未自动覆盖` 或 `需要你决定` |

### 7.3 术语表（同物同名，只用一个）

| 概念 | 只用这一个词 | 不得混用 |
|---|---|---|
| 正在读的版本 | **当前稿** | 最新稿、现行稿 |
| 非当前的版本 | **历史稿** | 旧稿、历史版本 |
| 本机未提交的导入 | **未完成的导入** | 草稿导入、待提交文件 |
| 带段落进画布 | **带入画布** | 引用到画布、选文进画布 |
| 项目/内容被归档 | **已归档** | 已停用 |
| 无权限 | **只读** | 无权、受限 |

## 8. 按规则重画后各状态的通知轨内容

| 屏 | 通知轨（语义 / 文案 / 动作） |
|---|---|
| ② 阅读 · 有导入说明 | 中性 · `导入时有 3 条说明。` · [展开] |
| ⑤ 导入 · 读取中 | 中性 · `正在读取文件。读取期间已选文件会保留。` · 无 |
| ⑤ 导入 · 预览 | 中性 · `导入还没有确认。确认后新稿成为当前依据，已有引用继续指向原版本。` · [确认导入] [取消] |
| ⑤ 导入 · 冲突 | **提醒**· 标题 `本机有一个未完成的导入，与当前稿不一致。` · 说明 `需要你决定保留哪一份。` · [用本机文件继续] [放弃本机文件] |
| ⑤ 导入 · 失败 | **失败** · `文件无法完整解析。已选文件仍保留在本机。` · [重新选择] [尝试纯文本导入] |
| ⑥ 草稿恢复 | 中性 · `文件已保留，离开后可继续导入。` · [继续导入] |
| ⑦ 归档只读 | **受限** · 徽标 `已归档` + `仍可阅读与带入画布。恢复项目后可导入新稿。` · 无 |
| ④ 历史稿只读 | **受限** · 徽标 `历史稿 · 只读` 在版本行内（**不进通知轨**，因为它是版本属性） · [返回当前稿] |
| ⑧ 读取失败 | **失败** · `剧本正文读取失败。` · [重试] |

**注意两处例外，并有明确理由**：

- **历史稿的只读徽标放在版本行内**（不是通知轨）—— 它是**版本属性**,与"当前稿／历史稿"同行才成立;
- **归档提示放在页头之上**（不是通知轨）—— 它是**项目级状态**,影响整页（含「⋯」动作）,放在页级位置更合理。

除这两处,**其余状态一律进通知轨**。

## 9. 落地检查（实施时逐条核对）

1. 状态信息只有**两个合法位置**：通知轨（内容级）／页级横幅（项目级）。无第三处。
2. 所有状态信息用**同一个组件**;不新增 `Alert` 或自绘状态块。
3. 通知轨宽度与左边界**唯一**（对齐内容区）。
4. 语义只用**四种**;不用图标区分。
5. 文案遵守 §7 的句式、标点、术语表。
6. 同时出现多条时按**错误 > 警告 > 中性**取一条,其余合并为摘要。
7. 通知轨动作**默认文字动作**（主选加粗 + 次选常规）；只有高影响、需要停顿确认才用按钮。
8. 通知**一律一行**；类别标签用徽标，不额外占一行。
9. 三个合法位置**共用同一内容列**；禁止全出血与负边距。
10. 通知轨内**不得出现 `Button`、不得出现标题**；字号只用 26/20/14/12/11 五档。
