# 可灵与万相：写实短剧制作流程核查

核查日期：2026-09-07。只使用官方指南、官方 API 文档及快手公告；未进行付费生成或质量横评。本文区分产品端已描述能力、正式 API 证据和工作台设计推论，不把宣传中的“一致性保证”视为实测结果。

## 结论

- 不能把“音画一体、多镜头生成、多模态参考”当作 Seedance 独有能力。可灵 3.0/3.0 Omni 与万相当前版本都有对应官方证据；实际差别更在参考材料组织、控制参数、能力组合限制及返工方式。[K1][K2][W1][W2]
- 不能用品牌名作为能力配置：可灵 3.0 与 Omni 的入口不同；万相 2.2、2.6、2.7、3.0 的模式和输入协议有明显差异。2026-09-02 更新的阿里云型号表已列出 `wan3.0-video`，不应只拿无声的 Wan 2.2 代表“其他常见模型”。[K1][K2][W1]

## 可灵：先组织 Elements，再选择单镜头、多镜头或编辑

| 维度 | 官方证据 | 工作台流程含义（设计推论） |
|---|---|---|
| 3.0 基础制作 | 文生、图生、首尾帧；图生入口可绑定 Element；有原生声音。[K1] | 已设计好起始构图时，可以由首帧和绑定角色进入生成；不能因此把所有制作强制为图生。 |
| 镜头控制 | Multi-Shot 自动安排切换；Custom Multi-Shot 可逐镜头描述内容和时长；关闭多镜头时采用单镜头。自动模式仍可能根据内容选择单镜头。[K1] | 镜头组需要“模型安排”和“明确镜头计划”两种选项；有多镜头开关不等于结果一定按计划切镜。 |
| 角色资产 | Elements 可由多角度图或角色视频建立，角色可关联音色；3.0 指南也有音色绑定，不能误写成 Omni 独有。[K1][K3] | 保存角色资产版本，以及供应商 Element 对应关系；已绑定音色时避免再生成冲突的声音描述。 |
| 3.0 Omni | 将图像、视频、Elements 与文字组合为参考；支持原生音画和多镜头。更适合以组合参考或已有视频作为创作起点。[K2] | 参考面板必须表达各素材用途，不能只提供一个“上传图片”字段。 |
| 原生对白 | 3.0 提示词可指定人物与台词的对应关系；这属于生成控制能力，不是对白准确性验收结果。[K1] | 台词仍结构化保存，生成后检查漏词、串人、口型及情绪。 |
| 已有视频返工 | Omni 指南明确沿用 O1 的编辑方式；O1 官方列出主体/背景/局部内容修改，以及用视频参考生成前后镜头、借用动作和运镜。[K2][K4] | 对已有片段提出修改，而非每次从空白重生成；编辑输出仍是新候选，需要和原版比较。 |

特别限制：本次读到的 Omni 指南把“直接传入视频”与“开启 Native Audio”组合标为暂不支持。用视频建立角色 Element、再引用该 Element，与把视频直接作为生成/编辑输入，是不同流程，不能混淆。该指南页发布于 2026-02-06，接入时需再次按实际版本核验，不能把限制写成永远不变的产品规则。[K2]

产品与 API 边界：已定位官方开放平台的 3.0 Omni API 页面，但当前网页提取只得到标题，未取得完整参数正文。本报告因此确认上述产品端流程，不宣称所有 UI 能力已在正式 API 同步开放，也不采用转售商 API 参数代替官方证据。[K5]

## 万相：当前 3.0 已统一多种生成与编辑，但模式组合仍受约束

- 当前官方指南把 `wan3.0-video` / `wan3.0-video-prime` 定义为统一入口，通过 `input.media[].type` 与提示词区分文字生成、首尾帧、组合参考、视频编辑和延长；官方提供对应 HTTP 与 SDK 示例。这是正式 API 证据，不只是消费端宣传。[W2][W3]
- 官方文生说明支持带时间标记的多镜头描述，并可生成对白、背景音乐、环境/动作声音；参考模式允许图片、视频、音频组合。视频编辑可表达元素、光线、台词等修改，延长可向前、向后或双向进行。[W2]
- **首帧/首尾帧模式不能同时传参考音频等其他类型。** 若需要音频驱动，官方建议改用 `reference_image + reference_audio` 参考模式；这样不能再承诺严格固定首尾画面。官方 FAQ 还指出 Wan 2.7 的首尾帧模式支持 `driving_audio`，新版本并不是旧版本全部能力组合的简单超集。[W3]
- API 默认可输出有声视频；时长与输入视频总量等限制按模式校验。相同 seed 也不保证每次完全一致，因此不能把重复调用或“重新生成”称为确定性重放。[W3]
- 旧版 Wan 2.6 参考生视频已经能从参考中提取形象与音色（如有），按 `character1` 等顺序标识绑定角色，支持多角色及多镜头；接入旧模型时不能直接复用新 3.0 的媒体字段。[W4]

设计推论：面向万相 3.0，可先选择制作意图，再自动呈现兼容的参考输入。不要让用户填好首尾帧、声音和全部参考，直到提交才收到不兼容错误。已有成片返工可尝试视频编辑，但没有证据表明“一次生成的多个镜头”会自动变成可分别无损重算的时间线节点。

## 两者共同影响我们的短剧工作台

1. **统一的是内容对象和用户意图，不是所有供应商的参数。** 角色、声音、台词、镜头计划共享；适配层按具体模型、版本、任务模式和地区编译合法输入。
2. **区分参考用途。** 首帧是起始画面约束，角色视频可以是身份样本、动作参考或被编辑的原片；同一种文件类型不代表同一种制作作用。
3. **支持三种制作路径。** 逐镜头生成、按镜头组音画生成、基于已有视频修改；它们都可以使用顶级模型，不必将“逐镜头”解释成落后模型的专属方式。
4. **返工按实际可处理片段设计。** 多镜头输出先保存为完整媒体，记录镜头采用区间；只修改其中一个镜头时，可裁取目标片段提交编辑或重生成，再检查衔接。这个过程不承诺其他帧完全不变。
5. **不能把原生声音当作可编辑分轨。** 官方“有声输出”并不能证明分别返回人声、音乐、音效音轨。工作台需记录原声、替换声音和混合音轨的来源，编辑后重新检查口型与时间。

以上五项为产品/架构推论；正式接入仍要通过双人对白、服装切换、道具交互及局部返工样片确认，不给未经测试的模型效果排名。
