# 场次自由画布：TapNow / LibTV 基础交互核对

核对日期：2026-09-09。用途：为首版场次画布的交互示意提供依据，不扩充模型或 Agent 范围。

已定前提：每个场次一张自由画布；镜头制作提供分镜、画布两种模式；素材、生成任务及镜头候选共用，剪辑与固定稿审阅共用。该前提是我们的产品决定，不是竞品事实。

证据等级：**D**＝本轮阅读的官方操作文档；**V**＝公开官网或用户截图可见的界面；**I**＝我们的设计推论。没有登录、付费生成或实测多人协作。历史研究仅用于定位，本表重新核对关键官方页面；不采用旧研究中 LibTV 前端代码文案来补足操作证据。

## 2. 建议复用的机制（I）

1. **选中什么，就围绕什么操作。** 画布默认突出材料和成果；单选出现精简的对象工具栏与局部输入，多选出现组合参考入口。场次要求、镜头列表和 Chat 可收起，避免全部面板常驻。
2. **让“继续尝试”足够直接。** 从结果的 `+` 选择图片或视频任务，显式显示参考缩略图及用途，填写本次要求。选择已有结果不会自行发起生成；确认生成时冻结输入及参数。
3. **线表达关系，输入框表达本次实际使用。** 用户能看清哪些内容可参考、哪些已进入本轮输入。我们的生成快照保存实际素材版本，后续挪动节点或删线不会改写已提交任务。
4. **探索结果与正式采用分别操作。** 新结果保留来源，可另开尝试；通过“加入 SH04 候选”回到共享镜头记录。画布摆放不改分镜顺序，新结果不自动替换采用或剪辑。
5. **保留空间操作的可恢复性。** 撤销用于画布编辑；结果历史用于找回媒体；审阅稿用于固定成片版本，三者分别命名。删除展示节点不连带删除共享成果。
6. **导航行为形成完整一套。** 选择、框选、平移、缩放和文本编辑不抢同一操作。可借鉴 TapNow 的组合并在界面展示帮助；若另加 Space 临时手形等习惯操作，应明确是我们的设计并避开输入焦点。

“分镜模式切到关联节点并恢复视口”“每场次只设一张画布”“候选与审阅共享”等均属于我们的业务约束，不归因于两家产品。Chat 可以辅助解释和准备输入，直接操作链路应能独立完成基本制作。

## 3. 当前证据不能证明的点

- LibTV 的具体连线引用规则、复制继承范围、撤销边界、历史恢复语义和快捷键，不能根据静态截图推定，也不能套用 TapNow 的说明。
- 任意连接都触发自动重跑、所有编辑都另建节点、局部生成一定只改变标记区域，均未获得普遍保证。
- 大量视频同时出现在画布时的实际性能、断网恢复、多端冲突、多人编辑与费用一致性，未实测。
- 两种制作模式之间的镜头绑定、采用、剪辑与固定稿关系，仍需我们自行设计与验证，竞品画布功能不能代替这部分工作。

本轮不执行任何模型任务，不将界面按钮清单直接扩大为 MVP 功能清单。
