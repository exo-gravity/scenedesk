# 剧本：完整用户旅程与核心页面状态设计

日期：2026-09-18。**状态：设计提案，待确认。** 前置：[UX 重新设计](2026-09-18-script-page-ux-redesign.md)（诊断）、[重构 A 方案](2026-09-18-script-page-refactor-a.md)。

## 1. 旅程地图（谁、为什么进来、看到什么）

```
                    ┌─ 新项目，还没有剧本 ─────────────┐
                    │  目的：把初稿弄进来                │
                    │  出口：有了一份当前稿              │
                    └───────────────┬───────────────────┘
                                    ▼
   ┌─ 团队阅读 ────────────────────────────────────────┐
   │  目的：一起读同一份、确认哪一版是依据               │
   │  出口：确认"当前稿"，或切去看历史稿                 │
   └───────────────┬───────────────────────────────────┘
                   ▼
   ┌─ 选段引用 ────────────────────────────────────────┐
   │  目的：把某段原文带进画布，作为画面依据             │
   │  出口：画布上出现一个带原文与版本的新节点           │
   └───────────────┬───────────────────────────────────┘
                   ▼
   ┌─ 稿子更新了（外部重写/飞书改了）──────────────────┐
   │  目的：带进新稿，但不静默改变已有生成依据           │
   │  出口：新稿成为当前稿；旧引用仍指向旧版本           │
   └───────────────────────────────────────────────────┘

  横切：项目归档 / 权限不足 / 离线 · 刷新 / 导入失败 / 多标签页
```

**关键设计原则（贯穿全部状态）**

| # | 原则 | 理由 |
|---|---|---|
| P1 | **阅读是主体**,导入与引用是围绕它的动作 | 每次打开都在读;导入只在开头发生 |
| P2 | **状态分离** —— 无剧本 / 有剧本 / 只读历史 是三套不同的页面,不是一套加条件 | 现在把它们塞进同一条操作行,导致空态出现两个导入入口的投影 |
| P3 | **版本是正文的属性**,不是动作行的一部分 | "我读的是哪一版"比"怎么去创作依据页"更重要 |
| P4 | **引用跟随选区**,不常驻 | 未选文时它不可用,不该占最重的位置 |
| P5 | **不可静默改变依据** —— 换稿必须显式确认,旧引用不动 | 领域不变量:导入新版本不静默改变已有生成依据 |
| P6 | **草稿必留** —— 导入中断/刷新/冲突都不丢已选内容 | 领域不变量:失败请求和刷新后都保住草稿输入 |

## 2. 状态清单（按维度,共 8 个维度）

| 维度 | 取值 | 来源 |
|---|---|---|
| S1 有无剧本 | 无剧本 ｜ 有剧本 | `selected` 判定 |
| S2 版本关系 | 当前稿 ｜ 历史稿（只读） | `history !== tree.currentScriptRevisionId` |
| S3 编辑态 | 只读 ｜ 纯文本编辑中 | `legacy` / `showNotes` |
| S4 权力 | 可写 ｜ 只读（归档／权限） | `active`、项目 `status`、`role` |
| S5 导入阶段 | 空 ｜ 已选文件 ｜ 读取中 ｜ 预览待确认 ｜ 提交中 ｜ 已保存 ｜ 失败 | `draft.stage` / `draft.value` |
| S6 草稿恢复 | 无 ｜ 有未提交草稿 ｜ 已恢复 ｜ 已冲突 | `draft.recovered` / `committed` / `error` |
| S7 导入警告 | 无 ｜ 有（导入说明） | `showNotes` / `warnings.length` |
| S8 引用 | 未选文 ｜ 已选文 | `selectedExcerpt` |

## 3. 核心页面（逐屏）

### 3.1 屏 ① 无剧本（空态）

**用户目的**：把初稿弄进来。**页面只剩这一件事。**

```
                        导入你的初稿剧本
              把已确定的剧本带到这里，与项目成员一起阅读。
          ┌──────────────┐   ┌────────────────┐
          │  导入 Word    │   │   从飞书导入     │
          └──────────────┘   └────────────────┘
                   支持 .docx，最大 4 MB
```

| 规则 | 内容 |
|---|---|
| 动作 | 两个**平级**入口（同一件事的两种来源,同权重、同尺寸、同描边） |
| 位置 | 居中说明区；**页头只留标题**,不出现标签页、不出现「⋯」里的活跃动作 |
| 不做 | 不再出现"第二处说明"（现在操作行 273 与居中 833 各说一遍） |
| 只读时 | 两个入口替换为一行说明：`项目已归档／你没有导入权限` |

### 3.2 屏 ② 有剧本 · 阅读（主屏）

**用户目的**：读,并随时知道读的是哪一版。

```
剧本                                                       ⋯
──────────────────────────────────────────────────────────
当前稿 · 纯文本 · 旧钥匙_第1集_初稿.docx · 8 月 12 日更新
        ⚠ 导入时有 3 条说明                                    ← 仅在 S7 有警告时出现
──────────────────────────────────────────────────────────
      第 1 集 · 重逢
      01　咖啡厅 / 日 / 内
      雨刚停。窗外的光落在桌面上。……
```

| 规则 | 内容 |
|---|---|
| 骨架 | **一条阅读列**（1120）。页头、版本行、正文同起一条左边界 |
| 正文 | **无卡片装饰**（去掉白底与边框）,直接在内容区上 |
| 版本行 | 左:当前稿／来源／文件名／更新时间；右:动作（见下） |
| 动作归属 | **「重新导入 Word」「从飞书导入」收进「⋯」**;不再常驻成排按钮 |
| 标签页 | **不再出现**（原「剧目设定」移出本页） |
| 警告 | S7 有值时出现一行可展开的提示,展开显示逐条导入说明 |

### 3.3 屏 ③ 选段引用（同一屏的交互态）

**用户目的**：把这一段带进画布。

```
      雨刚停。窗外的光落在桌面上。林夏与周远相对而坐。   ← 选中（高亮）
      ┌────────────────────────────┐
      │ 带入画布 →   （当前稿 v3）   │                  ← 就近气泡
      └────────────────────────────┘
```

| 规则 | 内容 |
|---|---|
| 未选文 | **气泡不出现**（页面最重的元素不再是空转按钮） |
| 已选文 | 气泡出现在**选区附近**;显示将带入的版本,避免"带错了版本" |
| 落点 | 画布上出现新节点,带**原文范围 + 确切版本** |
| 失败 | 气泡内就地报错并保留选区（不丢已选内容） |
| 只读历史稿 | 允许引用,但气泡必须写明**历史稿 · 只读**,并禁止"引用后覆盖当前稿"的暗示 |

### 3.4 屏 ④ 历史稿（只读）

```
剧本                                                       ⋯
──────────────────────────────────────────────────────────
历史稿 · 只读 · 旧钥匙_第1集_初稿.docx · 8 月 5 日      [ 返回当前稿 ]
──────────────────────────────────────────────────────────
      第 1 集 · 重逢
      ……（旧版本正文）
```

| 规则 | 内容 |
|---|---|
| 视觉 | **明确只读标识**（历史稿 · 只读）;不出现编辑类动作 |
| 出口 | 「返回当前稿」是唯一主动作 |
| 引用 | 允许（要能在旧版基础上做画面）,但气泡标注历史版本 |
| 切换 | 通过版本行右侧的版本入口进入,而不是混在操作行里 |

### 3.5 屏 ⑤ 导入（Word 或飞书）—— 五种状态

**这是目前最碎的一块（S5 有 7 个取值）。统一成一个流程:**

| 阶段 | 页面表现 |
|---|---|
| ① 空 | 屏 ① / 屏 ② 的「⋯ → 重新导入 Word」 |
| ② 已选文件 | 打开预览区:文件名、「尚未导入 · 请核对正文和显示说明」、`取消` / `确认导入` |
| ③ 读取中 | 预览区显示进度（`读取中…`）,期间**保留已选文件**（P6） |
| ④ 预览待确认 | 预览正文（含版式说明）+ 提示"预览不改变当前稿" |
| ⑤ 提交中 / 已保存 | `导入已保存。` 并**刷新正文与版本行**;失败则就地报错 + `重试` |

| 规则 | 内容 |
|---|---|
| 位置 | 打开**当前稿之上**的预览区（不是弹窗）,因为要对照读 |
| 确认 | **必须显式确认**才替换当前稿（P5）;确认文案点明"新稿将成为当前依据,已有引用不变" |
| 飞书 | 同构:来源不同（`飞书 · {标题} · 读取于 {时间}`）,流程一致 |
| 失败 | 区分**读取失败**（文件问题）与**提交失败**（服务问题）,各自给可执行动作 |

### 3.6 屏 ⑥ 草稿恢复与冲突

| 状态 | 表现 |
|---|---|
| 有未提交草稿 | 版本行上方一行：`文件已保留，离开后可继续导入。` |
| 刷新后恢复 | 预览区自动还原,并提示来源与时间 |
| 冲突（文件与当前稿不一致） | **显式让人裁决**:`用本机文件继续` / `放弃本机文件,以当前稿为准`;不自动覆盖（P5） |
| 已提交 | 清除草稿提示,正文更新 |

### 3.7 屏 ⑦ 归档 / 只读

```
项目已归档：仍可阅读与引用，恢复项目后可导入新稿。
```

| 规则 | 内容 |
|---|---|
| 允许 | 阅读、切历史稿、选段引用（引用不改变项目事实） |
| 禁止 | 导入、编辑纯文本、确认依据 |
| 呈现 | 顶部一行 Alert;被禁动作**不显示**（而不是灰掉一排） |

### 3.8 屏 ⑧ 加载与失败

| 状态 | 表现 |
|---|---|
| 加载中 | 阅读列的骨架（不是居中转圈）,避免布局跳动 |
| 读取失败 | 就地错误 + `重试`;保留页面骨架 |
| 版本找不到 | `没有找到此固定剧本版本，请重新选择历史版本。` + 版本入口 |

### 3.9 屏 ⑨ 「⋯」菜单（动作的家）

| 分组 | 项 |
|---|---|
| 导入 | 重新导入 Word ｜ 从飞书导入 |
| 版本 | 查看历史稿 ｜ 下载原件 |
| 说明 | 导入说明（有警告时） |
| 编辑 | 编辑纯文本（可写时） |
| 关联 | 剧目设定 ｜ 创作依据 |

## 4. 与现状的差异汇总

| 现状 | 本设计 |
|---|---|
| 无剧本/有剧本共用一条操作行 | **三套页面**（空态／阅读／历史稿） |
| 「选文带入画布」常驻且最重 | **跟随选区**出现 |
| 960 纸面 + 白底边框 | **1120 阅读列,无卡片装饰** |
| 操作行贴内容区右缘,与正文不对齐 | 全部对齐**一条阅读列** |
| 「剧目设定」与「剧本正文」并列标签 | 移出本页,进「⋯」 |
| 「创作依据」band 常驻且与菜单重复 | 移除,入口进「⋯」 |
| 导入入口分散三处 | 空态两个平级；有剧本时收进「⋯」 |
| 导入阶段散落在同一区域 | 统一的**预览区**（含确认与冲突裁决） |
