# 剧本页：从用户体验视角重新考虑布局与信息呈现

日期：2026-09-18。**状态：设计提案，待确认。** 这是对 [重构 A 方案](2026-09-18-script-page-refactor-a.md) 的重新审视 —— 我先前把问题定位为"对齐基准漂移",看到有剧本的真实页面后认为**那个定位偏了**。

## 1. 用户在这页要做的四件事

| # | 任务 | 频率 |
|---|---|---|
| 1 | **把稿子弄进来**（Word／飞书） | 每个新项目 1–2 次 |
| 2 | **读它** —— 团队一起读同一份 | **每次打开都在做** |
| 3 | **引用某段带进画布** | 每次想做分镜时 |
| 4 | 确认"官方依据是哪一版" | 偶发,但一旦出错代价高 |

**结论:第 2 项是这页的主体,其余三项是围绕它的动作。** 而当前布局把第 1 项当成了页面级主操作。

## 2. 真实页面暴露的问题（1449×723 实测）

| # | 问题 | 实测证据 | 属于 |
|---|---|---|---|
| **D1** | **「选文带入画布」在没选任何文字时也是实心主按钮,且位置最靠右** —— 页面最重的视觉元素是一个**此刻不可用**的动作 | 实测它排在操作行最右、实心深色;而未选文时它是空转的 | 层级错误 |
| **D2** | **操作行的右边缘按内容区对齐（1385）,正文纸面却只有 960 宽居中（353–1313）** —— 按钮漂浮在正文之外 | `paper` 实测 x353 w960;操作行右端 1385 | 分栏矛盾 |
| **D3** | **正文被做成"卡片里的文档"** —— 纸面有白底 + 边框,而它本来就在内容区里 | `paper` 白底 + 边框;页面背景本身已是浅色 | 过度包装 |
| **D4** | **960 的阅读宽度被浪费** —— 右侧 350+px 空白,而每一行的操作行却跑满 1165 | 内容区 1233 = 纸面 960 + 空白 273 | 空间分配 |
| **D5** | **标签页把「剧目设定」和「剧本正文」并列** —— 一个是剧本内容,一个是项目配置 | Tab 实测 x250,与标题同起 | 分类混乱 |
| **D6** | **「创作依据」band 与「⋯」菜单重复,且不随标签切换消失** | 它是 `section` 直接子元素,与 `<Tabs>` 平级 | 归属错误 |
| **D7** | 空态与"重新导入"共用同一条操作行,导致空态时一行里出现两个导入入口的不同投影 | portal 把按钮投到 toolbar,空态卡片里只剩下"选择文件" | 状态未分离 |

**我之前只报了 D6/D7（并把它们归因于"四套基准"）。真正的根因是 D1–D4:这页把"导入与引用"当成了页面级主操作,而"阅读"才是主体。**

## 3. 重新设计:状态分离 + 单一阅读列

### 3.1 两个状态彻底分开（解决 D7）

**无剧本** —— 页面只剩一件事:导入。

```
                    导入你的初稿剧本
           把已确定的剧本带到这里，与项目成员一起阅读。
        [ 导入 Word ]      [ 从飞书导入 ]
              支持 .docx，最大 4 MB
```

- 一块居中的说明区,**两个平级入口**（同权重:同一件事的两种来源）
- 不再出现"某处还有第三种导入方式"的错觉

**有剧本** —— 页面只剩一件事:读。

```
剧本                                      ⋯
导入已确定的初稿，与项目成员一起阅读。        ← 说明行收短，或随项目名一起进面包屑
──────────────────────────────────────────
当前稿 · 纯文本 · 旧钥匙_第1集_初稿.docx  · 8 月 12 日更新
──────────────────────────────────────────
        第 1 集 · 重逢
        01 咖啡厅 / 日 / 内
        雨刚停。窗外的光落在桌面上。……
```

- **版本行（当前稿／文件名／时间）贴在正文上方**,而不是与操作行混在一起 —— 它是**正文的属性**,不是动作
- 导入与更多动作**退到标题行的「⋯」**;`重新导入 Word` 只出现在「⋯」里
- **「选文带入画布」不再常驻**,改为**选中文字后就近出现**（见 3.3）

### 3.2 一条阅读列贯穿（解决 D2/D4/D5）

- **正文列就是这条列**,页头与标签页**不加缩进**（不再出现 250 与 273 两套）
- **去掉纸面的白底与边框**（D3）—— 它已经在内容区里,再加一层卡片是双重包装
- **阅读宽度取 1120**（内容区 1233 之内留 56 边距）,比现在的 960 宽,同时把右侧空白的浪费收掉
- **「剧目设定」从这页移出**（D5）:它是项目配置,不是剧本内容。建议归到项目设置,或作为「⋯」里的入口

### 3.3 引用动作跟随选区（解决 D1）

- **未选文时:不出现**。页面最重的元素不再是一个空转按钮
- **选中文字后:在选区附近浮出**「带入画布 →」（可选:同时显示将带入的版本名）
- 依据:参考产品在同类场景都用**就地/气泡**动作（LibTV「节点内并列动作」、即梦「选中后展开编辑」）,而不是常驻工具栏按钮

### 3.4 依据与版本（解决 D6）

- **「创作依据」band 移除**;入口收进标题行「⋯」
- 但要在正文上方**明示当前依据的版本**（当前稿／历史稿 · 只读）—— 因为"我读的是哪一版"比"怎么去创作依据页"更重要

## 4. 与先前方案的关系

| 先前 | 本次修正 |
|---|---|
| 重点放在"统一四套基准" | **基准只是症状**;根因是把导入/引用当页面级主操作 |
| 保留 960 纸面 + 边框 | **去掉纸面装饰**,阅读列放宽到 1120 |
| 建议把标签页「剧本正文」改名为「正文」 | **更彻底:「剧目设定」移出该页**,这页只留正文 |
| 「选文带入画布」建议常驻但禁用 | **改为跟随选区出现**;常驻禁用仍然占着最重的位置 |
| 空态按钮移进卡片 | 保留（两个平级） |

## 5. 需要你确认

1. **「剧目设定」移出剧本页** —— 同意吗?（它是项目配置）
2. **引用动作改为"选中文字后就近出现"** —— 同意吗?（当前有草稿恢复机制,要确认改后仍能恢复）
3. **阅读宽度 1120 + 去掉纸面白底/边框** —— 同意吗?
4. **版本信息（当前稿／文件名／时间）贴在正文上方** —— 同意吗?
5. 先前的 A/B/C 基准问题在本次方案里**自然消失**（只有一条阅读列）,是否接受不再单独选择基准?
