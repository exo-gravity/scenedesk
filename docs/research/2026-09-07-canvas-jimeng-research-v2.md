# 即梦 AI / Dreamina：画布与无限画布复核 v2

调研日期：2026-09-07。研究对象为国内即梦、国内无限画布与 Octo 发布线索，以及海外 Dreamina 官方披露的 Octo / Vibe Create 工作区。国内与海外分别记录。

本轮重新检索并读取官网、公开应用页面、官方营销说明与品牌发布线索；没有登录、执行生成、消费积分、操作共享浏览器或安装工具。下文是公开资料核查，不是产品实操评测。功能定位有较充分证据，具体账户可用范围、真实操作细节和生产效果仍有边界。

## 1. 对整体调研最有价值的结论

- **即梦不能仅归类为图片编辑画布。** 国内官网仍介绍图层式智能画布，公开应用首页已经突出 Agent；还需单独看待无限画布发布和 Octo 叙事工作区线索。[国内官网](https://jimeng.jianying.com/)、[公开产品首页](https://jimeng.jianying.com/ai-tool/home)
- **海外 Octo 把画布放在产品中心。** 它公开展示的是创意对话、参考资产、分镜、生成和剪辑串联的工作环境，覆盖短片、概念设计及品牌内容；并非仅在分镜表外增加自由摆放视图。[Octo 官方介绍](https://dreamina.capcut.com/ai-video/octo)
- **其价值主张是持续的创作上下文。** AI 利用对话、引用及工作区中的内容参与创作；画布承担显式摆放、就地讨论和阶段衔接。该定位值得借鉴，但公开宣传的“完美一致性”“没有等待”不能当成已验证效果。[AI Creative Workspace](https://dreamina.capcut.com/ai-video/ai-creative-workspace)
- **画布与时间线仍分工。** 官方操作说明要求把生成片段加入时间线后进行编排和导出；空间布局没有因此自动成为成片顺序。[AI Canvas 使用步骤](https://dreamina.capcut.com/ai-video/ai-canvas)
- **人机共创、多会话、团队空间是三个不同概念。** 本轮不能证明国内或海外画布具有多人实时共编、正式审片及交付版本管理；也不能据此断言它们没有这些功能。

## 2. 证据等级

| 标记 | 含义 | 使用边界 |
|---|---|---|
| A | 官方域名的公开产品页面、协议或可直接读取的入口 | 确认该页面及其描述；不是账号实测 |
| B | 官方营销文章中的具体功能说明 | 可研究定位和宣称的操作，但效果、兼容和可用性需二次验证 |
| C | 品牌同名社媒发布，尚未闭合具体作者 ID；其他媒体只用作检索线索 | 不单独作为国内已上线功能的最终依据 |
| P | 基于材料做出的产品分析或建议 | 不冒充竞品事实或本项目已确定需求 |

“官方披露”和“实际验证”是两条轴。B 级材料虽来自官方域名，仍可能有营销概括、更新滞后和细节不一致。

## 3. 国内即梦：三类入口分别评价

### 3.1 智能画布：画面内部的合成与修改

**A：** 官网列出多图层、多图融合、局部重绘、扩图、消除和抠图。它处理的是一张图如何组合和修整。适合短剧参考图、人物与环境合成、关键帧准备；这些用途属于 P 级推论。官网没有公布这一段的更新日期，不能用它判定当前全部画布能力，更不能推断旧能力已经下线。[官网“智能画布”](https://jimeng.jianying.com/)

### 3.2 无限画布与 Agent：首页状态与发布记录

**A：** 本次重新读取 `ai-tool/home`，可见 Agent 模式、自动使用技能、灵感搜索、技能和短片入口；公开 HTML 的可见文字另包含“灵感、生成、资产”。直接打开 `ai-tool/assets-canvas` 仅得到应用壳，无法从中核查按钮、节点连接或编辑器行为。[当前产品首页](https://jimeng.jianying.com/ai-tool/home)、[画布地址](https://jimeng.jianying.com/ai-tool/assets-canvas)

**C：** 2025-11-07 的“即梦 AI”同名抖音发布介绍在同一画布生成与编辑、Agent 共创、多会话并行和多模态创作，并称当时已在网页版上线。这能提供演进线索；具体账号身份核对的最后一步仍有限制，见第 4 节。[无限画布发布记录](https://www.douyin.com/video/7569887004834417961)

**未知：** 当前无限画布与首页 Agent 会话是否一一对应；会话是否共享整个画布；哪些素材自动进入上下文；同名画布入口在不同账号是否相同；图片图层编辑是否嵌入新工作区。

### 3.3 Octo：叙事创作工作区，需要补入比较

**C：** 本轮找到 2026-04-13 “即梦 AI”同名发布的 Octo 内测介绍，邀请申请并展示由 Octo 共创的短片；抖音精选页可读到作者显示名和发布日期。它说明国内 Octo 是必要的进一步核查对象，但不足以证明当前已全量开放，也不能把海外教程的所有操作直接移植为国内事实。[国内 Octo 发布记录](https://jingxuan.douyin.com/m/video/7628200608813550894)

**未知：** 国内 Octo 的正式入口、当前灰度范围、与通用无限画布的继承关系、是否独立保存项目、是否存在与海外一致的分镜和时间线功能。未将第三方内测教程标题中的“团队协作”当作实时共编证据。

## 4. 国内发布账号身份链：本轮重验结果

本次直接读取[即梦官网](https://jimeng.jianying.com/)的公开 HTML，页脚社媒链接确实指向：

- [抖音账号](https://www.douyin.com/user/MS4wLjABAAAATAf2FKPSpZx_TdDWzwzNlznaEE6HttAqJgrnRPGdW24adAIlxfGeasDraUIR5JRp)。
- [B 站账号](https://space.bilibili.com/3546611372264291)，链接的可访问标签为“即梦 AI-B 站空间”。

这是对旧研究记录的重新核验，**不是本轮新增发现**。网页文本提取会遗漏只有图标的社媒入口，公开 HTML 能补足“官网 → 账号”这一段。

但是，抖音账号页返回空正文，相关视频页没有提供可读取的作者 ID；B 站个人页及尝试打开的视频页返回 412。本轮没有越过访问限制。

因此仍未闭合“具体发布视频 → 官网关联账号”的最后一步。当前结论是：**官网关联账号已确认；两条同名品牌发布与该账号的精确对应尚未确认。** 不以粉丝数量、相同头像、同名或评论回复代替 ID 验证。

## 5. 海外 Dreamina Octo：官方描述的工作方式

以下均明确限定为 Dreamina 海外官方披露；材料主要是产品营销页和介绍文章，未获得稳定的版本化帮助中心操作规范。

| 研究项 | 官方披露及证据 | 对设计的含义与未验证事项 |
|---|---|---|
| 产品定位 | A：将想法发展为结构化视频项目，画布连接故事、角色、场景与视频；面向创作者、独立导演及营销团队。[Octo](https://dreamina.capcut.com/ai-video/octo) | P：画布是默认创作工作区，属于产品组织方式；不能只当一张参考白板 |
| 对象组织 | A：文字、图像、声音可放入工作区；脚本块、角色卡和视频节点可组合为可移动分组。[AI Canvas](https://dreamina.capcut.com/ai-video/ai-canvas) | 未证明分组具有权限、审批或批次执行含义 |
| 对话入口 | A：在画布位置用 `/` 呼出创意对话；Agent 根据会话和画布提出创意方向。[Octo](https://dreamina.capcut.com/ai-video/octo) | P：适合围绕当前材料继续创作；可见区域、邻近节点、整个项目之间的实际取材优先级不明 |
| 素材输入 | A：官方描述拖入图、视频、声音、文档及参考，并把它们纳入同一工作区。[AI Creative Workspace](https://dreamina.capcut.com/ai-video/ai-creative-workspace) | P：降低重复导入与上下文重述；单文件上限、解析错误处理和权限未验证 |
| 节点创建 | B：可以通过对话创建内容节点，也可由工具栏／空白处菜单手动添加。[官方 Octo 工作流介绍](https://dreamina.capcut.com/ai-video/tapnow-ai-review) | 未找到要求用户先画完整可执行 DAG 的证据；也未找到条件、循环和流程发布的规格 |
| 引用语义 | B：资产可标记为选定参考，通过 `@` 用于生成器或对话。[官方 Octo 工作流介绍](https://dreamina.capcut.com/ai-video/tapnow-ai-review) | 存在明确引用动作，不能将“同处画布”“位置相邻”“模型已使用”视为同义 |
| 生图与修改 | A：对话及手动节点可以生图；提供提示词修改、局部修整、超清、裁切和移除等操作。[AI Creative Agent](https://dreamina.capcut.com/ai-video/ai-creative-agent) | 没有查到不可变版本、父子候选记录、采用与撤回机制的完整定义 |
| 视频制作 | A：官方列出图转视频、首尾帧、多帧、声音和关键帧提取等操作。[AI Creative Agent](https://dreamina.capcut.com/ai-video/ai-creative-agent) | 这是产品能力描述，不能当成某一 Seedance API 在某一地区的参数清单 |
| 分镜 | A：工作区列出分镜区域，并将脚本、人物设定、分镜、视频生成连成流程。[Vibe Create](https://dreamina.capcut.com/ai-video/vibecreate) | P：叙事结构与自由空间可以同时存在；未证明它等同于我们的“集—场次—镜头”模型 |
| 剪辑衔接 | A：选中视频后加入时间线，在时间线中处理顺序、声音与输出。[AI Canvas](https://dreamina.capcut.com/ai-video/ai-canvas) | P：空间坐标、叙事顺序、剪辑时间应分开建模 |
| 输出 | A：官方步骤写到 MP4 下载，以及时间线裁切和排序。[Octo](https://dreamina.capcut.com/ai-video/octo)、[AI Creative Workspace](https://dreamina.capcut.com/ai-video/ai-creative-workspace) | 不能推出完整影视后期、调色、混音或所有 NLE 工程互通 |

### 三个需要明确降级的宣传点

1. **一致性效果。** 官方把标记参考描述为跨场景一致性的基础，但“完美一致”是效果宣传。能够引用资产与生成效果达标，需要分别验证。[AI Canvas FAQ](https://dreamina.capcut.com/ai-video/ai-canvas)
2. **工程导出。** 官方的竞品比较文章称可导出工程文件衔接 Premiere / Final Cut，而一般操作页只写视频导出或继续使用外部软件。未取得格式、轨道保留范围和兼容说明，因此只记录为 B 级待核查能力。[工作流营销文章](https://dreamina.capcut.com/ai-video/tapnow-ai-review)、[Vibe Create 操作步骤](https://dreamina.capcut.com/ai-video/vibecreate)
3. **免费和全量可用。** Vibe Create FAQ 仍写 closed beta，AI Canvas 页面则使用免费日积分和订阅的通用描述。各页缺少清晰的功能版本与地区可用表。不能据此宣称 Octo 对所有账号免费开放。[Vibe Create FAQ](https://dreamina.capcut.com/ai-video/vibecreate)、[AI Creative Workspace FAQ](https://dreamina.capcut.com/ai-video/ai-creative-workspace)

## 6. 团队、分支与执行：哪些仍然未知

### 团队能力

国内即梦的官方付费协议已明确团队空间，个人与团队的资产、积分和生成记录原则上分别管理，成员退出后不能继续访问团队内容；本轮重新读取的版本更新日为 2026-08-03、生效日为 08-10。这是团队服务的直接依据，不能称即梦只是个人工具。[官方付费服务协议，3.9 与 4.1.3](https://lf3-cdn-tos.draftstatic.com/obj/ies-hotsoon-draft/dreamina/b966ce40-d931-4397-8def-38fe5d03c729.html)

但协议没有证明多人同时编辑画布、光标可见、节点占用、冲突处理、镜头审批和交付冻结。海外页面所称 collaborative AI / shared canvas，正文主要指创作者与 Agent 的共同上下文。以上均保持未知，不能推成不存在。

### 候选与版本

本轮明确找到“修改、选择参考、继续生成”的公开描述，未找到以下操作规则：同一镜头多候选如何比较；采用某候选是否更新所有引用；旧剪辑是否自动变化；生成失败是否保留输入；修改分镜后是否标记下游过期。画布上能够保留多个对象，不自动证明上述版本治理完整。

### 连接与执行

“链接视觉想法”“连接资产”“节点系统”等官方用语不足以证明可执行连线。海外文章披露的 `@` 引用比空间邻近更明确；本轮没有验证通过拉线确定模型输入，也没有验证上游变化自动触发下游、批次费用确认或可发布的复用流程。

## 7. 对我们短剧优先工作台的设计启发（P）

1. **核心问题应从“是否做无限画布”改为“创作者如何在同一上下文中组织参考、讨论、生成和返工”。** 比较候选和保留设定有价值；拖拽空间是否是最佳承载方式仍需任务原型验证。
2. **画布可承载正式制作，不必局限于灵感阶段。** 海外 Octo 的定位说明对话、资产和分镜可以在一个工作区中推进；我们若只做自由参考板，会遗漏这一价值方向。
3. **也不宜直接把整个剧目塞进一张画布。** Octo 的公开介绍不足以证明其在长剧集、多成员和大量候选情况下的可用性。应测试场次、单集与自定义创作板的导航和引用需求，而非只凭竞品名词决定粒度。
4. **先保持数据一致，再提供多种入口。** 分镜记录、资产版本、候选、剪辑引用和审阅决定应能在列表、画布、时间线之间识别同一对象；空间位置不应成为资产唯一归属或审批状态。
5. **选择上下文必须可解释。** 无论使用选区、`@`、连接或 Agent 自动取材，都要能看到实际参考了什么、修改影响哪里、何时产生费用。否则画布会隐藏问题而非减少问题。
6. **公共能力可以复用，业务默认流程可以不同。** 同一套资产引用、生成、候选和时间线可以服务短剧与广告；当前用短剧任务实现和验证，广告不需要提前进入首版范围。

## 8. 下一轮实际界面验证清单

- 用公开／获授权账号分别确认国内智能画布、无限画布、首页 Agent 和 Octo 的入口与共享记录关系。
- 同一角色参考用于两组拍法：检查实际输入、生成结果位置、候选比较、选用与回退。
- 移动分组、调整分镜顺序、加入时间线：检查三个动作是否改变不同的数据。
- 修改某个已采用参考：检查旧成片、新生成和审阅状态各如何处理。
- 邀请两位内部成员操作同一画布：区分共享资产、异步访问与实时共编。
- 核查 MP4、素材包和所谓工程输出的实际内容，避免将营销描述当工程兼容承诺。
