# LibTV 与审片协作调研

调研日期：2026-09-07。用途：为 10 人以内 AI 短剧工作室的工作台设计提供依据。

## 方法与证据范围

使用官方网站、官网导航进入的官方使用指南，以及 Frame.io 官方帮助文档。LibTV 指南由官网左下角「帮助 → 使用教程」直接链接；通过浏览器读取正文。官网和指南中的功能描述属于厂商公开说明，未进行付费生成或质量评测，也未验证企业版完整权限体系。

搜索摘要仅用于定位来源。飞书文档顶部的 AI 速览未作为模型参数或性能依据。本轮实际读取了指南的更新公告、脚本新版正文与目录。浏览器进一步跳转项目菜单章节时超时，因此不对该章节的具体能力作判断。

## 已核实事实

|---|---|---|
| 首页以项目、画布创作、模型工具、Agent 和作品案例组织入口 | [LibTV 官网](https://www.liblib.tv/)；浏览器现场观察 | 产品已覆盖自由探索与生成入口，单纯堆叠模型选择器难构成鲜明定位 |
| 使用指南列出文本、图片、视频、音频、脚本五类节点，支持连线组织工作流 | [指南：基础节点与工作流](https://resonate.feishu.cn/wiki/Loxfw6XHziYRk0kKzdjcFfp9nhb#FhDMdLMKnoApVoxFgQYcci31nsd) | 无限画布适合表达创作依赖；是否适合作为多人生产的主界面需要验证 |
| 新版脚本包含剧本拆解、角色/场景/道具提取、分镜编辑、提示词构造、批量生图和生视频 | [指南：新版脚本正文](https://resonate.feishu.cn/wiki/Loxfw6XHziYRk0kKzdjcFfp9nhb#Gp7IdiGn5oIWygxc9xecnVzPnfb) | “剧本到分镜到视频”本身已是竞争功能，不能直接宣称为差异化 |

| Frame.io 提供媒体版本管理 | [Frame.io 版本说明](https://help.frame.io/en/articles/9101068-versioning-in-frame-io) | 创作候选、替换版本和审阅上下文需要明确关联 |

## 尚未核实

- LibTV 是否提供镜头级负责人、细粒度审阅权限、版本批准、跨集依赖变更提醒、项目成本归集，以及这些能力在哪种套餐可用。
- CLI 的服务端授权、限流、稳定性承诺、计费语义、商用集成许可及多工作室隔离方式。
- 官网模型卡片和宣传中的时长、折扣，与官方开放 API 的可用能力及价格是否相同。
- 宣传效果在连续剧的多角色、换装、跨集场景中的实际稳定性。

“未核实”不等于“不支持”。本次研究不能证明存在未被满足的市场需求；需要真实制作项目验证。

## 核心设计启发

推荐探索“镜头的生产组织与返工闭环”：围绕一个稳定的镜头身份，关联剧本依据、资产版本、生成候选、审阅决定、交付引用和成本。画布作为可选创作视图，与镜头列表使用同一套对象。

这一定位仍需被证伪：若现有工具组合已低成本满足团队协作，应进一步收窄到连续性检查、返工影响分析或交付回溯等高频痛点，而不是建立重复录入的管理系统。
