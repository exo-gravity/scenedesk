## 2. LibTV：画布是制作主空间，生成、结构化脚本与剪辑工具嵌入其中

### 2.1 当前入口与定位

当前[官网](https://www.liblib.tv/)的直接创作入口为“新建画布创作”。同页展示 Agent、模型入口、导演台、逐帧拉片和片段重拍。导演台的页面说明强调 3D 场景中的空间控制，拉片强调上传视频后提取参考，重拍强调修改片段。**证据：本轮读取官方页面。**

据此可判断，LibTV 把画布用作专业视频制作的基础容器，页面入口覆盖准备参考、构图、生成和返工。不能仅凭这些入口断言整集排期、正式审片、协作权限已经完整满足工作室需求。**后一句为研究判断。**

[官方 CLI 页面](https://www.liblib.tv/cli)与画布入口并存，并提供 Agent 接入及使用指南链接。说明该产品的制作执行能力还有程序化入口；不能将画布理解为必须由用户手工搭完所有步骤的唯一通路。**证据：官方页面；后一判断为推断。**

### 2.2 本轮核查到的画布设计细节

以下均取自[官网公开 HTML](https://www.liblib.tv/)返回的界面词典。核查方式：只读请求页面、解析 `self.__next_f.push` 数据、按下表键名查找文案。**这不是现场功能测试，也不是成功取得飞书指南正文。** 表中键名用于复查，不建议作为我们产品的接口设计。

| 观察主题 | 可核查键名 | 本轮文案表达的设计 | 可以得出的有限结论 |
|---|---|---|---|
| 画布对象 | `addAsTextNode`、`addAsScriptNode`、`image`、`video`、`historyAudioTab` | 文本、脚本与媒体被区别处理 | 画布并非只有图片卡片；脚本有专属处理入口 |
| 参考连接 | `modeTypeNeedConnectMedia`、`imageModelUnsupportedForConnectedImages`、`modeTypeIgnoreConnectedMedia` | 模型／模式要求不同种类和数量的媒体输入，某些模式忽略特定连接 | 边可以表达生成输入关系，不能一律理解为镜头播放顺序 |
| 脚本连接 | `disconnectEdgeMessage` | 断开后失去脚本关联，后续生成不再使用该脚本信息 | 连接有业务影响，绝非纯装饰连线 |
| 候选探索 | `createCopyTip`、`createCopyGeneratingTip` | 副本保留参数与上游连接；下游需重新选择连接；运行中副本需另行触发任务 | 探索分支与原有下游关系分开处理，适合尝试新提示词／参考 |
| 结果展开 | `expandAllImages`、`expandAllVideos` | 多个图像或视频结果可展开 | 候选比较存在空间展开的设计；具体布局、同步播放尚未验证 |
| 历史检索 | `historyAllCanvases`、`historyCurrentCanvas`、`historyAllRatings`、`historyDetailInputAssets` | 按画布范围、媒体类型、评级查询结果，并查看参考信息 | 存在结果记录和检索设计；不能据此声称具备正式版本审批或不可变交付快照 |
| 结构化脚本 | `scriptV2NodeManualStoryboardWrite`、`scriptV2FloatingToolbarGenerateStoryboard`、`scriptV2BatchStepComposePrompts` | 人工编写或批量形成分镜，再为镜头组织生成提示 | 自由画布与结构化分镜操作共存 |
| 资产依赖 | `batchStoryboardMissingRefsTooltip`、`scriptV2AssetAnchorLine` | 批量视频流程提示检查角色／场景／道具参考图，并将参考绑定到提示 | 所需输入的完整性检查属于制作能力，画布只是展示和操作入口之一 |
| 批次执行 | `groupNodeToolbarPromptReferenceimageGenerateConnect` | 先检查组内生成器的提示与参考连接，再执行整组 | 分组具有执行用途；并非所有空间分组都应推断有相同语义 |
| 剪辑入口 | `videoComposeEmptyHint`、`clipTimelineEmptyVideoHint`、`openVideoCompose` | 视频接入剪辑节点之后，在剪辑工具中处理 | 画布负责把素材送进剪辑，时间线另行承载时序编辑 |
| 编辑期间约束 | `clipDisconnectAgentEditingBusy` | 智能剪辑进行时限制断开素材关系 | 执行状态与画布修改存在协调规则 |
| 3D 与画布边界 | `directorConnectPanoramaHint`、`directorTimelineGuideStep5` | 全景图作为导演台输入，预览动画后输出视频回画布继续编辑 | 画布可组织专用工具的输入输出，无需把工具内部操作全摊成通用节点 |
| 团队内容 | `saveToTeamAssets`、`historyTeamScope`、`shareUpgradeTeamDesc` | 团队素材、团队生成记录与权限管理有对应界面文案 | 有团队设计线索；开放范围、套餐和具体规则须实测／查正式文档 |
| 多人编辑 | `collabNodeEditingBy`、`collabNodeSyncRetry`、`collabFollowControllerConnectDisconnectStopCollab` | 显示节点被他人编辑、同步中不可编辑，以及协作断开后停止跟随 | 公开前端包含节点占用与协作跟随设计；不能只凭文案宣称本账号当前能实时共编 |

这些细节使“连线”至少出现三种不同目的：把输入提供给生成器、把脚本信息关联到后续制作、把媒体送进剪辑。它们都不等同在空间里把卡片排成一行。**这是对前端文案的设计归纳，未验证所有连接规则。**

研究伙伴提供的 [2026-06-09 画布发布视频页](https://www.bilibili.com/video/BV1pQE76TEiT/)经本轮搜索重新取得标题、日期、简介和作者文本。页面发布者名为商汤 Seko AI，简介链接 `seko.sensetime.com`，内容描述自动建立工作流、自由节点连线、每集单独画布及跨集资产调用。**证据：品牌账号线索和发布页说明，未观看完整操作视频；未取得公司官网反向指向该账号的链路，不能将精确交互步骤提升为闭合认证的一手操作文档。**

这两层材料共同提示一项重要设计方向：画布既服务人查看和调整制作关系，也可以把中间资产及上下文提供给 Agent，减少后续任务重新整理输入的工作。该价值需要资产标识、关系和选用状态支撑，无限平面本身不能实现记忆。**这是研究归纳。**

当前未知：每集画布的创建／合并与跨集引用规则、边是否表达固定版本、候选历史、人工多人实时共编，以及正式剪辑和审片状态。即使公司谈到创作者和工作室协作，也不能据此填成同屏共编已经验证。

## 8. 跨产品归纳：同叫画布，承担的任务不同

| 形态 | 国内证据 | 核心任务 | 不宜混同的能力 |
|---|---|---|---|
| 制作关系画布 | LibTV 首页及公开前端设计 | 准备输入、连到生成器、展开候选、组织分支、送入剪辑 | 不是把所有边都当播放顺序；不是有历史就有审批版本 |
| 流水线调整画布 | 纳米公司披露 | 打开中间步骤，修改脚本／分镜／素材相关内容 | 非线性编辑不自动等于可自由编程的通用工作流 |
| 剧本结构与资产画布 | 千幕官方页面 | 看清集场镜、资产覆盖和任务／挑选进度 | 项目结构图不自动承担片段时间线或工作室排产 |
| Agent 的可接手制作上下文 | Seko 公司正式发布 | 积累角色、场景、剧本与风格供续集调用 | 画布位置本身不产生资产记忆；Skill 复用不自动等于用户可发布任意节点模板 |
| 多任务画布空间 | FD Studio 品牌视频页线索 | 按任务分散节点密度、跨空间取用素材 | 多 Tab 和复制不能直接证明跨画布引用或同步 |

对当前方案的启示均属于研究建议：

1. **需要画布内有真实制作操作。** 如果仅允许摆卡片，LibTV 所体现的输入检查、依赖、批量和局部返工价值就没有落地。
2. **画布可以是整体制作环境，也可以是特定阶段的操作面。** 国内证据不支持用一个固定定义概括全部产品；不能因为竞品叫无限画布，就默认必须把整部剧铺在同一张无边界图中。
3. **必须显式区分关系。** 参考输入、脚本关联、生成来源、当前选用、剪辑顺序应有清晰规则；空间位置不能隐式改变正式镜头顺序。
4. **候选探索与正式采用分开。** LibTV 前端对副本上下游区别处理是值得研究的设计线索；我们应当独立定义采用、更新剪辑及重新审阅的规则。
5. **专用编辑器可以留在画布内部入口中。** 3D 导演工具和时间线各自承载适合自己的操作，不需要通通退化成普通卡片属性。
6. **多人能力要用实际冲突用例验收。** 团队套餐、共享素材、实时存在、节点占用、多人同时编辑、审片权限是不同能力，不能一并归到协作已支持。

## 9. 后续最值得补的实际使用证据

- 相同一场戏，分别完成参考准备、生成两个候选、复制探索分支、采用一个结果并送入剪辑。
- 修改上游角色参考或脚本，检查现有结果是否改变、是否提示重做、费用是否可预知。
- 两人同时打开并操作同一镜头，检查谁能修改、冲突和断线如何恢复。
- 把局部制作方法保存后用于下一场戏，检查哪些资产、参数、版本、位置和连接被继承。
- 较多镜头、候选和素材共存时，检查定位、收起、搜索和自动布局是否仍能支持日常制作。

这些都尚未本轮实测，不能用厂商宣传或公开前端词典替代。
