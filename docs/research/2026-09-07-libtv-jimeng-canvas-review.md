# LibTV、即梦画布：从交互形态回到业务问题

日期：2026-09-07。状态：根据用户追问修正分析层次；研究与产品判断，不新增已承诺的 MVP 功能。

后续更新：同日重新调研的 [国内外画布市场复核 v2](2026-09-07-canvas-market-review-v2.md) 补入更多当前产品与操作证据，并将“场次内可选视图”扩展为“主要创作工作区与不同粒度的原型对比”。本页保留讨论历史，当前市场判断优先参考 v2；MVP 范围仍需产品决策。

## 1. 先区分三层

| 层次 | 需要回答的问题 | 本工作台示例 |
|---|---|---|
| 业务能力 | 用户需要完成什么 | 指定画面局部修改、正确使用参考、比较候选、保留采用版本、复用制作步骤 |
| 交互方式 | 用户怎样表达和查看 | 图层画布、节点画布、候选对比面板、表格、时间线、对话或侧栏 |
| 执行与数据机制 | 系统怎样做到并保留结果 | 模型调用、蒙版、参考关系、任务依赖、输入快照、版本、成本与权限 |

画布是一种空间化交互载体。评价重点应是它是否让目标任务更容易、更准确或更省时，而不是是否有无限缩放、节点和连线。底层能力未建立时，增加画布不能自动提供一致性、可追溯性、工作流复用或可靠协作。

## 2. LibTV 和即梦包装了不同能力

### LibTV：将内容及制作关系可视化

此前同日实际读取的官方指南包含文本、图片、视频、音频、脚本节点，以及关联、脚本拆解、资产、分镜和按范围生成。它将素材与加工步骤放在同一个制作环境。证据沿用当日已读正文，本轮未重取飞书正文；详见 [既有核查](2026-09-07-libtv-and-review.md)、[官方指南](https://resonate.feishu.cn/wiki/Loxfw6XHziYRk0kKzdjcFfp9nhb)。

官网当前还提供 Agent/CLI 接入入口，但本轮未安装或执行。此入口支持将「业务执行能力」与「用户操作界面」分开看待，不据此断言 CLI 与界面所有功能完全一致。[官方 CLI 入口](https://www.liblib.tv/cli)

产品推论：核心问题是多种素材和步骤之间的上下文、引用与重复操作。节点画布可以可视化这些关系；资产侧栏、结构化制作表单和模板也可以承载部分相同能力。

### 即梦：图像编辑画布与创作空间必须分开评价

真正官网公开页的「智能画布」明确包括多图层、多图融合、局部重绘、扩图、消除与抠图。这组能力主要解决对画面局部及构图的控制。[即梦官网](https://jimeng.jianying.com/)

当前应用首页已有 Agent 与技能入口；另找到无限画布发布线索，但尚未完整核实社媒作者与官网账号关联，不能将其细节视为完整产品实测。旧智能画布也不能代表即梦当前所有创作入口。详细证据与边界见 [即梦专项核查](2026-09-07-jimeng-canvas-official.md)。

图像编辑画布里的位置、大小、图层与选区会影响实际图像；节点工作区中的卡片位置通常只用于布局，输入依赖由明确引用或连接表达。这两种画布虽然都能拖拽，解决的问题不同。Agent 是表达与执行入口，不自动证明多人共编、严格版本或审片能力。

## 3. 需要解决的底层问题与替代交互

| 真实问题 | 画布可能提供的帮助 | 其他可行方式 |
|---|---|---|
| 很难用文字精确说明修改位置和构图 | 直接选区、拖动物体、调整大小与图层 | 专用图像编辑面板；仍需要空间操作，但不需要全项目无限画布 |
| 多个角色、场景、声音参考难以同时正确使用 | 把当前参考与生成对象并置，显式表达用途 | 角色/场景选择器、资产侧栏、分镜详情表单 |
| 随机生成产生很多备选，难以比较和继续 | 并置候选并显示分支与来源 | 候选网格、同步对比播放器、版本历史 |
| 多步骤反复传递素材，容易漏步骤或用错输入 | 连接输入输出并可视化执行路径 | 固定流程、批处理表单、模板、Agent 或 API |
| 内部交接时难以说明当前方案 | 共同查看参考、候选和带位置的反馈 | 绑定版本的审片面板、项目记录和任务交接 |

共同价值是减少记忆、查找、重复输入和沟通歧义。画布是否优于替代交互，取决于该任务的关系复杂度、并行探索需求与空间表达需要。

## 4. 利弊

### 适合使用时的收益

- 同时呈现多个参考和方案，减少来回切换和凭记忆比较。
- 直接指向视觉对象或区域，减少仅用语言表达时的歧义。
- 呈现非线性探索和输入来源，便于从既有候选继续。
- 在同一工作环境连接准备、生成与局部编辑，减少素材搬运；这部分收益也来自工具集成，应与布局收益区分。

### 可能增加的成本

- 用户要花时间摆放、分组和整理；画布变大后可能难以定位。
- 空白画布增加起步负担，节点类型和连线规则增加学习成本。
- 空间排列容易被误读为故事顺序、依赖或采用关系，必须明确语义。
- 多媒体预览和大量节点有性能成本，多人修改也需要处理布局与内容冲突。
- 自由分支会放大候选、版本和费用管理问题，需要独立机制保障。
- 标准化高频生产可能用批量表单更快；需要精确时序的操作由时间线承担。

画布不会凭自身保证人物一致、台词正确、局部修改无损，也不会自动记录可靠版本、批准或权限。应分别建设与验收这些能力。

## 5. 对本工作台的建议修正

先将需求定义为：

1. 正确复用已确认角色、场景与声音参考，减少重复配置。
2. 围绕一个镜头或镜头组比较候选，选择结果并继续修改。
3. 精确表达需要改变的区域或范围，并保留采用和历史版本。
4. 将验证成熟的步骤用于后续镜头和项目。

再选择交互：参考选择与日常生成可采用结构化分镜界面；局部图像修改用专用编辑画布；多方案探索可以采用场次画布；成熟流程可以封装为模板。画布可以是主创常用界面，但不因它存在就要求全部成员以自由连线组织生产。

前一轮「优先验证场次画布」保留为交互假设，不预设它一定优于卡片与侧栏。比较时两种界面应具备相近的参考、候选、编辑和版本能力，避免将新增业务功能的效果误算为画布效果。

验收围绕同一场戏，记录准备输入、比较候选、指定返工和交接的时间，检查误用版本与采用错误；同时记录布局整理成本、质量和实际费用。由净收益决定是否纳入 MVP。
