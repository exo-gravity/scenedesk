## 对写实短剧工作台的产品推论

以下是设计推论，不是即梦已经具备相应制作管理能力的证明。

1. **图像编辑画布与创作空间需要区分。** 前者解决某张参考图如何修好，后者解决人物、场景、文本、候选和后续生成如何放在同一上下文。我们的场次画布可以调用图像编辑能力，不必首版自建完整图层编辑器。
2. **自由摆放只有和可执行操作结合才有持续价值。** 当前即梦的 Agent 入口提示：选择画面后直接提出修改、从素材继续生成，可能比手工连节点更适合制作成员。选中内容的作用范围、输入引用和费用预览仍须可见。
3. **多会话适合并行探索，但需要明确采用结果。** 例如「连续双人对白」与「逐镜头正反打」各有一个尝试区，最终候选仍应绑定同一个场次/镜头记录。不能让会话数量替代作品版本管理。
4. **团队能力不应作为竞品的假定空白。** 我们可以强调剧目—集—场次—镜头、固定资产版本、选用状态和交付审片，但这些应通过实际工作流比较证明，不能因为竞品有自由画布就断言其无法协作。
5. **产品流程与供应商接入分开。** 即梦网页版里存在某项编辑/Agent 功能，不表示 Seedance API 自动提供同样能力；接入工作台仍要逐项核验模型服务。

## 下一轮实际界面应核对

- 新建画布、Agent 会话和素材库之间的入口及关系。
- 选中素材后发起的生成/编辑如何保留引用、提示词和结果历史。
- 多会话能否共享指定素材，是否能清楚辨认各自上下文。
- 视频生成、剪辑、声音和画布空间的具体边界。
- 团队版是否支持共同编辑同一画布，或仅共享空间和资产。
- 一场双人对白从两种拍法探索到采用和局部返工的实际操作数、时间、费用。
