# 短剧 MVP：场次制作用户旅程与交互设计 v0.1

日期：2026-09-09。状态：依据本轮已确认的产品选择形成的设计细化稿，其业务选择现已并入实施包 v1.1。布局和按钮是本稿建议，尚未做目标用户走查或真实制作验证；09-09 收尾已同步主稿、领域、接口和验收，当前权威增补见 [14](implementation/14-scene-mvp-closure.md)。

目标：一名 AI 制作人员主责，团队协助与审阅，完成一场戏，并让成果能够进入整集。借鉴已有产品的具体做法，范围以当前 MVP 为准。

## 1. 已确认的产品边界

| 决策 | 当前约定 |
|---|---|
| 客户与内容 | 中小工作室内部团队，不设 10 人上限；AI 写实短剧优先，长期支持广告 |
| 主场景 | 从已有戏文与部分参考出发，完成镜头制作、连续组接、审片和返工 |
| 主操作者 | 一名制作人员承担这场戏的大部分制作与修改；其他成员可补资产、处理声音或接后期 |
| 交付结果 | 经过确认、可用于整集的场次基础成片，加已选源素材、使用区间和实际具备的音频／字幕 |
| 首条验证路径 | 现代、少量角色、对白、反应镜头与简单动作；作为测试样本，不限定平台长期题材 |
| 创作决定权 | 制作人员自主调整镜头实现与候选；剧情、正式台词和已确认共同设定的变更交主创确认 |
| 主创介入 | 首次建立或明显改变关键方向时确认方案；整场连续观看后确认结果，疑难镜头可提前讨论 |
| AI 范围 | 提出分镜、参考与提示建议，准备局部修改；制作人员确认明确的生成范围后执行，采用和审片由人决定 |

主创是本项目承担创作确认的负责人职责，首期沿用项目权限，不新增一套复杂角色。场次主责可以用一项关联场次的制作任务表示，无需给每个镜头都创建人工任务。

场次确认属于内部制作交接。完整 MVP 还需支持整集编排、最终审阅交付和下一集复用；单个场次跑通只是第一条工程切片。

## 3. 一个场次，三个相互接续的工作视图

首期推荐以“制作／剪辑／审阅”承接三类操作，共用场次、素材与版本。它们是同一工作中的视图，切换时保留当前场次及已知对象定位。

### 3.1 制作：看依据，做镜头，从候选继续

顶部显示项目、集、场次、主责人员，以及当前工作提示。左侧用集／场次导航定位内容；中央按叙事顺序展示镜头卡；选中镜头后展开播放器和最近候选，侧栏展示要求与本次参考。

镜头卡默认只呈现：编号、叙事意图、当前采用缩略图、可理解的工作提示。精细机位、完整提示、来源版本和历史按需展开。视频候选首期切换播放，图片可并置查看；不建设同步视频比较播放器。

常用动作保持就地可见：准备生成、继续尝试、采用、加入剪辑、查看相关意见。资产库以选择器打开，选择或导入后返回原镜头；不要求来回切换项目页面才能完成一次引用。

资料尚不齐全时允许先做局部试作。角色／造型草稿可以在项目内用于尝试，界面标识其状态；确认共同设定与发起普通生成是不同操作。

### 3.2 剪辑：尽早连起来看，随时返回制作

采用现有方案中的顺序主视频轨、基础音频层和字幕轨。支持加入片段、排序、裁切、基本音量与静音、字幕编辑、保存及连续预览。可以只加入几个镜头开始查看，不等待整场全部制作完成。

选中片段时能查看实际使用的源媒体与区间。平台掌握映射时可回到对应镜头或候选；外部导入成片缺少映射时明确显示未知，由人关联。

替换默认保持原片段时长，需有足够长的源区间；改变时长时进入剪辑调整，并检查受影响的声音与字幕。它沿用现有替换规则，不自动变速、补帧或静默挪动关联内容。

### 3.3 审阅：确认一份具体场次版本

提交审阅时固定剪辑内容并生成可播放稿。主创进入该版本，播放器旁展示意见和本轮修改说明。点击时间码定位原稿，首期支持时间点及整体意见；可保留已有接口的时间范围字段，不以复杂区间控件作为第一条切片前置。

主创可以选择“需要修改”或“确认可用于整集”，都针对当前固定稿。评论处理完成不会自动批准；后续草稿和新版本也不会继承这次批准。

一个场次可以同时显示“已确认 v1”和“草稿 v2 制作中”。生成作业、候选采用、审阅决定各自保留，不压成一个可随意手工修改的总状态。

## 4. 第一条完整操作路径

下表是建议交互，非竞品实操案例。三类操作允许穿插；不是要求全部镜头同步经过阶段审批。

| 步骤 | 用户动作与输入 | 成果落在哪里 | 必须保留的操作边界 |
|---|---|---|---|
| J01 接到场次 | 从我的工作或项目打开场次，查看戏文、要求和已有参考 | 当前场次及主责工作 | 未填完全部剧目设定也能开始；接手者看得见当前依据 |
| J02 补齐依据 | 选择已有造型／场景，或导入参考并说明用途 | 项目资产、素材或本次引用 | 普通素材不必都升级为设定资产；草稿试作不改变正式依据 |
| J03 调整分镜 | 人工拆镜、补镜；必要时请求分镜提案 | 可编辑镜头与待采纳提案 | AI 不直接重写已有镜头、台词和采用；正式内容变更由主创确认 |
| J04 准备生成 | 选镜头或镜头组；核对实际参考、提示、模式、数量与消耗 | 一份明确的生成计划 | 仅本次修改与保存为后续要求分开；不强制先图后视频 |
| J05 执行并比较 | 按计划生成；等待时可继续其他工作；检查候选 | 作业记录及归档后的候选 | 原作业与原候选保留；一个视频可由人标出多个镜头区间 |
| J06 采用与组接 | 选候选区间并采用，就地加入剪辑或更新指定草稿 | 采用记录及实际剪辑使用 | 采用成功不自动改变旧剪辑；重复加入或失败恢复有明确结果 |
| J07 连续检查与提交 | 检查画面、实际对白、声音、字幕和衔接，生成审片稿 | 固定场次版本 | 临时文本不冒充实际对白；生成完成不等于声画正确 |
| J08 根据意见返工 | 从原稿意见定位问题，继续制作或剪辑，回复处理结果 | 新候选／新稿及旧意见处理说明 | 旧时间码仍定位旧稿；已知来源才自动跳转，未知映射由人明确 |
| J09 确认与交接 | 主创确认指定场次稿，导出场次工作包或进入整集 | 已确认稿及配套工作材料 | 场次确认不自动批准整集；实际缺少的独立音轨不得在清单中伪造 |

第一次内部切片可以使用导入媒体检查 J01—J09；真实主模型路径在早期并行验证。完整 MVP 必须再用真实生成和真实团队工作检验，并完成整集接续及第二集复用。

## 5. 把 Agent 缩成三个明确入口

AI 辅助从当前对象进入，不要求首期建设全项目聊天空间、工具市场或通用 Agent 编排器。每份文字提案可重新打开、编辑并采纳，不能仅存在于聊天回复中。TapNow 的独立文字产物与再次修订入口提供了这种参考。[产物管理](https://docs.tapnow.ai/en/docs/agent/manage-agent-outputs)

| 入口 | 输入范围 | 输出与人的决定 |
|---|---|---|
| 生成分镜建议 | 选定戏文、已有项目设定与用户明确补充 | 新增镜头建议及资产需求；人编辑、采纳到指定场次，不自动覆盖已有结构 |
| 准备本次提示 | 当前镜头要求、实际选中的参考与可用模型模式 | 可编辑提示草案，说明引用用途；人核对后形成生成计划 |
| 按意见准备修改 | 一条具体反馈、被评论版本、已知来源和指定候选 | 说明修改项与保留项，准备新尝试；新结果仍需检查与采用 |

批次内范围、数量和预算已经明确时，可以一次确认后连续执行。变更正式台词、扩大范围或增加消耗时重新呈现变化；不把自动重试变成无限购买。AI 效果、模型能力及费用仍需按实际接入验证。

首期“继续尝试”可以通过调整提示和参考后重生成完成；选区重绘、视频精确替换、口型修复等只有在所选路径验证可用时才开放。没有验证的能力提供导入外部修复结果的接续入口，不能仅凭竞品按钮列入承诺。

## 6. 一次返工怎样算真正处理完

示例：主创在场次 v1 的 00:18 留言“递钥匙时手部异常，保留人物、钥匙样式和当前节奏”。这是研究样例，未实际生成。

1. 制作人员从该意见打开 v1 对应时间；平台已有剪辑映射时显示实际源片、候选与使用区间。
2. 选择继续尝试，预填已知参考，明确修复手部、保留身份和道具；核对后使用已验证路径重做，或导入外部修复结果。
3. 查看新候选，同时检查保留项是否意外改变。满意后采用，在原草稿的目标片段选择替换；源区间不足原时长时需要另选区间或调整剪辑。
4. 连续播放修改点前后，检查动作接续、对白、声音与字幕。保存后提交 v2，在原意见下关联处理说明与新稿。
5. 主创切换查看 v1／v2，判断问题是否解决并确认 v2。v1 的意见、时间码与历史决定仍可查看。

“新视频已经生成”“制作人员提交了修改结果”“主创确认了新稿”是三个事实。首期用清楚的入口和记录连接它们，无需为每条意见建复杂审批流程；需要他人协助时才从意见建立轻任务。

Frame.io 的时间评论与版本机制可供借鉴，但其公开资料没有证明成片时间码能定位原生成任务，也没有证明剪辑变化后评论会自动语义对齐。这些关系要依据我们自己的剪辑使用记录处理。详见[有界补查](/Users/gandy/Documents/ChatGPT/drama_platform/docs/research/2026-09-09-review-handoff-patterns.md)。

## 7. MVP 采用与后置清单

| 首期采用 | 简化方式 | 明确后置 |
|---|---|---|
| 场次主责与团队支持 | 当前项目成员中指定主责，意见关联轻任务，复用现有权限 | 跨组织制作、多级任务排程、外包门户 |
| 参考、候选与持续创作 | 参考卡、候选列表、图片并置、视频切换、继续尝试 | 无限画布、任意执行图、同步多视频比较 |
| AI 辅助与生成 | 三个限定入口、明确计划、一条已验证主视频路径，按需要补图片和声音 | 自主完成整场的 Agent、复杂工具规划、Skill 市场 |
| 基础编排与声音 | 主视频轨、基础音频与字幕、实际听看核对、明确替换 | 专业合成调色、高级分轨、自动口型修复、专业工程往返 |
| 内部审片 | 固定稿、时间点意见、回复、新稿关联、整场确认 | 自动评论迁移、复杂批注、多级审批、实时共编 |
| 复用与交付 | 项目资产、基础共享、源素材工作包与已知使用关系 | 可执行工艺作者平台、版本迁移工具、广告业务入口 |

普通参考复用和“从候选继续”属于必需制作能力。自由空间及连线只是候选呈现方式，继续保留 UX-01 验证。我们可以先完成上表的操作，不为保留可能性同时开发两套工作区。

MVP 仍保留基本的租户／项目隔离、版本冲突处理、费用与在途状态、媒体归档恢复、已确认版本保护。减少首期深度应从高级界面和通用能力入手，不省略会直接造成重复消费、丢失成果或错误交付的行为。

## 8. 与既有设计的衔接

本稿是新的讨论结论与交互细化入口。[完整方案 v1.2](/Users/gandy/Documents/ChatGPT/drama_platform/docs/ai-drama-workbench-product-design-v1.1.md) 和[既有交互规格](/Users/gandy/Documents/ChatGPT/drama_platform/docs/implementation/02-interaction-spec.md) 现已按下面的变化同步；下表保留变更缘由，详细当前规则见 [14](implementation/14-scene-mvp-closure.md)。

| 项目 | 处理方向 | 本轮同步位置 |
|---|---|---|
| 场次主责 | 用关联场次的主责任务表达，不增加租户角色或强制逐镜派单 | 需求、任务与页面默认定位 |
| 创作决定权 | 允许草稿试作，正式台词／共同设定变更留下明确确认与版本依据 | 剧本及设定草稿、提案采纳、确认记录；不用逐字段权限系统 |
| 有限 AI | 原稿只含初次 create 拆解；本稿增加提示准备与按反馈准备新尝试 | 文本提案接口、计划准备、任务结果；既有结构自动重写仍后置 |
| 场次内拆镜 | 提案应采纳到用户正在处理的场次 | 现已增加明确 target 与内容／提案双版本检查，生产业务接口仍待实现 |
| 场次交付 | 确认场次稿并形成内部工作包，进入整集继续制作 | 复用剪辑／审阅／工作包规则，保留整集最终交付资格判断 |
| 候选与剪辑 | 采用后在当前上下文就地加入或替换；实际使用继续独立记录 | 原候选、采用和两种替换模式可沿用，补动作接续与失败反馈 |
| 试点评价 | 第一阶段优先验收团队能完成、修改、接手与交付 | 人工、费用与周期保留为观察数据，不能作为先证明差异化的门槛 |

本轮已确认的业务方向已集中同步到 PRD、接口和验收。页面布局与按钮安排仍需通过交互走查及真实制作验证，后续迭代以统一实施基线为准。

## 9. 内部走查与实现验收的最小清单

- 从有戏文、部分参考的场次开始，缺资料可以就地补充。
- 切换镜头、进入素材选择器或 AI 提案后，能够回到原工作上下文。
- 从旧候选继续尝试，旧结果和既有剪辑保持可辨识。
- 一个视频用于多个镜头时，实际源区间清楚，媒体无需重复上传。
- 采用后可以加入剪辑；加入失败时保留已成功采用并可单独恢复，不重复生成。
- 替换镜头改变时长时，相关声音与字幕能明确处理和复查。
- 主创在固定版本的时间点给意见，制作人员提交新稿后仍能找到原意见和处理结果。
- 外部成片没有逐镜映射时清楚显示未知，允许人工关联；不制造自动追溯结果。
- 场次已确认后继续修改会形成新稿，原批准不自动继承。
- 两位成员分别承担制作与主创职责时，可以自行完成接手和确认；角色也允许由同一人兼任。
- 整集接续、下一集复用与实际后期交接仍在完整 MVP 验收内。

上述首先用导入媒体和固定样例走查，再使用真实模型与目标团队验证。工程贯通、生成质量和真实团队可用性分别记录；本稿不预先声称任一项通过。
