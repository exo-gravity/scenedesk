# 整体产品方案 review

> 历史方案／评审记录：保留当时判断，后续短剧优先、每场双模式及已确认布局见[当前文档入口](README.md)。本文建议不自动进入当前 MVP 或待办。

日期：2026-09-07。范围：整体产品与优先级、短剧端到端制作、未来广告复用、资产、生成、声音、剪辑、审片、协作、权限、费用、MVP 和迭代计划。

基线：用户已确认长期支持短剧与广告、当前优先短剧设计、尽可能复用底层核心能力；短剧优先 AI 写实和 Seedance 等领先模型，中小工作室不设 10 人上限，首版内部协作与简单权限。

方法：逐项交叉检查当前设计及专项文档，推演修改、跨镜头采用、外部精剪、成员退出与未来广告接入情境；复查 Seedance 的官方发布和正式接口资料。未运行产品代码、付费生成、多人试用或成片质量测试。本报告中的新设计规则是 review 建议，不等于用户已批准全部实施细节。

## 1. 总体结论

**整体方向和主要对象划分成立，建议保留；当前方案可以进入详细原型和关键制作验证，但尚不足以冻结完整研发日程或承诺量产效果。**

当前应集中完成短剧制作体验及一条可验证的交付路径。未来广告复用的重点是媒体、执行、版本、剪辑、审阅和费用机制；两类业务继续保留自己的内容语义和用户操作方式。

本次优先处理三类事项：已有开放问题需要落实验收标准；部分首版能力深度需要收敛；对象之间的操作与状态关系需要明确。已将设计建议同步至短剧主稿和相关文档；模型接入、成片质量、客户需求及成本仍保留为待验证。

## 2. 全面检查结果

| 检查维度 | 结论 | 当前处理 |
|---|---|---|
| 长期定位与首版优先级 | 一致 | 长期双场景，首版短剧；广告不阻塞首发 |
| 首批用户与价值 | 方向成立，实际购买与持续使用证据缺失 | 区分主操作人员、项目负责人、付款决策者；通过同任务对照试点验证 |
| 项目、剧目与内容层级 | 合理 | 管理范围与短剧内容分开，保留单集／场次／镜头；不要求未来广告创建剧集 |
| 剧本与创作设定 | 功能齐全，默认操作深度需收敛 | 从文本和明确格式起步，局部建议采纳，冲突保留待确认草稿 |
| 分镜与生成 | 主入口合理，控制项可能形成录入负担 | 当前场次为日常制作入口，精细参数按需展开 |
| Seedance 与其他模型 | 优先级合理，生产通路未实测 | 一条已验证主路径加基本返工；能力按实际账号展开 |
| 声音、粗剪与精剪 | 已区分声音阶段，但最终交付验收需固定路径 | 平台审片版及素材包、必要外部精剪、回传确认 |
| 候选、采用、剪辑与审片 | 对象已有区分，状态同步尚不充分 | 补齐显式同步、版本冻结和过时结果提示 |
| 资产与版本复用 | 规则较完整 | 保留共享／项目两范围和固定版本，补齐采用更新与业务含义分层 |
| 团队、租户与权限 | 当前内部范围下相互一致 | 保留固定角色与项目范围，不增加审批层或外部角色 |
| 画布 | 已回到业务价值讨论 | 先以卡片、侧栏、对比和基础剪辑满足任务，再验证画布收益 |
| 公共核心模块 | 方向正确，需在接口与数据设计中落地 | 生成、媒体、剪辑不强依赖场次；人工任务与生成执行职责分开 |
| 费用、容量与恢复 | 财务与权限思路较完整，运行与总成本证据不足 | 保留预占与核对，补充媒体容量、归档、运行成本和估算差异处理 |
| MVP 与路线图 | 无需扩大业务范围，需限制每项深度 | 明确第一版必做与按验证前移项；历史路线图与当前基线分开 |

## 3. 重点发现、影响与修订

### R1：首发交付标准尚未成为同一份可验收约定

类型：已有开放问题，需要在开发范围冻结前解决。优先级：关键。

证据：[短剧主稿](ai-drama-workbench-product-design-v1.0.md) 的「声音与粗剪」「MVP 交付边界」与第 12 节分别谈到平台简单成片、外部精剪和完成作品，但样本规格与采用路径仍未确定。原稿已承认 MP4 无法重建外部工程，本次不把该限制描述为新发现。

影响：团队可能分别把“可以观看的整集审片版”和“达到发行要求的最终成片”当作 MVP 完成，导致剪辑器范围、质量和工时估算不一致。

建议：默认以平台形成审片版和素材包、必要时外部精剪、最终回传确认构成闭环。能直接达标的简单成片可以在平台交付。样本预先约定画幅、时长、声音、字幕、质量及是否需要外部精剪。

已同步：明确回传成片独立版本、使用新文件时间码、记录交接来源与外部工时。未取得外部工程时，平台只保证已登记文件及来源，不声称完整镜头采用细节或外部工程可重建。

仍待完成：与试点团队约定实际样本和可用标准。当前只能形成设计验收条件，不能宣布通过。

### R2：首版的能力名称已齐全，但各项深度需要限制

类型：范围收敛。优先级：重要。

证据：复核前，短剧主稿第 7 节将“单镜头及镜头组生成”同时写入完成依据，其他章节又按接入能力展开；剧本、设定、分镜、批量、编辑等范围若各自完整展开，会形成多个并行建设方向。

影响：研发容易把支持的长期制作方式理解为首版全部实现，或先完成所有工具视图再验证作品可用性。

建议与同步：

- 先验证一条 Seedance 优先的主生成路径及重做替换；数据关系仍支持连续素材用于多个镜头。
- 输入先覆盖文本和明确格式，AI 按选定范围提出建议；不确定匹配保持待确认，历史内容继续保留。
- 分镜参数作为按需控制，默认只显示当前任务需要的输入。
- 镜头卡、参考侧栏、候选对比与基础整集预览先行；独立动态分镜编辑、通用节点、完整 Agent 和复杂资产编辑后置。

已有必要的声音、资产版本、内部审阅、预算和失败恢复继续保留，不把基本生产可靠性当作可任意删减的附属功能。路径收敛不等于降低用户要求的写实质量标准。

### R3：生成、选用、剪辑使用与审片之间缺少明确操作规则

类型：行为设计缺口。优先级：关键。

证据：原稿已要求分开存储候选、选用与审片，但没有完整定义“更改镜头选用后，已有剪辑如何更新”“生成期间镜头要求变化后，返回结果如何呈现”。

影响：可能发生预览仍播放旧候选、已审版被替换、评论时间码错位、过时结果自动被采用等问题。这些直接影响团队对工作台的信任。

已同步的默认规则：

| 情境 | 应有行为 |
|---|---|
| 新候选返回 | 入库后可比较，现有选用与剪辑保留 |
| 更改当前选用 | 提示直接剪辑引用，由用户确认更新草稿范围并检查时长、区间与声音 |
| 修改已审内容 | 派生新草稿，新版重新确认；旧版决定和交付保留 |
| 生成时上游要求改变 | 显示结果所用输入与当前要求的差异，保留结果供人工选择 |
| 同一长片段用于多个镜头 | 每个采用保留独立区间，不因一个镜头返工自动替换其他使用 |

这些是纸面设计规则，仍需原型和后续实现验证；不声称已经完成自动影响分析。

### R4：主操作路径需要比模块导航更明确

类型：体验设计缺口。优先级：重要。

证据：主稿列出了剧目内七个区域和较多分镜字段，虽然已建议创作者停留在当前上下文，但尚缺首次使用的最小路径和默认必填深度。

影响：用户可能先整理完整资产库、逐镜填写所有导演参数或重复维护任务，才能开始真实创作。

建议与同步：以“继续制作当前场次”为日常主入口；从已有剧本／分镜选择一场，参考和候选在当前区就地使用。保留全部功能区域供查找，精细参数按需展开。负责人、当前版本和待处理原因清楚可见，人工任务按交接需要添加。

试用关注：另一成员能否直接找到正确参考、采用结果及返工意见；界面简化是否实际减少操作，而非把必要控制藏到无法发现的位置。

### R5：公共模块复用要落实到业务含义的归属

类型：对既有正确方向的细化。优先级：重要。

证据：整体 v0.2 已明确公共模块不依赖剧集／场次；资产专项把角色身份、造型、文件、版本与参考准备合写在一个功能模块中，进入实现设计时仍可能重新耦合。

建议与同步：公共模块管理媒体、通用版本、用途引用、生成执行、剪辑、审阅和费用；短剧模块解释角色身份、剧情状态和分镜，未来广告模块解释商品／课程事实与创意。制作协作与生成执行职责分别说明。

复用检查用代表性广告任务在纸面进行：没有剧集时仍可生成、采用、剪辑和导出；上传视频与生成视频可共同使用；相同素材的不同使用不重复计算生成费用。当前不实现空置广告业务或通用工作流引擎。

这里没有推翻既有租户、项目、媒体和作业划分，也不承诺未来广告接入无需修改接口。

### R6：Seedance 生产通路属于未完成的关键验证

类型：已有技术风险，已复核公开证据，账号与质量仍未知。优先级：关键。

本次复核的海外 BytePlus LAS 文档列明 Seedance 2.5 接口，但服务地区、参考素材和输出规格有具体约束：文档限制真人脸参考直接上传，并提供白名单素材库通路；该接口的 2.5 输出列为 480p／720p，结果链接有效 24 小时。这些是该服务的说明，不外推国内方舟或用户账号，也不据此断言虚构写实角色全部受禁。[LAS 正式文档](https://docs.byteplus.com/en/docs/byteplus_las/video_gen_enhanced)

官方发布提供多参考及连续叙事等能力描述，支持优先评估方向，仍不能替代本项目样片测试。[Seedance 2.5 发布](https://seed.bytedance.com/en/blog/one-take-creation-flexible-referencing-introducing-seedance-2-5)

建议与同步：形成地区、服务、账号版本、参考素材通路、媒体组合、声音、输出、费用和恢复的接入记录，并分别标明文档支持、账号可用与样片通过。先做一场对白和一次局部返工，再验证跨集复用。

该项未因文档修改而关闭。目标版本、采购方式、实际质量和可用成本仍需真实接入与试作，当前无已验证账号和付费测试结果。

### R7：制作成本指标合理，但商业和运行证据尚不完整

类型：已有验证方向的补充。优先级：重要。

证据：主稿已有每分钟合格成片成本、时间及对照试点；资产专项将高级生命周期管理后置。当前仍无真实完成率、人工支持量、外部精剪成本或持续使用记录。

建议与同步：区分日常操作、内容确认与付款决策；同一任务比较现有工具组合，成本覆盖失败尝试、生成等待、人工帮助、外部精剪及基础媒体运行。先明确试点容量、归档、保留及恢复范围，高级自动清理后续再做。

预算预估、预占和实际账单分别记录；估算差异影响后续可提交额度并可核对，不能把估算当绝对费用保证。无实测时不设置虚构收益比例、完成率、价格套餐或日历工期。

### R8：历史研究中的路线图仍可能被误读成当前范围

类型：文档一致性。优先级：一般。

证据：[历史市场复核](research/2026-09-07-workbench-market-review.md) 第 5 节仍有早期客户审片安排，且指向旧核心稿；当前用户要求内部协作。历史双场景 MVP 计划已标记过时，但尚缺统一阅读入口。

已同步：增加文档索引，历史研究标注证据快照与旧方案建议的区别；当前整体方向、短剧细节、专项与未来广告参考分别定位。历史事实未按新产品方向重写。

## 4. 保持不变的设计

- 长期双场景、当前短剧优先，广告不增加当前首版验收条件。
- 项目管理与剧目内容分开；场次表示戏剧行动，场景资产表示可复用空间。
- 分镜工作台为制作入口，故事板为视图，画布按实际任务价值决定。
- 支持单镜头及连续片段的内容关系，不把一次调用等同一个镜头。
- 声音贯穿生成前、中、后；参考声音、原生声音与独立音轨分别考虑。
- 资产共享／项目两范围、明确版本、显式发布引入；采用与批准分开。
- 一个客户团队空间对应当前租户，固定内部角色，Owner/Admin 全项目能力与普通成员项目范围保持一致。
- 模块化单体及必要后台进程，权限、预算、异步恢复随真实流程提供。

## 5. 进入详细设计后的产物顺序

1. **短剧样板任务与交付约定**：先把内容、规格、质量参考、网页／外部精剪分工写成一页。缺真实素材时可以继续示例原型，质量验收保持待定。
2. **三段主要操作的原型**：创建与第一场准备；当前场次生成、比较与返工；整集编排、审片和交付。用状态情境贯穿，公共能力在设计中标注。
3. **首个正式模型通路验证记录**：账号与样片结果决定具体能力，不以全型号支持作为开始条件。
4. **可验收的研发任务**：每项写清输入、操作、成功和失败结果、版本及权限；按可运行流程分批交付，再根据研发资源排期。
