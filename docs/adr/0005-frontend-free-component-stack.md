# MVP 通用 UI 采用 Mantine，核心创作工作区自主设计

状态：accepted，2026-09-09。用户明确确认本次 Mantine 建议，并要求写入文档后讨论视觉规范。接受的是技术选型与使用边界，不表示主应用已迁移或完整业务验收通过。

MVP 使用 Mantine 作为唯一通用 UI 库，基础表单优先复用 Mantine Form，多面板优先使用 Mantine Splitter。通用按钮、输入、弹窗和菜单直接使用主库；核心镜头卡、资产选择、候选比较、片段条和审阅界面由业务组件组合实现。集中主题与有作用域的 CSS 维护产品视觉，组件默认外观不是产品视觉规范。具体版本起点、许可证和接入计划见 [17](../implementation/17-frontend-component-selection.md)。

选择依据是当前场次制作、生成参数、审阅与团队管理的综合覆盖，以及明确的免费商用许可、现有 React/Vite 兼容性和局部集成证据。基础组件减少重复开发，工程投入集中于版本、引用、声画关系和返工闭环。需要自建专业业务组件是通用库的共同边界，不足以单独否定 Mantine。

不混用第二套通用 UI，不修改第三方源码来强行适配页面，不为每个按钮增加透传包装。先贯通一个真实场次页面；只有出现具体且难以通过公开 API 解决的障碍，才重开 Kumo 或独立分隔布局组件的评估，不平行维护两套完整实现。

代价是集中维护主题、作用域样式、组件版本升级和必要交互回归，并验证高密度布局、键盘、播放器与拖拽的组合。镜头、采用、CutRevision、权限和费用独立于组件内部状态，未来增加广告或画布不需要重建这些事实。

后续用户授权“完成剩下内容”，专业组件已核对并经隔离样例裁决为 React Flow、Media Chrome、dnd-kit、Query，Virtual按需使用，详见17及[研究记录](../research/2026-09-09-specialized-stack-closure.md)。此前研究状态保留在历史记录，当前不得继续视为待选；专业库尚未整体迁入主应用，不代表真实业务验收。场次自由画布已由用户纳入首版，完整专业编辑器仍后置。
