日期：2026-09-07。状态：对核心设计 v0.2 的资产模块补充讨论稿。已确认方向为中小工作室、AI 写实优先、Seedance 等第一梯队模型优先；下文的信息架构、页面与规则为设计建议，未进入产品实现。

初版仅支持工作室内部协作，采用固定角色；外包、Guest 和细粒度共享权限留待长期实际需求出现后扩展。

## 1. 定位与入口

资产库保存团队反复使用的设定与实际制作素材，并记录它们如何用于作品。资产的选择应直接发生在剧目和镜头上下文内。

| 入口 | 用户在这里做什么 | 默认内容范围 |
|---|---|---|
| 工作室导航「资产库」 | 管理可跨剧目复用的角色外观、场景、道具、声音、风格参考与通用素材 | 已显式发布的共享内容；可以另行筛选自己有权访问的剧目内容，不扩大权限 |
| 剧目导航「资产」 | 确认本剧角色与造型、场景、声音，查找本剧生成或导入的素材 | 本剧创建内容、已引入的共享版本及本剧制作素材，跨单集使用 |
| 分镜／剪辑内「选择资产」侧栏 | 为当前场次、镜头组、镜头或音轨选择参考和素材 | 优先当前剧目；按使用目的筛选，可切换有权访问的共享内容 |

建议工作室导航：工作室首页 / 剧目 / 资产库 / 制作任务 / 用量与设置。

建议剧目导航：概览 / 剧本 / 剧目设定 / 资产 / 分镜 / 剪辑与声音 / 审片与交付。

「剧目设定」编排故事背景、人物关系、风格和默认设定引用；「资产」提供可引用的具体版本和媒体。设定页上的角色入口打开同一角色详情，不另存一套角色资料。剧目资产跨集使用，场次和镜头保存自己的采用关系及剧情状态，不逐集复制角色文件。

## 2. 内容分为设定资产与制作素材

两类内容共用底层媒体能力，分别提供适合其目的的浏览方式，不要求用户在两边各上传一次。

| 类别 | 内容组织 | AI 写实方向的重点 |
|---|---|---|
| 角色 | 角色身份说明、外观参考、多个造型、默认声音及其版本 | 身份、服装造型与声音分别明确；当前表演意图来自场次或镜头 |
| 场景 | 空间说明、参考图、可选布局图及白天/夜晚等表现变体 | 人物位置、门窗、桌椅等空间关系可供前后镜头复用 |
| 道具 | 外形说明、参考图、必要的状态变体 | 信件、手机等参与剧情的物件可核对外观和使用状态 |
| 声音 | 声线说明、试听样本、可用配音服务绑定或声音参考 | 区分声音身份、表演示例、实际台词音频与混合音轨 |
| 风格参考 | 图像或视频参考、风格说明、用途 | 明确用于灯光、画面、动作或运镜等，不自动把整个参考板全部提交模型 |
| 制作素材 | 上传/生成的图片、视频、配音、音效、音乐及成片文件 | 按来源、集/场/镜头、创建者、采用情况和审阅情况检索 |

角色条目是有意义的组合，而不等于一张人像图。例如「林夏」包含日常装与晚宴装两种造型，各有参考媒体；声音可由角色默认引用，也可因剧情需要显式改变。支持多角度参考和声音样本，但不要求用户为每个角色先填齐一套固定数量的素材。

「日常装」与「晚宴装」是可并存的造型；「晚宴装 v1」与「晚宴装 v2」是同一造型的修订，不能混成一条只能保留最新项的历史。

场次记录此刻的服装、伤痕、情绪和道具持有情况。角色库保存可复用的设定；不因某场戏愤怒或受伤，就改写角色的全部默认状态。

所有实际生成结果先自动登记到本剧制作素材，并关联来源作业与镜头/片段。选用、收藏或整理为设定是后续动作；没有选用的候选仍可查找，失败且没有产物的任务只留执行记录。存储或转码未完成时显示处理中，不能标记为可用于生成的参考素材。

已登记的角色参考图同时也是媒体记录。默认的「角色」页展示角色条目；「全部素材」可以查到相关文件，但不产生第二份上传或另一套版本。

## 3. 页面与关键操作

### 资产列表

顶部显示当前工作室/剧目范围、分类、搜索、标签及状态筛选，提供「新建」「上传」「从共享库引入」。角色和场景默认用图卡，制作素材提供图卡与列表切换。MVP 搜索覆盖名称、描述、标签、来源剧本对象和镜头编号；自动视觉识别与语义搜索后续增加。

角色卡展示代表图、角色名、选定造型、设定版本及确认状态；视频卡展示预览、时长、来源集/场/镜头及采用情况。无需让每个卡片承担所有后台元数据。

制作素材默认突出已采用、待审或最近生成内容；提供「全部候选」筛选。生成结果自动归档，不自动进入工作室共享库，也不自动替代已确认的角色或场景参考。

### 资产详情

| 区域 | 内容与操作 |
|---|---|
| 预览 | 角色参考、造型切换、声音试听，或视频/音频预览 |
| 设定与参考 | 文字设定、参考用途、默认项与可选项、实际引用媒体 |
| 版本 | 草稿、已确认版本、修订说明、对比、选择某版继续修改 |
| 使用位置 | 引用它的单集、场次、镜头及生成记录，按当前访问权限展示 |
| 来源与范围 | 上传或生成来源、创建者、所属库、允许复用的范围和必要的使用说明 |

主要操作为「用于当前场次/镜头」「设为该角色的参考」「创建修订」「引入本剧」「发布共享版本」「归档」。复杂素材批量编辑、关系图和审批链可以后置。

### 从剧本到生成的一次完整使用

1. 导入剧本后，AI 提出角色、场景、道具条目草稿，并关联剧本出处；已有条目给出匹配建议，由人确认，不自动合并同名角色。
2. 美术或主创生成/上传角色参考，比较后选定造型与版本，补充场景、道具和必要声音参考。
3. 在「第 1 集 · 第 3 场」选择「林夏 · 晚宴装 v2」「客厅 · 夜景 v1」和对应声音参考。场次为下属镜头提供默认引用。
4. 编辑单个镜头时可以覆盖默认项，例如回忆镜头改用日常装；覆盖在界面上可见。新增草稿沿用默认值，已提交或已确认内容保持原引用，其他未提交草稿显示变更待确认。
5. 提交前展示本次实际输入的剧本片段、参考媒体、用途、设定版本及预计费用。创作者可以减少不相关参考，或修正冲突。
6. 结果自动进入当前剧目制作素材，并出现在对应候选区域。优秀画面可通过「整理为角色参考」成为一个待确认的新设定版本，而不反向自动覆盖旧设定。

## 4. 与 Seedance 优先策略的关系

工作台管理的是「角色、场景、声音与用途」；提交模型的是符合具体 API 的文字和参考媒体。模型中的素材序号或素材 ID 不能代替本平台的角色身份。

一个资产可以保存许多参考，但本次生成只选择与意图相关、符合实际接口限制的一组。建议用途包含人物身份、服装、空间、动作、运镜、风格、声线、对白节奏等；这些用途是本产品的创作语义，由已验证适配器转成具体请求，不宣称供应商都有对应的专用参数。

供应商引用、上传状态与有效期单独记录。需要供应商素材库的输入，在当前账号和服务支持时准备相应引用；使用本平台媒体引用保留可追溯性，不直接将一个供应商的素材 ID 当作唯一资产。现有正式 API 证据及服务差异见 [Seedance 核查](research/2026-09-07-seedance-priority.md)。

原生音画片段可作为完整素材使用。能否分别引用声音或画面，依据实际素材和 API 能力判断；混合音轨不会因为进入声音分类就自动变成可无损分离的对白音轨。

## 5. 版本、复用与权限

### 固定引用与局部修订

资产条目具有稳定身份；其已确认版本固定设定和引用的媒体集合。镜头/场次引用一个明确版本并说明用途，实际生成输入进一步记录最终媒体和参数。旧图替换为新图时形成新版本，历史生成和交付不漂移。

新版本可提示直接受影响的引用位置；用户选择哪些草稿采用新版。修改不自动触发收费重做，不自动取消历史审片决定；新产物需要自己的选用或审阅结论。完整跨集间接影响分析归入后续迭代。

同一素材可以被不同镜头使用，一段视频可以按区间形成多个候选或剪辑片段。它们只记录用途与区间，不因每次引用都创建一次生成费用。

候选产生、当前选用和剪辑实际使用分别记录。新增候选不自动进入剪辑；更换当前选用后列出仍用旧候选的直接剪辑引用，由用户确认更新哪些草稿并检查时长、区间与声音。已送审、已批准和已交付版本保持固定，新修改产生自己的版本与审阅结论。

### 工作室共享与剧目隔离

剧目创建的内容默认保持剧目范围。MVP 共享库对有效内部成员开放读取和引入，Owner/Admin 负责发布、修订与公共资产制作；项目负责人及协作者可维护本剧资产。初版不单设资产维护者角色，不提供逐资产权限开关。

Owner/Admin 明确具有全项目治理与内容访问权，普通成员按项目参与。生成和下载能力随固定角色开放，生成费用另外受工作室/项目预算约束。长期可以增加专门资产维护职责、共享集合授权及外部访问范围；新 Guest 不自动继承内部共享库读取权。平台内的资产保管归属不替代客户合同中的知识产权约定。

发布共享版本是显式操作：有权者选择需要共享的设定、媒体和使用说明。发布形成独立的共享条目及固定版本，不附带源剧本、其他候选或源项目的访问权限。发布前需要同时有来源读取权限及发布权限，不能借共享操作越过项目隔离。

从共享库引入本剧时，记录所用版本和本剧的使用授权；本剧成员可以使用这些明确引入的内容。共享库更新不会改写本剧采用的版本。需要改造共享内容时，创建本剧派生条目并保留来源；多个剧目不共同编辑同一个活跃草稿。

普通「下架共享」只阻止新引入，不删除已有剧目的已引入版本。删除工作室成员不删除其制作贡献。若业务以后需要撤回已授予的使用权，应单独定义撤回流程；不能把下架按钮当作能收回所有已导出文件的操作。

### 状态与清理

设定状态区分草稿、已确认、已归档；素材可用性区分处理中、可用、失败。选用情况与审阅情况分别记录，不能把「文件可下载」「已选用」「已批准」混为一个状态。草稿可以用于明确标识的试作，不要求所有尝试先走正式审批。

被生成记录、设定版本或交付引用的内容优先归档，仍保留历史访问所需数据。物理清理前检查引用和保留策略；未采用不等于没有依赖，未采用视频也可能是后续续写或编辑的输入。自动清理大量试作、生命周期策略与批量存储优化后续再做。

## 6. 模块设计与最小数据关系

资产模块对其他模块提供少量稳定能力；在模块内部处理文件保存、预览、参考准备、版本与访问权限，不要求各页面重复拼装这些规则。

| 对外能力 | 内部必须处理的规则 |
|---|---|
| 查找与预览 | 当前用户可见范围、分类、标签、来源及媒体可用性 |
| 建立/修订设定 | 资产稳定身份、造型等并存变体、明确修订版本、引用媒体 |
| 引用用于制作 | 源和目标范围权限、用途、明确版本、可用媒体与片段区间 |
| 准备生成参考 | 已选媒体、当前供应商/账号约束、访问地址或供应商引用、实际输入记录 |
| 发布/引入共享内容 | 有权的显式发布、固定快照、本剧使用记录、派生关系 |
| 查使用位置与归档 | 直接引用、可见性过滤、保留历史所需内容 |

核心关系：设定条目 → 设定版本 → 参考媒体；场次/镜头 → 资产引用 → 明确设定版本；生成作业 → 实际输入与输出媒体 → 候选/剪辑区间。工作室和剧目定义访问范围，共享发布与引入定义跨范围复用关系。

长期公共模块复用时，将文件、通用版本、引用和参考准备机制与业务含义分开。角色身份、造型及剧情状态由短剧模块组织，本文相关操作是短剧业务与公共资产模块协作的能力；未来广告商品资料不需要伪装成角色设定。

媒体记录与物理对象分别管理。原文件、预览、代理文件及供应商副本属于不同产物；可复用同一底层文件时也必须各自满足业务授权，不能因内容相同就继承其他项目的访问权限。

项目素材明确租户与项目；工作室共享内容明确共享范围，制作费用记入工作室公共制作成本。跨独立租户的复用不继承工作室共享库规则，需要单独授权的导出/导入或转移；统一结算账户不提供隐式素材访问。

## 7. MVP 与后续迭代

| 版本 | 范围 |
|---|---|
| MVP | 剧目资产与基础工作室共享库；角色/造型、场景、道具、声音、风格及制作素材；上传与生成自动登记；关键词/标签筛选；侧栏选择；固定版本；直接使用位置；显式共享引入；归档与权限 |
| V1 | 更完整的变体比较、跨集间接影响检查、按需增加内部资产维护职责、批量整理、连续性检查辅助 |
| V2 | 语义/视觉检索、相似素材识别、可复用参考组合与制作模板、存储生命周期与供应商引用优化 |

MVP 验收例：两个剧目分别引入同一客厅共享版本；一个剧目修改夜景设定后不改变另一个剧目；同一角色跨两集引用可查；一个镜头更换造型后旧交付仍可重建；普通成员能使用共享参考但不能读取未加入项目的剧本和素材；Owner/Admin 可访问全部项目并发布共享，协作者不能修改共享原版；一次生成的连续片段用于多个镜头时来源和费用仍一致。

该模块验收还需覆盖生成成功但素材入库失败、参考准备失败、使用已归档版本、角色同名匹配冲突，以及归档仍被续写或编辑引用的素材。本文定义待验证行为，没有声称已经完成实现或测试。
